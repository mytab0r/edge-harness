# Дельта-спека: journal-tasks-hands — приоритет пула по графу блокировок

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Автономный
воркер (конвейер пула)», пп. 26/28.

## MODIFIED: Выбор свободной задачи учитывает приоритет, не только дату

~~Свободная = открыта, метка `task`, без assignee; открытый PR без
исполнителя задачу из пула НЕ исключает — она остаётся кандидатом как
задача на доводку существующего PR (#245).~~

Требование: среди СВОБОДНЫХ задач (критерий свободы не меняется — открыта,
метка `task`, без assignee, без живой аренды #121) выбор идёт по трём
уровням приоритета, в этом порядке:

1. Метка `area:process` (задача про сам процесс работы — протокол,
   гвардии, контракт, приёмка, аренда, ревью-гейты, CI-ворота) — раньше
   любой задачи без этой метки, независимо от остальных уровней.
2. Внутри уровня — число ОТКРЫТЫХ задач, которые эта задача блокирует
   (нативный GitHub-граф `blockedBy`/`blocking`, читается через
   `scripts/lib/task_deps.py`, не прозопарсинг тела) — больше блокирует,
   выбирается раньше.
3. При равенстве — номер issue как proxy даты создания (монотонен по
   построению GitHub) — меньше номер, раньше выбор.

Граф зависимостей пуст или ни одна задача пула не помечена `area:process`
→ видимый сигнал (предупреждение в stderr `free_task.py`), не молчаливое
вырождение в сортировку по номеру без объяснения; сам выбор при этом не
останавливается — вырождение в уровень 3 для всех кандидатов легитимно.

Сценарий: задача A (`area:process`, блокирует 1 открытую) и задача B (без
`area:process`, блокирует 10 открытых) — A выбирается раньше B: мета-уровень
решает первым, число блокируемых не пересматривает порядок между уровнями.

Сценарий: задачи A и B обе без `area:process`, A блокирует 3 открытые, B —
0 → A выбирается раньше B.

Сценарий: задачи A (#50) и B (#80), обе без `area:process`, обе блокируют
0 → A выбирается раньше B (меньше номер, proxy даты).

Сценарий: блокирующая задача C, которую блокировала выбранная ранее задача
D, закрывается → следующий запуск планировщика/воркера видит уменьшённое
число блокируемых у D (пересчёт живой, не кэш) без ручного снятия метки
или правки графа.

## MODIFIED: Захват задачи воркером — источник пула

Требование, добавленное этим изменением: пул кандидатов для выбора (до
фильтра свободы и аренды) собирается через `scripts/lib/task_deps.py`
(GraphQL) — REST-листинг (`gh issue list`) не отдаёт поля
`blockedBy`/`blocking`/`issueDependenciesSummary`, только GraphQL. Сборка
пула — одно место, не два расходящихся запроса (REST для списка + GraphQL
для графа): `task_deps.py` возвращает всё необходимое (`number`, `title`,
`assignees`, `labels`, число ОТКРЫТЫХ `blocking`) одним пагинированным
запросом.
