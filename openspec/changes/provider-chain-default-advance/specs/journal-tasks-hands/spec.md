# Дельта-спека: умолчание классификатора цепочки провайдеров перевёрнуто (#1084)

Правит требование «Требование: классификация перехода — по классу отказа…»
из дельта-спеки `llm-provider-chain-failover`
(`openspec/changes/archive/llm-provider-chain-failover/specs/
journal-tasks-hands/spec.md`, раздел «ADDED: Автоматический переход между
LLM-провайдерами по классу отказа»).

## MODIFIED: Классификация перехода — умолчание «переключаемся», не «стоп»

Было: «Любой другой отказ (нет ни одного из этих признаков в stderr) —
цепочка ОСТАНАВЛИВАЕТСЯ немедленно, следующие провайдеры не трогаются: смена
провайдера не спасает от битого ключа/модели/запроса, а сожжённая впустую
попытка против исправного провайдера дороже честного быстрого отказа.»

Требование: буквальный текст `STREAM_CLOSED:` в stderr (обрыв SSE-потока без
терминального `[DONE]`) переключает на следующего провайдера, тем же
классом, что `HTTP_404:`/`EMPTY_RESPONSE:` — прод-форма дословно, «dsh:
STREAM_CLOSED: SSE stream ended without [DONE]» (прогон worker.yml
2026-09-13T09:39Z, задача #1055/#1087; тот же текст — OpenRouter-2, тот же
прогон 2026-09-13T00:07Z, другой канал).

Требование: класс отказа, НЕ совпавший ни с одним явным признаком
(`quota_exhausted`/`rate_limit_retry_budget_exceeded`, наш таймаут `rc=124`,
`HTTP_404:`/`EMPTY_RESPONSE:`, `STREAM_CLOSED:`, `INVALID_REQUEST:` про
max_tokens, пустой stderr), ПЕРЕКЛЮЧАЕТ на следующего провайдера — не
останавливает цепочку. Довод: цена ошибки «переключились зря» — время
следующей записи цепочки, ограниченное её длиной (не бесконечный цикл);
цена ошибки «остановились зря» — потеря всей оставшейся цепочки и всего
прогона целиком, как показал живой инцидент #1084. Частичный результат
агента (коммиты в ветке задачи) при этом не теряется — критерий успеха
воркера смотрит на origin, не на факт «эта попытка ответила» (см. delta
`worker-success-criterion`/#935/#937).

Требование: явный именованный стоп-класс (возврат «стоп», а не
«переключаемся») существует ТОЛЬКО для причин, чей прод-форма (текст
stderr, номер живого прогона) подтверждена документально в комментарии
рядом с классом — тем же порядком, что `HTTP_404`/`RATE_LIMIT`/
`INVALID_REQUEST`/`STREAM_CLOSED`. На 2026-09-13 такой подтверждённой
причины нет: прежний кандидат (`INVALID_API_KEY:`, явный отказ credentials
записи) существовал только как синтетическая фикстура смоука с #727, ни
один живой прогон его не показал — снят как неподтверждённый (AGENTS.md,
«не знаешь — пиши "не подтверждено"», «Тест кормит прод-форму данных, а не
пересказ»). Функция `dsh_chain_should_advance`
(`scripts/lib/dsh-ci.sh`) на этот момент не несёт ни одной ветки с
`return 1`. Появление живой цитаты подтверждённого нелечимого переключением
отказа — повод добавить именованную стоп-ветку тем же порядком (прод-форма
+ номер прогона), не повод считать текущее умолчание временным недосмотром.

Не входит: ошибка контракта вердикта модели (ответ получен, `rc=0`, но без
финальной строки «ВЕРДИКТ: …») по-прежнему не попадает в эту функцию вовсе
— решается выше по стеку (`ai_review.py::parse_verdict`), не затронута этим
change (унаследовано от `llm-provider-chain-failover` без изменений).
