# Цепочка провайдеров: умолчание классификатора отказа перевёрнуто

Задача: #1084.

Дельта-спека: [specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Summary

`dsh_chain_should_advance` (`scripts/lib/dsh-ci.sh`) до этого change несла
умолчание «нераспознанный класс отказа — стоп, цепочка дальше не идёт»,
задокументированное как ADDED-требование в уже архивной дельта-спеке
`openspec/changes/archive/llm-provider-chain-failover/specs/
journal-tasks-hands/spec.md` («Любой другой отказ — цепочка ОСТАНАВЛИВАЕТСЯ
немедленно… сожжённая впустую попытка против исправного провайдера дороже
честного быстрого отказа»). Живой инцидент показал обратное: новый класс
транспортного сбоя (`STREAM_CLOSED`, обрыв SSE-потока) не совпадал ни с
одним из перечисленных признаков и падал в этот стоп-класс, останавливая
всю цепочку целиком — ровно тот сценарий, которого исходное требование
пыталось избежать («сожжённая попытка»), но applied к транспортному сбою, а
не к настройке/credentials.

Это предложение переворачивает умолчание: нераспознанный класс отказа
теперь ПЕРЕКЛЮЧАЕТ на следующего провайдера, а не стопорит цепочку. Именной
стоп-класс, который должен был остаться единственным исключением
(`INVALID_API_KEY:`), при проверке оказался неподтверждённой синтетической
фикстурой смоука с самого #727 — ни один живой прогон его не показал — и
снят целиком до появления живой цитаты (AGENTS.md, «не знаешь — пиши
"не подтверждено"»).

## Problem / Motivation

Живой инцидент (прогон worker.yml 2026-09-13T09:39Z, задача #1055/#1087):
GLM — единственный реально отвечавший провайдер цепочки в этом окне (медиана
~1207с, 14 успешных завершений за предыдущие сутки, остальные записи цепочки
либо молчат, либо падают раньше) — оборвал SSE-поток без терминального
`[DONE]`. Текст `STREAM_CLOSED: SSE stream ended without [DONE]` не совпадал
ни с одним явным признаком `dsh_chain_should_advance` и падал в стоп-класс:
цепочка остановилась, пять непопробованных записей (Ollama-2/3/1,
NVIDIA-NIM-1/2) не тронуты, прогон потерян целиком.

Тот же текст видели у OpenRouter-2 той же ночью, в другом прогоне
(2026-09-13T00:07Z) — второй живой замер, не один. Задача #1084 называла
порог «3+ живых замера» до решения по добавлению нового явного класса; этот
change решает задачу иначе — не добавлением ТРЕТЬЕЙ строки в список
известных транспортных сбоев (тот же паттерн, что уже потребовал трёх
отдельных инцидентов ради трёх строк — #737/#877/#1062), а переворотом
умолчания, при котором третий живой замер для решения не нужен: каждый
новый, ещё не виденный текст транспортного сбоя переключает по умолчанию, а
не стопорит цепочку до тех пор, пока кто-то не заметит упавший прогон и не
допишет строку постфактум.

## Scope

### In

- `scripts/lib/dsh-ci.sh::dsh_chain_should_advance`: явный переключаемый
  класс `STREAM_CLOSED:` (симметричный уже существующему
  `HTTP_404:`/`EMPTY_RESPONSE:`); умолчание для НЕ распознанного класса
  изменено со «стоп» на «переключаемся».
- Снятие именованного стоп-класса `INVALID_API_KEY:` как неподтверждённого
  прод-формой (см. «Не подтверждено» в комментарии над функцией) — на
  2026-09-13 в функции нет ни одной ветки, возвращающей «стоп».
- `scripts/lib/test/dsh-provider-chain.smoke.sh`: сценарии, доказывающие
  оба факта мутацией (снятие явной ветки `STREAM_CLOSED` красит отдельный
  сценарий; возврат старого умолчания — отдельный сценарий).
- `docs/runbooks/switch-llm-provider.md` — раздел «Цепочка провайдеров»
  назвал новое умолчание и честно — отсутствие подтверждённого стоп-класса.
- Эта дельта-спека, отменяющая требование «любой другой отказ — стоп» из
  архивной `llm-provider-chain-failover`.

### Out

- Поиск/добавление НОВОГО подтверждённого стоп-класса (например, живая
  цитата отказа credentials) — не входит: как только появится прод-форма
  из реального прогона, она добавляется отдельной точечной правкой тем же
  порядком, что HTTP_404/RATE_LIMIT/INVALID_REQUEST/STREAM_CLOSED (прод-
  форма + номер прогона + именованная ветка).
- Пул Claude (`anthropic-oauth-pool`, #1097/PR #1099) — отдельный механизм
  на отдельном протокольном пути (`_dsh_patch_profile_anthropic_pool`), не
  проходит через `dsh_chain_should_advance` вовсе.
- Обработка ошибки контракта вердикта модели (`ai_review.py::parse_verdict`)
  — уже решена выше по стеку, эта функция её не видит, не меняется этим
  change.

## Acceptance criteria

- [x] `dsh_chain_should_advance` переключает на `STREAM_CLOSED:` явной
      веткой — доказано смоуком, мутация (снятие ветки) красит отдельный
      сценарий с точным сообщением.
- [x] Умолчание для нераспознанного класса — «переключаемся», не «стоп» —
      доказано смоуком, мутация (возврат старого catch-all `return 1`)
      красит отдельный сценарий.
- [x] Именованный стоп-класс `INVALID_API_KEY:` снят, честно
      задокументирован как неподтверждённый — не осталось активной ветки с
      `return 1` в функции.
- [x] `docs/runbooks/switch-llm-provider.md` назвал новое умолчание.
- [x] Эта дельта-спека отменяет требование архивной `llm-provider-chain-
      failover` («любой другой отказ — стоп»).
