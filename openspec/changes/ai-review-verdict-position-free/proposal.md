# ai-review-verdict-position-free: вердикт принимается по единственности, не по позиции (#1332)

Задача: #1332. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Второй гейт конвейера (#18) различает `approve`/`rework`/`error` по машиночитаемой
строке `ВЕРДИКТ: …` (`scripts/review/ai_review.py::parse_verdict`). Контракт требовал
от этой строки ДВУХ свойств сразу: единственности И позиции (последняя непустая
строка ответа). Второе свойство не снимало неоднозначности — её снимает первое, —
но отбрасывало корректные вердикты целиком.

Замер 2026-09-16 (тринадцать последних вердиктов по комментариям PR): десять
`contract_violation`, три `transport_error`, **ноль `approve`, ноль `rework`**. Гейт
не выдал ни одного пригодного вердикта, при этом каждый прогон — живой вызов модели
и минуты раннера. Разбор одиннадцати упавших прогонов по логам:

| раз | причина |
|---|---|
| 5 | строки «ВЕРДИКТ: …» нет вообще |
| 3 | строка есть, но не единственная и/или **не последняя** |
| 3 | цепочка исчерпана (отказ ДО модели) |

Живой случай третьей строки — PR #1328, прогон `ai-review.yml` 35155260819: модель
выдала `ВЕРДИКТ: approve` ПЕРВОЙ строкой и следом содержательный разбор; гейт
выбросил одобрение, PR встал с меткой `ai:failed`. Модели, обслуживающие цепочку,
склонны дописывать мета-комментарий после решения — контракт, воюющий с этой
склонностью, проигрывал ей на каждом прогоне.

## Что делается

- `parse_verdict` требует от маркера ТОЛЬКО единственности; позиция не проверяется.
  Ноль маркеров и два маркера по-прежнему `error` — решение не угадывается по прозе
  (AGENTS.md, «алерт не гадает»).
- Промпт (`scripts/review/ai_prompt.md`) перестал обещать, что не-последняя строка
  ломает разбор: просит ставить её последней ради читателя-человека и отдельно
  предупреждает, что забыть строку совсем — самая дорогая ошибка.
- Второй дефект того же разбора: отказ ДО ответа модели (исчерпание цепочки, пустой
  дифф, транспорт) печатался под шапкой «ответ не соответствует контракту вердикта»,
  хотя модель ничего не отвечала. Шапка разведена по классам функцией
  `error_headline`; признак класса — общая константа `REVIEW_NEVER_HAPPENED_PREFIX`,
  на которую переведены все семь веток составителя причины (одно место правды вместо
  подстроки, повторённой в каждой). Тот же класс, что закрывался в
  `scripts/worker/task.sh` (#1322): одна шапка на разные классы отказа.

## Что НЕ делается этой дельтой

Пять отказов из одиннадцати — ответ БЕЗ строки вердикта вовсе. Это не обрыв по лимиту
вывода: сырой ответ прогона 35164733834 целый, заканчивается `КЛАСС: скрытая-регрессия`
— то есть модель рассуждает вслух и не доходит до маркера. Промпт усилен, но механизма
это не даёт; остаток остаётся в #1332 после мержа этой части.

## Носитель решения

Тесты `scripts/review/test_ai_review.py`, мутационно проверенные (каждая мутация
краснит СВОЮ проверку): возврат требования позиции; снятие единственности; возврат
общей шапки отказа; ветка отказа-до-модели, написанная мимо константы префикса.
