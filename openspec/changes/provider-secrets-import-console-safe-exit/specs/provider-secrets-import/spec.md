# Дельта-спека: печать отчёта provider_secrets_import.py не маскирует успех

Новая узкая капабилити-спека для `scripts/lib/provider_secrets_import.py`
(файл ранее не описывался ни в одной дельте openspec — проверено
`grep -rl provider_secrets_import openspec/`, пусто). Мержится в
`openspec/specs/journal-tasks-hands.md` не требуется — скрипт не часть
конвейера пула/hands, он одноразовый CLI оператора (см. докстринг файла).

## ADDED: кодировка stdout безопасна для отчёта

Требование: перед первой печатью в `main()` вызывается канонический
`scripts/lib/console_utf8.py::ensure_utf8_stdio()` (тот же хелпер, что
issue #723/PR #726 подключает во всех точках входа репозитория) — один раз
при импорте файла (bootstrap-блок) и ещё раз явно первой строкой `main()`.
Stdout переключается на UTF-8 с `errors="backslashreplace"`, если поток это
поддерживает (`hasattr(stream, "reconfigure")`). Отчёт `render_report(...)`
(несёт не-ASCII символы — кириллицу, стрелку `→`) печатается без падения
на Windows-консоли/перехваченном stdout независимо от локали процесса
(cp1251, cp866).

Сценарий: `main()` вызван с настоящим `io.TextIOWrapper(encoding="cp1251",
errors="strict")` вместо stdout — отчёт долетает до stdout целиком (символ
`→` виден в потоке в UTF-8-байтах), код возврата 0.

## ADDED: код возврата не зависит от успеха печати отчёта

Требование: необратимые действия (`set_secret`/`set_variable` при `--apply`)
выполняются РАНЬШЕ печати финального отчёта в `main()`. Сбой печати самого
отчёта (`UnicodeEncodeError`) перехватывается отдельно от всей остальной
логики `main()`: код возврата остаётся `0`, а в stderr уходит громкое
сообщение о сбое печати вместе с текстом отчёта (не теряется молча) — это
не тот же случай, что провал самой записи секретов/переменной (тот
по-прежнему остаётся в теле отчёта построчно, `secret_status`/`suite_status`,
и не подменяется этим механизмом).

Сценарий: `--apply` реально выполнил `set_secret`/`set_variable` (мок
регистрирует вызовы), stdout — поток, чей `write` падает на не-ASCII символе
(нет `reconfigure`, симулирует крайний случай, когда предыдущее требование не
сработало) → `main()` возвращает `0`, вызовы `set_secret`/`set_variable`
зафиксированы как реально произошедшие.

## Не изменяется

Семантика `secret_status`/`suite_status` (идемпотентность, дисквалификация по
рангу, состав отчёта построчно) — эта дельта не трогает `select_accounts`,
`classify_snapshot`, `classify_probe`, `probe_provider` (область PR #781).
