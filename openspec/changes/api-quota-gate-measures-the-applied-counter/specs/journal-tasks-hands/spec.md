# Дельта-спека: руки (journal-tasks-hands) — гейт квоты GitHub API (#1437)

## MODIFIED: Ранний отказ по квоте GitHub API

~~Гейт читает `.resources.core` из `gh api rate_limit` и сравнивает
`remaining` с порогом. Мало квоты — дорогой шаг пропускается, job остаётся
зелёным.~~

Требование: гейт принимает решение по счётчику, который РЕАЛЬНО применяется,
и никогда — по счётчику, который его не предсказывает.

Сценарии:

1. Источники остатка расходятся → решение по МЕНЬШЕМУ. Живой случай:
   `rate_limit` отдал полный бак 5000/5000 за 2 мин 41 с до 403 по тому же
   токену в том же job'е; `remaining == limit` означает, что на этом
   счётчике не потрачено ничего, то есть он не тот.
2. Оба остатка печатаются рядом в каждом прогоне, а не только при пропуске.
   Иначе следующий 403 снова придётся ловить отдельной кампанией: замер
   обязан быть побочным продуктом обычной работы.
3. Применяемый счётчик прочитать не удалось (нет заголовков, отказ запроса,
   репозиторий не назван) → громкий отказ, дорогой путь НЕ идёт вперёд.
   Откат к «ну, `rate_limit` же сказал ок» — это и есть исходный дефект,
   перенесённый на этаж ниже.

## ADDED: Все читатели API job'а — за одним гейтом

Требование: шаг workflow, которому передан токен job'а (`GH_TOKEN:
${{ github.token }}`), либо стоит за условием гейта квоты своего job'а,
либо перечислен в реестре исключений с ПРИЧИНОЙ.

Сценарии:

1. Шаг читает API мимо гейта и в реестре его нет → нарушение, CI красный.
2. Шаг закрыт гейтом → нарушения нет.
3. Запись реестра без причины → нарушение: разрешение без основания
   неотличимо от «дописали, чтобы позеленело».
4. Запись реестра, которой в workflow больше не соответствует незакрытый шаг
   (закрыли гейтом, переименовали, удалили) → нарушение: реестр не имеет
   права врать про размер долга.
5. Токен выдан на уровне job или workflow, а не шага → шаг всё равно
   считается читателем API: радиус там шире, и проверка только step-level
   `env` пропустила бы самый широкий случай молча.
6. Шагу передан личный PAT (`secrets.*`), а не токен job'а → под требование
   не попадает: это другой бюджет, гасить шаг из-за чужой квоты — тормоз
   без причины.
7. Условие ссылается на гейт из ДРУГОГО job'а → не считается закрытым:
   `steps.<id>` виден только внутри своего job'а, в чужом вычисляется в
   пустую строку и шаг исполняется всегда.
8. Сам шаг-гейт нарушением не считается никогда — иначе гвардия штрафовала
   бы ровно за починку.

Признак «шаг читает API» машинный (наличие токена job'а в `env` шага, job'а
или workflow), а не чтение `run:` на глаз: разбор прозы команды пропустил бы
любой вызов через собственный скрипт.

## Честный потолок

Что заголовки `X-Ratelimit-*` отражают применяемый бак именно для
`github.token` в Actions — не подтверждено (замер сделан на PAT). Решение по
минимуму безопасно при любом исходе, но «измеритель починен» сказать пока
нельзя; можно сказать «измеритель больше не полагается на источник,
доказанно не предсказывающий отказ».

Из 29 измеренных незакрытых шагов этим изменением закрыто 3 (все в
`repo-ci.yml::test`, кроме перебора каталога гвардий — его гасить целиком
неверно по существу). Остальные 26 зафиксированы реестром с причиной и
разбираются отдельными задачами со своим замером на каждую.
