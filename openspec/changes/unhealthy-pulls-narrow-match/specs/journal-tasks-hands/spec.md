# Дельта-спека: `unhealthy_pulls` больше не в списке широкой семантики (#286)

Уточняет `openspec/specs/journal-tasks-hands.md`, п. 17.1 («Резолвер
«PR → задача» для контекста AI-ревью, #259»).

## MODIFIED: п. 17.1 — `unhealthy_pulls` сопоставляет PR с задачей узко

Базовая спека, п. 17.1 (хвост абзаца): «Правила `reap_stale`/
`unhealthy_pulls`/`after_merge` намеренно продолжают использовать широкую
семантику упоминания — сужение там было бы регрессией, не улучшением».

Это утверждение верно для `reap_stale`/`after_merge` (там ошибка широты
дешевле — «не тронули вовремя»), но было неверным для `unhealthy_pulls`:
там та же широта означала «сняли аренду ЧУЖОЙ задачи» по случайному
упоминанию номера в прозе тела чужого PR — цена ошибки другая, сужение там
не регрессия, а починка (живой случай: 2026-09-04 задача #90 дважды
лишилась аренды из-за тела PR #181, чья собственная задача по имени ветки
— #179, к #90 отношения не имеет).

Тот же хвост абзаца одновременно правит и активная дельта
`telegram-merge-declared-task-only` (#404, `after_merge` — выбор задачи для
Telegram-сообщения о слиянии). Обе дельты несут ОДИНАКОВЫЙ текст замены
(см. ниже), чтобы сложение с базовой спекой не зависело от порядка, в
котором они архивируются: какая бы из двух ни применилась последней,
результат — один и тот же полный текст, не половина.

Замена хвоста абзаца:

> Правило `reap_stale` и `after_merge` (освобождение замков, напоминания о
> пост-мерж проверке) намеренно продолжают использовать широкую семантику
> упоминания — сужение там было бы регрессией, не улучшением. `unhealthy_pulls`
> (#286) в этот список не входит: сопоставление PR → задача там — ТОЛЬКО
> `task_ref.resolve_pr_task` (имя agent-ветки, тело PR не читается), та же
> узкая семантика, что уже использует `contract_check.py` и
> `scripts/review/ai_review.py`. PR без agent-ветки нужной формы не
> сопоставляется ни с одной задачей вовсе — «задача не определена», а не
> «наверное вот эта». Утверждение «этот PR выполнил задачу N» (выбор задачи
> для Telegram-сообщения о слиянии) широкой семантикой тоже не является —
> это узкий вопрос о декларации (`task_ref.declares_task`), как у приёмки
> (#404).

## Не меняется

`UNHEALTHY_PR_AFTER_MINUTES` (120, `pulse_guard.py`) в этом change не
меняется — это предусловие для его уменьшения: до правки матчера
уменьшение порога учащало бы именно те ложные снятия чужой аренды, которые
эта правка устраняет.

`reap_stale` и `after_merge` продолжают использовать широкую семантику
(`pr_references_issue`/`task_ref.extract_task_refs`) без изменений — не
предмет этого change.
