# dsh-pulse-self-update: морда dsh-edge обновляется пульсом, а не schedule'ом

Задача: #73. Проблема: GitHub schedule на репо не тикает вовсе (0 запусков
deploy-dsh-edge по cron; то же измерение, что заставило перенести пульс в DO —
см. config.ts HEARTBEAT), а npm dsh-edge релизится по несколько раз в сутки —
плашка «есть апдейт» возвращается между ручными деплоями.

## Решение

В существующий alarm-тик DO (edge-harness) добавлена самопроверка:

1. Пульс сверяет версию, которую отдаёт публичный `/api/health` морды, с
   `version` из `https://registry.npmjs.org/dsh-edge/latest`.
2. Расхождение при истёкшем троттле (`DSH_EDGE_UPDATE.throttleMs`) →
   `workflow_dispatch` `deploy-dsh-edge.yml` (тот же механизм, что dispatch
   orchestra). Деплой ставит последнюю → следующий тик видит равенство.
3. Пометка попытки пишется в storage ДО диспетча — упавший деплой не
   превращает пульс в штурм.
4. Любой сбой сверки не роняет пульс: тик перезакладывается до проверки.

## Спека

- `openspec/specs/journal-tasks-hands.md` — новый раздел «Самообновление морды»
  (п.23–25): требование к сверке, троттлу и живости пульса при сбоях.

## Что вне рамок

- Даунгрейд на конкретную версию — вручную через workflow_dispatch с input.
- Автообновление каркаса (edge-harness) — деплой и так следует за main.
