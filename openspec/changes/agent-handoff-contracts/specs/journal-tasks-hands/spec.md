18. Задача закрывается исполнителем ПОСЛЕ пост-мерж проверки, с
    приложением улик в задаче. Ключевые слова авто-закрытия
    (`Closes|Fixes|Resolves #N`) в теле PR запрещены: контракт отклоняет
    такой PR (GitHub закрыл бы задачу при слиянии), оркестратор задачи не
    закрывает никогда - мерж доказывает PR, а не готовность задачи. После
    слияния оркестратор диспетчеризует прогон tester по задаче (тем же
    каналом, что `dispatch_worker`) вместо только напоминания;
    "исполнитель" в этом пункте — tester, запущенный этим прогоном, а не
    обязательно тот же агент, что открывал PR. Оркестратор по-прежнему
    НЕ закрывает задачу сам ни в каком случае: закрытие — действие
    tester-прогона при `GATE #2: PASS` (`specs/agent-handoff-contracts/
    spec.md`, "Приёмка после мержа диспетчеризуется автоматически"),
    публикуемое тем же путём, каким сейчас публикуется напоминание.

Единственное изменение относительно действующего текста: напоминание
`after_merge` дополняется автоматическим запуском tester по тому же
множеству задач (не заменяет ручной путь - человек по-прежнему может
провести пост-мерж проверку и закрыть issue сам, до того как отработает
автоматический прогон). Правило "оркестратор не закрывает задачи никогда"
не меняется - закрывает по-прежнему исполнитель (tester), не сам
оркестратор.
