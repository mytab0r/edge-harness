# Дельта-спека: реестр реакций на мерж (#955, следствие #929)

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Конвейер
(оркестратор)»: новый подраздел «Реакция на мерж без push-события (#955)».

## ADDED: единый реестр вместо точечных диспатчей

Требование: workflow, которым для срабатывания нужен push-прогон по
`main` (`repo-ci.yml`, `codeql.yml`, `worker-ci.yml`, `deploy-worker.yml`,
`deploy-dsh-edge.yml`), явно диспатчатся после каждого автономного мержа
(`scheduler.py::after_merge`) по одной декларативной таблице
`config/merge-reactions.json` («путь-префикс → workflow»), а не отдельными
рукописными вызовами на каждый канал.

Требование: workflow, сознательно исключённый из авто-диспатча (например
`plugin-forge.yml` — нужны динамические входы, которых плоская запись
`prefix→workflow` не выражает), перечислен в разделе `excluded` реестра с
причиной — молчаливое отсутствие записи неотличимо от забытого случая.

## ADDED: дедуп диспатча по head_sha

Требование: перед диспатчем каждого workflow реестра проверяется, есть ли
уже прогон Actions API на `merge_commit_sha` этого мержа; если есть —
диспатч не повторяется (закрывает живой класс двойного прогона: push-событие
+ ручной/явный dispatch на один и тот же коммит).

Требование: сбой проверки или диспатча ОДНОГО workflow (сетевая ошибка,
квота) не отменяет диспатч остальных workflow того же реестра — каждый
элемент реестра обрабатывается независимо, сбой отражается наблюдением в
списке действий мержа, не поднимается как общее исключение, обрывающее цикл.

## ADDED: гвардия — новый push-workflow не может остаться незарегистрированным

Требование: `.github/workflows/*.yml` с триггером `on.push`, покрывающим
`main`, обязан быть либо записью реестра (`reactions`), либо записью
`excluded` с причиной — иначе CI красится. Проверка распознаёт все три
валидные формы ключа `on:` в GitHub Actions: словарь (`on: {push: {...}}`),
список коротких имён событий (`on: [push, ...]`) и одиночную строку
(`on: push`) — все три безусловно триггерят push по всем веткам, включая
`main`, когда явного `branches` без `main` нет. Форма, которую распознать
не удалось, трактуется как покрывающая `main` (fail loud), не пропускается
молча.

## ADDED: инвариант отличает «нарушение» от «не смог проверить»

Требование: инвариант, находящий слияния без прогона реакции на свой
`head_sha`, помечает каждого кандидата статусом: `missing` (настоящее
нарушение — прогона нет) либо `unchecked` (проверка не удалась — сеть,
квота на Actions API). Отчёт показывает `unchecked` отдельной строкой и не
засчитывает его как «нарушений нет» — сбой инструмента не должен читаться
как здоровое состояние.
