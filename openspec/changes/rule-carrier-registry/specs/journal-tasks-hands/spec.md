# Дельта-спека: журнал (journal-tasks-hands) — реестр правил: носитель, доказательство, доставка

## ADDED: Реестр правил (правило → носитель → доказательство → исполнитель)

41. Каждое нормативное правило репозитория (`AGENTS.md`,
    `docs/agents/PROTOCOL.md`) обязано иметь запись в машиночитаемом
    реестре — один файл `docs/agents/rules/<id>.md` на правило (YAML-шапка
    + текст), а не строка в общем списке. Шапка несёт: `id` (совпадает с
    именем файла), `statement` (короткая формулировка), `scope`
    (непустое подмножество `{human, worker, reviewer, hands, system}`),
    `carrier` (`file::symbol` исполняемого носителя ИЛИ
    `"none: <причина>"`), `carrier_status` (`proven`/`pending`/
    `infeasible`), `proof` (`mutation:<путь к .diff>` ИЛИ
    `"none: <причина>"`). `AGENTS.md` и три промпта исполнения — не
    первоисточник текста, а генерируемая проекция реестра (см. п.43).

    41.1. `carrier` хранится в форме `file::symbol` (имя функции, класса
        или константы), не `file:line` — номер строки резолвится только
        при рендере человекочитаемого вида, не хранится в реестре: правки
        не относящихся к правилу мест того же файла (частая ситуация на
        файлах с несколькими открытыми PR одновременно) не обязаны
        обновлять номер строки в реестре.

    41.2. `carrier_status: infeasible` допустим только с непустой причиной
        в теле файла правила, объясняющей, почему автоматическая проверка
        невозможна или неоправданно дорога — не взаимозаменяем с `pending`
        (правило механизируемо, но ещё не сделано): счётчик долга (п.42)
        учитывает только `pending`.

    41.3. Гвардия схемы (тестовый файл по образцу `scripts/lib/
        test_label_registry.py`) отклоняет запись реестра с отсутствующим
        обязательным ключом, `scope` вне перечисленного множества,
        несогласованной парой `carrier_status`/`proof` (по таблице:
        `proven` требует `carrier` в форме `file::symbol` и `proof` в
        форме `mutation:...`; `pending`/`infeasible` требуют `carrier`
        либо в форме `file::symbol` без мутанта, либо `none: <причина>`),
        или ссылкой `carrier`/`proof`, не резолвящейся в реально
        существующий файл/символ на момент проверки.

42. Число записей реестра с `carrier_status: pending` не может расти
    относительно того же множества файлов на `origin/main` (храповик, не
    ручная константа-порог): проверка на каждый push/PR сравнивает текущее
    число с числом на базовом коммите (`git show <base>:<путь>` по каждому
    файлу реестра) и называет id всех новых `pending`-записей в тексте
    отказа, если число выросло. Снижение долга не требует отдельного шага
    «поднять порог» — базовая точка сравнения сама подтягивается вниз с
    каждым слиянием.

43. `AGENTS.md`, `docs/agents/WORKER-PLAYBOOK.md`,
    `scripts/review/ai_prompt.md` и файл-преамбула канала рук
    (`scripts/hands/RULES-PREAMBLE.md`) несут секции, генерируемые из
    реестра фильтрацией по `scope` (`worker` → плейбук воркера, `reviewer`
    → промпт ревьюера, `hands` → преамбула рук, объединение `worker` +
    `reviewer` + `hands` + `human` → `AGENTS.md`); правило со `scope`,
    состоящим только из `system`, не печатается ни в один из
    человекочитаемых/промптовых файлов — оно существует в реестре только
    для машинной сверки (п.44).

    43.1. Генератор поддерживает режим сравнения: сгенерированный вывод
        сверяется с закоммитенным содержимым внутри объявленных маркеров
        каждого из перечисленных файлов; расхождение — отказ обязательной
        проверки с именем команды, которую нужно запустить и закоммитить
        результат (тот же класс гейта, что применяется к lock-файлам
        пакетных менеджеров).

    43.2. Ручная правка текста правила напрямую в одном из четырёх файлов
        (в обход соответствующего файла реестра) не сохраняется:
        следующий прогон генератора-сравнения находит расхождение и
        требует правки исходного файла реестра, а не сгенерированной
        проекции.

44. Носитель (гвардия по исходнику, `check_*`-функция инвариантов
    состояния репозитория), не упомянутый ни одной записью реестра как
    `carrier`, — находка инварианта обратной связности: правило
    репозитория «носитель обязан быть объявлен» действует симметрично —
    объявленный текстом носитель без кода такой же дефект, как код-носитель
    без объявленного правила. Носитель, рождённый расследованием инцидента
    без отдельного абзаца в `AGENTS.md` (класс «инцидент оставляет
    инвариант, а не только фикс»), получает запись реестра с `scope:
    [system]` и не обязан порождать прозу в `AGENTS.md` — сама запись
    реестра и есть требуемый инвариантом след.

## ADDED: Доказательство носителя — мутационный харнес

45. `carrier_status: proven` требует воспроизводимого факта: применение
    объявленного мутанта (unified diff, нарушающий инвариант, который
    называет правило) к изолированной копии дерева на текущем коммите
    (не к рабочей копии, в которой ведётся разработка) приводит
    объявленный `proof`-тест к ненулевому коду выхода; отсутствие такого
    факта — `carrier_status` не может быть `proven`, максимум `pending`.

    45.1. Патч, переставший применяться к текущему дереву (код-носитель
        изменился несовместимо с мутантом), — красный результат сам по
        себе, не молчаливый пропуск: несовпадение мутанта с кодом
        означает, что связь «правило ↔ носитель» либо устарела, либо
        никогда не была честно доказана.

    45.2. На каждый push/PR мутационная проверка запускается только для
        правил, чей `carrier`-файл входит в список файлов, изменённых
        этим PR относительно базовой ветки (выборочный режим) — полный
        прогон по всем объявленным мутантам выполняется по расписанию
        (не реже раза в сутки), независимо от того, что изменилось в
        конкретном PR: расписание ловит класс «носитель разучился ловить
        нарушение из-за правки в другом месте кода», выборочный режим —
        держит цену проверки в PR близкой к нулю.
