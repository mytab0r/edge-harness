# Задачи: dsh-streaming

Исполнение — через пул Issues. Правила — [PROTOCOL](../../../docs/agents/PROTOCOL.md).
Этот change — дизайн-фаза задачи #69: реализация стартует только после ревью
владельца. Порядок ниже — порядок реализации, первые пункты проверяют самые
рискованные допущения дизайна (см. «Не подтверждено» в design.md).

## 1. Плагин dsh-hands-streamer (в `scripts/dsh-hands-streamer/`)

- [x] Подписки по канону `installWritePath()`: `session/created`,
      `session/event`, `session/flush`, `session/disposed`; `apply` без
      `HANDS_SPOOL` — no-op + warn (чужой ручной прогон не ломается).
- [x] Allowlist-фильтр: `turn/start|end`, `step/start|end`, `user/message`,
      `assistant/message`, `tool/call`, `tool/result`; всё прочее — счётчик
      отброшенного по типам (файл статистики), не в спул.
- [x] Caps payload (константы в одном месте плагина): текст ассистента 48 000,
      `tool/call.arguments` 16 000, текст `tool/result` 16 000; при ОБРЕЗКЕ
      `truncated: true` + исходный размер. Флаг ставится только по факту
      обрезки: неурезанное событие уходит без полей усечения — гвардия в
      юнит-тестах (короткие assistant/message и tool/result не помечаются;
      регрессия на ложный `truncated: true` по наличию текста).
- [x] NDJSON-строка `{v, session_id, seq, time, type, data}` синхронным
      append с `\n`; `session/flush` → write-through файла (никакой сети в
      листенере — барьер `sessions.flush()` dsh-headless не должен уметь
      падать от журнала). Write-through обеспечен синхронным append'ом
      каждой строки — буфера нет, листенеру flush сливать нечего.
- [x] Аварийный клапан `MAX_EVENTS` на сессию: превышение → стоп записи +
      `capped: true` в статистику (громко, не тихо).
- [x] Юнит-проверка контракта спула: фикстура — настоящий `Session.append`
      над `@deepseek-ai/dsh-session` (tarball), не пересказ событий
      (правило «тест кормит прод-форму»); обрыв последней строки без `\n`
      читается как torn tail. (`node --test`, 12 проверок; шаг в repo-ci.)

## 2. Клиент `dsh_task.sh` — drain-цикл

- [x] `HANDS_SPOOL=…` — путь в `$RUNNER_TEMP`, экспорт до
      старта dsh; курсор дрена в файле рядом (счётчик полных строк:
      незавершённая последняя строка — torn tail — не считается).
- [x] Фоновый drain-цикл (интервал ~1 с): новые полные строки спула →
      `redact` на строке → journal-seq (существующий счётчик, посев без
      изменений) → батчи ≤50 строк и ≤700 KB в `POST /api/events` c
      `--connect-timeout`/`--max-time` (зависший curl не вешает стрим и job);
      сбой середины прогона мягкий (батч остаётся в спуле, ретрай следующим
      тиком). Один писатель journal-seq сохранён: drain-цикл и основной поток
      никогда не пишут одновременно, счётчик живёт в файле рядом со спулом.
      seq привязан к позиции строки спула — ретрай тех же строк несёт ТЕ ЖЕ
      seq (идемпотентность `UNIQUE(task_id, seq)` при потерянном ответе
      сервера); верхняя граница аллокации фиксируется до поста — сбой батча
      оставляет дырку, не переиспользование. Курсор дрена — принятые строки,
      обновляется после каждого принятого батча (строки, дописанные во время
      чтения, остаются на следующий тик; принятые не перечитываются).
- [x] kind `session_event`, payload `{session_id, session_seq, type, turn?,
      step?, payload}` — серверных правок не требует; зафиксировать в
      дельта-спеке `openspec/changes/dsh-streaming/spec.md` перед мержем
      кода (правило «меняешь поведение — дельта-спека»).
- [x] Финальный drain перед `job_end` — жёсткий (5 ретраев с бэкоффом, как в
      слайсе 1); после него — `stream_note` (debug) со статистикой плагина
      (счётчики отброшенного, `capped`).
- [x] Громкий отказ «стрим не доставил событий»: прогон успешен, а
      `session_event` == 0 → `agent_error` + `job_end fail` (молчаливая
      деградация слоя доказательств запрещена).
- [x] dsh-прогон завершён, но спул не создан вовсе → тот же громкий отказ с
      другим сообщением: «плагин не смонтировался» ≠ «событий не было».
      (Плюс гвардия до старта dsh: `--dump-config` без строки плагина —
      job падает сразу.)

## 3. Морда — минимальная проекция (рендер уже живого канала)

- [x] `session_event` в ленте журнала: строка читаемого вида
      `turn 3 / step 2 · tool:bash · ok`, усечённый текст; без дерева сессий
      (вне слайса). Канал доставлять не надо — replay + `events.live` уже
      существуют ([спека, п.4-8](../../specs/journal-tasks-hands.md)).
- [x] Гвардия «клиент работает ключами» (ADR 0004) не нарушается: новые kind
      рендерятся из данных события, новых маршрутов нет
      (`npm run check` — зелёный).

## 4. Доказательства (критерий готовности #69)

- [ ] E2E из морды: во время прогона видны `turn/step/tool`-события ДО
      `job_end`; после — финальный ответ и `done`, как в слайсе 1.
- [ ] Нагрузочная рамка: стрим живого прогона не превышает разумный бюджет
      строк (замер: событий на прогон из `stream_note`-статистики).
- [ ] Отказные ветки прогнаны, каждая громкая:
      - плагин не смонтировался (`--dump-config` без строки) → job падает до
        старта dsh;
      - спул не создаётся при живом dsh → `agent_error` «стрим не доставил»;
      - журнал недоступен серединой прогона → прогон выживает, события
        доезжают финальным drain'ом;
      - ретрай job'а → новая сессия (новый `session_id`), дублей нет;
      - обрыв строки спула (kill -9 в момент записи, симуляция обрезкой) →
        torn tail пропущен, префикс доставлен.

## Границы

- Токен-стрим (`assistant/chunk`), богатый UI сессии, субагенты, интерактив —
  вне слайса (design, «чего дизайн намеренно не решает»).
- Сервер DO не меняется вовсе; если окажется, что меняется — это отход от
  дизайна и повод вернуться к ревью, не тихая правка.
