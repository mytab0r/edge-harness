# inbox-auto-revive-configured-token: автодовод failed-директив после появления GH_ISSUES_TOKEN

Задача: #304. Дельта-спека: `specs/journal-tasks-hands/spec.md` (п.34).

## Класс закрываемой ошибки

Критерий #20: «ни одно сообщение владельца не теряется — у каждой директивы
есть issue-след». Пока `GH_ISSUES_TOKEN` не задан, директива честно уходит в
`failed` с `error=issues_not_configured` (ADR 0011) — это правильно (fail
loud вместо тихой потери), но единственным газом был ручной
`POST /api/messages/process {retry_failed:true}`. Владелец, который добавил
секрет через веб-интерфейс (см. ADR 0011, «Миграция»), ожидал бы, что этим
и закончил — но без этого change накопленные `failed` так и остаются
`failed`, пока кто-то не вызовет ручной газ.

## Аудит перед решением (#357)

Проверено на живом репозитории 2026-09-06: `gh secret list` не показывает
`GH_ISSUES_TOKEN`, issues с меткой `source:inbox` — ноль. Раньше сформулированное
предположение «решение владельца — узкий GH_DISPATCH_TOKEN не расширяем,
задачу создаёт job с `permissions: issues: write`» — это РАННЯЯ позиция из
того же обсуждения (PR #173, комментарий 2026-09-03T15:25), впоследствии
превзойдённая финальным, полностью прошедшим ревью и слитым решением: свой
отдельный узкий секрет `GH_ISSUES_TOKEN` (ADR 0011, документ уже существует
в репозитории — `docs/decisions/0011-inbox-issues-token.md`). Код уже
устроен именно так (`cf-worker/src/harness.ts::#createIssue`) —
архитектурных изменений в этом change нет, только автоматизация газа.

## Решение

Пульс DO (`alarm()`), увидев `env.GH_ISSUES_TOKEN` заданным, сам возвращает в
`new` ТОЛЬКО failed-сообщения с `result.error == "issues_not_configured"` —
без отдельного флага «уже разбужено один раз»: строка `issues_not_configured`
пишется `#createIssue` исключительно при отсутствии токена, значит, пока
токен настроен, она физически не может появиться заново — множество
подходящих строк монотонно опустошается. Прочие `failed` (сеть, 403/422,
`stuck_reclaimed`) не трогает — «без штурма прочих failed» (критерий #304).

## Что вне рамок

- Ручной `retry_failed` не убирается — остаётся газом для ЛЮБОЙ причины
  провала, не только `issues_not_configured`.
- Секрет `GH_ISSUES_TOKEN` этим change не заводится — остаётся шагом
  владельца (ADR 0011, «Миграция»).
