# Дельта-спека: журнал (journal-tasks-hands) — автодовод после GH_ISSUES_TOKEN (#304)

Дополняет п.34 (issue-след директивы под `GH_ISSUES_TOKEN`, ADR 0011) —
не отменяет, добавляет автоматический газ вместо только ручного.

## MODIFIED: Инбокс владельца

34. Директива и правка доков (`doc_edit`) → issue под узким `GH_ISSUES_TOKEN`
    (только Issues:RW, ADR 0011) с метками `task`+`source:inbox`. Не заданный
    токен, сеть, 5xx/429 — повторяемая ошибка: сообщение возвращается в `new`
    до `LIMITS.messageMaxAttempts` попыток, затем честный `failed`. Прочие
    4xx — `failed` сразу. Газ после устранения причины —
    `POST /api/messages/process {"retry_failed": true}` (обнуляет попытки
    для ВСЕХ failed, любой причины).

    **Автодовод после появления токена (#304):** пульс (`alarm()`), увидев
    `env.GH_ISSUES_TOKEN` заданным, перед разбором очереди сам возвращает в
    `new` failed-сообщения с `result.error == "issues_not_configured"` —
    узко, только эту причину, не весь `failed`. Отдельного флага «уже
    разбужено один раз» не требуется: `#createIssue` пишет эту строку
    ИСКЛЮЧИТЕЛЬНО при отсутствии токена (первая проверка функции), поэтому
    пока токен настроен, строка физически не появляется заново — множество
    подходящих сообщений монотонно опустошается на первом же тике после
    деплоя с секретом. Владелец: добавил секрет через веб-интерфейс → следующий
    деплой синхронизировал его в воркер → следующий тик пульса сам довёл
    накопленные директивы до issue, без ручного `retry_failed`.
