# guard-catalogue-survives-quota: гвардии каталога переживают исчерпанный бюджет API (#1004)

Задача: #1004. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Прогон 35727716021 (PR #1458, 2026-09-22) показал половину класса, которую
#1437 не закрыл. Гейт квоты отработал ИДЕАЛЬНО:

```
12:33:59 ##[warning]rate_guard: применяемый счётчик GitHub API исчерпан для job'а
         «repo-ci» — дорогой путь пропущен, job остаётся зелёным
```

А обязательная проверка `test` всё равно покраснела — двумя минутами позже, на
шаге «Каталог гвардий»:

```
12:36:58 ##[error]гвардия каталога 'decision-doc-numbering-guard' провалилась
         Traceback … decision_numbering.py … open_pull_refs …
         HTTP 403: API rate limit exceeded for installation
```

Шаг каталога гейтом не гасится — и это правильно: он гоняет ВЕСЬ каталог, где
подавляющее большинство гвардий в API не ходит, и гасить его целиком значило
бы снимать проверки, к квоте отношения не имеющие.

## Ложная посылка, которую я сам и размножил

`run_guards.sh` и комментарий шага в `repo-ci.yml` обосновывали проводку
токена фразой «ни одна гвардия каталога сегодня не читает `gh api` … без
единого потребителя». Issue #1004 завела это как дефект и назвала ОДНОГО
потребителя.

Замер 2026-09-22 (`api_quota_gate_guard.catalogue_modules_reading_api`) даёт
**четырёх**: `ci-guard-registration`, `decision-doc-numbering-guard`,
`mutation-claim-guard`, `plugin-manager-roster-guard`.

Хуже: закрывая #1437, я процитировал этот комментарий в причине реестра
(`_GUARD_CATALOGUE`) вместо того, чтобы замерить — и внёс ложную посылку в
свежий код. Правится тем же PR, вместе с двумя исходными местами.

## Что делается

Одна обёртка на все четыре — `rate_guard.run_guard_main`: исчерпанный бюджет
даёт `::warning::` и код 0 (проверка пропущена, job зелёный), любая другая
ошибка проходит наверх нетронутой. Классификатор один и тот же у гейта и у
обёртки (`rate_guard.is_rate_limit_refusal`), две копии регулярки разошлись бы
на первом же новом тексте отказа.

Класс держит `api_quota_gate_guard.catalogue_problems`: модуль каталога,
читающий API без обёртки, красит CI.

## Честный потолок

Пропущенная гвардия НЕ выполняется — это осознанный размен: красная
обязательная проверка по чужой квоте стоит дороже одного пропуска, а
следующий прогон после сброса бюджета проверит то же самое. Пропуск виден
`::warning::`, а не молчит.
