## Этап 2 — миграция существующих задач-хвостов (следующий PR)

- [x] `scripts/lib/migrate_review_findings.py` (написан этим PR, ЕЩЁ НЕ
      исполнен в `apply`-режиме) — читает открытые задачи-хвосты
      (`gh api ... "Хвост чеклиста ревью PR" in:title is:open`), извлекает
      находки (`- [ ] текст`), для каждой — путь файла: сначала регэксп по
      тексту находки (существующий путь в дереве репозитория), иначе
      broadcast на все файлы породившего PR при фанауте ≤
      `MAX_BROADCAST_FANOUT` (=20), иначе — ручной разбор (design.md,
      развилка 5). Пишет реестр ОДНИМ прогоном (не по находке).

      **Реальный дозорный прогон `plan` (только чтение, 2026-09-14):** 111
      открытых хвостов (число растёт со дня ревизии #1262 — было 110), 415
      находок суммарно. Без потолка broadcast: 221 exact + 194 broadcast →
      1611 записей (медианный фанаут 15 файлов, максимум 100 — PR #409). С
      потолком `MAX_BROADCAST_FANOUT=20`: конечное число пересчитывается
      следующим прогоном `plan` перед `apply` (число «после потолка» не
      застывшая цифра — открытых хвостов на момент реального `apply` будет
      больше 111). **Ручной разбор (PR недоступен) — 0 из 415**: все 111
      породивших PR читаются API без исключения.
- [ ] Прогон `apply` в CI (workflow_dispatch, PAT с contents:write на
      `orchestra`, НЕ из личного рабочего дерева агента) — числа в отчёте
      публикуются в задаче #1262 как факт с адресом (не «перенесено»,
      а «перенесено, реестр на data/review-findings, коммит SHA»).
- [ ] Проверка `search/issues "Хвост чеклиста" in:title is:open` → 0 ПОСЛЕ
