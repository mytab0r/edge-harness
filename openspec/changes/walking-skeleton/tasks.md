# Задачи: walking-skeleton

Порядок значим: каждая следующая опирается на проверенный результат предыдущей.
Задача считается закрытой по видимому результату, а не по «шаг прошёл».

> Ход работ 2026-08-28: код скелета написан, тесты (16) и локальный smoke на `wrangler dev`
> зелёные. Пункты, требующие живого деплоя (и все замеры), остались открытыми — до них
> будет можно дотянуться только после настройки Cloudflare-креденшелов, см. `cf-worker/README.md`.

## 1. Каркас Cloudflare

- [x] `cf-worker/wrangler.jsonc`: воркер, SQLite-backed Durable Object,
      Workers Assets со `single-page-application` и `run_worker_first: ["/api/*"]`
- [x] Durable Object с фиксированным именем `owner`, таблицы событий и очереди в `ctx.storage`
- [x] `.github/workflows/deploy-worker.yml`: деплой при изменениях в `cf-worker/**`
      (требует секретов `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`, без них падает громко)
- [ ] **Доказательство:** воркер отвечает на публичном URL, страница открывается,
      `wrangler tail` показывает запрос *(локальный аналог пройден: `wrangler dev` + smoke)*

## 2. Журнал событий

- [x] `POST /api/events` — приём батча событий с порядковыми номерами
- [x] Идемпотентность: повторная доставка батча не двоит записи *(тест-гвардия зелёная)*
- [x] `GET /api/events?after=&limit=` — replay с пагинацией и заголовком «есть ещё»
- [x] **Доказательство:** тест шлёт батч дважды, в журнале одна копия; replay после
      перезапуска отдаёт те же события *(на настоящем DO SQLite в vitest; переживание
      рестарта процесса доказывается деплоем)*

## 3. Живая страница

- [x] WebSocket `GET /api/events.live`, принят через `acceptWebSocket` (гибернация)
- [x] Клиент писать в сокет не может — попытка закрывает соединение *(тест: код 1008)*
- [x] Страница: журнал, статус рук, кнопка постановки задачи
- [x] Heartbeat: «руки живы», если отметка свежее порога; порог объявлен одной константой
      (`HEARTBEAT_FRESH_MS` в `cf-worker/src/harness.ts`)
- [x] **Доказательство:** событие, записанное через POST, появляется на открытой странице
      без перезагрузки *(проверено smoke-скриптом на wrangler dev: broadcast доходит
      живому сокету; vitest-петля это не доставляет — см. research/22)*; перезагрузка
      сохраняет журнал *(replay-тесты)*

## 4. Руки

- [x] `POST /api/tasks` кладёт задачу в очередь и дёргает `repository_dispatch`
- [x] `.github/workflows/hands.yml` на `repository_dispatch`, **файл на default branch**
      (иначе триггер молча возвращает 204 и ничего не запускает)
- [x] Job шлёт heartbeat и события батчами, выполняет тривиальную работу, завершается
      *(клиент `scripts/hands_client.py` проверен end-to-end на `wrangler dev`;
      seq засевается с сервера — повторный запуск не теряет события)*
- [x] Секрет для `POST /api/events` — из Actions secrets, в логи не печатается
- [ ] **Доказательство:** нажатие кнопки в браузере приводит к появлению job'а, его событий
      на странице и исчезновению статуса «руки живы» после завершения *(нужен живой деплой
      + секреты `HANDS_TOKEN`, `GH_DISPATCH_TOKEN`, `vars.HARNESS_URL`)*

## 5. Замеры — ради них всё и делалось
