# Задачи: walking-skeleton

Порядок значим: каждая следующая опирается на проверенный результат предыдущей.
Задача считается закрытой по видимому результату, а не по «шаг прошёл».

## 1. Каркас Cloudflare

- [ ] `cf-worker/wrangler.jsonc`: воркер, SQLite-backed Durable Object,
      Workers Assets со `single-page-application` и `run_worker_first: ["/api/*"]`
- [ ] Durable Object с фиксированным именем `owner`, таблицы событий и очереди в `ctx.storage`
- [ ] `.github/workflows/deploy-worker.yml`: деплой при изменениях в `cf-worker/**`
- [ ] **Доказательство:** воркер отвечает на публичном URL, страница открывается,
      `wrangler tail` показывает запрос

## 2. Журнал событий

- [ ] `POST /api/events` — приём батча событий с порядковыми номерами
- [ ] Идемпотентность: повторная доставка батча не двоит записи
- [ ] `GET /api/events?after=&limit=` — replay с пагинацией и заголовком «есть ещё»
- [ ] **Доказательство:** тест шлёт батч дважды, в журнале одна копия; replay после
      перезапуска отдаёт те же события

## 3. Живая страница

- [ ] WebSocket `GET /api/events.live`, принят через `acceptWebSocket` (гибернация)
- [ ] Клиент писать в сокет не может — попытка закрывает соединение
- [ ] Страница: журнал, статус рук, кнопка постановки задачи
- [ ] Heartbeat: «руки живы», если отметка свежее порога; порог объявлен одной константой
- [ ] **Доказательство:** событие, записанное через POST, появляется на открытой странице
      без перезагрузки; перезагрузка сохраняет журнал

## 4. Руки

- [ ] `POST /api/tasks` кладёт задачу в очередь и дёргает `repository_dispatch`
- [ ] `.github/workflows/hands.yml` на `repository_dispatch`, **файл на default branch**
      (иначе триггер молча возвращает 204 и ничего не запускает)
- [ ] Job шлёт heartbeat и события батчами, выполняет тривиальную работу, завершается
- [ ] Секрет для `POST /api/events` — из Actions secrets, в логи не печатается
- [ ] **Доказательство:** нажатие кнопки в браузере приводит к появлению job'а, его событий
      на странице и исчезновению статуса «руки живы» после завершения

## 5. Замеры — ради них всё и делалось

- [ ] Не менее 20 замеров задержки от `repository_dispatch` до первого heartbeat
- [ ] Расход CPU на одно входящее событие в Durable Object (метрики или `wrangler tail`)
- [ ] Проверка гипотезы: сбрасывается ли бюджет CPU на бесплатном плане до 10 ms
- [ ] **Доказательство:** числа записаны в
      [`docs/research/99-open-questions.md`](../../docs/research/99-open-questions.md),
      соответствующие пункты переведены из «неизвестно» в измеренное

## 6. Выводы

- [ ] ADR о том, годится ли задержка для интерактивного сценария
- [ ] Если задержка неприемлема — зафиксировать это как факт и назвать цену альтернатив,
      а не молча смириться
- [ ] Дельта-спека: поведение журнала, heartbeat и очереди переезжает в `openspec/specs/`
