# integrations-hub: интеграции внешних систем как инструменты агента

Задача: #115 (эпик). Смежные: [design](design.md), [задачи](tasks.md),
[дельта-спека журнала](specs/journal-tasks-hands/spec.md),
[ADR 0010](../../../docs/decisions/0010-integrations-edge-plugin-rest-tools.md).

## Зачем

Запрос владельца 2026-08-31: раздел интеграций, чтобы можно было разрабатывать
и подключать интеграции (Jira, Bitbucket, Confluence, Slack, Telegram), и
агент ими пользовался. Сегодня ни одного из этих инструментов у агента нет:
чат морды умеет только runner_task/runner_status (GitHub), Telegram живёт в
job'ах раннеров и в чат не торчит.

Архитектурно владелец задал рамку: интеграция = инструмент агента в раннере
(DSH-плагин по прецеденту runner-bridge #95) + хранение кредов (секреты репо
для job'ов, env воркера для морды) + описание в UI (раздел «Интеграции» в
морде по прецеденту plugin-manager #102). Жёсткое ограничение: весь UI —
клиентский DSH-плагин внутри настоящей морды, никаких отдельных страниц.

## Что делается

Один плагин `@edge-harness/dsh-plugin-integrations` (сервер + клиент) и один
реестр `dsh-edge/integrations.json`:

- **Инструменты** (сервер): `jira_issue` (статус и комментарии Jira Cloud),
  `confluence_page` (поиск CQL и чтение страницы), `bitbucket_pr` (создание
  PR в Bitbucket Cloud), `slack_post` (отчёт в канал). Сквозной сценарий
  эпика — `jira_issue` → `runner_task` → `bitbucket_pr` → `slack_post`.
- **Креды**: секреты репозитория → env воркера синком деплоя по именам из
  реестра; значения и их base64-производные не светятся в выводах (scrub).
- **UI** (клиент): секция Settings → Интеграции — состав из реестра, статус
  из журнала (`integration_status`), имена ключей с описаниями.
- **Статусы**: деплой пишет `integration_status` (ready / not_configured с
  именами отсутствующих секретов / failed) в псевдо-задачу `integration:<id>`.
- **Telegram** — переиспользован (#91): в реестре с `wired: "jobs"`, своего
  тула в морде у него нет.

## Чего дизайн намеренно не решает

- Запись в Jira/Confluence (комментарии, переходы статуса) — только чтение;
  при потребности добавляется отдельным инструментом той же половины плагина.
- Git-синхронизация веток Bitbucket (пуш кода) — `bitbucket_pr` создаёт PR
  между существующими ветками; транспорт кода в Bitbucket — отдельная задача,
  если владельцу понадобится.
- MCP-серверы Atlassian/Slack — отвергнуты (ADR 0010): в dsh-edge нет
  MCP-клиента; возврат — при портировании.
