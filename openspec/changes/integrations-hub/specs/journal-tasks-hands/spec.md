# Дельта-спека: журнал (journal-tasks-hands) — статусы интеграций (#115)

## ADDED: Статусы интеграций (integration_status)

Требование: для каждой интеграции из реестра `dsh-edge/integrations.json`
деплой морды пишет в журнал событие `integration_status` в псевдо-задачу
`integration:<id>` — `data: {integration, state, detail?}`. Состав синка и
снимка (какие интеграции, какие имена секретов) шаг деплоя читает из реестра
в рантайме; перечисление имён в env шага — это проводка `${{ secrets.NAME }}`
(GitHub не умеет отдавать секреты динамически), которую держит гвардия
проводки, а не второй список для ручной синхронизации. Состояния:
`ready` (все объявленные секреты синхронизированы, морда задеплоена и
доказана канарейкой), `not_configured` (часть секретов отсутствует — их
имена в `detail`, значения не называются), `failed` (деплой упал после
синхронизации секретов). Транспорт и механика (посев `seq` с сервера,
ретраи, fail-loud градация: финальный статус обязан доехать, иначе job
красный) — общие с `plugin_status`, `scripts/lib/journal_status.sh`.

Сценарий: секрет интеграции не задан в репозитории → деплой зелёный
(интеграция без секрета — незавершённая настройка, а не поломка морды),
в журнале `not_configured` с именами, читатель — раздел «Интеграции» морды
(клиентский плагин `integrations`). Отсутствие событий при живом журнале —
честное «деплой ещё не отчитывался», а не «подключено».

Сценарий: гвардия проводки (`node dsh-edge/integrations.mjs`) на CI и на
деплое — секрет, объявленный в реестре, но не упомянутый в workflow'е своей
проводки (`morde` → deploy-dsh-edge.yml, `jobs` → worker.yml), красит прогон
громко: иначе интеграция молча вечно `not_configured` при существующем
секрете.
