# automations-core: автоматизации — ядро (эпик #116)

Задача: #116. Заведено постфактум — находка AI-ревью PR #241, п.3: change
затрагивает новое API и третий режим аутентификации, а change-каталога не
было. Ядро уже слито (см. коммиты `agent/116-automations-core`), эта
дельта-спека документирует то, что реализовано, и явно откладывает морду.

## Зачем

Владельцу нужен способ реагировать на события конвейера без ручного участия:
собрать дайджест по расписанию, дёрнуть раннера на внешний webhook (например,
из чата), среагировать на событие журнала (`dispatch_failed` и т.п.) задачей
или прогоном. Требование раскладки — ADR 0002 (исполнение в раннере, не в
Workers) и research/30 (dispatch вместо cron не входит в отвергнутый список).

## Что уже сделано (ядро)

- Модель конфига `{trigger → task → report}` — `cf-worker/src/automations.ts`
  (единственное место правды формы: PUT-валидация, раннер и UI читают одну
  и ту же форму).
- Хранилище — таблица `automations` в DO SQLite (журнал остаётся источником
  фактов о прогонах, конфиг — отдельно).
- Триггеры: `schedule` (интервал в часах, кулдаун пульсом), `webhook`
  (внешний вход с HMAC-подписью), `journal` (kind события журнала, кулдаун
  `AUTOMATIONS.journalCooldownMs`, гвардия от зацикливания по собственным
  service-kind'ам автоматизации — `reservedJournalKinds` в `config.ts`).
- Задачи: `digest` (встроенный сборщик), `hands` (прямой прогон раннера по
  тексту), `pool` (issue с меткой `task` — подхватывает существующий пульс
  orchestra).
- Отчёт: `slack`/`telegram`, секреты каналов — в секретах репозитория, в
  конфиге только тип и target.
- API: `GET /api/automations`, `PUT /api/automations/:id`, `DELETE
  /api/automations/:id`, `POST /api/webhooks/:id` — третий режим
  аутентификации (подпись `AUTOMATION_WEBHOOK_SECRET`), задокументирован в
  `openspec/specs/journal-tasks-hands.md` п.20.
- Исполнение — `scripts/automations/run.sh` в раннере (не в Workers): читает
  конфиг через `GET /api/automations`, форма и секреты каналов те же, что
  использует дайджест.
- Journal-триггер срабатывает и на внутренние системные kind'ы
  (`task_queued`, `dispatch_failed`, `task_dispatched`, `first_heartbeat`),
  не только на события из батча раннера — закрыто той же находкой ревью,
  которая завела этот change.
- Троттлинг записи журнала для неаутентифицированного webhook-входа —
  не чаще одного события на reason за `AUTOMATIONS.webhookRejectThrottleMs`.

## Что явно отложено (часть 2, не в этом change)

Морда — DSH-плагин «Автоматизации» по прецеденту plugin-manager (список
автоматизаций, `last_run`, включение/выключение, правка конфига), без
отдельных страниц и воркеров. Заведено отдельной задачей в беклог по итогам
того же ревью, ссылка — issue, созданный `scripts/review/file_tasks.py --pr
241` («DSH-плагин «Автоматизации» — часть 2 эпика #116»). До неё владелец
правит конфиг только через `PUT /api/automations/:id` напрямую.
