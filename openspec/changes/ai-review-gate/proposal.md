# ai-review-gate: AI-ревью диффа — второй гейт с вердикт-меткой

Задача: #18. Детерминированное ревью (первый гейт) ловит секреты, размер и
некомпилируемость, но не содержание: соответствие ADR/спекам и скрытые
регрессии остаётся на человеке. Этот change вводит второго ревьюера —
DSH-агента в trust-зоне без GitHub-токена — и делает его вердикт меткой,
которую оркестратор требует для слияния.

## Решение

1. `scripts/review/ai_review.py` — доверенный транспорт: `gather` (факты PR,
   дифф-пак, задача пула из #N тела, промпт по `scripts/review/ai_prompt.md`)
   и `verdict` (разбор ответа, маскирование, канонический комментарий,
   метка). `scripts/review/ai_dsh.sh` — прогон DSH headless (пины и GLM-патч
   из общей `scripts/lib/dsh-ci.sh`).
2. `.github/workflows/ai-review.yml` — триггер `labeled: review:ok` (первый
   гейт прошёл) и `workflow_dispatch` (input `pr` — повтор после сбоя).
   Trust-зона по шагам: gather (GH_TOKEN) → DSH (НИ GitHub-токена, ни
   git-креденшелов; выход — только файл ответа) → verdict (GH_TOKEN).
3. Контракт вердикта — паттерн живого решения владельца в Harness
   (pr_loop.py): последняя непустая строка ответа ровно `ВЕРДИКТ: approve`
   или `ВЕРДИКТ: rework`; отсутствие/неоднозначность — `error`, никогда не
   одобряет. Метки: `ai:ok` / `ai:changes-requested` / `ai:failed` (последняя
   — с красным job: fail loud).
4. `scripts/lib/review_labels.py` — одно место правды: имена меток обоих
   гейтов, формулировка гейта слияния (`merge_label_gate`: `review:ok` И
   `ai:ok`), снимаемые AI-метки (`ai_verdicts_to_drop`).
5. `scripts/orchestra/scheduler.py` — merge_queue спрашивает гейт у
   `review_labels.merge_label_gate` (до: только `review:ok`).
6. `scripts/review/check_pr.py` — при каждом запуске снимает `ai:*`: вердикт
   AI действителен только для head, на котором сделан (скрипт выполняется на
   каждый пуш). Вместе с проверкой head в verdict-шаге закрывает гонку
   «слив по протухшему вердикту».
7. `scripts/review/file_tasks.py` — задачи в беклог из ревью одной командой:
   `python scripts/review/file_tasks.py --pr N` создаёт issue с меткой `task`
   из канонических фенсов последнего ревью-комментария, идемпотентно по
   заголовку открытой задачи.

## Спека

- `openspec/specs/journal-tasks-hands.md` — «Конвейер (оркестратор)» п.15
  меняется (слияние требует оба гейта), добавляется раздел «AI-ревью
  (второй гейт)» (п.30–34): trust-зона, контракт вердикта, привязка к head,
  задачи в беклог одной командой.

## Что вне рамок

- Ревью мержей/тегов, событий вне PR — гейт определён только на PR.
- «Взятие в работу» задач, заведённых из ревью: это обычные задачи пула,
  их берёт воркер/человек по протоколу.
- Качество находок модели (промпт-инженерия) — настраивается в
  `scripts/review/ai_prompt.md` без смены спеки: контракт ответа неизменен.
- Стрим транскрипта ревью в морду (#119-механика) — отдельная задача, если
  владельцу понадобится наблюдать ревью живьём.
