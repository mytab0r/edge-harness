# Дельта-спека: руки (journal-tasks-hands) — один прогон воркера на задачу (#1448)

## MODIFIED: Диспатч воркера

~~Адресный диспатч доводки гейтится свободным слотом (`free_worker_slot`,
#827): до `WORKER_MAX_CONCURRENCY` прогонов одновременно, пока свободен хотя
бы один слот — диспатч уходит.~~

Требование: свободный слот — НЕОБХОДИМОЕ, но не достаточное условие. Перед
КАЖДЫМ адресным диспатчем проверяется, не идёт ли уже прогон воркера по ЭТОЙ
ЖЕ задаче; идёт — диспатч не выполняется.

Сценарии:

1. По задаче идёт прогон воркера, второй слот свободен → диспатч НЕ
   выполняется, строка отчёта называет ФАКТ: номер задачи и номер живого
   прогона. Молчаливый пропуск не годится — читатель отчёта не должен
   гадать, почему доводка не пошла.
2. Прогон по задаче завершён → диспатч выполняется как раньше. Иначе
   задача, которую однажды доводили, не получила бы доводки никогда:
   тормоз, который нечем снять.
3. Прогоны идут по РАЗНЫМ задачам → оба разрешены. Это и есть смысл двух
   слотов (#827), и требование его не отменяет.
4. Состояние прогона прочитать не удалось → диспатч этого прохода
   пропускается, строка отчёта ⚠️ называет причину. Отказ чтения НЕ
   приравнивается к «живых прогонов нет»: это разные факты, и молчаливое
   их смешение — тот же класс, что закрывает правило «fail loud, не
   silent-wrong».

Требование распространяется на ВСЕ адресные пути диспатча — их три:
доводка по находкам ai-review, расшивка конфликта и адресный прогон при
закрытом WIP-гейте. Признак «адресный» машинный, не на глаз: вызов
`worker.yml/dispatches` несёт `inputs[task]=<номер>`; вызов без него —
generic-дренаж пула, там задачу выбирает сам воркер через аренду.

Закрыть один путь из нескольких значит оставить дверь, через которую дубль
входит ровно так же. Оба раза это находилось не рассуждением: первая
редакция фикса закрыла только доводку ai-review, а задача называла расшивку
конфликта (ai-review PR #1449); третий путь нашёлся прочёсом ВСЕХ вызовов
`worker.yml/dispatches` — их четыре, адресных три.

Почему адресный путь вообще видит задачу с живым прогоном свободной:
адресные диспатчи СНИМАЮТ аренду перед запуском, а «свободная» в пуле
означает «без назначенца». Ни свободный слот, ни отсутствие назначенца
живость прогона не отражают — отсюда и требование.

Признак «прогон по этой задаче» — машинный и не разбор прозы: REST API не
отдаёт `inputs` прогона вовсе (в ответе есть только `display_title`/`name`),
поэтому номер задачи из прогона взять неоткуда. Берётся обратная связь:
воркер сам пишет в ЗАДАЧУ маркер git-шага со своим номером прогона, формат
уже разбирает `ai_rework_attempts`. Живость определяется по признаку
ЗАВЕРШЁННОСТИ (`status != "completed"`), а не перечислением неконечных
статусов — белый список пропускал `pending` (#1260 закрывал ровно этот класс
в соседней ветке того же файла).

## Честный потолок

Прогон, диспатченный секунды назад, до git-шага ещё не дошёл и маркера не
оставил — в этом окне дубль по-прежнему возможен. Порядок окна — минута
против наблюдавшегося разрыва в два с половиной часа. Закрыть его полностью
можно маркером на самом диспатче; делать это до того, как окно окажется
живым, значит чинить незамеренное.

Generic-дренаж пула берёт задачу через аренду, а адресные диспатчи аренду
снимают сами — гейт выше закрывает и этот путь, но корень (снятие замка
перед диспатчем) остаётся. Вариант «передавать замок вместо снятия» назван
в #1448 отдельной работой: он меняет контракт с `task.sh`.
