# no-double-dispatch-per-task: два прогона воркера по одной задаче — не параллелизм, а двойная работа (#1448)

Задача: #1448. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Живой случай 2026-09-22, снятый с Actions:

```
04:48:52  in_progress  worker (slot 2): задача #1426
07:20:34  in_progress  worker (slot 1): задача #1426
```

Адресные диспатчи гейтились только свободным слотом (`free_worker_slot`,
#827), а слотов два. Проверки «прогон ПО ЭТОЙ задаче уже идёт» не было
нигде: `git grep` по `active_run_for_task|run_for_task` давал ноль.

Свободный слот означает «есть куда запустить», а не «по этой задаче никто не
работает». Смысл двух слотов (#827) — две РАЗНЫЕ задачи одновременно; два
прогона по одной задаче этим смыслом не покрыты никогда.

## Цена, измеренная

1. **Квота DO.** Прогон воркера льёт транскрипт в морду по ~360 `rows_read`
   на событие. Два прогона того дня дали 22 828 записей и 8 218 671 чтений
   при суточном лимите 5 000 000 (#1443). Дубль — половина суточной квоты
   аккаунта на уже делаемую работу.
2. **Гонка за ветку.** Оба пушат в одну `agent/<N>-*`; за сутки наблюдалось
   дважды — второй канал перетирал коммиты первого.
3. **Бюджет GitHub API** — из того же, чьё исчерпание красит живые PR чужой
   причиной (#1437).

## Что делается

Гейт «по этой задаче уже идёт прогон» во ВСЕХ адресных путях диспатча.
Адресных путей три (доводка по находкам ai-review, расшивка конфликта,
адресный прогон при закрытом WIP-гейте); признак адресности машинный —
`inputs[task]` в вызове `worker.yml/dispatches`, всего таких вызовов
четыре.

Признак живости тоже машинный: маркер git-шага, который воркер сам пишет в
ЗАДАЧУ со своим номером прогона (формат уже разбирает `ai_rework_attempts`),
плюс запрос состояния этого прогона.

## Чего это НЕ делает

Generic-дренаж пула (`dispatch_worker` по свободной задаче) закрывается тем
же гейтом, но корень остаётся: адресные диспатчи СНИМАЮТ аренду перед
запуском, поэтому задача выглядит свободной для следующего прохода. Вариант
«не снимать замок, а передавать его» назван в #1448 и требует согласования с
`task.sh` (тот берёт аренду в первые секунды и обязан узнать свою) — это
отдельная задача, не этот change.
