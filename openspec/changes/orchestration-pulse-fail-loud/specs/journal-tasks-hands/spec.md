# Дельта-спека: журнал (journal-tasks-hands) — пульс оркестрации (#269)

## ADDED: Пульс оркестрации (дёргает workflow_dispatch orchestra)

30. DO-пульс на каждом тике (issue #269) дёргает `workflow_dispatch`
    `orchestra.yml` тем же alarm'ом, что чинит #23–25 (самообновление морды):
    единственное доказательство приёма — HTTP 204 от GitHub
    (`docs/research/21-github-actions.md`, «успешный HTTP-код — не
    доказательство запуска»); любой другой код ответа (в частности 403
    вторичного rate-limit, 404 протухшего токена/репозитория) — не успех, а
    fail-loud исход, а не тихо трактуемый как удача.
31. Alarm перезакладывает следующий тик (`HEARTBEAT.selfOrchestrationMs`,
    `src/config.ts` — единственное место правды) ПЕРВОЙ операцией, до
    какой-либо попытки dispatch'а: падение или невозможность dispatch'а
    (нет секретов, сеть, отказ GitHub) не может остановить цепочку тиков.
32. Исход последней попытки dispatch'а — видимый durable-артефакт, а не
    строка в логе, который никто не смотрит между дедами:
    `status.last_pulse` (`ts`, `dispatch_ok`, `detail`, `run_confirmed`) и
    предвычисленный сервером `status.pulse_healthy`. Различение обязательно:
    «возможности нет» (секреты не заданы, `detail: "not_configured"`) —
    здоров, это конфигурация, а не поломка; «возможность есть, но dispatch
    провален» — нездоров сразу, без ожидания порога свежести; успешный тик,
    не обновлявшийся дольше `2 × selfOrchestrationMs`, — тоже нездоров (сам
    alarm перестал тикать, а не просто dispatch отказал).
33. HTTP 204 доказывает только ПРИЁМ dispatch'а GitHub'ом, не запуск (находка
    ревью; частый виновник тихой потери — workflow-файл не на default branch,
    `docs/research/21-github-actions.md`, «🔴 Ловушка: файл обязан лежать на
    default branch»). Настоящее подтверждение запуска — появление нового
    run'а `orchestra.yml`, проверяется на СЛЕДУЮЩЕМ тике сравнением id
    последнего run'а (`fetchLatestOrchestraRunId`) с id, замеченным перед
    предыдущим dispatch'ем (`confirmPreviousRun`) — без синхронного ожидания
    внутри alarm. `run_confirmed: false` (принят, но запуск не появился) —
    нездоров сразу, тем же путём, что и явный отказ dispatch'а.
