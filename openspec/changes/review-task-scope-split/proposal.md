# review-task-scope-split: масштаб находки — хвост дописываем в PR, отдельно заводим issue (#426)

Задача: #426. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Автомат `file_tasks.py` заводил issue на каждый блок `ЗАДАЧА: … КОНЕЦ ЗАДАЧИ`
из вердикта AI-ревью без разбора масштаба находки. Замер по маркерам
`filed: #N` за реальные сутки (2026-09-05 03:37 → 2026-09-06 03:37 UTC,
PR #313/#395/#162/#173): 22 задачи заведено автоматом, 5/22 (23%,
консервативная нижняя оценка объективным прокси-критерием) — «хвосты»,
которые правило репозитория «чинить в том же PR, а не плодить задачи»
требует дописывать, а не выносить issue.

## Что делается

- Контракт вердикта (`scripts/review/ai_prompt.md`) получает обязательное
  второе поле блока задачи, сразу после заголовка: `МАСШТАБ: хвост|отдельно`.
  `хвост` — правка укладывается в уже изменённые ЭТИМ PR файлы и не требует
  нового дизайна/спеки/решения владельца. `отдельно` — находка затрагивает
  файлы/область, которых PR не касался, либо требует решения/дизайна/
  измерения, неуместных внутри текущего PR.
- `build_comment` (`scripts/review/ai_review.py`) фенсит (и, значит, отдаёт
  `file_tasks.py`) ТОЛЬКО блоки `отдельно`. `хвост` уходит прозой в раздел
  «Доделай в этом PR» — содержимое видно автору полностью, issue не
  заводится.
- Отсутствие поля МАСШТАБ НЕ трактуется молча как «отдельно» (fail loud):
  отдельный видимый раздел «⚠️ Без объявленного МАСШТАБА», issue не
  заводится, решение — за ревьюером/владельцем вручную.
- `file_tasks.py` дополнительно фильтрует по scope защитой в глубину на
  случай искажённого/ручного комментария — граница проведена ОДНИМ местом
  (`build_comment`), второй копии условия нет.

## Что с прежним поведением (суперсессия)

Требование `openspec/changes/ai-review-gate/specs/journal-tasks-hands/spec.md`
(«канонические блоки предложенных задач заводятся в пул одной командой…»)
описывало поток «любой блок ЗАДАЧА → issue» без разбора масштаба —
суперсессия отмечена там же, текст исходного требования не переписан.

## Проверено

- `python -m pytest scripts/review/test_ai_review.py scripts/review/test_file_tasks.py
  scripts/lib/test_label_registry.py -q` — зелёные (кроме `test_redact_*`,
  известный дефект среды Windows).
- Мутация 1: `_split_scope` молча трактует отсутствие поля как «отдельно» —
  `test_build_comment_tail_scope_not_fenced` краснеет.
- Мутация 2: убрать секции «Доделай в этом PR»/«Без объявленного МАСШТАБА»
  из `build_comment` — тот же тест краснеет (содержимое хвостов/безполевых
  находок перестаёт быть видимым).

## Что вне рамок

- Регулярный (не одноразовый) замер доли хвост/отдельно/без-поля по потоку
  ревью — заведена отдельная задача в беклог этим же PR.
