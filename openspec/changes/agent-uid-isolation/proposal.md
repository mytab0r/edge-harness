# agent-uid-isolation: dsh идёт под выделенным юзером без docker, ключ не живёт в его env (#140)

Задача: #140. Замер: [docs/research/40-model-shell-key-exposure.md](../../docs/research/40-model-shell-key-exposure.md).
Дельта-спека: `specs/runner-isolation/spec.md` — новая способность «изоляция
адаптера модели на раннере».

## Класс закрываемой ошибки

Заявка «агент ключ не видит» опиралась на одно вырезание env
(`*KEY*/*TOKEN*/*SECRET*`) в model-shell вызовах. Замеры живым прогоном:

1. Прямое чтение `/proc/<pid-dsh>/environ`: в старой конфигурации (dsh —
   потомок job-цепочки) в живом замере запрещено, **но механизм запрета не
   атрибутирован** (контрольный эксперимент: same-uid не-потомок environ
   читает, так что yama как объяснение не годится). В изолированной
   конфигурации (dsh через sudo-exec, ключ через env_keep) точная пара
   model-shell→dsh **читается, и env_keep доставляет ключ в этот читаемый
   environ** (замер 5, repo-ci 2026-09-10: READABLE, `DEEPSEEK_API_KEY`
   present-nonempty, bash- и node-образы stand-in). Прежняя формулировка
   этого proposal «/proc-вектор закрыт ядром» и «не подтвердился»
   опровергнуты замером и сняты.
2. Тот же класс **подтвердился через docker-сокет** (группа docker — дефолт
   образа раннера): контейнер `--pid=host --cap-add SYS_PTRACE
   --security-opt apparmor=unconfined` прочитал environ dsh, где лежат
   `DEEPSEEK_API_KEY`, `GH_TOKEN`, `HANDS_TOKEN`, `TELEGRAM_BOT_TOKEN`,
   `DSH_EDGE_ACCESS_KEY`.

## Решение

Обе ветки критерия задачи, одно место правды — `dsh_provider_proxy_start` /
`dsh_agent_isolation_prepare` / `dsh_agent_run` в `scripts/lib/dsh-ci.sh`,
врезано во все три обёртки (worker `task.sh`, hands `dsh_task.sh`,
ai-review `ai_dsh.sh` — класс #93/#94):

- **Ключ не живёт в env dsh** («передача ключа только адаптеру»): реальный
  base_url+ключ держит локальный прокси в домене транспорта (127.0.0.1,
  файл состояния 0600); dsh получает локальный эндпоинт и подменный ключ;
  `dsh_agent_run` подменяет значения при каждом запуске домена агента и
  синхронизирует файл состояния (цепочка провайдеров #727 совместима).
  Чтение environ dsh моделью (замер 5: READABLE) отдаёт только подмену;
  environ самого прокси — другой uid, его чтение запрещено ядром (гарантия;
  prepare 8б доказывает на каждом прогоне);
- **отдельный uid без docker**: model-shell наследует uid агента, сокет
  docker ему недоступен (EACCES) — закрывает подтверждённый docker-эскейп;
  environ транспорта (другой uid) нечитаем тем же uid-барьером — гарантия
  ядра, а не свойство среды;
- значения агенту едут через sudoers `env_keep` (память sudo), не через argv
  (`/proc/*/cmdline` читаем всеми) и не через файлы в домене агента; РЕАЛЬНЫЙ
  ключ через границу транспорт → агент больше не идёт вовсе (8д);
  `GH_TOKEN`/`HANDS_TOKEN`/`TELEGRAM_*`/`DSH_EDGE_ACCESS_KEY` в env dsh не
  попадают вовсе;
- воркспейс и каталог спула передаются агенту; gh-конфиг зеркалится (режим
  `gh`) либо сносится с проверкой отсутствия (режим `nogh`, граница #18);
- подготовка доказывает изоляцию до запуска dsh (прокси здоров, env-проводка,
  docker-denied, environ-denied на настоящем uid-барьере, отсутствие
  реального ключа и наличие подмены в env агента) и падает громко при
  отказе — запуск без изоляции запрещён;
- гвардии: `scripts/lib/test/agent-isolation.guard.sh` в repo-ci (настоящий
  sudo, свойства как факты окружения, включая живой замер точной пары
  model-shell→dsh и механику прокси: upstream-заглушка видит реальный ключ)
  + smoke bash-клиентов (прогон dsh обязан идти через `dsh_agent_run`, патч —
  в дом агента).

## Что вне рамок

- PAT в `~/.config/gh/hosts.yml` остаётся читаемым моделью по построению
  (единственный gh-канал, переживающий env-вырезание; модель обязана уметь
  открывать PR). Зафиксировано в замере как осознанная граница.
- Траты квоты провайдера легальными вызовами модели (и — с той же натяжкой —
  прямые вызовы в локальный прокси) — штатная работа агента, не утечка:
  значение ключа прокси не отдаёт.
- Задачи, которым нужен docker на раннере: эскалация владельцу (blocked).
  Газ — вынос ключа с раннера; решение владельца, не воркера.
