# Дельта-спека: изоляция адаптера модели на раннере

Новая способность `runner-isolation`: секрет провайдера недоступен
model-shell, которым управляет модель. Мержится в базовую спеку одновременно
с реализацией (#140). Секрет не выдаётся процессу DSH вовсе: реальный
base_url+ключ живёт в домене транспорта (локальный прокси-держатель), DSH
получает локальный эндпоинт и подменное значение.

## ADDED: изоляция адаптера модели

Требование: любой запуск DSH с доступом к секрету провайдера (worker, hands,
ai-review) идёт под выделенным непривилегированным пользователем, не
состоящим в группе docker, и без секрета в собственном окружении: реальный
ключ держит локальный прокси в домене транспорта, DSH общается с провайдером
через него. Запуск без изоляции, без прокси или при недоказанной изоляции —
громкий отказ шага, а не понижение до прежнего поведения. Секрет не
доставляется ни через argv (читаем всеми через /proc/*/cmdline), ни через
файлы в домене агента.

Сценарий: model-shell пытается прочитать `/var/run/docker.sock` → отказ по
правам (uid агента вне группы docker), независимо от состояния демона.

Сценарий: model-shell пытается прочитать environ любого процесса транспорта →
отказ (uid агента отличается от uid транспорта, ядро запрещает чтение без
CAP_SYS_PTRACE) — это гарантия ядра, в отличие от рёбер same-uid.

Сценарий: model-shell читает environ самого DSH (same-uid родитель;
research/40, замер 5 — чтение успешено) → в прочитанном нет секрета
провайдера: `DEEPSEEK_API_KEY` — подменное значение прокси,
`DEEPSEEK_BASE_URL` — 127.0.0.1 прокси. Подмена и отсутствие реального
значения доказываются подготовкой на настоящем uid-барьере (8д) на каждом
прогоне.

Сценарий: транспорт стартует прогон → прокси-держатель поднимается до
подготовки и проходит health-check; подготовка доказывает env-проводку
подмены агенту, docker-denied и (на настоящем uid-барьере) environ-denied до
запуска dsh; любой отказ подготовки красит шаг до какой-либо дорогой работы.
Механика прокси доказана в CI: upstream-заглушка видит реальный ключ из
файла состояния, тело и путь проходят насквозь.

Сценарий: цепочка провайдеров (#727) меняет реального провайдера между
попытками → каждый запуск домена агента синхронизирует файл состояния прокси
(dsh_agent_run), попытка ходит к своему провайдеру, секрет в env агента не
появляется ни на одной попытке.

Сценарий: подготовка зондирует same-uid ребро «дочерний шелл читает environ
родителя» (вектор #140). Ребро измерено: в конфигурации sudo-exec оно
READABLE (research/40, замер 5) — закрытие достигается не запретом чтения, а
отсутствием секрета в читаемом environ. Вердикт зонда печатается в лог
каждый прогон (`::note::`) без покраски: среда из репо не настраивается
(правило «тормоз без газа»); молча-меняющаяся среда запрещена.

Сценарий: CI (repo-ci) на каждом PR исполняет продакшн-путь подготовки с
настоящим sudo на одноразовом юзере и проверяет те же свойства как факты
окружения, включая живой замер точной пары model-shell→dsh; красная гвардия
блокирует слияние.

Сценарий: прокси-держатель не поднялся или умер → соединение агента с
провайдером рвётся, прогон падает громко (провайдер недоступен); повтор
прогона поднимает прокси заново — жизненный цикл держателя равен жизни job.

Сценарий: подготовка не может установиться (нет sudo, нет node для прокси и
т.п.) → громкий `::error::` с указанием причины и газа (вынос ключа с
раннера — решение владельца), job красный, прогон без изоляции не начинается.
