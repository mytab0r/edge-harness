# Дельта-спека: изоляция адаптера модели на раннере

Новая способность `runner-isolation`: секрет провайдера, выданный процессу DSH,
недоступен model-shell, которым управляет модель. Мержится в базовую спеку
одновременно с реализацией (#140).

## ADDED: изоляция адаптера модели

Требование: любой запуск DSH с секретом провайдера в env (worker, hands,
ai-review) идёт под выделенным непривилегированным пользователем, не состоящим
в группе docker; запуск без изоляции или при недоказанной изоляции — громкий
отказ шага, а не понижение до прежнего поведения. Секрет доставляется процессу
DSH только через каналы, нечитаемые model-shell (память sudo/env_keep), — не
через argv и не через файлы в домене агента.

Сценарий: model-shell пытается прочитать `/var/run/docker.sock` → отказ по
правам (uid агента вне группы docker), независимо от состояния демона.

Сценарий: model-shell пытается прочитать environ любого процесса транспорта →
отказ (uid агента отличается от uid транспорта, ядро запрещает чтение без
CAP_SYS_PTRACE).

Сценарий: транспорт стартует прогон → подготовка доказывает env-проводку
секрета агенту, docker-denied и (на настоящем uid-барьере) environ-denied до
запуска dsh; любой отказ подготовки красит шаг до какой-либо дорогой работы.

Сценарий: CI (repo-ci) на каждом PR исполняет продакшн-путь подготовки с
настоящим sudo на одноразовом юзере и проверяет те же свойства как факты
окружения; красная гвардия блокирует слияние.

Сценарий: подготовка не может установиться (нет sudo и т.п.) → громкий
`::error::` с указанием причины и газа (вынос ключа с раннера — решение
владельца), job красный, прогон без изоляции не начинается.
