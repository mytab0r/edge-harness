# stall-detector: устойчивый простой конвейера → задача пула

Задача: #201. Дельта-спека: `specs/journal-tasks-hands/spec.md` этого change
(домен `openspec/specs/journal-tasks-hands.md`, раздел «Конвейер
(оркестратор)»/«Автономный воркер»).

## Класс закрываемой ошибки

Оркестратор уже умеет НАЗВАТЬ причину простоя — печатает её строкой в отчёт
пульса (`GITHUB_STEP_SUMMARY`) каждый прогон, — но строка там и умирает.
Каждый новый вид поломки требовал человека, который читает лог, понимает
класс и заводит задачу вручную (замер: 2026-09-02/03, около пятнадцати
дефектов конвейера за сутки, ни один не породил автоматической задачи).

## Решение

Модуль `scripts/orchestra/stall_detector.py`, вставка — один вызов
`detect_and_act(...)` и один `escalate_stale_auto_tasks(...)` в
`scheduler.py::main()` после сборки отчёта пульса. Читает уже готовый отчёт
(тот же список строк, что печатается), не пересчитывает состояние GitHub
заново.

1. **Отпечаток** — из уже посчитанных структурированных данных отчёта
   (красный чек, пауза предохранителя, просроченная задача и т.п.), не из
   свободного пересказа; каждый Signal несёт дословную строку-улику.
2. **Дедупликация** — по машиночитаемому ключу `` Отпечаток: `<fp>` `` в
   теле открытой задачи с меткой `auto-detected`, не по похожести
   заголовка; совпадение — комментарий с новой уликой, не вторая задача.
3. **Устойчивость** — отпечаток обязан продержаться `STALL_PERSIST_MINUTES`
   (30 мин) с момента первого наблюдения (маркер-комментарий в
   `WATCHDOG_ISSUE`, тот же канал, что `pulse_guard`); разовый блип не
   плодит задачу. Маркер живёт вечно, поэтому счётчик обязан сбрасываться
   по факту закрытия прошлой автозадачи с тем же отпечатком — иначе блип
   после решения находит старый маркер и заводит вторую задачу мгновенно.
4. **Суточный потолок** — `STALL_DAILY_CAP` (5) новых автозадач в сутки;
   превышение не тонет молча, кричит строкой отчёта.
5. **Эскалация** — автозадача, не закрытая дольше `ESCALATE_AFTER_HOURS`
   (48 ч), эскалируется владельцу тем же каналом, что `pulse_guard`
   (issue-комментарий + Telegram), ровно один раз.

Принятая плата: детектор исполняется ВНУТРИ того же пульса, который
проверяет — если сломан сам детектор или оркестратор, самолечения здесь
нет. Мёртвый пульс закрывает только внешний сторож (#194) и heartbeat
(#120), не этот механизм — честно назван потолок, не скрыт.

## Что вне рамок

- Живой прогон приёмки (реальный незнакомый простой на проде, ожидание
  порога/повтора/потолка в реальном времени) — часы реального времени и
  шум в трекере; вместо этого поведение доказано юнит-тестами на
  прод-форме данных с мутационным доказательством каждой гвардии
  (`scripts/orchestra/test_stall_detector.py`).
- Метка `auto-detected` в реестре `docs/agents/LABELS.md` — правится тем же
  PR, что и код (см. `docs/agents/LABELS.md`, строка `auto-detected`,
  задача #207 задала формат реестра).

Шаг CI на `test_stall_detector.py` в `repo-ci.yml` изначально не был частью
этого change (был назван вне рамок в раннем ревью PR #248) — добавлен позже
этим же PR (коммит c40fcc5), потому что находки AI-ревью справедливо указали:
без него мутационная броня модуля не исполняется ни одним прогоном CI.
