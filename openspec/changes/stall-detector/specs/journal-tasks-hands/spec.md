# Дельта-спека: журнал (journal-tasks-hands) — детектор устойчивого простоя

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Конвейер
(оркестратор)»/«Автономный воркер» — новый механизм, встроенный в тот же
пульс оркестратора, не отдельный workflow.

## ADDED: Детектор устойчивого простоя → задача пула

Требование: каждый пульс оркестратора (`scheduler.py::main()`) после сборки
отчёта пульса (тот же список строк, что печатается в `GITHUB_STEP_SUMMARY`)
передаёт его в `stall_detector.detect_and_act(...)`. Отчёт разбирается на
отпечатки из уже посчитанных структурированных данных (красный обязательный
чек, пауза предохранителя, просроченная задача, сбой архива сессии,
отсутствие вердикта AI после исчерпанных повторов) — не из свободного
пересказа; каждый отпечаток несёт дословную строку отчёта как обязательную
улику. Здоровый пульс (пустой список сигналов) не делает ни одного сетевого
вызова.

Сценарий: пульс без предупреждений в отчёте — `detect_and_act` возвращает
пустой список и не читает/не пишет через GitHub API.

Требование: незнакомый отпечаток заводит задачу пула (метки `task` +
`auto-detected`) только если он устойчив — держится дольше
`STALL_PERSIST_MINUTES` (30 минут) подряд с момента первого наблюдения.
Первое наблюдение оставляет маркер-комментарий в `WATCHDOG_ISSUE` (issue
#120, канал `pulse_guard`), задача заводится только когда маркер того же
отпечатка уже старше порога — разовый блип отчёта не плодит задачу.

Сценарий: отпечаток впервые появился в отчёте пульса — оставлен маркер,
задача не заводится; тот же отпечаток держится 35 минут подряд — задача
заводится с уликами.

Требование: маркер первого наблюдения в `WATCHDOG_ISSUE` не удаляется и
живёт неограниченно, поэтому счётчик устойчивости обязан сбрасываться по
факту закрытия прошлой автозадачи с тем же отпечатком — сайтинги маркера
ДО момента закрытия этой задачи не засчитываются в устойчивость НОВОГО
эпизода. Без этого сброса один блип того же отпечатка после решения задачи
находит старый маркер и заводит вторую задачу мгновенно, не продержавшись
ни минуты в новом эпизоде.

Сценарий: задача по отпечатку `gate:pipeline-paused` закрыта; спустя 5 минут
тот же отпечаток снова появляется в отчёте один раз — маркер многодневной
давности в счёт не идёт, детектор оставляет новый маркер первого
наблюдения нового эпизода и ждёт `STALL_PERSIST_MINUTES` заново, задача не
заводится.

Требование: открытая задача с тем же отпечатком (машиночитаемая строка
`` Отпечаток: `<fp>` `` в теле, метка `auto-detected`) — новая улика
комментарием в неё, вторая задача с тем же отпечатком не заводится никогда
при живом дубликате.

Сценарий: отпечаток `check:red:test` уже открыл задачу #300 — следующее
наблюдение того же отпечатка добавляет комментарий с новой уликой в #300,
новая задача не заводится.

Требование: суточный потолок `STALL_DAILY_CAP` (5 новых автозадач за
последние 24 часа, считается по факту создания, не по текущей открытости)
— превышение не тонет молча, а кричит строкой отчёта «потолок исчерпан»,
задача с превысившим потолок отпечатком не заводится, нужен человек.

Требование: автозадача, не закрытая дольше `ESCALATE_AFTER_HOURS`
(48 часов), эскалируется владельцу тем же каналом, что предохранитель
конвейера (`pulse_guard.escalate` — issue-комментарий + Telegram), ровно
один раз (маркер эскалации на самой задаче не даёт повторить).

Сценарий: автозадача открыта 50 часов назад и всё ещё не закрыта —
эскалация владельцу с текстом, заканчивающимся разделом «Что дальше»;
повторный пульс не эскалирует её снова.

Требование: детектор не занимается самолечением — исполняется ВНУТРИ того
же пульса оркестратора, который проверяет; если сломан сам оркестратор,
детектор не сработает. Мёртвый пульс закрывают только внешний сторож
(#194) и heartbeat (#120), не этот механизм.
