# dsh-edge-plugin-system: плагины в морде по манифесту (форк-серия)

Задача: #78. Эпик: #77 — dsh-edge на Cloudflare должен стать полноценным DSH-хостом
как десктоп: плагины устанавливаются через морду, плагин по запросу в чате пишет
агент в GH Actions раннере («plugin-forge»), после чего морда перезапускается с
новым плагином. Смежное: [design](design.md), [задачи](tasks.md).

## Зачем

Сегодня подключить плагин к морде dsh-edge невозможно в принципе, и это доказано
по первоисточникам ([research/11](../../../docs/research/11-dsh-edge.md),
[белое пятно #43](https://github.com/mytab0r/edge-harness/issues/43)):

- серверная композиция статическая: алиасы бандла выводятся только из литеральных
  импортов в `apps/dsh-edge/src` (`bundle-standalone.mjs`), инсталлы — статическая
  очередь `context.plugin(...)` в `session-store.ts`. Плагин, который никто не
  импортирует, в воркер не попадает вовсе;
- веб-ростер клиентских плагинов строится из upstream-патчей
  (`cordis.patch.yml` опубликованных `dsh-base`/`dsh-web-app`) плюс встроенный
  `ui-edge` — клиентская часть плагина туда без правки сборки не попадает;
- `npm install` плагина в pnpm-standalone не включает его в бандл И рвёт пять
  обязательных pnpm-патчей для Workers — зелёная сборка при молча неверном
  составе (класс silent-wrong, закрытый громким падением шага в #43).

Класс ошибки, который закрывает change: **«пайплайн зелёный — а плагина в
деплое нет»**. Гвардия состава (манифест ↔ артефакт) — часть дизайна, а не
приятная добавка.

## Проверка против отвергнутых вариантов

Каждый пункт — из
[30-rejected-alternatives](../../../docs/research/30-rejected-alternatives.md):

- **#5 «Dynamic Workers» (возврат: платный CF).** Динамическая загрузка плагинов
  в рантайме на Workers Free невозможна — апстрим-спайк
  [pawaca/dsh-edge#43](https://github.com/pawaca/dsh-edge/issues/43) это и
  исследует (`node:module` internals недоступны, `import()` npm-спецификаторов
  нет). Дизайн строит статическую композицию: плагины бандлятся кодогенерацией
  ДО сборки. Worker Loaders — не предлагаем.
- **#3 «туннель DO → job» / ToS.** Forge — обычный конечный job (собрал,
  оттестировал, выложил релиз, умер), тот же класс активности, что hands;
  долгоживущих соединений нет, CF в forge не участвует вовсе.
- **«Решение, стоящее денег»** (AGENTS.md): всё построено на бесплатных планах —
  GH Actions публичного репо, Workers Free (direct-режим), релизы GitHub.

## Что делает (фаза дизайна — этот change)

Ответы на семь вопросов дизайна — в [design](design.md), все — по
первоисточникам (исходники `pawaca/dsh-edge` прочитаны через GitHub API
2026-08-29, файлы-улики процитированы по строкам):

1. **Манифест** — JSON-файл в этом репо; PR с его правкой = аппрув владельца.
2. **Форк-серия** — патчи поверх клона апстрима с пином SHA (не форк-репо):
   кодогенерация файла импортов до бандла, инсталл-цикл в `session-store.ts`,
   расширение веб-ростера.
3. **Рантайм** — изоляция отказа плагина по прецеденту самого dsh-edge;
   аварийный выключатель переменной воркера.
4. **Workers-совместимость** — чеклист plugin-forge (границы `nodejs_compat`).
5. **Канал обновления** — forge → релиз → манифест → деплой; статусы — события
   журнала (`plugin_status`), не отдельная KV-запись.
6. **Безопасность** — источник только релизы этого репо, пин sha256,
   ревью владельца.
7. **Апстрим** — что контрибьютим назад (алиасы, результаты спайка #43).

План PoC (минимальный hello-world проходит forge → deploy → виден в морде) —
в [design](design.md), порядок реализации — в [tasks](tasks.md). Реализация
стартует только после ревью владельца.

## Вне рамок

- Транспорт «исходник плагина из чата в forge» (authoring UX агента) —
  отдельный дизайн следующего слайса; канал этого дизайна начинается с
  «forge собрал tarball».
- Плагины runner-профиля (hands) — живут как есть (релиз `plugins-v1`,
  установка в `dsh_task.sh`); этот change — только про морду dsh-edge.
- Автообновление плагинов без аппрува владельца — противоречит модели доверия
  (плагин = код в воркере владельца).
- Всё, что стоит денег, не строится.
