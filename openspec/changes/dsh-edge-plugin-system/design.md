## Факты-основания

Четыре файла определяют всё решение:

1. **`apps/dsh-edge/standalone/scripts/bundle-standalone.mjs`.** Алиасы бандла
   выводятся функцией `publishedPackageAliases()`: она сканирует **все `.ts`
   файлы `apps/dsh-edge/src`** регэкспом (строки 83-84)

   ```js
   /['"]((?:@deepseek-ai|@cloudflare)\/[^'"]+|(?:just-bash|fast-png|jpeg-js)(?:\/[^'"]*)?)['"]/g
   ```

   и для каждого найденного литерального спецификатора резолвит пакет в
   `standalone/node_modules` в алиас wrangler-бандла. Два следствия:
   плагин без литерального импорта в `src` в бандл не попадает; **плагин с
   чужим npm-скоупом в бандл не попадает даже с импортом** — регэксп знает
   только `@deepseek-ai`, `@cloudflare`, `just-bash`, `fast-png`, `jpeg-js`.
   Рядом два громких гварда: `DIRECT_GZIP_BUDGET_BYTES = 900 * 1024` (строка 14,
   direct-режим) и `requirePublishedDependencyInputs()` по `bundle-meta.json`
   (строки 209-226): runtime-зависимости обязаны резолвиться из
   `standalone/node_modules`, workspace-исходники — запрещены.
2. **`apps/dsh-edge/src/session-store.ts`.** Композиция — статическая очередь
   `await this.context.plugin(...)` в `EdgeSessionStore.initialize()`
   (`new Context()` — строка 193). Внутри уже есть **прецедент изоляции
   отказа**: LLM-плагин ставится в `try/catch` с
   `console.error('… failed to initialize; model operations will be
   unavailable.')` (строка 245) — DO живёт без модели, но не падает.
3. **`apps/dsh-edge/standalone/scripts/assemble-standalone-web.mjs`.** Ростер
   клиентских плагинов: `deploymentPatches` (строки 25-28) — два файла
   `cordis.patch.yml` из опубликованных `@deepseek-ai/dsh-base` и
   `@deepseek-ai/dsh-web-app`; имена достаются регэкспом `name: '…'`, минус
   `edgeExcludedPackages` (38-48), плюс `edgeClientPackages` — встроенный
   `dsh-edge-client-ui` (31-36). От пакета с клиентской частью требуются
   `dsh.client.platform === 'web'` и экспорт `./client`. **Дисциплина ошибок
   тут двоякая** (важно для патча 0003): отсутствие `./client` при web-декларации
   — громкая ошибка (строки 86-93), битый `inject` — громкая (строка 199), а вот
   пакет без web-декларации в списке declared **молча пропускается**
   (`continue`, строка 180). Манифестная часть не имеет права наследовать эту
   тишину — для её записей патч добавляет громкий гвард (см. серию).
4. **Апстрим-спайк [pawaca/dsh-edge#43](https://github.com/pawaca/dsh-edge/issues/43).**
   Динамическая загрузка (`cordis-plugin-loader`) на Workers упирается в
   отсутствие `node:module` internals и рантайм-`import()` npm-спецификаторов;
   рабочее направление, которое там же исследуется, — **предрегистрация
   модулей** (статический бандл + регистрация имён). Наш дизайн — частный
   случай этого направления: предрегистрация через кодогенерацию.

Плюс два наших факта: текущий `deploy-dsh-edge.yml` ставит npm-префаб и патчит
каталог моделей хирургией минифицированного бандла; релиз `plugins-v1` этого
репо уже содержит tgz-артефакты плагинов — формат источника существует.

## Форма: сборка

```
edge-harness (этот репо)                      GH Actions: build-dsh-edge.yml
┌──────────────────────────────────┐          ┌─────────────────────────────────────────────┐
│ dsh-edge/upstream.json           │  пин SHA │ 1. clone pawaca/dsh-edge @ <SHA>            │
│ dsh-edge/plugins.json  (манифест)│─────────▶│ 2. git apply dsh-edge/patches/*.patch       │
│ dsh-edge/patches/000*.patch      │          │    — громко, чужой порядок = красный job    │
│ dsh-edge/PATCHES.md (почему/     │          │ 3. pnpm --dir apps/dsh-edge/standalone      │
│                   когда снять)   │          │    install --frozen-lockfile                │
│ релиз plugins-vN: *.tgz          │─────────▶│ 4. скачать tgz каждого плагина из релиза,   │
│   (артефакты plugin-forge)       │  sha256  │    сверить sha256 из манифеста,             │
│                                  │          │    pnpm --dir …standalone add <tgz> --save-exact
└──────────────────────────────────┘          │ 5. node dsh-edge/codegen-edge-plugins.mjs   │
                                              │    манифест ──▶ src/edge-plugins.generated.ts
                                              │              + standalone/edge-plugins.json │
                                              │ 6. bundle-standalone direct                 │
                                              │    алиасы: регэксп+наш скоуп (патч 0001)    │
                                              │    подхватывает generated-импорты;          │
                                              │    gzip-бюджет 900 KiB — громко             │
                                              │ 7. ГВАРДИЯ СОСТАВА: каждый enabled-плагин   │
                                              │    манифеста обязан быть в bundle-meta.json │
                                              │    (сервер) и в dist/plugins (клиент)       │
                                              │    — иначе красный job                      │
                                              │ 8. verify-standalone + wrangler deploy      │
                                              │    + канарейка (как в deploy-dsh-edge.yml)  │
                                              └─────────────────────────────────────────────┘
```

Ключевой порядок: патчи применяются к чистому клону, зависимости ставятся
**pnpm** (не npm!), кодогенерация — до бандла. Класс ошибки #43 закрыт тремя
независимыми стенами: pnpm сохраняет `patchedDependencies`, кодогенерация даёт
литеральные импорты в `src`, гвардия состава сверяет артефакт с манифестом.

## Форма: рантайм

```
DshEdgeInstance (DO) — старт
  └─ EdgeSessionStore.initialize():  ядро без изменений (как у апстрима)
      └─ installEdgePlugins(context, …)        ← сгенерированный модуль,
           для каждого плагина в порядке          вставлен патчем 0002 в хвост
           манифеста:                                initialize()
             ┌─ в аварийном выключателе (env)? ──▶ skip + console.error (громко)
             ├─ try:  await context.plugin(модуль) → storage-ключ статуса ready
             └─ catch: console.error(id, err)      → статус failed,
                       НЕ ронять DO (прецедент строки 245 session-store.ts)
```

Никакого чтения манифеста в рантайме нет: в бандл попадают только enabled-плагины
(выключение = компиляция). DO не знает слова «манифест» — он инсталлирует
сгенерированный список.

## Манифест

Файл `dsh-edge/plugins.json` в этом репо. Единственное место правды о составе
морды; меняется только PR-ом, merge PR = аппрув владельца (см. «Безопасность»).

```jsonc
{
  "version": 1,
  "plugins": [
    {
      "id": "hello",
      "package": "@edge-harness/dsh-plugin-hello",
      "source": {
        "release": "plugins-v2",                  // релиз ЭТОГО репо, не URL
        "asset": "dsh-plugin-hello-0.1.0.tgz",
        "sha256": "…"                             // пин байт артефакта
      },
      "server": true,   // бандл воркера + инсталл в DO
      "client": true    // веб-ростер; требует dsh.client-декларацию в пакете
    }
  ]
}
```

Разделение правды: **как** плагин монтируется — живёт в самом пакете
(`dsh.client`: `platform`, `inject`, `immediately`, `external`; серверный
экспорт — главный модуль пакета), это контракт апстрима, читается сборкой из
установленного пакета. **Что** включено и **откуда** — только в манифесте.
Валидация манифеста (схема: id, скоуп пакета, sha256-форма, уникальность id,
существование release/asset) — в кодогенераторе, до любых дорогих шагов.

Пин апстрима — рядом, `dsh-edge/upstream.json`: `{ "repo": "pawaca/dsh-edge",
"sha": "…" }`. Обновление пина — ручной PR с полным прогоном сборки; темп
апстрима (19 релизов за 8 дней) делает автоматику здесь опасной, а не удобной.

**Почему файл в репо, а не vars и не артефакт релиза.** Правка манифеста должна
быть (а) ревьюимой владельцем до деплоя, (б) видимой в истории (diff версий и
sha256), (в) атомарной с кодом патчей, которые она предполагает. Vars не дают
ни diff, ни ревью, ни связи с патчами. Манифест-в-релизе разрывает связь
«манифест ↔ патчи» и превращает ревью в правку релиза мимо PR.

## Форк-серия: патчи поверх клона, не форк-репо

**Сравнение.** Форк-репо даёт честный git-историю правок, но апстрим релизится
несколько раз в сутки — rebase-налог платится при каждом обновлении пина, а
дрейф форка от апстрима накапливается молча. Патч-серия в этом репо с пином SHA
даёт: темп обновления выбираем мы (пин меняется PR-ом), каждый патч мал,
задокументирован и падает громко при неприменимости (`git apply` — красный
job), а вся серия ревьюится как обычный код репо. Возврат к форк-репо — если
серия вырастет до постоянного переписывания логики апстрима (счётчик: больше
шести патчей или любой патч >100 строк — сигнал пересмотреть, порог в
`PATCHES.md`).

Состав серии (каждый патч — запись в `dsh-edge/PATCHES.md` с причиной и
условием снятия, по образцу `audit.json` апстрима):

| Патч | Что делает | Почему обязателен |
|---|---|---|
| `0001-alias-scope.patch` | добавляет наш скоуп в регэксп `publishedPackageAliases()` (строки 83-84) | без этого алиас для `@edge-harness/*` не построится никогда, импорт в generated-файле не резолвится |
| `0002-edge-plugins-module.patch` | + `installEdgePlugins(context, …)` в хвост `initialize()` (после `WorkspaceRegistry`); сгенерированный `src/edge-plugins.generated.ts` патч не содержит — его создаёт кодогенератор | точка инсталла; после ядра, потому что плагины могут опираться на его сервисы |
| `0003-web-roster-manifest.patch` | `assemble-standalone-web.mjs`: после upstream-патчей читает `standalone/edge-plugins.json` и дописывает client-имена в `declared`; для манифестных записей добавляет громкий гвард web-декларации и `./client` | ростер; апстримный путь тихо пропускает пакет без декларации (строка 180) — для манифеста тишина = зелёная сборка без плагина, тот же класс, что #43, поэтому тут гвард громче апстрима |
| `0004-model-catalog-const.patch` (опционально) | каталог моделей из build-time константы вместо регэкспа по минифицированному бандлу | убирает самую хрупкую хирургию текущего `deploy-dsh-edge.yml`; делается только если ПоК покажет, что место в исходниках стабильно |

Кодогенератор `dsh-edge/codegen-edge-plugins.mjs` читает манифест и пишет два
артефакта — серверный:

```ts
// Generated from dsh-edge/plugins.json — do not edit.
import hello from '@edge-harness/dsh-plugin-hello'

export const edgePlugins: { id: string; plugin: unknown }[] = [
  { id: 'hello', plugin: hello },
]
```

и клиентский `standalone/edge-plugins.json` (список id с `"client": true`).
Пустой манифест → пустой список → сборка вырождается в апстримную: патчи
деградируют мягко в апстримное поведение, деплой без плагинов легален. Импорт именно главного
модуля пакета: резолв экспорта делает существующий код алиасов, и его же громкие
ошибки (`does not export … for the standalone Worker build`) достаются плагину
с кривым `exports` бесплатно.

## Рантайм: инсталл и изоляция

Инсталл-цикл — в сгенерированном модуле, вставленном в хвост `initialize()`.
Три правила:

1. **Изоляция по прецеденту апстрима** (строка 245 `session-store.ts`): отказ
   одного плагина не роняет DO — `console.error` с id и ошибкой (observability
   воркера включён: `observability.enabled: true`), статус `failed` в
   storage-ключ, инсталл продолжается. Это та же философия, что у firehose
   dsh-streaming: подписка/плагин деградирует до предупреждений, агент жив.
   Граница изоляции честно названа: cordis-Context после `plugin()`,
   бросившего исключение, может остаться с частично смонтированным сервисом —
   контракт проверяется в PoC (см. «Не подтверждено»).
2. **Порядок = порядок манифеста.** Нефиксируемый порядок — недетерминизм,
   который нельзя отладить; порядок объявления читается вслух и ревьюится.
3. **Аварийный выключатель — переменная воркера** `DSH_EDGE_PLUGINS_OFF`
   (csv id): сломанный в рантайме плагин выключается без пересборки. Это
   осознанное второе место правды — семантика «аварийный клапан, каждое
   срабатывание громко в лог», не конфигурационный канал; штатное выключение —
   только через манифест и пересборку.

Статусы инсталла цикл пишет в DO storage (`dsh-edge-plugins:<id>` → ready/
failed + текст) — это ключи того же DO, новой инфраструктуры нет; поверхность
UI поверх них — см. «Чего не решает».

## Workers-совместимость: чеклист plugin-forge

Плагин бандлится в воркер с `nodejs_compat`, но без Node за его пределами.
Forge обязан гонять чеклист на каждом tarball и клеймит отказ громко, по пункту:

- **Объявлен `inject` под каждый читаемый сервис** (контракт cordis 4).
  Чтение `ctx.<service>` в apply без объявления в `inject` бросает
  `cannot get property "<service>" without inject` — рантайм-падеж, который
  инсталл-цикл изолирует в статус `failed`, а сборка остаётся зелёной
  (класс #100). Эталон формы — апстримные плагины: `dsh-tool-web` объявляет
  `inject: ['tools', 'web', 'systemPrompt']`. Ловится дымом инсталла
  (`smoke-edge-plugins.mjs`), до форжа — вручную перед публикацией релиза.

- **Запрещённые импорты** (grep по исходникам и по сборке): `node:fs`,
  `node:child_process`, `node:net`, `node:dgram`, `node:module` (динамические
  части), `koffi`, `node-pty` и любые нативные аддоны. `node:path`/`node:url` —
  разрешены.
- **Нет рантайм-`import()`** npm-спецификаторов и чтения файлов «рядом с
  бандлом» — всё статическое, всё в бандле.
- **Нет `node:fs` на горячем пути**: ФС в Edge — VFS Computer'а (`/workspace`),
  у плагина нет своего диска. Персистенция — только через host-сервисы cordis
  (по контрактам upstream-плагинов); собственных SQL-таблиц у плагина нет.
- **CPU-дисциплина** (10 ms на invocation, Workers Free —
  [research/20](../../../docs/research/20-cloudflare-free.md)): никакого тяжёлого
  синхронного разбора между `await`'ами на пути событий сессии.
- **Размер**: gzip-бюджет direct-воркера 900 KiB общий; forge мерит вклад
  tarball'а в бандл (по `bundle-meta.json` пробной сборки) и отказывает при
  вкладе выше порога-константы.
- **Клиентская часть** (если `client: true`): один бандл на экспорте `./client`,
  `dsh.client.platform === 'web'`, `inject` только в пакеты ростера. Нарушение
  инжектов ловит встроенный гвард сборки (строка 199); отсутствие декларации у
  манифестного плагина ловит громкий гвард патча 0003 (апстримный путь тих —
  строка 180).
- **Интеграционный прогон** tarball'а на локальной сборке клона с патчами
  (wrangler dry-run + минимальный smoke в miniflare/vitest —
  [research/22](../../../docs/research/22-cf-testing-toolchain.md)) до публикации
  релиза.

## Канал обновления и статусы

```
форж (workflow_dispatch, job):                    деплой (build-dsh-edge.yml):
 checkout → чеклист совместимости                  триггер: dispatch после merge PR
 → сборка tarball → интеграционный smoke             с правкой манифеста (или вручную)
 → релиз plugins-vN (тарболл + checksums)          … схема «Сборка» выше …
 → событие plugin_status {state:"built"}           → события deploying → ready/failed
 → PR с правкой plugins.json (sha256, версия)      → канарейка прода как улика
 └── владелец ревьюит и мержит ──┘                 → морда перезапущена, ростер
                                                      показывает плагин после reload
```

**Статусы — события журнала (`kind: plugin_status`), не отдельная KV-запись.**
Форж и деплой-джобы постят в существующий `POST /api/events` (тот же
`HANDS_TOKEN`, тот же клиентский паттерн, что у hands) в псевдо-задачу
`plugin:<id>`: `data: {plugin, state: building|built|deploying|ready|failed,
detail?}`, `source: forge|deploy`. Почему журнал:

- replay + live (`GET /api/events`, `/api/events.live`) и идемпотентность
  (`UNIQUE(task_id, seq)`) уже есть — ноль нового серверного кода
  ([спека](../../specs/journal-tasks-hands.md));
- канал мульти-акторный (форж, деплой, позже — триггер из морды): журнал даёт
  таймлайн попыток; KV-запись хранит только «последнее состояние», теряет
  историю и создаёт гонку писателей;
- бюджет строк DO (100k/сутки) не чувствует событий, случающихся раз в деплой;
- морда уже умеет показывать события журнала (слайс dsh-streaming).

«Готов» в dsh-edge UI доказывается самим фактом: после перезапуска плагин в
ростере и его эффекты в чате. События `plugin_status` при этом остаются
durable-улейкой конвейера в журнале этого репо.

## Безопасность

- **Плагин = код в воркере владельца** — уровень доверия максимальный, поэтому
  источник ограничен конструктивно: `source.release` — только релизы этого
  репо, никакие URL в манифесте не легальны (валидатор отвергает), sha256 пинит
  байты артефакта (переписанный релиз = красная сборка, не тихая подмена).
- **Аппрув владельца = merge PR с правкой манифеста.** Форж не может задеплоить:
  деплой читает манифест из main, а main меняется только через PR (защита
  ветки + оркестратор). Цепочка «форж собрал → владелец посмотрел diff (версия,
  sha256, назначение) → мерж → деплой» не имеет обхода внутри системы.
- **Секреты плагинам не выдаются**: инсталл-цикл передаёт только cordis-сервисы,
  не env и не ключи; чтение env воркера плагином — вне контракта.
- Пин SHA апстрима + патчи в ревью = supply chain сборки закрыт тем же PR-путём.

## Апстрим

Отношение к `pawaca/dsh-edge` — reuse с отдачей, не односторонний форк:

- **Контрибьютим назад:**
  - расширение регэкспа алиасов (`0001`) — маленький обобщаемый PR апстриму
    («позвольте дополнительный скоуп опубликованных пакетов»); он уменьшает наш
    патч до нуля, если принят;
  - результаты PoC — комментарий/PR в их спайк
    [pawaca/dsh-edge#43](https://github.com/pawaca/dsh-edge/issues/43): наша
    сборка — рабочее доказательство направления «предрегистрация вместо
    динамической загрузки» (builtins/статический бандл) на Workers Free;
  - чеклист Workers-совместимости — кандидат в их документацию, если владельцу
    апстрима пригодится.
- **Не контрибьютим** (специфично для харнеса): манифест, кодогенератор,
  форж-пайплайн, статусы журнала.
- **Патч-серия живёт по дисциплине апстрима**: каждая запись `PATCHES.md` несёт
  `removeWhen`-условие снятия (как их `audit.json`) — патч, чьё условие
  наступило, снимается, а не копится.

## Девиации реализации (PoC #80, PR #81 — факты вместо проекта)

Реализация PoC вскрыла расхождения проекта с фактическим апстримом и
уточнила решения. Этот раздел — место правды о том, как система устроена
СЕЙЧАС; текст выше читается как проект до PoC.

1. **Один workflow, а не два.** Вместо «build-dsh-edge.yml + деплой» сборка и
   деплой живут в едином `deploy-dsh-edge.yml`: непустой манифест → source-build
   (клон@SHA → патчи → tgz со сверкой sha256 → pnpm add → кодоген → build →
   гвардия → verify → деплой → канарейка), пустой → npm-префаб. Разделение
   «сборка отдельно от деплоя» не дало бы ничего: артефакт между job'ами
   передавать ради экономии пары минут не стоит.
2. **`bundle-meta.json` эфемерен.** `bundle-standalone.mjs` бандлит во
   временную папку и удаляет её — метафайл недолговечен, гвардия состава
   (`verify-edge-plugins.mjs`) сверяет манифест с durability-артефактами:
   литерал состава `id:"<id>"` в обоих `worker/{direct,isolated}/index.js`
   (его приносит сгенерированный модуль, сам импорт резолвится алиасом 0001
   и при неразрешении валит сборку) и клиентский бандл + boot-граф в `dist`.
3. **0003 шире заявленного: включает `verify-standalone.mjs`.** Строгая
   сверка boot-графа с `expected-boot-graph.json` не знала бы о манифестных
   записях и покрасила бы любую сборку с новым клиент-плагином; патч делит
   записи на апстримные (сверяются с reviewed-контрактом) и манифестные
   (наличие в графе и в dist).
4. **Каталог моделей остаётся хирургией на собранном бандле — на обоих путях.**
   Source-build без этого шага тихо вернул бы селектор к DeepSeek (литералы
   каталога едут из адаптера `dsh-llm-deepseek`); шаг «Патч каталога моделей»
   снят с гейта префаба и применяется после любого пути сборки — форма
   литералов на source-build та же (минифицированный esbuild, проверено).
   Патч 0004 «каталог из build-time константы» — по-прежнему правильное
   постоянное решение, отложен за PoC.
5. **pnpm-патчей апстрима семь, не пять** (`dsh-api-gateway` и `dsh-sandbox`
   добавились к пяти из design) — все семь пережили `pnpm add tgz`;
   `docs/research/11` исправлен.
6. **`plugin_status`: промежуточные статусы best-effort.** Лежащий журнал не
   блокирует деплой морды (не-финальные статусы ретраят и предупреждают,
   но не красят job); финальные `ready`/`failed` — по-прежнему fail loud.
7. **Идентификаторы импорта плагинов получают префикс `p_`** в
   сгенерированном модуле — id формально может совпасть с зарезервированным
   словом JS (`class`, `default`).
8. **Первый настоящий плагин (#95, runner-bridge) — факты первого применения
   конвейера вне PoC.** Форжа ещё нет (п.3 задач), чеклист
   Workers-совместимости прогонялся руками: плагин ходит в GitHub API через
   `fetch` (запрещённых импортов нет, единственный импорт — апстримный
   `defineTool`; tarball 6.8 KiB против бюджета 900 KiB). Токен GitHub
   секреты-плагинам не «выдаётся» (см. «Безопасность») — плагин читает env
   воркера сам через `process.env` (заполнение секретами включено по
   умолчанию с compat date ≥ 2025-04-01;
   [research/20](../../docs/research/20-cloudflare-free.md)); деплой
   синхронизирует секрет `GH_RUNNER_TOKEN` из `GH_DISPATCH_TOKEN` и задаёт
   переменную `GH_RUNNER_REPO`. Это осознанное расширение контракта
   («чтение env воркером плагина — вне контракта» писалось про
   инсталл-цикл, не про рантайм инструмента): инструмент — код владельца в
   воркере владельца, секрет не покидает воркер и не попадает в вывод
   инструментов. Сервер-only запись (`client: false`) не попадает в
   клиентский ростер и не задевает гвард патча 0003. Каждый fetch — под
   `AbortSignal.timeout(15с)` и отменой хода агента: зависший вызов не
   держит turn; ошибки инструментов — громкие тексты агенту (он их
   озвучит), не сырые исключения.
9. **#100: гипотеза «инсталл позже точки композиции тулов» опровергнута;
   настоящая причина — контракт cordis 4 на inject.** Улика (прод, свежая
   сессия: в тулсете агента 9 апстримных тулов, плагинных нет при зелёной
   сборке) сначала выглядела как тайминг: `installEdgePlugins` стоит в хвосте
   `initialize()`, после `AgentLoop`. Чтение собранного апстрима показало,
   что снапшота тулсета не существует вообще: `ToolRuntime` при старте
   регистрирует у `SystemPrompt` живой провайдер
   (`ctx.systemPrompt.tools(context => this.wireSchemas(context.scope))`),
   и каждая сборка хода (per turn, `systemPrompt.assemble`) читает реестр
   тулов заново; `header.tools` в `buildRequest` — durable-журнал запроса,
   а не источник. Настоящая причина: оба плагина объявляли `inject: []`,
   а в apply читали `ctx.tools` — cordis 4 бросает
   `cannot get property "tools" without inject`, инсталл-цикл честно
   изолировал отказ в статус `failed` + `console.error` (кто не смотрел —
   тот не видел), и тулов не было. Урок: изоляция без читателя статуса —
   тихий отказ, поэтому класс закрывается гвардией на сборке —
   [`smoke-edge-plugins.mjs`](../../../dsh-edge/smoke-edge-plugins.mjs)
   инсталлирует каждый серверный плагин в настоящий cordis + ToolRuntime
   (Node, не workerd: покрывает путь монтирования, не execute());
   мутационное доказательство — против релизов 0.1.0 дым красный с той самой
   ошибкой, против 0.1.1 (объявлен `inject: ['tools']`) — зелёный.
   Хвост `initialize()` для инсталла оставлен как есть: с объявленным
   inject cordis сам дождётся сервисов. Релизы `plugins-hello-v0.1.1` /
   `plugins-runner-v0.1.1`, манифест перепинован.

## Отвергнутые варианты

**Форк-репо dsh-edge вместо патч-серии.** Темп апстрима (несколько релизов в
сутки) превращает синхронизацию форка в постоянный rebase-налог, дрейф
накапливается молча. Патчи с пином SHA падают громко и ревьюятся в этом репо.
Возврат — по порогу роста серии (см. «Форк-серия»).

**Динамическая загрузка плагинов в рантайме (cordis-plugin-loader).**
На Workers невозможна по построению рантайма (`node:module` internals, нет
`import()` npm-спецификаторов — читано в апстрим-спайке #43); предложить её —
предложить отвергнутое #5 (Dynamic Workers, paid-only) под другим именем.

**`npm install` плагинов в standalone.** Белое пятно #43: npm переопределяет
`node_modules` поверх pnpm-дерева, пять обязательных патчей теряются, плагин в
бандл не попадает — зелёная сборка с молча неверным составом. Заменено pnpm
`add <tgz>` + кодогенерацией + гвардией состава.

**Публикация плагинов в публичный npm / под чужим скоупом.** Скоуп
`@deepseek-ai` не наш; публичный npm открывает supply chain наружу и второй
место правды версий. Релизы этого репо с sha256-пином достаточны и ревьюятся
тем же PR-путём.

**Манифест в vars / в артефакте релиза.** Нет diff и ревью до деплоя (vars);
разрыв связи «манифест ↔ патчи» и ревью мимо PR (релиз). См. «Манифест».

**Рантайм-манифест (воркер читает список на старте, код всех плагинов в
бандле).** Мёртвый вес в бандле при бюджете 900 KiB, вторая правда о составе
(бандл ≠ включённое), а гибкости не добавляет: любое изменение всё равно
требует пересборки. Включение = компиляция.

**Статусы в отдельной KV-записи.** Один писатель побеждает гонкой, история
попыток теряется, нужен новый API для чтения. Журнал уже даёт replay/live,
идемпотентность и рендер в морде. См. «Канал обновления».

**Своя поверхность статусов в dsh-edge UI в этом же слайсе.** Требует
fork-эндпоинта (`/api/plugins` поверх storage-ключей) и клиент-плагина —
полезно, но не блокирует критерий «плагин виден в морде»; отложено за PoC
(см. «Чего не решает»).

## Чего дизайн намеренно не решает

- **Транспорт «исходник плагина из чата в форж»**: как агент в dsh-edge
  пишет код плагина и как он доезжает до раннера (worker-fetch dispatch,
  перенос файлов через API, scaffold-генератор) — отдельный дизайн следующего
  слайса эпика #77. Канал этого дизайна начинается с «форж собрал tarball».
- **Поверхность статусов внутри dsh-edge UI** (настройки-секция клиент-плагина
  поверх storage-ключей и fork-эндпоинта) — после PoC, отдельным патчем серии.
- **Автообновление плагинов и автообновление пина апстрима** — всегда PR
  владельца (модель доверия + темп апстрима).
- **Управление плагинами без передеплоя** — невозможно по построению
  (статический бандл); аварийный выключатель — клапан, не канал управления.
- **Плагины runner-профиля** (hands) — не трогаются.
- **Marketplace, сторонние авторы, мульти-тенантность** — вне модели
  «плагины владельца для воркера владельца».

## Не подтверждено

1. **`pnpm add <tgz>` сохраняет пять pnpm-патчей standalone.** Ожидается да
   (`patchedDependencies` — часть установочного контракта pnpm), но прогон не
   выполнялся. Проверка — первый шаг PoC: сборка после `add` обязана пройти
   `verify-standalone`; иначе — план Б, коммит tgz-распаковки в патч-серию.
2. **Контракт `verify-standalone.mjs` / `verify-determinism.mjs` относительно
   сгенерированного файла** — скрипты не читались; сгенерированный модуль может
   их сломать (детерминизм, инвентарь). Читать до патча 0002.
3. **Запас gzip-бюджета** под плагины: сколько из 900 KiB свободно на текущем
   апстриме — замер PoC (hello-world с пробной сборкой).
4. **Поведение cordis `Context.plugin()` при броске исключения** — остаётся ли
   Context консистентным для следующих инсталлов (частичный монтаж сервисов).
   Контракт upstream-кордиса в этом месте не читался; PoC включает негативный
   плагин-тест (инсталл, бросающий ошибку, → DO жив, остальные плагины стоят).
5. **Прокидка env/аварийного выключателя до места инсталла** — что из `env`
   воркера доходит до `EdgeSessionStore.initialize()` через конфиг каретки,
   не трассировалось; мелочь патча 0002, проверить по `instance.ts`.
6. **Хранение статус-ключей в DO storage** — допустимость и namespace-правила
   (`dsh-edge-plugins:*`) рядом с ключами апстрима (`dsh-kv:*`,
   `dsh_session_events`) не подтверждены; проверить миграционные/чистящие
   контракты, чтобы не конфликтовать с их логикой.
7. **Сквозная задержка forge→deploy→морда** («минуты» — оценка: job ~3-5 мин +
   деплой + канарейка), замеряется PoC-прогоном полного канала.
8. **Форма `dsh.client`-декларации минимального клиент-плагина без `inject`**
   (ростер-запись `{id, url, rev}` без инжектов) — прочитана в коде сборки, но
   живой мордой не проверена; PoC использует простейшую декларацию и
   подтверждает монтирование.
