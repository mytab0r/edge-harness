# epic-branch-guard: PR не заводится на эпик — отказ на входе в task-branch

Задача: #376. Дельта-спека: `specs/journal-tasks-hands/spec.md` — правка п.28
«Захват задачи воркером» (вход в задачу — `scripts/git/task-branch`).

## Класс закрываемой ошибки

Ветка `agent/77-dsh-edge-dsh` (PR #162) была привязана прямо к эпику #77 и
прожила 44 раунда ревью, прежде чем закрылась без слияния (#268: «раздроблено
на два PR по решению владельца»). Причина не в качестве кода, а в самой форме
задачи: критерий приёмки эпика («плагин виден в морде») распределён по трём
стройкам эпика и физически недостижим в одном PR — каждый раунд ревью законно
находил очередной кусок, которого не хватает, потому что PR, скоупленный на
номер эпика, не сходится по определению. Гвардия постфактум (ревью находит
несходимость на N-м раунде) стоит N раундов; отказ на входе стоит одну
проверку номера задачи.

## Решение

`scripts/git/task-branch <N>-<slug>` — единственный вход в создание
agent-ветки (см. `docs/agents/PROTOCOL.md`) — после подтверждения свежести
`origin/main` и ДО `git switch -c` спрашивает: является ли `<N>` эпиком.
Признак эпика не заводится заново — `scripts/lib/epic_guard.py` импортирует
`is_epic_issue` из `scripts/orchestra/scheduler.py` (уже рабочая логика
приёмки #335, PR #342: заголовок с префиксом «ЭПИК» ИЛИ незакрытые нативные
sub-issues, `sub_issues_summary`). Один признак эпика, два места его
применения (приёмка и вход в ветку) — как и было для `is_epic_issue` изначально
(#335 уже разводит «эпик» и «обычная задача» на выходе конвейера; эта задача
делает то же самое на входе).

Отказ называет газ (не просто «нельзя»): что делать вместо этого («заведи
узкую задачу на конкретную стройку эпика #N») и, если сеть отдала список,
открытые нативные sub-issues эпика — конкретные номера, а не общая фраза.

Проверка охватывает случай #77: заголовок начинается с «ЭПИК» (первый
признак `is_epic_issue`), второй признак (`sub_issues_summary`) совпадает —
расширять `is_epic_issue` не потребовалось.

## Проводка

`scripts/lib/epic_guard.py` (CLI: `<номер>` → exit 0/1/2) — отдельный узкий
блок в `scripts/git/task-branch`, не переформатирующий соседний код (файл
одновременно правят PR #360 — аренда задачи, PR #358 — проверки «задача
открыта/не blocked»; блок гвардии эпика независим от обеих правок и встанет
рядом при последующем ребейзе).

Отказ — та же категория ошибок, для которой `task-branch` уже требует рабочую
сеть (`git fetch`/`ls-remote` до этого блока): офлайн-режима у входа в задачу
нет, поэтому сбой сети/`gh` при проверке эпика тоже громкий (exit 2), не
тихий пропуск проверки.

## Что вне рамок

- Спор о носителе признака эпика (заголовок vs sub-issues vs отдельная метка)
  закрыт `is_epic_issue` (#335/PR #342), здесь не переоткрывается.
- Ретроактивная гвардия «уже открытый PR привязан к эпику» — не входит: это
  про НОВЫЕ ветки, существующие PR закрываются вручную (см. #162).
