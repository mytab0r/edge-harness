# Дельта-спека: гвардия «PR не заводится на эпик» во входе задачи

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Автономный воркер
(конвейер пула)», п.28. Мержится в базовую спеку одновременно с реализацией
(#376).

## MODIFIED: Вход в задачу отказывает на номере эпика

~~Работа идёт в ветке `agent/N-slug` от свежего origin/main (вход —
`scripts/git/task-branch`)~~

Требование: `scripts/git/task-branch <N>-<slug>` перед созданием ветки
проверяет, является ли `<N>` эпиком (`is_epic_issue`,
`scripts/orchestra/scheduler.py` — то же место правды, что использует
приёмка #335): заголовок с префиксом «ЭПИК» ИЛИ незакрытые нативные
sub-issues. Если `<N>` — эпик, `task-branch` завершается ошибкой ДО
`git switch -c` (ветка не создаётся) с текстом, называющим газ — завести
узкую задачу на конкретную стройку эпика — и, по возможности, список
открытых sub-issues эпика. Работа идёт в ветке `agent/N-slug` от свежего
origin/main только для N, не являющегося эпиком.

Сбой проверки (сеть/`gh` недоступны) — громкая ошибка (вход в задачу без неё
не даётся), той же категории, что уже существующая проверка свежести
origin/main выше по тому же скрипту: офлайн-режима у входа в задачу нет.

Сценарий: `task-branch 77-anything` (#77 — эпик, заголовок «ЭПИК: …») →
отказ до создания ветки, сообщение называет узкую задачу вместо эпика и
список открытых под-задач #77.

Сценарий: `task-branch 268-anything` (#268 — обычная открытая задача) →
ветка создаётся как обычно, гвардия эпика не вмешивается.
