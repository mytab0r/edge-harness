# pipeline-self-review: периодическая саморевизия конвейера (#1025)

Задача: #1025. Код: `scripts/orchestra/self_review.py`,
`.github/workflows/self-review.yml`, `config/self-review-checklist.json`.
Дельта-спека: [specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Владелец, 2026-09-12, дословно: «Почему не автономный воркфлоу? Что ему не
хватает? Почему он сам не делает то, чего ему не хватает?»

Ответ на третий вопрос: у конвейера нет контура «заметить нехватку
способности → поставить себе цель → построить недостающее». Все существующие
детекторы (`pulse_guard.py::failure_watch`, `stall_detector.py`,
`health_regression.py`, `dependabot_alert_watch.py`, `checklist_tail_labels.py`)
реактивны к УЖЕ НАЗВАННОМУ классу дефекта — у каждого есть список сигнатур,
отпечатков или порогов, и они ищут именно их. Ни один не задаёт открытый
вопрос «что здесь странно» без подсказки класса заранее — а именно так
находились все живые дефекты последних суток (человек смотрел на данные,
которые API и так отдавал, и спрашивал, что не сходится). Данные были
доступны всё время; не хватало вопроса, не инструмента для его получения.

## Что делается

Периодический (раз в 6 часов, `.github/workflows/self-review.yml`) трёхшаговый
трест-контур — тот же приём, что `ai-review.yml` (ADR 0007):

1. **gather** (доверенный, read-only) — собирает сырой дайджест периода
   (72 часа): прогоны отслеживаемых workflow (аггрегат + до 20 свежих на
   workflow), churn меток по НЕДАВНО обновлённым issues/PR (потолок
   запросов, не полная история), свежие комментарии watchdog-issue #120,
   снимки `data/pipeline-health`, сводку пула задач/PR. Строит промпт:
   открытый вопрос + сырые данные + чек-лист известных классов
   (`config/self-review-checklist.json`, ДАННЫЕ, не код).
2. **investigate** (недоверенный, БЕЗ GitHub-токена) — гоняет промпт через
   DSH транспортом `scripts/review/ai_dsh.sh`, **переиспользован без
   изменений**: скрипт уже общий, ничего специфичного для PR-ревью внутри
   него нет.
3. **apply** (доверенный, write) — разбирает ответ по контракту находок,
   ЖЁСТКО отбрасывает находки без проверяемого факта (`has_verifiable_fact`),
   дедуплицирует (точный отпечаток среди self-review issues,
   открытых+закрытых + токенная похожесть по всему открытому пулу,
   `scripts/lib/duplicate_guard.py`), считает суточный потолок
   (`SELF_REVIEW_DAILY_CAP = 3`), заводит задачи с меткой по классу находки
   и печатает, ПОЧЕМУ задач заведено 0, если это так.

## Три исхода находки, не один

- `дефект`/`белое-пятно` → обычная задача пула.
- `знание` → задача `self-review:knowledge`: тело прямо требует записать
  вывод в AGENTS.md/docs, а не закрыть разовым фиксом (правило «вывод,
  оплаченный инцидентом, живёт в репозитории»).
- `инструмент` → задача `self-review:instrument`: тело прямо требует новый
  скрипт в `scripts/measure/`/новую величину снимка здоровья/новую гвардию
  **и** доказательство на истории, что новая метрика поймала бы уже
  известный инцидент.

## Доказательство работоспособности (живой прогон, не синтетика)

Прогнан `self_review.py gather --repo mytab0r/edge-harness --hours 120`
против РЕАЛЬНОГО репозитория 2026-09-12 (окно 2026-09-07..2026-09-12,
захватывает эталонные сутки 09-10..12). Дословный разбор дайджеста —
design.md, «Доказательство работоспособности».

Итог одной фразой: находит (б) — петлю меток на #782 — чисто и без
подсказки (60 переключений за окно, первая строка списка `label_churn` по
убыванию); находит (в) — красный деплой dsh-edge — по агрегату (12 провалов
против 6 успехов) и по самому списку прогонов (виден непрерывный ряд с
2026-09-07 по утро 2026-09-12); НЕ находит (а) в текущей конфигурации —
агрегат по worker.yml показывает повышенный процент провалов (58/100), но
конкретный всплеск сразу после мержа #878 срезан потолком выборки (20
последних прогонов на workflow — при высокой частоте прогонов после
восстановления это окно уже не достаёт до момента регрессии). Названо
честно, не подогнано — см. design.md.

## Тормоза и газ

Суточный потолок (`SELF_REVIEW_DAILY_CAP = 3`, свой счётчик, не общий с
`ci-failure`/`auto-detected`/`self-audit`) — газ автоматический, окно 24ч
уезжает само. Дедуп в два слоя — не даёт находке возвращаться после
закрытия как невалидной (класс #962) и не даёт пересекаться с обычной
задачей другого происхождения. Отказ транспорта на этапе `gather`
(`GatherTransportError`) красит прогон — не возвращает пустой дайджест как
«в конвейере тихо».

## Честная граница

Это ОДИН дорогой вызов модели раз в 6 часов над выборкой за 72 часа — не
полнота. Пропущенный инцидент, целиком случившийся и закрывшийся внутри
одного интервала между прогонами, не будет замечен. Механизм НЕ заменяет
reactive-детекторы (#201/#477/#830) — он ищет то, у чего ещё нет ни
отпечатка, ни сигнатуры, и стоит дороже одного прогона `ai-review` из-за
объёма контекста (весь дайджест периода, не диффа одного PR).
