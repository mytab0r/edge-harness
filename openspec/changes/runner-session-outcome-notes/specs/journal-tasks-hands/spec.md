# Дельта-спека: журнал (journal-tasks-hands) — заметки-итоги в сессии раннера после мержа/приёмки (#480)

## ADDED: Конвейер (оркестратор)

38. Сессия раннера `harness-<N>` в морде dsh-edge получает короткие
    заметки-итоги ПОСЛЕ конца агента — в тех местах, где оркестратор УЖЕ
    обнаруживает факт как часть существующего одноразового действия (новый
    периодический опрос сессий не заводится):

    - PR слит в main (`after_merge`) → «🔀 PR #N слит в main.» в сессию
      каждой задачи, которую PR декларирует/упоминает и которая ещё открыта.
    - Задача закрыта приёмкой или провалила приёмку (`accept_merged_tasks`,
      #227) → заметка с исходом и уликой («✅ … закрыта приёмкой (…): …»/
      «♻️ … не закрыта приёмкой (…) — …»).
    - Задача возвращена в пул из-за нездорового PR (`unhealthy_pulls`) →
      заметка с причиной («♻️ … возвращена в пул: PR #N нездоров (…).»).

    Заметка — событие `assistant/message` через `POST /api/sessions/harness-
    <N>/ingest` (тот же патч 0004, что дренирует живой транскрипт, #119);
    `session_id = harness-<номер задачи>` — тот же детерминированный вывод,
    что уже использует архив сессий. Один HTTP-логин на весь проход
    вызывающей функции, не на каждую заметку. Отсутствие сессии раннера
    (`HTTP 404` — задача без раннера, ручной PR) — норма, заметка не
    появляется и прогон не красится; недоступность самой морды — best-effort
    (#629): видимая строка ⚠️ в отчёте, никакого жёсткого сбоя из этой
    возможности не существует — недоставленная заметка не валит слияние/
    приёмку/возврат в пул (они уже случились и не откатываются). Отдельно от
    отчёта конкретного прогона — эскалация владельцу не чаще раза в
    календарные UTC-сутки (комментарий-маркер + Telegram в задаче-статусе
    #120, throttle по дате маркера), чтобы долгая недоступность морды не
    слала сигнал на каждый пульс.

    Намеренно НЕ покрыто отдельным событием: «PR открыт» (уже видно живым
    транскриптом — тул-колл агента `gh pr create` дренируется во время
    хода) и положительный вердикт гейтов (секунды/минуты спустя сменяется
    слиянием, которое и так даёт заметку выше; отдельное отслеживание
    потребовало бы нового опроса каждого открытого PR на каждый пульс).
