# Дельта-спека: журнал (journal-tasks-hands) — заметки-итоги в сессии раннера после мержа/приёмки (#480)

## ADDED: Конвейер (оркестратор)

38. Сессия раннера `harness-<N>` в морде dsh-edge получает короткие
    заметки-итоги ПОСЛЕ конца агента — в тех местах, где оркестратор УЖЕ
    обнаруживает факт как часть существующего одноразового действия (новый
    периодический опрос сессий не заводится):

    - PR слит в main (`after_merge`) → «🔀 PR #N слит в main.» в сессию
      каждой задачи, которую PR декларирует/упоминает и которая ещё открыта.
    - Задача закрыта приёмкой или провалила приёмку (`accept_merged_tasks`,
      #227) → заметка с исходом и уликой («✅ … закрыта приёмкой (…): …»/
      «♻️ … не закрыта приёмкой (…) — …»).
    - Задача возвращена в пул из-за нездорового PR (`unhealthy_pulls`) →
      заметка с причиной («♻️ … возвращена в пул: PR #N нездоров (…).»).

    Заметка — событие `assistant/message` через `POST /api/sessions/harness-
    <N>/ingest` (тот же патч 0004, что дренирует живой транскрипт, #119);
    `session_id = harness-<номер задачи>` — тот же детерминированный вывод,
    что уже использует архив сессий. Один HTTP-логин на весь проход
    вызывающей функции, не на каждую заметку. Отсутствие сессии раннера
    (`HTTP 404` — задача без раннера, ручной PR) — норма, заметка не
    появляется и прогон не красится; недоступность самой морды — видимая
    строка 🚨 в отчёте, не валит слияние/приёмку/возврат в пул.

    **Изменение #1430** (доводка этого же change'а, не новый). Исход отказа
    различается по СОДЕРЖАНИЮ отказа, а не по коду ответа: по коду «формат
    сессии не мигрируется» и «исчерпана квота DO» неотличимы (оба
    `HTTP 500 Internal runtime error`), а лечатся противоположно — первый не
    вылечится никогда (формат в хранилище сам не изменится, дефект #1404,
    фикс #1405 спас только новые события), вторая лечится сбросом квоты в
    00:00 UTC. Терминальные маркеры содержания перечислены один раз —
    `scheduler.py::SESSION_TERMINAL_FAILURES` — и читаются ОБОИМИ вызывающими
    морды: заметками-итогами и архивом сессий (вторая рукописная копия
    условия — отложенный рецидив, живой случай: PR #1431 сделал различение в
    заметках и оставил архив в вечном повторе).

    | исход отказа | повтор | отчёт | прогон |
    |---|---|---|---|
    | норма: `HTTP 404` — задачи без раннера нет | не нужен | строки нет | зелёный |
    | терминальный: `SessionFormatUnsupported*` (формат не мигрируется) | не поможет никогда | ⚠️ с номером задачи и причиной; в архиве номер уходит из очереди `session:archive-pending` | зелёный |
    | сломанная возможность: квота DO, сеть, таймаут, незнакомый отказ | поможет (или починка причины) | 🚨 | красный |

    Умолчание для незнакомого отказа — «сломанная возможность», громкий путь:
    незнакомый отказ громче, чем надо, стоит лишнего сигнала; тише, чем надо,
    — молчаливого накопления. Повреждение хранилища
    (`SessionPersistenceCorruptionError`, ADR 0027) терминальным НЕ считается.

    Намеренно НЕ покрыто отдельным событием: «PR открыт» (уже видно живым
    транскриптом — тул-колл агента `gh pr create` дренируется во время
    хода) и положительный вердикт гейтов (секунды/минуты спустя сменяется
    слиянием, которое и так даёт заметку выше; отдельное отслеживание
    потребовало бы нового опроса каждого открытого PR на каждый пульс).
