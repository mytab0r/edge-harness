# telegram-merge-declared-task-only: «выполнена» — только об объявленной задаче

Задача: #404 (находка AI-ревью PR #402 по #170; вердикт rework приехал
следом за слиянием). Родитель #170 закрыт приёмкой и не переоткрывается.

## Проблема

`after_merge` выбирал задачу для «задача #N выполнена — слито в main»
первым подходящим номером из `task_ref.extract_task_refs` (широкая
семантика «любое упоминание», отсортировано по возрастанию). Тело
`#79\n\n…Заодно поправил соседний баг из #78.` (обе открыты) давало
сообщение про #78 — канал говорит «выполнена» о задаче, которую PR не
делал и которую приёмка (#227) не закроет. То же враньё каналу, против
которого затевался #170; нарушение доктрины #259: «этот PR выполнил
задачу N» — узкий вопрос (декларация первой строкой), не упоминание.

## Решение

Захват `first_task` перенесён на ветку `task_ref.declares_task(...)` —
тот же предикат, что уже выбирает текст напоминания в той же функции и
тот же, по которому приёмка собирает `merged_pr_map`. Объявленных
подходящих задач нет (dependabot, orchestra:skip, задачи из прозы) —
сообщение не отправляется вовсе. Широкая семантика для замков
(`claim_task.release`) и напоминаний остаётся как была — это заявленный
осознанный выбор (#259, докстринги after_merge).

## Гвардия

`test_scheduler.py::test_after_merge_announces_only_declared_task_not_prose_mentions` —
тело объявляет #79 и упоминает #78 (обе открыты, метка task): в сообщении
#79 и его заголовок, ни #78, ни её заголовка; и
`test_after_merge_without_declared_task_sends_nothing` — без декларации
сообщений нет. Доказано мутацией: захват до проверки declares_task (как в
слитом PR #402) красит оба теста.

## Критерий готовности

Оба теста зелёные, мутационная проба красная, контракт и проверки PR
зелёные; видимый результат — сообщение в чате после ближайшего мержа
называет именно объявленную задачу.
