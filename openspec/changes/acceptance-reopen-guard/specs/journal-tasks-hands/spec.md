# Дельта-спека: журнал (journal-tasks-hands) — приёмка не закрывает переоткрытую задачу заново (#363)

## ADDED: Конвейер (оркестратор)

18.2. Приёмка (`accept_merged_tasks`, #227), ветка `state in ("ok", "docs")`, перед
    закрытием задачи проверяет, не закрывала ли она уже ЭТУ пару (issue, слитый
    PR) раньше — признак: маркер-комментарий `ACCEPTANCE_OK_MARKER`/
    `ACCEPTANCE_DOCS_MARKER` с номером именно этого PR (`scheduler.py::
    acceptance_pr_marker`, то же место правды, что у формата маркеров веток
    `partial`/`fail`). Этот маркер приёмка сама оставляет непосредственно перед
    `PATCH state=closed` при первом закрытии — «маркер найден» равносильно
    «PATCH по этому PR уже прошёл», это прямая улика факта закрытия, а не
    косвенная примета вроде `closed_at > merged_at` (не различает причину
    закрытия) или события `closed` в timeline (не хранит, каким PR вызвано).

    Найдя маркер, приёмка молча уходит: не трогает evidence, не шлёт комментарий
    повторно, не дёргает `PATCH`/assignee/`claim_task.release`. Без этой
    проверки задача, переоткрытая человеком или агентом, на следующем же пульсе
    снова матчилась со старым уже слитым PR через `merged_pr_map` (мерж не
    исчезает), улика того PR оставалась валидной, и приёмка закрывала issue
    заново за 20–80 секунд — переоткрытие отменялось раньше, чем кто-либо успевал
    начать доработку (живой случай #131 ← PR #132, три переоткрытия за время
    работы над PR #359).
