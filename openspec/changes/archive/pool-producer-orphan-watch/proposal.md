# pool-producer-orphan-watch: инвариант 23 — производитель задач пула без измеримого потребителя (#1277)

Задача: #1277. Дельта-спека: [specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Замер 2026-09-14/15 (`gh api graphql`, `mytab0r/edge-harness`, поиск
`"Хвост чеклиста ревью PR" in:title`): 112 открытых задач одного
производителя (`scheduler.py::after_merge`, хвост чеклиста ревью), 0
когда-либо закрытых, 0 когда-либо взятых в работу, старейшая висит 8
суток. Категория ускорялась (8 задач за предыдущую неделю, до 23/сутки на
пике). Ни один механизм репозитория этого не увидел — долг нашёл человек,
не система.

Репозиторий несёт девять программных производителей задач пула, все —
через одну точку `scripts/lib/pool_issue.py::create_pool_issue`:
`scripts/review/file_tasks.py` (review-findings), `pulse_guard.py::
failure_watch` (failure-watch), `stall_detector.py` (stall-detector),
`dependabot_alert_watch.py` (dependabot-alert-watch), `upstream_drift.py`
(upstream-drift), `health_audit.py` (health-audit), `merge_health_watch.py`
(merge-health-watch), `scheduler.py::after_merge` (checklist-tail),
`scheduler.py::replace_closed_task_prs` (task-replacement). Ни один не
несёт счётчика на выходе.

## Что делается

1. **Признак производителя** (`scripts/lib/pool_issue.py`): `create_pool_issue`
   принимает обязательный `producer: str`, проставляемый скрытым
   HTML-комментарием `<!-- pool-issue-producer: <id> -->` первой строкой
   тела — единственная точка создания делает пропуск признака невозможным
   для следующего производителя (тот же приём, что уже применён к
   `labels` с `task`, #526). Живой замер показал минимум двух
   производителей без отличительной метки (review-findings,
   checklist-tail — оба несут только `labels=["task"]`) и двух, делящих
   одну и ту же метку `auto-detected` (stall-detector, task-replacement) —
   заголовок/метка сами по себе не различают производителя надёжно.
   Все девять вызовов обновлены (`pulse_guard.py`, `stall_detector.py`,
   `dependabot_alert_watch.py`, `upstream_drift.py`, `health_audit.py`,
   `merge_health_watch.py`, `scheduler.py` ×2, `file_tasks.py`).

2. **Классификатор и пороги** (`scripts/lib/producer_orphan_watch.py`,
   новый модуль, чистая логика без сети): маркер тела — первичный признак;
   `_legacy_classify` (title/label-эвристика) — заморожённый запасной путь
   только для issue без маркера (заведены до этого PR). Пороги из живого
   замера (2026-09-15, полный дамп `label:task`, 828 issue):
   `MIN_SAMPLE_SIZE=10`, `DEAD_CLOSE_RATE_MAX=10%`, окно 30 дней,
   `min_oldest_open_hours=24` (то же значение, что `scheduler.STALE_HOURS`).
   Три исхода на каждого производителя отдельно — `check_result.CheckResult`
   (issue #1096): недостаточно данных → `unknown()`, доля закрытия здоровая
   → `ok()`, доля на/ниже порога при достаточном возрасте → `violation()`.

3. **Инвариант 23** (`scripts/orchestra/repo_invariants.py`): фетч задач
   пула за окно (`search/issues`, `created:>=...`), вердикт по каждому из
   девяти производителей, отдельная строка отчёта на каждого (третье
   состояние видно, не спрятано). ЭСКАЛИРУЮЩИЙ (`ESCALATING_INVARIANTS`) —
   решение обосновано в дельта-спеке; НЕ в `CI_GATING` (состояние
   репозитория, не вина текущего PR, тот же принцип, что у 1/5/9/10/12 и
   соседей).

## Честная граница

Инвариант называет ТОЛЬКО факт «у производителя X нет измеримого
потребителя за окно». Решение, что с этим делать (остановить
производителя, поднять приоритет находок, перевести на другой носитель —
как уже сделано для самого хвоста чеклиста отдельным изменением
#1262/#1268) — не машинное, называется явно в докстрингах и не
подделывается под автоматику.

## Отвергнутые варианты

Классификация ТОЛЬКО по title/label-эвристике (без маркера тела)
отвергнута: живой замер показал минимум двух производителей без единой
отличительной метки и review-findings, чьи заголовок и тело пишет модель
AI-ревью и в принципе не поддаются эвристике — признак сломался бы на
первом же переименовании заголовка любого из девяти. Единый счётчик на
всех девять сразу (одно число, не по производителю) отвергнут: он не
различил бы «один мёртвый среди восьми здоровых» от «слегка проседают
все», а именно первое — реальный найденный случай.
