## ADDED: Конвейер (оркестратор)

18.2. Приёмка по ссылке — второй закрывающий рядом со штатной приёмкой
    (п.18/18.1): каждый прогон оркестратора (`orchestra.yml`, шаг после
    планировщика, `scripts/orchestra/reference_closure.py`) закрывает задачи
    пула, которые слитый PR явно заявляет ЧУЖИМИ — не именем ветки, а
    строгим маркером в теле (`task_ref.also_closes_targets`: список
    глагольных форм «закрывает/закрываю/закрыт(а|о|ы)?» рядом с `#N`).
    Русские формы GitHub как директиву не распознаёт (фиксированный
    английский список ключевых слов) — автозакрытия при мерже нет
    структурно, запрет `Closes/Fixes/Resolves` (#953) не задет. Открытый
    корень и любое упоминание `#N` не годятся для необратимого действия
    (живой ложный срабатывания «закрытие #806» на теле PR #986 — отклонён
    экспериментом и мутационным тестом). Прошедшее время («закрыл(а|и)?»)
    исключено из списка отдельно (находка ai-review PR #1046, круг 4, живой
    пул 323 слитых PR): форма ловила прозу о ЧУЖОМ прошлом действии («тот же
    класс, что закрыла #294» — PR #576; «приёмка закрыла #320» — PR #358),
    не заявление ЭТОГО PR о себе — ни один из живых настоящих заявлений
    прошедшее время не использует.

    18.2.1. Собственная задача ветки закрывающего PR исключена — её
        закрывает штатная приёмка; второй механизм не дублирует маркеры и
        комментарии на ту же пару (задача, PR). Дальнейшие машинные
        отклонения до улики: #120, не open, эпик, без метки `task`,
        маркер приёмки-по-ссылке для этого PR уже стоит (идемпотентность),
        назначен исполнитель, конкурирующий открытый PR (та же узкая
        семантика `resolve_pr_task`, что у штатной приёмки). Каждый
        кандидат печатается закрытым или пропущенным с названной причиной —
        молчаливого пропуска нет. Кандидат, у которого номер СТРУКТУРНО и
        ОКОНЧАТЕЛЬНО не задача (это номер PR, или issue вовсе не существует
        — 404) печатается тихо (⏭️), не громкой ⚠️: исход не изменится на
        следующем прогоне, красный шаг месяцами без этого различения —
        нарушение «тормоз без газа» (находка ai-review PR #1046, круг 4,
        живой триггер — кандидат #294 из тела PR #576).

    18.2.2. Материальная улика — те же категории и функции штатной приёмки
        (`classify_acceptance`/`deploy_evidence`/`script_evidence`/
        `docs_missing`, только читаются), плюс ТРИ проверки второго
        источника: коммит слияния — предок main (compare API, класс #925:
        «зелёный прогон» не цитируется для sha вне main); файлы добавленной
        гвардии каталога (#749) с текстовым признаком мутационного
        доказательства в называемом тесте (честная граница: текстовый
        признак, не повторный прогон мутации); и, если тело PR называет путь
        `openspec/changes/<id>`, — этот change заархивирован
        (`referenced_change_archived`, находка ai-review PR #1046, круг 4:
        живой кандидат #218 называет активный, ещё не заархивированный
        change и без этой проверки прошёл бы уликой). Сбой самой проверки
        (сеть/секрет/API, включая compare) — эскалация владельцу (#120 +
        Telegram) с дедупом на эпизод, задача не тронута — тот же исход,
        что у штатной приёмки; «проверка сломана» и «улика не подтвердилась»
        не смешиваются.

    18.2.3. Порядок записи при закрытии — PATCH `state=closed` ПЕРВЫМ,
        маркер-комментарий вторым: сбой закрытия оставляет задачу открытой
        без маркера — следующий прогон повторяет попытку целиком; сбой
        комментария при уже закрытой задаче — громкая ⚠️-строка отчёта
        (красный шаг, continue-on-error), а не замороженный кандидат:
        закрытую задачу следующий прогон отсекает по состоянию. Обратный
        порядок (комментарий → закрытие) запрещён именно этой формулировкой:
        он порождал вечную открытую задачу с комментарием «Закрываю.»
        (находка ревью PR #1046).

    18.2.4. Потолок закрытий за прогон — 5 (REFERENCE_CLOSURE_RUN_CAP):
        газ против аномалии, обоснование числа — докстринг модуля; кандидаты
        сверх потолка печатаются с причиной, рассматриваются следующим
        прогоном. Шаг в workflow несёт гейт квоты (`steps.quota.outputs.
        skip`), `DSH_EDGE_URL` (нужен deploy-категории улики — без него
        `deploy_evidence` кидает RuntimeError, находка ai-review PR #1046,
        круг 4) и continue-on-error — красный шаг виден, зелёный статус
        job'а, который читает пульс, не гасится.
