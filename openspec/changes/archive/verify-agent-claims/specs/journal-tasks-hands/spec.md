# Дельта-спека: машинная проверка заявлений агента в теле PR (#968)

> Требования 19.1–19.6 влиты в источник правды
> [`openspec/specs/journal-tasks-hands.md`](../../../../../specs/journal-tasks-hands.md)
> как 18.3.1–18.3.6 (раздел «Конвейер (оркестратор)», провенанс-пометка
> там же) — здесь консервация истории решения, актуальное поведение читай
> в центральном файле.

Дополняет описание конвейера (`openspec/specs/journal-tasks-hands.md`,
раздел «Конвейер (оркестратор)» — гейты обязательных проверок PR), рядом с
[ADR 0026](../../../../../../docs/decisions/0026-verify-agent-claims-machine-check.md).

## ДОБАВЛЕНО: заявления о мутации исполняются, не читаются

19.1. PR-гейт repo-ci исполняет мутационные заявления тела PR: блок
     «## Доказательство мутацией» (строка «Тест: `python -m pytest
     <путь>[::<test_id>] -q`» + блок ```diff``` с патчем, снимающим фикс)
     прогоняется как есть — тест обязан быть зелёным до мутации, покраснеть
     под ней и вернуть зелёный после отката. Тест, оставшийся зелёным под
     патчем, делает заявление ЛОЖНЫМ (`false_claim`) — это блокирующий исход,
     не предупреждение: структурная гвардия, которую не красит снятие её
     собственной проверки, не гвардия (класс #893).

19.2. Заявление исполняется ВСЕГДА, когда блок присутствует в теле PR —
     независимо от того, какие файлы PR меняет: автор написал блок — он
     заявил, и мотивирующий случай #893 (ложное «доказательство мутацией» в
     PR, трогавшем только `scripts/git/` и `scripts/lib/`) не проходит мимо
     механизма. ОБЯЗАТЕЛЬНЫМ (наличие в теле) блок держится только для PR,
     меняющих `scripts/ci/guards/*.sh` — цена дорогого прогона не ложится на
     тех, кто не заявлял; расширение обязательности за пределы каталога —
     по замеру, не угадыванием (задача в беклоге находок PR #1028).

19.3. Вердикт различает `proved`/`false_claim`/`setup_error` и печатает фазы
     прогона (до/под/после), а не только exit code: ненулевой exit ≠ «гвардия
     покраснела» (правило «Доказывай доказыватель»). Рабочее дерево после
     прогона восстанавливается; при неудавшемся откате — аварийно
     (`git checkout --` по путям патча), исход несёт факт `tree_restored`
     (None/True/False), и False останавливает цикл по остальным заявлениям:
     прогон по мутированному дереву дал бы вердикт по чужой причине.

## ДОБАВЛЕНО: «класс закрыт» и «непроверено» — проверка слова и честная граница

19.4. Блок «## Класс закрыт» (строки «Grep: `<ERE>`» и «Ожидается совпадений:
     <N>») проверяется живым `git grep` дерева: фактическое число совпадений,
     не равное заявленному — блокирующий `::error::`. Ошибка ИСПОЛНЕНИЯ
     паттерна (битый ERE, rc>=2) — тоже громкий `::error::` с газом, а не
     необработанный сбой прогона: отказ без названного газа не принимается.

19.5. Формулировки из известного списка непроверяемых («прогнал на реальной
     истории», «проверил живьём», …) при отсутствии раскрытия под
     «## Непроверено машиной» дают `::warning::`, НЕ блок: та же фраза
     легитимно встречается в пересказе ЧУЖИХ инцидентов, и жёсткая блокировка
     по подстроке давала бы ложные отказы. Это сознательно не гвардия, а
     видимость читателю — решение остаётся за ревью.

## ДОБАВЛЕНО: два формата мутационного доказательства разведены по поверхностям

19.6. `MUTATION-PROOF` (ADR 0023 — закоммиченные файлы, исторический ref,
     движок `mutation_recipe_guard.py`) и блок «## Доказательство мутацией»
     (тело PR, гипотетическое состояние текущего дерева) — разные поверхности
     одного класса заявлений; ни один не заменяет другой. Секция заявления,
     несущая узнаваемую форму `MUTATION-PROOF`, получает адресный отказ с
     объяснением обеих поверхностей, а не общую ошибку «не найдена строка
     Тест:»; произвольная команда (`run:`) из непроревьюированного тела PR не
     исполняется — форма команды «Тест:» сужена до argv-формы pytest.
