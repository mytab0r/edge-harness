# Proposal: окно `merge_throughput` — предыдущие полные сутки, не «сегодня»

Задача: #1155.

## Проблема

`scripts/measure/pipeline_health.py::collect` считал `merge_throughput` запросом
`search/issues?q=…merged:{сегодня}..{сегодня}`, а снимок берётся один раз в календарные
сутки UTC, вскоре после полуночи (`should_snapshot`). Итог — метрика мерила «слито за
первые несколько минут суток», не «слито за сутки»: живая история `data/pipeline-health`
несёт `merge_throughput=0` за 2026-09-11..09-13, тогда как прямой запрос
`merged:2026-09-11..2026-09-11` отдаёт `total_count=16`. AGENTS.md называет слияния PR
единственным доказательством жизни конвейера («Мерить нужно видимый исход, а не
heartbeat») — этот носитель был мёртв четверо суток, и ни один потребитель (в т.ч.
`health_regression.py::classify_metric`, сравнивающий 0 с 0) не мог закричать.

## Решение

`collect()` считает `merge_throughput` окном **полных предыдущих календарных суток UTC**
(`merge_throughput_window(today)` → `[вчера 00:00, сегодня 00:00)`), используя уже
существующий `search_merged_prs` (тот же примитив, что `merge_health_watch.py`). Границы
окна несутся в самом снимке (`merge_throughput_window_start/_end`) — подпись значения
обязана соответствовать тому, что померено (AGENTS.md); отсутствие этих полей в старой
строке снимка — структурный маркер «посчитано сломанной формулой».

Обоснование выбора окна, цена альтернативы, решение по старой истории и таблица соседних
метрик — `design.md`.

## Границы (не входит)

- `do_rows_read_pct` (`scripts/measure/quotas.py`) несёт родственный, но НЕ идентичный
  дефект (алиасинг снимка/сброса суточной квоты, не окно-против-подписи) — заведён
  отдельно, issue #1278, здесь не чинится.
- Пересчёт задним числом строк истории `data/pipeline-health.jsonl` — не делается этим
  change (запись на data-ветку — прод-операция вне обычного суточного пульса); вместо
  этого `health_regression.py::classify_metric` исключает немаркированные легаси-точки
  `merge_throughput` из построения baseline (см. design.md, «Решение по истории»).
