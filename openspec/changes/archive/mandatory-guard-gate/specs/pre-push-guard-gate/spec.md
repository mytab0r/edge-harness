# Дельта-спека: pre-push-guard-gate — обязательный локальный гейт гвардий (#1280)

## ADDED: Локальный гейт перед `git push`

1. Любой `git push` из рабочего дерева, где `core.hooksPath=.githooks`
   настроен (ставится безусловно `scripts/git/task-branch` — и путь
   автономного воркера, `GITHUB_ACTIONS=true`, и путь локальных рабочих
   деревьев `.claude/worktrees/<N>-slug>`), запускает
   `.githooks/pre-push` → `scripts/lib/pre_push_guard_gate.py` ДО того, как
   коммиты уходят на сервер.

   1.1. Режим `full` (`GITHUB_ACTIONS=true` — одноразовый чекаут CI):
   полный каталог `scripts/ci/run_guards.sh`, без единого исключения — та
   же проверка, что и обязательный серверный чек `test`, выполненная
   раньше по конвейеру.

   1.2. Режим `local` (иначе): тот же каталог, но
   `scripts/ci/run_guards.sh` вызывается с `GUARD_CATALOG_SKIP=
   "decision-doc-numbering-guard invariant-numbering-guard"` — обе
   исключённые гвардии используют `decision_numbering.py::fetch_refs`
   (`git fetch --depth 1`, ловушка #1228), мутирующий ОБЩИЙ `.git`
   всех рабочих деревьев задачи; измерено 2026-09-15: единичный
   локальный прогон без исключения перевёл `git rev-parse
   --is-shallow-repository` false → true. Обе гвардии остаются
   обязательными для слияния — их гоняет CI (`test`), не затронутый
   этим исключением.

2. Исход гейта — одно из трёх состояний
   (`scripts/lib/check_result.py`), не два:

   2.1. `ok` — все прогнанные гвардии зелёные, `git push` продолжается
   без вмешательства.

   2.2. `violation` — хотя бы одна гвардия каталога упала; `git push`
   отклоняется, сообщение называет причину (`scripts/ci/run_guards.sh`
   уже печатает `::error::гвардия каталога '<имя>'
   (scripts/ci/guards/<имя>.sh) провалилась` — гейт ретранслирует этот
   текст, не пишет второй).

   2.3. `unknown` — сама инфраструктура гейта не смогла запуститься
   (`scripts/ci/run_guards.sh` отсутствует, `bash` не найден в PATH);
   `git push` отклоняется с текстом, явно называющим третье состояние
   («НЕ СМОГ запуститься»), отличным от текста `violation` — это не
   «прошло».

3. Аварийный выход: переменная окружения
   `GUARD_GATE_SKIP_ACK="<причина>"`, установленная перед `git push`,
   пропускает ТОЛЬКО этот локальный гейт (любое из состояний 2.2/2.3),
   печатая причину пропуска в stderr. Обязательный серверный чек `test`
   (branch protection) эту переменную не читает и по-прежнему гоняет
   полный каталог гвардий после пуша — снятие локального гейта не
   открывает способ слить нарушение мимо CI, только возвращает цену
   ошибки к уровню, который был до этого change (узнать о нарушении из
   CI, не заранее).

4. `scripts/ci/run_guards.sh` (обязательный серверный чек `test`,
   `.github/workflows/repo-ci.yml`) не меняет поведения: вызов без
   `GUARD_CATALOG_SKIP` в окружении гоняет полный каталог, как и до
   этого change.

## Честная граница

Git-хук — обычный отслеживаемый файл каталога `.githooks/`: рабочее
дерево, чекаут которого не включает этот коммит (создано ДО того, как
`.githooks/pre-push` попал на его ветку), не увидит файл на диске и не
запустит гейт локально, пока не перебазируется на свежий `origin/main`.
Обязательный серверный чек `test` не зависит от возраста рабочего дерева
и остаётся последней инстанцией в любом случае. `git push --no-verify`
обходит любой git-хук технически — это свойство git, а не дыра этого
механизма: цель гейта не «сделать обход невозможным» (недостижимо для
локального хука в принципе), а убрать типовой случай «никто не подумал
спросить гвардию».
