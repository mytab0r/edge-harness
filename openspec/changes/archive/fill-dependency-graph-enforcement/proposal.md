# Propose: наполнить граф зависимостей и сделать заполнение обязательным на входе

## Summary

Задача #371 (владелец, 2026-09-06), прямое продолжение #361/PR #367
(`scripts/lib/task_deps.py`, единственное место правды на нативный
GitHub-граф `blockedBy`/`blocking`). #361 ввёл носитель и приоритет по
графу, но явно вынес за скобки: обратное заполнение графа для уже
открытых задач и обязательность заполнения на входе (`proposal.md`
#361, Out). Итог измерен здесь: на день внедрения (2026-09-06) граф был
пуст — 0 из 113 открытых задач пула имели `blockedBy`/`blocking` —
уровень 2 приоритета (`free_task.py::issue_priority_key`) не влиял ни на
что, деградируя всегда до тайбрейка по номеру.

## Problem / motivation

- Носитель есть (#361), но ничего его не наполняет: ни разовой миграции
  существующих зависимостей, названных прозой ДО перехода на нативный
  граф, ни требования на новых точках входа.
- Два поставщика пула не связаны с графом вовсе: `.github/ISSUE_TEMPLATE/
  task.yml`/`white-spot.yml` (человек/агент через форму или `gh issue
  create`) и `scripts/review/file_tasks.py` (автозаведение из находок
  AI-ревью — сегодня ОСНОВНОЙ поставщик пула). Ни один не спрашивает
  «чем блокируется» и не переносит ответ в нативный `blockedBy`.
- Рассинхрон «тело называет блокирующую задачу — граф не знает» —
  молчаливое неверное состояние: приоритет считается неверно, и никто
  не узнаёт об этом, пока не заметит вручную.

## Правило

1. Существующие явные зависимости (сформулированные в теле/комментариях
   до перехода на граф — «после #N», «зависит от #N», «блокируется #N»,
   «заблокирован(а) #N», «блокер — #N», «до закрытия #N») переносятся в
   нативный `blockedBy` РАЗОВО, только после проверки чтением каждой —
   не пакетно по регэкспу (ложная связь опаснее отсутствующей).
2. Оба поставщика пула требуют явного ответа «чем блокируется» —
   включая «ничем» явным выбором, не пропуском.
3. Рассинхрон «тело называет открытую блокирующую issue — граф не
   знает» — видимый сигнал на каждый push/PR, не молчаливый.

## Scope

### In

- Разовая миграция: связи `#254←#170` и `#258←#133` (обе проверены
  чтением полного тела и состояния обеих сторон, обе открыты на момент
  проставления) — поставлены через `task_deps.py block`.
- `.github/ISSUE_TEMPLATE/task.yml`, `white-spot.yml` — обязательные
  поля «Чем блокируется»/«Что блокирует» (task.yml, обе стороны) и «Чем
  блокируется» (white-spot.yml, одна сторона — white-spot почти никогда
  сам не блокирует другие задачи).
- `scripts/review/ai_prompt.md`, `scripts/review/ai_review.py` —
  контракт блока `ЗАДАЧА:` расширен обязательной последней строкой
  `БЛОКИРУЕТСЯ: …` (`parse_tasks`/`blocked_by_numbers`); блок без неё
  отбрасывается целиком, громкое предупреждение.
- `scripts/review/file_tasks.py` — перенос заявленной зависимости в
  нативный граф ПРИ СОЗДАНИИ issue (`wire_declared_dependency`), не
  отдельным обходом: номер уже известен в момент создания, дешевле и
  без риска устаревания. Номер вне текущего открытого пула с меткой
  `task` — не линкуется, громкое предупреждение (ложная связь опаснее
  отсутствующей).
- `scripts/lib/task_deps.py::fetch_pool` — опциональный параметр
  `include_body` (одно поле `body` в том же GraphQL-запросе, не второй
  проход) для детектора рассинхрона.
- `scripts/lib/declared_deps.py` (новый) — эвристический детектор
  «тело называет открытую блокирующую issue формулировкой зависимости,
  граф не знает»; НИЧЕГО не пишет сам, только предупреждает.
- `.github/workflows/repo-ci.yml` — шаг «Рассинхрон тела задачи и графа
  зависимостей», `::warning::` на каждую находку, не проваливает
  обязательный гейт `test` (эвристика по прозе — ложные срабатывания
  ожидаемы, см. design.md).
- `docs/agents/PROTOCOL.md` — раздел «Зависимости» получает подраздел
  «Заведение задачи требует явного ответа».

### Out

- Автоматическое исключение заблокированных задач из пула (EXCLUSION) —
  не строится: #361 явно оставил это отдельным, нерешённым вопросом
  (proposal.md #361, Out); сегодня `blocked_by_open` вообще не читается
  `free_task.py` ни в фильтре, ни в приоритете (проверено чтением кода)
  — см. `design.md`, раздел «Газ».
- Автоматический workflow, конвертирующий произвольный текст ЛЮБОГО
  issue (не только структурный блок `ЗАДАЧА:`) в связи графа при
  создании — тот же отказ, что в design.md #361 (развилка б):
  серверной валидации формы GitHub не делает для программных
  создателей, риск ложной связи из вольной прозы.
- Полная миграция графа «на всякий случай» — только явно
  подтверждённые чтением связи (2 из ~40 прочитанных кандидатов).

## Acceptance criteria

1. Живой запрос `task_deps.py pool` показывает >0 задач с непустыми
   `blocking_open`/`blocked_by_open` (было 0 на 113).
2. Оба поставщика пула (шаблон issue, `file_tasks.py`) не дают завести
   задачу без ответа о зависимостях — пропуск невозможен на уровне
   контракта (форма/промпт), перенос в граф — на `file_tasks.py`
   автоматический, на форме — ручной (`task_deps.py block`, тот же
   паттерн, что sub-issues).
3. `scripts/lib/declared_deps.py check` печатает `::warning::` на
   каждый обнаруженный рассинхрон, ничего не проваливает; живой прогон
   на этом репозитории — 0 находок после миграции.
4. Все новые/изменённые тесты — с мутацией (снят фикс → тест краснеет).
