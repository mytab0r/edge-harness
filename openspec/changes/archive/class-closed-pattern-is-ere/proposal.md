# class-closed-pattern-is-ere: паттерн «Класс закрыт» проверяется ERE, и об этом надо говорить до `git grep` (#1436)

Задача: #1436. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).
Замер: [docs/research/25-git-grep-regex-dialect.md](../../../docs/research/25-git-grep-regex-dialect.md).

## Зачем

`## Класс закрыт` проверяется вызовом `git grep -nE`, то есть POSIX ERE.
Пишут паттерны люди и агенты, привыкшие к Python `re`. Ловушек оказалось
две, и они лечатся по-разному — это выяснил замер, а не рассуждение.

**Громкая.** `(?:…)`, `(?i)`, `(?=`, `(?!` роняют git с текстом
`Invalid preceding regular expression`, который не называет ни причину, ни
лечение. Живой случай — PR #1434, прогон 35674153855: автор пошёл править
экранирование, потратив полный цикл CI плюс лишний коммит (одна правка тела
PR прогон не перезапускает).

**Тихая, и она опаснее.** `git grep -nE` НЕ падает на `\d` и на ленивых
квантификаторах — он считает совпадения и отдаёт правдоподобное число,
которое ничего не значит, а гейт «подтверждает» заявление, которого автор не
делал:

```
$ git grep -nE '\d'   -- only-digit.txt only-letter-d.txt
only-letter-d.txt:1:d       ← файл со строкой «5» НЕ совпал
$ git grep -nE 'q+?xyz' -- plain.txt
plain.txt:1:xyz             ← ни одного «q» в строке нет
```

## Поправка к самой задаче, названная вслух

Задача просила отвергать «как минимум `(?:`, `(?i)`, `(?=`, `(?!`, `\d`,
`\w`, `\s`, `\b`», поставив все восемь в один ряд. Замер показал, что
`\w`/`\s`/`\b` в `git grep -E` работают правильно — отвергать их значило бы
гнать автора переписывать рабочий паттерн, то есть тормоз без причины. А
главная опасность (ленивые квантификаторы) в задаче не названа вовсе, именно
потому что она молчит.

## Что делается

Проверка паттерна ДО `git grep`, с адресным сообщением на каждую ловушку:
какой конструкт найден, падает он или молчит, и чем заменяется. Носитель —
`ClassClosedClaim.__post_init__`, а не сам `run_class_closed_check`: объект с
ловушкой физически не существует, обойти проверку, собрав claim руками,
нельзя.

## Чего это НЕ делает

Не переводит проверку на PCRE (`git grep -P`): доступность `-P` зависит от
сборки git на раннере, и это отдельное решение с отдельным замером. Не
составляет полный список расхождений двух диалектов — закрыты те конструкты,
что реально встречаются, плюс найденные замером.
