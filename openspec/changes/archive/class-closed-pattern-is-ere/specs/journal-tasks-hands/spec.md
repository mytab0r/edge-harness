# Дельта-спека: руки (journal-tasks-hands) — паттерн «Класс закрыт» (#1436)

## MODIFIED: Проверка заявления «Класс закрыт»

~~Паттерн из тела PR передаётся в `git grep -nE` как есть; ошибка git
ретранслируется вызывающему.~~

Требование: паттерн проверяется на конструкты, которых POSIX ERE не знает
или понимает ИНАЧЕ, ДО вызова `git grep`. Сообщение называет факт, а не
ретранслирует чужой текст: какой конструкт найден, падает он или молчит, и
чем заменяется.

Сценарии:

1. Расширение группы (`(?:`, `(?i)`, `(?=`, `(?!`) → отказ до `git grep`,
   сообщение называет замену `(…)` для незахватывающей группы и говорит
   прямо, что у остальных аналога нет.
2. `\d` / `\D` → отказ. Обоснование в сообщении — измеренное поведение:
   `git grep -nE` не падает и матчит БУКВУ, а не цифру. Замена `[0-9]` /
   `[^0-9]`.
3. Ленивый квантификатор (`*?`, `+?`, `??`, `}?`) → отказ. `?` читается как
   «предыдущее необязательно»: замер — `q+?xyz` совпал со строкой «xyz».
   Лениво в ERE не выражается; замена через отрицающий класс.
4. GNU-расширения, которые РАБОТАЮТ (`\w`, `\s`, `\b`, `{n,m}`,
   `[[:digit:]]`) → проходят. Отвергать рабочий синтаксис — тормоз без
   причины: автор потратит заход на переписывание верного паттерна.
5. Экранированный метасимвол (`\(`, `\*?`, `\\d`) → проходит. Различает
   ловушку и литерал только чётность слэшей слева, поэтому проверка обходит
   паттерн посимвольно, а не регуляркой по нему.

Место проверки — конструктор заявления, не вызывающий код: claim с ловушкой
не должен существовать. Проверка в одном вызывающем оставила бы дверь любому
второму (и это ровно тот класс, за который репозиторий уже платил: «гейт
стоял в одном месте из трёх», #1448).

## Честный потолок

Полный список расхождений ERE и PCRE не составлялся — закрыты конструкты,
реально встречающиеся в паттернах этого репозитория, плюс найденные замером.
Появится новый — он и попадёт сюда, отдельной узкой правкой.

Перевод проверки на `git grep -P` (PCRE) не рассматривается этим изменением:
доступность `-P` зависит от сборки git на раннере, это отдельное решение со
своим замером.
