# Дельта-спека: журнал (journal-tasks-hands) — пригодность задачи проверяется до действия

## ADDED: Конвейер (оркестратор)

17.2. Контракт PR ↔ задача (`contract_check.py`) не выполняет НИ ОДНОГО
    изменяющего вызова (авто-назначение исполнителя, сверку дубликата PR)
    над задачей, признанной непригодной. Пригодность считается ОДИН раз, до
    любых действующих вызовов (`task_eligibility_problems`, одно место
    правды): задача существует как issue (не PR), открыта, несёт метку
    `task`, не несёт `blocked`. Непригодна хотя бы по одной причине —
    контракт только докладывает причину(ы) отказа, дальше по этой задаче не
    действует вовсе.

    Живой случай, который это закрывает (лог прогона 2026-09-06, PR #359):
    «contract: авто-назначение mytab0r на #131» сразу следом за «Задача #131
    закрыта — возьми открытую» — правило существовало в докстринге, но не в
    порядке проверок: авто-назначение стояло в той же ветке, что и проверка
    состояния issue, и не зависело от её результата.
