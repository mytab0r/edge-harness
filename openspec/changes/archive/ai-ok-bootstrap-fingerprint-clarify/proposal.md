# ai-ok-bootstrap-fingerprint-clarify: разбор «живого дефекта» ai:ok — root cause, не fingerprint (#828)

Задача: #828.

## Зачем

Заявление (наблюдалось многократно 2026-09-09, живые случаи PR #818, #819,
#826): метка `ai:ok` снимается при смене головы PR, даже когда дифф
относительно base не изменился (чистое подтягивание main / ребейз без
конфликта) — по правилу #294 (`review_labels.diff_unchanged`/
`diff_fingerprint`) `ai:ok` при неизменившемся диффе обязан пережить смену
головы. Задача — установить точно, кто снимает метку и почему.

## Класс проблемы

Не поведенческий дефект кода — гипотеза о баге в `diff_fingerprint`/
`ai_verdict_keep` (двухточечный дифф вместо трёхточечного) не
подтвердилась. `diff_fingerprint` (`scripts/lib/review_labels.py`) уже
строится по `patch` из `pulls/{n}/files` — трёхточечный дифф относительно
merge-base (закреплено #740, PR #333), устойчивый к чужим правкам того же
файла. `test_ai_verdict_keep_true_after_clean_merge_pr292` уже доказывает
keep-путь на реальном чистом подтягивании.

## Что установлено (root cause)

На всех трёх PR (#818/#819/#826) `ai:ok` был поставлен ВРУЧНУЮ (владельцем,
логин `mytab0r`, не `github-actions[bot]`) вместе с самодельным
комментарием, имитирующим формат вердикта AI-ревью (`pr: N | reviewer:
approve\n\n## Вердикт второго гейта — bootstrap (ai-review не вынес
вердикт, гейт медленный)`), в обход реального прогона `ai-review.yml`.

`review_labels.latest_ai_comment` (через `_is_trusted_verdict_author`, #294
— анти-подделка вердикта) доверяет ТОЛЬКО комментариям от
`github-actions[bot]`. Ручной комментарий эту проверку не проходит →
`stored_fp = None` → `check_pr.py::ai_verdict_keep` обязан вернуть `False`
(`diff_unchanged(None, …) = False`, «при сомнении считаем изменившимся» —
намеренно, AGENTS.md) → метка снимается на следующем же пуше, независимо от
того, изменился ли реальный дифф.

Это ТОЧНО поведение, уже закреплённое существующим тестом
`test_ai_verdict_keep_false_without_stored_fingerprint`
(`scripts/review/test_check_pr.py`) — часть анти-подделочной защиты #294, а
не баг. Разворачивать эту защиту (доверять меткам без backing-комментария
от `github-actions[bot]`) означало бы заново открыть дыру #294 (любой
участник публичного репозитория подделывает `approve`).

## Что делается этим change (без изменения контракта)

- Регресс-тест прод-формы на буквальном тексте комментария PR #818
  (`scripts/review/test_check_pr.py`), доказывающий, что bootstrap-метка
  никогда не переживает следующий пуш — даже при неизменном дифф-отпечатке.
  Мутация: наивный «фикс» (`stored_fp is None` трактуется как «сохранить»)
  красит и этот тест, и уже существующие
  `test_ai_verdict_keep_false_without_stored_fingerprint`/
  `test_security_hole_pr294_untrusted_comment_cannot_forge_ai_verdict`.
- Докстринг `scripts/lib/review_labels.py` рядом с `TRUSTED_VERDICT_LOGIN` —
  явно называет этот футган и правильный газ на «гейт медленный»:
  `gh workflow run ai-review.yml -f pr=N -f force=true` (заводит настоящий
  прогон с trusted-комментарием) вместо ручной подделки.
- Строка `ai:ok` в `docs/agents/LABELS.md` — та же честная граница, видимая
  в реестре меток, не только в исходнике.

## Что НЕ делается и почему

Код `review_labels.py`/`check_pr.py`/`ai_review.py` не меняется — текущее
поведение уже корректно и уже покрыто тестом с #294. Изменение означало бы
сознательно ослабить защиту от подделки вердикта ради практики, которая
сама и есть причина наблюдаемого «дефекта».
