Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Автономный
воркер (конвейер пула)», п. 26. Продолжает дельту `priority-broken-
mechanism-first` (архивирована, #224) — не переоткрывает её, добавляет
ОДИН уровень между уровнем 0 («сейчас красный») и уровнем `area:process`.

Требование: среди СВОБОДНЫХ задач (критерий свободы не меняется) выбор
идёт по ПЯТИ уровням, в этом порядке:

0. Задача сама несёт метку «механизм конвейера сейчас красный»
   (`ci-failure`/`self-audit`, `scripts/lib/free_task.py::BROKEN_LABELS`)
   ИЛИ транзитивно блокирует такую (`task_deps.blockers_of`) — раньше
   любого уровня ниже, потому что это измеримый факт простоя, а не
   самооценка природы задачи. Без изменений с #224.
1. **Новый уровень.** Метка `impact:system`
   (`scripts/lib/free_task.py::IMPACT_LABEL`) — задача СНИМАЕТ измеренный
   системный барьер (потолок пропускной способности, класс отказа,
   задевающий несколько механизмов конвейера сразу), если задача не
   попала в уровень 0 — раньше `area:process` и раньше обычной задачи,
   независимо от уровня 3. Самооценка заводящего/разбирающего задачу, а
   не факт (в отличие от уровня 0) — но явно объявленная меткой, не
   выведенная угадыванием по содержимому тела. Независим от `area:process`:
   задача может нести обе метки или только `impact:system`.
2. Метка `area:process` (задача про сам процесс работы), если задача не
   попала в уровни 0/1 — раньше любой обычной задачи, независимо от
   уровня 3. Критерий и постановка метки не меняются (были уровнем 1).
3. Внутри уровня — ТРАНЗИТИВНЫЙ вес графа блокировок: число ОТКРЫТЫХ
   задач этого же пула, которые закрытие текущей в конечном счёте
   приближает, включая цепочки длиннее одного прямого соседа. Без
   изменений (был уровнем 2).
4. При равенстве — номер issue как proxy даты создания. Без изменений
   (был уровнем 3). Тай-брейк ВНУТРИ каждого уровня, включая новый
   уровень 1, не тронут этим change: две барьерные задачи по-прежнему
   сортируются между собой по номеру — «старые долги не забываем»
   остаётся в силе там, где отдельного веса нет.

Граф пуст, ни одна свободная задача не помечена `area:process`/
`impact:system` и никто не «сейчас красный» (уровни 0–3 не отличают ни
одного кандидата) → видимый сигнал (предупреждение в stderr
`free_task.py`), сам выбор не останавливается — вырождение в уровень 4
для всех легитимно (уровень сдвинут с 3 на 4 этим change).

Для любой открытой задачи можно получить ответ, почему она на этом месте:
тир (включая новый уровень 1 и его источник — метку `impact:system`),
конкретные номера цепочки, транзитивный вес, чем сама заблокирована,
тай-брейк — без изменений в форме ответа (`priority_reason`), кроме
номеров уровней.

Сценарий: задача A несёт `impact:system` (без `area:process`) и задача B
несёт `area:process` (без `impact:system`) — A выбирается раньше B
независимо от транзитивного веса и номера: уровень 1 решает раньше
уровня 2.

Сценарий: задача C несёт и `area:process`, и `impact:system` — считается
уровнем 1 (`impact:system` перекрывает `area:process` там, где они
конкурируют), а не уровнем 2.

Сценарий: задача D (`impact:system`, номер 1172, заведена позже) и задача
E (`area:process` без `impact:system`, номер 1007, заведена раньше) — D
выбирается раньше E, хотя номер E меньше: уровень решает раньше номера.

Сценарий: задача F (`impact:system`, номер 50) и задача G (`impact:system`,
номер 90) — при равном транзитивном весе F выбирается раньше G: тай-брейк
по номеру ВНУТРИ уровня 1 не тронут этим change.
