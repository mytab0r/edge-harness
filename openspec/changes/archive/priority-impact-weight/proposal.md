# Propose: приоритет пула — вес барьера (`impact:system`), не только мета и граф

## Summary

Задача: #1178. Продолжает #361 (архивирован как `task-priority-blocking-graph`)
и #224 (архивирован как `priority-broken-mechanism-first`) — не переоткрывает
ни один из них, добавляет ОДИН новый уровень между уже существующими
уровнями 0 («сейчас красный») и `area:process`.

Замер #1178 (живой пул, 93 свободные задачи, 2026-09-14T00:30Z): тай-брейк
по номеру issue ВНУТРИ уровня `area:process` систематически топит
свежезаведённые барьерные задачи (заведены после живых замеров, номер
выше) под старыми «хвостами чеклиста ревью» той же меты (заведены
`after_merge` автоматически, номер ниже) — обеим не хватало отличающего
признака ВНУТРИ уровня.

## Problem / motivation

Голова очереди на момент замера — сплошь «Хвост чеклиста ревью PR #N»
(#1007/#1009/#1011/#1012/#1014/#1017/#1019). Задачи, снимающие измеренные
системные барьеры — #1161 (потолок пропускной способности прогона, ~33
прогона/сутки), #1172 (класс «механизм недостижим по построению», три
живых случая за сутки), #1149 (расхождение патч-серии `dsh-edge` с
апстримом, уже два прод-инцидента), #1141/#1160 (суммарное время прогона
воркера не ограничено), #1109 (миграция инвариантов на CheckResult) —
лежали в хвосте, потому что несут либо ту же метку `area:process`, что и
«хвосты чеклиста» (и тайбрейк решает по номеру — свежая барьерная задача
проигрывает старому хвосту), либо не несут `area:process` вовсе (тогда они
вообще не отличаются от рядовой задачи пула).

Это единственное, что реально требовало суждения человека: выбор «за что
браться» — не работа, а приоритет. Механизм на тот же вопрос отвечал
мелочью.

## Правило

Приоритет свободной задачи — ПЯТЬ уровней, в этом порядке (расширяет #224 —
уровень 0 не тронут):

0. Задача сама несёт метку «механизм конвейера сейчас красный»
   (`ci-failure`/`self-audit`) ИЛИ транзитивно блокирует такую — без
   изменений, см. дельту #224.
1. **Новый уровень.** Метка `impact:system` — задача СНИМАЕТ измеренный
   системный барьер (потолок пропускной способности, класс отказа,
   задевающий несколько механизмов конвейера сразу), если задача не
   попала в уровень 0. Самооценка заводящего/разбирающего задачу, а не
   факт (в отличие от уровня 0) — но явно объявленная меткой, не
   выведенная угадыванием по содержимому тела (тот класс риска уже
   отклонён для графа блокировок задачей #371/#529: «ложная связь опаснее
   отсутствующей» для структурного поля).
2. Метка `area:process` (была уровнем 1 до этого change) — без изменения
   критерия, если задача не попала в уровни 0/1.
3. Транзитивный вес графа блокировок — без изменений (был уровнем 2).
4. Номер issue как тайбрейк — без изменений (был уровнем 3). Тай-брейк
   ВНУТРИ каждого уровня, включая новый, не тронут: барьерная задача
   получает свой более приоритетный УРОВЕНЬ, а не переворот сравнения по
   номеру — «старые долги не забываем» остаётся в силе там, где сигнала
   веса нет.

## Почему не остальные три варианта, рассмотренных в задаче

- **Вариант 2 (парсинг числового предела в теле по регэкспу «потолок»,
  «X/сутки»).** Хрупко: ловит только конкретную формулировку текста,
  ломается на перефразировке, не даёт способа явно ОТКЛЮЧИТЬ ложное
  срабатывание. Не выбран.
- **Вариант 3 (явный реестр номеров барьеров в конфиге).** Прозрачно, но
  требует ручного сопровождения при каждом слиянии барьерной задачи —
  список стареет молча, если о нём забыли (тот же класс риска, что уже
  закрыт для `docs/agents/LABELS.md`: решение — механизм, не текст без
  проверки). Не выбран.
- **Вариант 4 (инверсия тай-брейка «свежие раньше» внутри уровня
  `area:process`).** Однострочный, но грубый: перевернул бы порядок
  ВНУТРИ уровня целиком, включая старые долги `area:process` без явного
  веса — они начали бы тонуть под ЛЮБОЙ свежей задачей той же меты, не
  только под барьерными. Не выбран (детали компромисса — design.md).

Выбран **вариант 1** (метка веса `impact:system`) — дешёвый, явный, не
требует ручного реестра и не трогает тай-брейк там, где сигнала веса нет.

## Живой прогон (доказательство, критерий #1178)

ДО (93 свободные задачи, снимок 2026-09-14T00:30Z, голова очереди — см.
тело задачи #1178): «Хвост чеклиста ревью PR #983» и ещё пять таких же
хвостов в первых семи местах; барьерные задачи — вне видимости.

Повторный прогон на пуле, снятом непосредственно перед этим change (350
свободных задач — пул вырос за счёт нового потока задач за сутки):
- До простановки `impact:system`: #1160/#1172/#1141/#1149 на местах
  142/144/335/339 (тайбрейк по номеру внутри `area:process` или вовсе
  без меты).
- После простановки `impact:system` всем шести барьерным задачам
  (#1161/#1172/#1149/#1141/#1160/#1109 — двум из них, #1161/#1109,
  назначен исполнитель, поэтому они вне свободного пула, но метка
  проставлена на будущее высвобождение): 4 из 4 свободных барьерных
  кандидата поднялись на места 6/7/8/9 — сразу за пятью реально красными
  задачами уровня 0 (места 1-5, не тронуты), впереди `area:process` и
  впереди любого «хвоста чеклиста» (ни один не появляется даже в топ-20
  очереди).

Мутация (снятие фикса — `impact_label` подменён на несуществующую метку,
тот же приём, что юнит-тест): на том же живом пуле барьерные задачи
возвращаются на прежние 142/144/335/339.

  двух местах.

  барьерным задачам, названным в #1178.
