# Дельта-спека: журнал (journal-tasks-hands) — резолвер «PR → задача» (#259)

## ADDED: Конвейер (оркестратор) — резолвер «PR → задача» для AI-ревью

17.1. Контекст задачи, который AI-ревью (второй гейт) показывает модели —
    результат ЕДИНОГО резолвера (`scripts/lib/task_ref.resolve_pr_task`),
    а не первого попавшегося числа `#N`, упомянутого где угодно в теле PR.
    Источники, в порядке убывания надёжности, останавливаемся на первом,
    который что-то дал:

    а) имя agent-ветки `agent/<N>-<slug>` — ветку такой формы создаёт
       только `scripts/git/task-branch` (enforced-правило, гвардия
       `.githooks/pre-commit`), номер подделать случайно нельзя;
    б) формальная связь GitHub `closingIssuesReferences`, если вызывающий
       код её добыл — необязательный источник, его недоступность не
       останавливает резолвер;
    в) декларация номера первой строкой тела PR (`declared_tasks`, то же
       правило, что уже применяет контракт из п.17).

    Любое упоминание номера в прозе описания сюда не годится ни при каких
    обстоятельствах — это отдельный вопрос («упоминает ли текст задачу»,
    `task_ref.extract_task_refs`/`references_task`), не «какая задача у
    этого PR». Ни один источник не дал числа → у PR нет задачи из пула для
    контекста ревью (dependabot, orchestra:skip, ручной PR без декларации),
    это не ошибка.

    Сценарий: PR с веткой `agent/227-…` и телом, где первая строка `#227`,
    а в прозе описания встречается `#120` (ссылка на другую задачу-канал
    эскалации) → контекст ревью — задача #227, не #120.

    Сценарий: PR от `dependabot[bot]`, ветка не `agent/…`, декларации в
    теле нет → «у PR нет задачи из пула», без обращения к номерам PR из
    changelog зависимости, случайно попавшим в тело.

    Область действия правила — потребители, которым нужна ИМЕННО эта
    задача PR (сейчас: контекст AI-ревью). Правило п.17 (контракт: у PR
    есть декларация задачи, назначение, отсутствие конкурента) не меняется
    этим пунктом. Правила `reap_stale`/`unhealthy_pulls`/`after_merge`
    (снятие просроченного назначения, возврат нездоровой задачи в пул,
    освобождение замка после мержа) намеренно продолжают использовать
    широкую семантику «упоминание где угодно в теле» — там ошибиться в
    сторону «не трогать живую работу» дешевле, чем в сторону «эта задача
    занята/можно закрыть», и сужение семантики там было бы регрессией, не
    улучшением.
