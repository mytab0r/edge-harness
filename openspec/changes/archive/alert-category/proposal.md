# alert-category: у сигнала владельцу появляется категория (#1461)

Задача: #1461. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Всё, что уходит владельцу, сыплется одним потоком: решение, которого от него
ждут, стоит вперемешку с «деплой откатился» и «пульс в норме». Категория не
выражена машинно нигде — только эмодзи внутри текста, который каждый
отправитель собирает сам.

Замер отправителей 2026-09-22 (вызовы пересчитаны СТРУКТУРНО — AST для
Python, разбор вызова для bash/TS, тем же способом, каким их проверяет
гвардия; не оценены на глаз):

```
scripts/orchestra/pulse_guard.py::send_telegram    7 вызовов (у решения
                                                   владельца две ветки —
                                                   с клавиатурой и без)
scripts/orchestra/scheduler.py                     1
scripts/orchestra/apply_owner_decision.py          1
scripts/worker/task.sh::telegram_report            4 вызова, bash,
                                                   отдельный отправитель
cf-worker/src/harness.ts::#telegramApi             4 sendMessage, TypeScript,
                                                   третий (плюс тост-ответ на
                                                   нажатие кнопки и правка уже
                                                   категоризованного сообщения
                                                   решения — новых сигналов
                                                   не создают)
```

Три несвязанных отправителя на трёх языках.

## Решение владельца (2026-09-22)

Четыре категории: **решение владельца**, **поломка**, **конвейер**,
**инфраструктура**. Набор выведен из замера выше — каждая покрывает реально
существующие точки отправки, пустых нет. Порядок значим: от «требует
человека» к «к сведению».

## Что делается

Реестр `scripts/lib/alert_category.py` — канон. `category` становится
ОБЯЗАТЕЛЬНЫМ именованным аргументом отправителя: умолчание «прочее» вернуло
бы ровно то состояние, ради ухода из которого категория и заводится.

Адресация отделена от категоризации намеренно: сегодня категория видна
префиксом первой строки, завтра тот же идентификатор станет
`message_thread_id` темы — и ни одна из семнадцати категоризуемых точек
отправки (9 Python + 4 bash + 4 TS) не изменится.

## Чего это НЕ делает

Не включает треды в личке. Для этого нужно (а) действие владельца в
@BotFather и (б) живой замер: есть неразрешённый отчёт
tdlib/telegram-bot-api#847 о `400 message thread not found` при отправке с
`message_thread_id` в приватный чат. Замер — отдельная узкая задача, и
строить маршрутизацию до него значило бы чинить незамеренное.
