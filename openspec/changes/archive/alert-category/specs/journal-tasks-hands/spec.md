# Дельта-спека: руки (journal-tasks-hands) — категория сигнала владельцу (#1461)

## ADDED: Категория сигнала

Требование: каждый сигнал, уходящий владельцу, несёт категорию из общего
реестра. Отправка без категории невозможна.

Сценарии:

1. Точка отправки называет категорию → сигнал уходит с видимой категорией
   отдельной ПЕРВОЙ строкой; текст сообщения не меняется и остаётся
   экранированным ровно как был.
2. Точка отправки категорию не назвала → отказ. Не «прочее»: молчаливое
   «прочее» и есть то состояние, ради ухода из которого категория заводится.
3. Категория не из реестра → отказ ДО сетевого вызова, одинаково при
   заданном и незаданном токене: это ошибка программиста, а не свойство
   окружения.
4. Новый вызов отправителя без категории → CI красный по исходнику. Рантайма
   мало: сигналы уходят из редких веток, и красный прогон случился бы у
   владельца в чате, а не в CI.
5. Категория указана, но её значение статически не разрешается (ссылка через
   неимпортированное имя, переменная, вызов) → тоже нарушение. Наличие
   аргумента без разрешимости — «имя есть, проводки нет».

Реестр живёт в трёх языках (Python — канон, bash для `task.sh`, TypeScript
для воркера): расхождение копий красит CI, тест читает все три исходника.
Копия допустима только под этим условием.

## Честный потолок

Категория — НЕ адрес. Сегодня она видна префиксом; тредов в личке этот
change не включает. Отделение сделано затем, чтобы включение тредов не
трогало точки отправки, но само включение требует действия владельца в
@BotFather и живого замера (tdlib/telegram-bot-api#847: неразрешённый отчёт
о `400 message thread not found`).

Гвардия проверяет все три отправителя по исходнику: Python — AST-разбором,
bash (`telegram_report` в `scripts/**/*.sh`) и TypeScript
(`#telegramApi("sendMessage")` в `cf-worker/src/**/*.ts`) — структурно.
Доводка по ai-ревью этого change (PR #1462): первая редакция гвардии
покрывала один отправитель из трёх, и сам PR прошёл свой гейт с пятью
некатегоризованными вызовами.

Гвардия проверяет ФОРМУ вызова, а не смысл выбора: что «деплой откатился»
отнесли к инфраструктуре, а не к поломке, машина подтвердить не может. Это
названо, а не выдано за проверку.

Не покрываются два вызова Bot API в воркере, которые НОВОГО сигнала в поток
не создают: `answerCallbackQuery` (тост-ответ на нажатие кнопки самим
владельцем) и `editMessageText` (правка УЖЕ отправленного и уже
категоризованного сообщения решения). Новый `sendMessage` мимо
`decorateAlert` красится.
