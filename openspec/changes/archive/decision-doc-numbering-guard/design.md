# Дизайн: номер ADR/research-документа не конфликтует между параллельными PR

## Развилка 1: сквозная нумерация vs смена схемы

**Проверено по `docs/research/30-rejected-alternatives.md`:** схема нумерации ADR/research
там не упомянута — решение принимается впервые, не повтор отвергнутого.

**Цена смены схемы** (замер на текущем дереве, `grep -c` по нему же):

| | `docs/decisions/` | `docs/research/` |
|---|---|---|
| Файлов сегодня | 17 (0001–0017 полных + 0019, пропуск 0018) | 15 |
| Ссылок вида `decisions/NNNN-*.md` / `research/NN-*.md` в репозитории | 68 | 222 |
| Файлов, несущих такую ссылку | 35 | 93 |

Переход на, например, `decision-<issue-number>-<slug>.md` или `decision-<YYYY-MM-DD>-
<slug>.md`: переименовать 12+15=27 файлов, переписать 290 ссылок в 128 файлах (git mv не
чинит текст ссылок — только путь), и УСТНЫЕ упоминания вида «ADR 0016» в уже слитых
коммитах/issue/PR (не грепается, не считано) станут отсылать в никуда без исторического
контекста. Выгода смены схемы — устранение риска коллизии НОМЕРА — целиком достигается
дешевле: гвардией ниже, без переименования единого файла. Смена схемы не выбрана.

Сквозная нумерация остаётся. Хронологический порядок номеров — это то, что теряется при
переходе на issue-number/дату, и это единственное реальное преимущество сквозной схемы
(ADR 0016 рядом с ADR 0017 — читатель видит порядок решений); не жертвуем этим без
причины дороже самой проблемы.

## Развилка 2: атомарная бронь номера (git-ref lock, ADR 0006) vs CI-гвардия

ADR 0006 уже даёт атомарный примитив — `refs/locks/task-<N>`, серверная атомарность через
422 на повторное создание рефа. Тот же приём мог бы забронировать номер
(`refs/locks/decision-<NNNN>`) ДО того, как автор напишет файл — тогда коллизии физически
невозможны с первого же шага, не только на CI.

**Не выбрано для этого класса** (в отличие от аренды задачи, где это ADR 0006 и есть):
- Аренда задачи защищает НАЗначение исполнителя — дорогой ресурс (агент тратит целый
  проход воркера). Номер ADR — дешёвый: если коллизия возникла, чинится переименованием
  одного файла в PR, который ещё не слит. Стоимость отказа несопоставима с
  инфраструктурой брони (создание/TTL/освобождение рефа на каждый новый ADR/research-док).
- Бронь требует, чтобы автор запросил её ДО того, как начнёт писать файл — лишний шаг,
  который легко забыть (в отличие от `claim_task`, здесь нет воркера/скрипта,
  принудительно вызывающего бронь первым действием: ADR пишется вручную агентом в рамках
  произвольной задачи).
- Слепая зона всё равно остаётся: два PR могут разойтись по номеру ДАЖЕ после брони, если
  бронь взята, а PR годами не мержится и не удаляется — нужен TTL-сборщик, тот же вопрос,
  что и у task-lease, но здесь без выигрыша (номер не блокирует чужую работу, в отличие от
  задачи).

Выбрано: гвардия, читающая main И открытые PR, — она не устраняет секундное окно гонки
между двумя PR, стартующими одновременно (этого не устранить без брони), но делает
коллизию НЕВОЗМОЖНОЙ В MAIN: первый из двух коллизирующих PR, который дойдёт до слияния,
«выигрывает» номер; CI второго покраснеет на актуальном `main` и на живом списке открытых
PR ДО того, как он сам сольётся — автор обязан переименовать до мержа. Тот же принцип, что
у `mark_conflicts`/`mechanical_rebase.py` (класс «конфликт лечится на PR, не после мержа»).

## Устройство

`scripts/lib/decision_numbering.py` — чистые функции + тонкая IO-обвязка (тот же приём,
что `repo_invariants.py`/`pulse_guard.py`: `check_*`/`find_*` без сети, testable мутацией;
`gh()`/`git()`-обвязка отдельно):

- `NUMBERED_ROOTS = {"docs/decisions": 4, "docs/research": 2}` — единственное место,
  которое знает оба носителя одного класса (docs/decisions и docs/research — тот же
  паттерн «NNNN-slug.md» под общим корнем; `openspec/changes/<id>` не подходит под этот
  же носитель — там ключ слаг, не число, коллизии номеров там нет по конструкции, вне
  объёма).
- `parse_numbered_files(paths, root, width)` — из списка репозиторных путей (любой
  источник: `git ls-tree`, `gh api .../files`) достаёт `{номер: имя_файла}` для файлов
  ПРЯМО под корнем.
- `next_free_number(existing_numbers, width)` — `max(existing) + 1`, с ведущими нулями.
  CLI `decision_numbering.py next docs/decisions` печатает номер, посчитанный по объединению
  main + все открытые PR (`gh api repos/{o}/{r}/pulls?state=open`, файлы каждого через
  `.../pulls/{n}/files`, статус `added`).
- `find_number_collisions(sources)` — `sources: {имя_источника: {номер: имя_файла}}`.
  Коллизия — номер, под который в разных источниках подставлены РАЗНЫЕ имена файлов (тот
  же номер + то же имя в main и в PR, который его лишь редактирует, — не коллизия). Два PR
  добавляют файл с ОДИНАКОВЫМ именем — не коллизия этого инварианта: это obj-level
  add/add-конфликт, который git обнаружит сам при ребейзе, вторая гвардия не нужна.

## Гвардия

`scripts/ci/guards/decision-doc-numbering-guard.sh` (каталог #749, без правки
`repo-ci.yml`): прогоняет `test_decision_numbering.py` (пуре-функции + поведенческий тест
на временном git-репозитории) и затем живой `decision_numbering.py check` на реальном
`GITHUB_REPOSITORY`/PR-номере текущего прогона (`GH_TOKEN` уже доступен job'у, `pull-
requests: read` — см. `.github/workflows/repo-ci.yml`).
