# Дельта-спека: журнал (journal-tasks-hands) — детерминированный груминг пула автозадач (#830)

Реализация: `scripts/orchestra/stall_detector.py::groom_auto_tasks`, вызывается из
`scheduler.py::main()` между `detect_and_act` (#201) и `escalate_stale_auto_tasks` (#427).
Пороги — константы `stall_detector.py` (одно место правды).

## ADDED: Груминг пула перед эскалацией владельцу

Требование: каждый пульс, ПОСЛЕ `detect_and_act` и ДО `escalate_stale_auto_tasks`,
`groom_auto_tasks(repo, now, lines)` читает уже готовый отчёт этого же пульса и закрывает
машинно-бесспорное среди открытых задач с меткой `auto-detected` — без обращения к LLM,
без гипотез по существу.

Требование: отпечаток стоп-задачи, отсутствующий в `extract_signals(lines)` этого пульса,
запускает или продолжает эпизод «тишины». Первое отсутствие оставляет переходный маркер
`[симптом-тишина: <fp>]` на `WATCHDOG_ISSUE` (тот же канал, что `_sighting_marker`
детектора появления, #201) — задача пока не закрывается. Эпизод тишины, продержавшийся
`RESOLVE_QUIET_MINUTES` (то же значение, что `STALL_PERSIST_MINUTES` — порог симметричен:
сколько нужно, чтобы ДОКАЗАТЬ появление отпечатка, столько же нужно, чтобы доказать его
исчезновение) без единого повторного появления отпечатка — задача закрывается с
комментарием-уликой («отпечаток не воспроизводится N минут») и переводом issue в `closed`.

Требование: если отпечаток снова появляется в отчёте раньше истечения порога — эпизод
тишины прерывается переходным маркером `[симптом-снова-жив: <fp>]` (тот же канал), и
следующее отсутствие того же отпечатка начинает НОВЫЙ эпизод тишины с нуля. Определение
«эпизод тишины сейчас идёт» — самый свежий из двух переходных маркеров этого отпечатка:
если последний по времени — «снова жив», эпизода нет; если последний — «тишина», эпизод
идёт с этого момента (тот же приём, что `_closed_task_reset_times` уже применяет для
сброса устойчивости появления, #248 — здесь симметрично для устойчивости исчезновения).

Требование: определение «отпечаток воспроизводится в этом пульсе» — ТОЛЬКО прямой пересчёт
`extract_signals(lines)` этого пульса, никогда — производная от того, постился ли
комментарий-улика `detect_and_act` (тот антиспам-канал МОЛЧИТ, если улика идентична
предыдущей, #248, и потому непригоден как признак «жив сейчас», см. proposal.md
«Отвергнутые варианты»).

Требование: два и более ОТКРЫТЫХ `auto-detected` с одним и тем же отпечатком (защита от
исторических/ручных дублей — заведение новой задачи с уже существующим отпечатком
`find_open_task` и так не допускает) — груминг закрывает все, кроме задачи с наименьшим
номером (самой старой), с комментарием, называющим номер задачи-выжившей. Задача, у которой
уже есть исполнитель (`assignees` не пуст), из этого закрытия исключается — воркер уже
взял её в работу, груминг груминг не отменяет уже начатую работу без доказательства, что
она не нужна; то же исключение действует и для закрытия по отсутствию отпечатка (а).

Требование: задачи без метки `auto-detected` (заведённые человеком) груминг не видит —
единственный источник данных для обеих проверок, `open_auto_tasks`, читает открытые issues
именно по этой метке; задачи, заведённые владельцем или другим агентом руками, физически
не попадают в выборку и не могут быть закрыты этим механизмом.

Требование: сбой сети/`gh` внутри `groom_auto_tasks` не должен молча проглатывать уже
посчитанный отчёт остальных стадий пульса (тот же приём, что `detect_and_act`/
`accept_merged_tasks`) — ошибка красит прогон отдельной строкой, отчёт до неё сохраняется.

## Явно НЕ в этой дельте (см. proposal.md)

- Судейское решение (устарела ли задача по существу, семантический дубль, приоритет,
  выбор из нескольких вариантов) — это PM-судейский груминг, этап 2, отдельная задача.
- Закрытие задачи по факту, что её PR уже слит/закрыт — уже полностью решено существующей
  стадией приёмки (`accept_merged_tasks`, #227) и `replace_closed_task_prs` (#543); стоп-
  задачи этого класса физически не имеют (они не указывают на внешний PR-таргет).
