## ADDED: Слот параллельности воркера (`WORKER_MAX_CONCURRENCY`)

Требование: до `WORKER_MAX_CONCURRENCY` прогонов `worker.yml` могут идти
одновременно (сегодня 2). Каждый прогон адресован в конкретный слот через
вход `slot` (`workflow_dispatch`, `1..WORKER_MAX_CONCURRENCY`) — `worker.yml`
несёт номер слота в `run-name` (единственное поле, по которому оркестратор
может прочитать вход `workflow_dispatch` для уже созданного прогона — REST
не отдаёт inputs в самом объекте run) и вычисляет `concurrency.group` из
этого же входа (`worker-<slot>`). Прогон без распознанного номера слота
(ручной запуск без входа, сторонний триггер) занимает слот 1 консервативно
— тот же слот, что был единственным до этого change, не третий свободный по
умолчанию.

Требование: значение `WORKER_MAX_CONCURRENCY` обосновано измерением, не
взято с потолка. GitHub Actions (concurrent job limit 20 на аккаунт,
`GITHUB_TOKEN` 5000 запросов/час на этот репозиторий, оба —
docs/research/21-github-actions.md) не ограничивают N=2. Провайдер-квота
(NVIDIA/GLM, цепочка `DSH_PROVIDER_CHAIN`) — единственный риск, для которого
в репозитории НЕТ измеренного числа (RPM/квота в минуту), только форма
отказа при полном исчерпании (`RATE_LIMIT: Weekly/Monthly Limit Exhausted`,
`docs/runbooks/switch-llm-provider.md`). В отсутствие этого числа
`WORKER_MAX_CONCURRENCY` взят консервативно (2, не 3+), а не подобран под
предполагаемый лимит.

## ADDED: Выбор свободного слота при dispatch

Требование: четыре места, реально отправляющие `workflow_dispatch worker.yml`
(`dispatch_worker` — 2 внутренних точки: обычный дренаж пула и доводка
адресной задачи при закрытом WIP-гейте; авто-расшивка конфликта
`dispatch_conflict_rework` — 1 точка; доводка PR по находкам ai-review
`dispatch_ai_review_rework` — 1 точка) выбирают номер свободного слота ОДНИМ
общим источником (`free_worker_slot`) — второе место правды не заводится. Слот
занят прогоном в статусе `in_progress` (не зависшим, см. существующий порог
`WORKER_STALL_MINUTES`, #815) или `queued`. Свободного слота нет ни одного —
поведение как раньше при «воркер занят» (наблюдение в отчёте пульса, ни
одного действия).

Требование: признак «воркер занят» для решений, НЕ являющихся выбором слота
под dispatch (эскалация авто-расшивки конфликта после исчерпания бюджета
попыток — «эта попытка ещё может идти, не эскалируем рано»; механический
ребейз, `mechanical_rebase.py`, — «воркер может пушить в ЛЮБУЮ конфликтную
ветку прямо сейчас, не трогаем head, пока идёт хоть один прогон»), остаётся
прежним: «активен хотя бы один прогон», не «все слоты заняты» — оба этих
решения репо-wide по своей природе (не привязаны к конкретному слоту), и
сужение до «свободен ли КОНКРЕТНЫЙ слот» дало бы им ложное «свободно», пока
на самом деле воркер в другом слоте ещё может задеть ту же ветку.

Сценарий: пул содержит свободную задачу, слот 1 занят прогоном
`in_progress`, слот 2 свободен -> `dispatch_worker` уходит в слот 2
(`-f inputs[slot]=2`), отчёт не пишет «воркер уже работает».

Сценарий: оба слота заняты (in_progress/queued, не зависшие) -> ни один из
трёх диспетчеров не отправляет dispatch, отчёт называет факт «оба слота
заняты», как раньше называл «воркер занят».

Требование: КАЖДЫЙ прогон `worker.yml` в статусе `in_progress`, идущий
дольше `WORKER_STALL_MINUTES` от своего `run_started_at` (fallback —
`created_at`), не занимает слот параллельности для решений диспетчеров — до
`WORKER_MAX_CONCURRENCY` прогонов проверяются НЕЗАВИСИМО (было — только
первый в списке, при N=1 воркере это не имело значения). Отмена и полное
освобождение аренды коррелирующей задачи (см. неизменную логику
`reap_stalled_worker_run`) выполняются для КАЖДОГО найденного зависшего
прогона за один пульс, не только для первого; задача, уже сопоставленная
одному зависшему прогону, не рассматривается повторно для другого в этом же
проходе.

Сценарий: слот 1 держит прогон `in_progress` 218 минут (зависший, задача
#815 арендована им), слот 2 держит прогон `in_progress` 230 минут (тоже
зависший, задача #820 арендована им) -> оба прогона отменяются, обе задачи
освобождаются (назначение + замок) в одном пульсе, каждая со своим
следом-комментарием.
