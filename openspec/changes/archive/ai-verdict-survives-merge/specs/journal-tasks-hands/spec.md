# Дельта-спека: журнал (journal-tasks-hands) — вердикт AI переживает подтягивание main (#252)

## ADDED: Конвейер (оркестратор)

30. Метка `ai:*` (второй гейт, AI-ревью #18, см. п.15/17) сохраняется при
    новом пуше в PR, если отпечаток диффа PR относительно base не изменился
    с момента последнего вердикта AI. Отпечаток —
    `review_labels.diff_fingerprint`: sha256 по отсортированному списку
    (имя файла, статус, blob-sha) из `gh api pulls/{n}/files`; блоб-sha, не
    число строк, поэтому две разные правки одинакового размера дают разные
    отпечатки. Отпечаток на момент вердикта хранится в поле `diff:` шапки
    ревью-комментария AI (`pr:`/`head:`/`reviewer:`/`diff:`,
    `ai_review.py::build_comment`) — второго хранилища не заведено.
    Детерминированное ревью (`check_pr.py`) при каждом пуше сравнивает
    текущий отпечаток с сохранённым (`review_labels.diff_unchanged`,
    решение — `check_pr.ai_verdict_keep`) и снимает `ai:*` только если они
    разошлись.

    Почему это не ослабляет гейт: подтягивание main без конфликтов создаёт
    только новый merge-коммит головы PR, патчи PR относительно base не
    меняются — ревьюер уже видел ровно этот дифф. Любая содержательная
    правка автора (в том числе одного файла) меняет как минимум один
    blob-sha, отпечаток расходится, метка снимается — как и раньше до этой
    дельты. Нет сохранённого отпечатка (комментарий без поля `diff:` —
    старый формат, комментария нет вовсе, сеть отказала при чтении) —
    трактуется как «дифф изменился»: метка снимается, гейт не ослабляется
    при неопределённости.

    Сценарий: слияние другого PR → оркестратор подтягивает отставший PR
    (п.17, только если он уже помечен `conflict` либо у него оба вердикта) →
    push мерж-коммита → `pull_request:synchronize` → `check_pr.py`
    пересчитывает отпечаток, видит совпадение с сохранённым → `ai:ok`
    остаётся. `ai-review.yml` при этом запускается как обычно (триггер —
    `workflow_run` от завершения `pr-review`, не метка, см. п.15/17
    и шапку `ai-review.yml`), но останавливается сам до дорогой работы: шаг
    `fingerprint` job'а `review` сверяет то же условие (тот же отпечаток,
    то же место правды `review_labels.should_run_ai_review`,
    `ai_review.py::cmd_should_run`) и отдаёт `go=false` до чекаута
    `pr-head`/`gather`/DSH — вызова модели на этом коде не происходит.

    Сценарий (контроль): автор пушит правку кода в тот же PR → отпечаток
    расходится → `ai:*` снимается, как до этой дельты → `ai-review.yml`
    перезапускается по свежему `review:ok`.
