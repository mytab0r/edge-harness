# Дельта-спека: journal-tasks-hands — автоперенос поля «Чем блокируется» для всех путей

Продолжает `openspec/changes/archive/fill-dependency-graph-enforcement/
specs/journal-tasks-hands/spec.md` (расширяет `openspec/specs/
journal-tasks-hands.md`, раздел «Автономный воркер (конвейер пула)»).
Носитель графа (`blockedBy`/`blocking`, `scripts/lib/task_deps.py`) не
меняется — эта дельта про то, что переносит структурное поле формы в
граф автоматически, не только для АИ-ревью-пути.

Значение обязательного поля «Чем блокируется» (`.github/ISSUE_TEMPLATE/
task.yml`/`white-spot.yml`, обязательное с #387) переносится в нативный
`blockedBy` АВТОМАТИЧЕСКИ на ближайшем прогоне `repo-ci` после push в
main — `scripts/lib/declared_deps.py::auto_wire`, вызывается шагом
workflow, не пульсом оркестратора (цена — см. design.md, развилка «в»).
Разбор структурный, по заголовку секции формы
(`declared_deps.py::form_field_numbers`), не по любому `#N` в теле.

Сценарий: задача заведена через форму `task.yml` с ответом «Чем
блокируется: #55», #55 — открытая задача пула → на ближайшем push в main
`declared_deps.py wire` ставит `blockedBy` без ручной команды, приоритет
#55 растёт на следующем запросе пула.

Сценарий: ответ поля — «ничем» → `form_field_numbers` возвращает пустой
список, авто-перенос эту issue пропускает без предупреждения (валидный
ответ обязательного поля, не пропуск).

Сценарий: поле в теле отсутствует вовсе (issue заведена до #387 или не из
этого шаблона) → `form_field_numbers` возвращает `None`, авто-переносу не
из чего переносить — issue пропускается тем же путём, что «ничем», без
шума. Ручная команда `task_deps.py block` остаётся доступной и работает
как раньше для этого случая.

Сценарий: ответ поля называет номер, закрытый или не входящий в открытый
пул с меткой `task`, либо саму эту issue → номер не линкуется, БЕЗ
предупреждения: `auto_wire` фильтрует такие номера до передачи в
`wire_dependencies` — ложная связь опаснее отсутствующей, а путь
периодический (каждый push в main), предупреждение без ограничения
частоты было бы постоянным шумом на каждый прогон, хотя ссылка на
закрытую «не влияет ни на что» (тот же случай, о котором `find_desync`
молчит намеренно). Предупреждение сохраняется в одноразовых путях
(АИ-ревью) — его печатает сам `wire_dependencies`.

## ADDED: Единый цикл переноса на оба пути заведения задачи

`scripts/lib/task_deps.py::wire_dependencies` — единственное место,
переносящее список объявленных номеров в граф (пропуск номера вне
открытого пула/самоссылки с логом, иначе `add_dependency`). Оба
поставщика связей (`file_tasks.py::wire_declared_dependency` для
строки «БЛОКИРУЕТСЯ:» АИ-ревью-пути, `declared_deps.py::auto_wire` для
поля формы) вызывают эту функцию — не два похожих, расходящихся со
временем цикла.

## Честный охват на день внедрения (не домысел)

Живой замер `task_deps.py pool` на 2026-09-06: из 135 открытых задач с
меткой `task` секцию «Чем блокируется» несёт ровно одна (заведённая для
самой этой задачи) — обязательность поля (#387) введена только что,
остальные 134 задачи старше и поля не несут вовсе. Прямой эффект
авто-переноса на день внедрения — 0 новых связей graph; эффект
накапливается по мере появления НОВЫХ задач через форму, не мгновенно.
Уровень 2 приоритета (`blocking_open`) остаётся редко решающим, пока
относительная доля задач с заполненным и подтверждённым полем не
вырастет — это не дефект механизма авто-переноса, а отражение возраста
обязательного поля и общей разреженности реальных межзадачных
зависимостей в этом пуле (разовая миграция #371 подтвердила чтением
всего 2 связи из ~40 кандидатов на 113 задач).
