# Дельта-спека: руки (journal-tasks-hands) — гвардии каталога и бюджет API (#1004)

## ADDED: Гвардия каталога, читающая API, переживает исчерпанный бюджет

Требование: модуль, который запускает гвардия каталога `scripts/ci/guards` и
который читает GitHub API, обязан пропускать свой `main` через общую обёртку
квоты. Исчерпанный бюджет — предупреждение и код 0, не падение.

Сценарии:

1. Бюджет исчерпан (403 «rate limit exceeded», первичный или вторичный) →
   `::warning::`, код 0, шаг каталога продолжает перебор. Обязательная
   проверка не краснеет причиной, к диффу автора отношения не имеющей.
2. Любая ДРУГАЯ ошибка → проходит наверх нетронутой, гвардия краснеет.
   Проглотить настоящую поломку было бы silent-wrong — ровно то, ради чего
   класс и чинится.
3. Гвардия каталога в API не ходит → обёртки от неё не требуется. Требовать
   от всех — тормоз без причины на десятках гвардий.
4. Тест гвардии, а не её прод-модуль, читает API по заглушкам → потребителем
   не считается: бюджет он не тратит.
5. Новый потребитель появился без обёртки → CI красный с адресным
   сообщением: какой модуль, какая гвардия, что добавить.

Признак «читает API» — вызов API в ПРОД-модуле, который гвардия реально
запускает, а не в её тестах. Признак «обёрнут» — использование общей обёртки,
не своя копия обработки: классификация отказа обязана быть одна на все
поверхности, иначе копии разойдутся на первом же новом тексте отказа.

## Честный потолок

Пропущенная по квоте гвардия НЕ выполняется — проверка в этом прогоне не
сделана. Размен назван: красная обязательная проверка по чужой квоте стоит
дороже одного пропуска, а следующий прогон после сброса бюджета проверит то
же самое. Пропуск виден `::warning::` в логе, а не молчит.

Обёртка ловит отказ по ТЕКСТУ ответа GitHub. Если GitHub изменит формулировку,
классификатор перестанет узнавать отказ и гвардия снова упадёт трейсбеком —
громко, не молча. Второго признака (код ответа отдельным полем) у текущих
вызовов нет: они поднимают `RuntimeError` со строкой.
