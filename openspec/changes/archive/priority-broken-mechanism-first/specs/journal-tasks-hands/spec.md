# Дельта-спека: journal-tasks-hands — «сейчас красный» и транзитивный вес графа

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Автономный
воркер (конвейер пула)», п. 26. Продолжает дельту `task-priority-blocking-
graph` (архивирована, #361) — не переоткрывает её, добавляет уровень
0 и обобщает уровень 2 (был прямой счётчик, стал транзитивный).

## MODIFIED: Выбор свободной задачи — четыре уровня приоритета, не три

~~Среди СВОБОДНЫХ задач выбор идёт по трём уровням приоритета, в этом
порядке (#361): (1) метка `area:process` — раньше любой задачи без неё,
независимо от остальных уровней; (2) внутри уровня — число ОТКРЫТЫХ задач,
которые задача блокирует (нативный граф `blockedBy`/`blocking`, не
прозопарсинг); (3) при равенстве — номер issue как proxy даты создания.~~

Требование: среди СВОБОДНЫХ задач (критерий свободы не меняется) выбор
идёт по четырём уровням, в этом порядке:

1. Задача сама несёт метку «механизм конвейера сейчас красный»
   (`ci-failure` — провал ключевого workflow, классифицированный как наш
   дефект; `self-audit` — регрессия метрики здоровья конвейера) ИЛИ
   транзитивно блокирует хотя бы одну такую (обратный обход того же
   нативного графа `blockedBy`/`blocking`) — раньше любой задачи без этого
   признака, независимо от остальных уровней. Это факт («конвейер стоит
   сейчас, измеримо»), не самооценка природы задачи (в отличие от уровня 2).
2. Метка `area:process` (задача про сам процесс работы), если задача не
   попала в уровень 1 — раньше любой обычной задачи, независимо от уровня 3.
3. Внутри уровня — ТРАНЗИТИВНЫЙ вес графа блокировок: число ОТКРЫТЫХ задач
   этого же пула, которые закрытие текущей в конечном счёте приближает,
   включая цепочки длиннее одного прямого соседа (A блокирует B, B
   блокирует C — A получает вес за обоих). Не может быть МЕНЬШЕ прямого
   счётчика #361 (если цель цепочки не входит в ту же выборку issue, вес
   берётся из прямого поля GraphQL, не теряется).
4. При равенстве — номер issue как proxy даты создания (без изменений).

Граф пуст, ни одна СВОБОДНАЯ задача не помечена `area:process` и никто не
«сейчас красный» (уровни 1–3 не отличают ни одного кандидата) → видимый
сигнал (предупреждение в stderr `free_task.py`), не молчаливое вырождение;
сам выбор не останавливается — вырождение в уровень 4 для всех легитимно.

Для любой открытой задачи можно получить ответ, почему она на этом месте:
тир, конкретные номера цепочки (не просто факт «да, блокирует красную»,
а КАКУЮ именно), транзитивный вес, чем сама заблокирована, тай-брейк.

Сценарий: задача A несёт `ci-failure`, задача B несёт `area:process` и
блокирует 10 открытых напрямую — A выбирается раньше B: уровень 1 решает
раньше уровня 2 независимо от веса B.

Сценарий: задача C не несёт ни `ci-failure`, ни `area:process`, но
напрямую блокирует открытую `ci-failure`-задачу D — C получает уровень 1
(транзитивный предок сломанного механизма), не уровень 3.

Сценарий: задача E блокирует F, F блокирует G (все открыты, ни одна не
`area:process`/`ci-failure`) — транзитивный вес E равен 2 (F и G), не 1
(только F, как посчитал бы прямой счётчик #361).

Сценарий: задача H (`area:process`, вес 1) и задача J (`area:process`,
блокирует напрямую цель вне текущей GraphQL-выборки, прямой счётчик 5,
но цель не видна как узел графа) — J выбирается раньше H: транзитивный вес
не может быть меньше прямого счётчика (см. правило 3 выше).
