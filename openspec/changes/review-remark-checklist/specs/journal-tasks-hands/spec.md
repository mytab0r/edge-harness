# Дельта-спека: журнал (journal-tasks-hands) — третья категория находок ревью (#462)

## ADDED: Чеклист некритичных замечаний в теле PR

Требование: находка AI-ревью несёт РОВНО один из трёх исходов. Блокирующая
находка (расхождение с ADR/спекой, скрытая регрессия, silent-wrong и т.п.) —
проза в комментарии, не более 5, вердикт `rework`. Некритичная, но нужная
находка — блок `ЗАМЕЧАНИЕ: <заголовок> / тело / КОНЕЦ ЗАМЕЧАНИЯ`
(`scripts/lib/review_checklist.py::parse_remarks`), вердикт остаётся
`approve`, если блокирующих находок нет. Работа вне рамок PR — блок `ЗАДАЧА`
(без изменений, `openspec/changes/ai-review-gate/specs/journal-tasks-hands/spec.md`).
Проза, не попавшая ни в одну из трёх форм, контрактом не предусмотрена.

Блоки `ЗАМЕЧАНИЕ` сливаются шагом `verdict` (`ai_review.py::cmd_verdict`) в
чеклист ТЕЛА PR — секцию между маркерами `<!-- ai-review:checklist:begin -->`
/ `<!-- ai-review:checklist:end -->` (`review_checklist.merge_checklist`), не
в комментарий: тело — постоянный носитель, комментарий лишь ссылается на
факт обновления. Повторный раунд ревью дописывает новые пункты по заголовку
(дедупликация), уже отмеченные автором пункты не перезаписываются.

Сценарий: ревью нашло 2 некритичных замечания при вердикте `approve` → тело
PR получает секцию с 2 непомеченными пунктами; автор отмечает один галочкой
GitHub в описании PR; следующий раунд ревью с ещё одним новым замечанием
дописывает третий пункт, отмеченный первый остаётся отмеченным.

## ADDED: Задача-хвост незакрытого чеклиста при слиянии

Требование: слияние PR с незакрытыми пунктами чеклиста не блокируется —
некритичная находка не становится критичной фактом слияния. `after_merge`
(`scripts/orchestra/scheduler.py`) читает незакрытые пункты
(`review_checklist.unresolved_items`) из тела слитого PR и заводит РОВНО ОДНУ
задачу-хвост со ссылкой на PR и перечнем всех незакрытых пунктов
(`review_checklist.tail_issue_title/tail_issue_body`, метка `task`),
идемпотентно по заголовку «Хвост чеклиста ревью PR #N» — повторный вызов не
дублирует issue.

Задача-хвост не несёт отдельной оценки ценности или приоритета: наследует
только ссылку на породивший PR и попадает в общий пул на общих основаниях
(возраст, либо граф блокировок — если #367 к этому моменту смержен).

Сценарий: PR слит с 3 незакрытыми пунктами чеклиста → заведена ровно одна
задача «Хвост чеклиста ревью PR #N» с телом из всех трёх пунктов; повторный
прогон `after_merge` на уже обработанном PR (гипотетический повтор события)
не создаёт вторую задачу — идемпотентность по заголовку.
