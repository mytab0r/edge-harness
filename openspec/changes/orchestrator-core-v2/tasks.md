# Задачи: orchestrator-core-v2

Это ПРОЕКТНЫЙ tasks.md: чекбоксы ниже — не подзадачи одного PR, а ЗАЯВКИ
на отдельные задачи пула (каждая заводится через `scripts/gh/issue-create`
своим номером, когда очередь до неё доходит, со ссылкой на этот change).
Пункты выполняются В ПОРЯДКЕ, каждый — самостоятельный PR со своим
критерием приёмки; следующий этап не начинается, пока предыдущий не прожил
минимум один полный цикл слияний без регресса (design.md, раздел 5.1).
Роль-исполнитель для КАЖДОГО этапа — разработчик (developer), приёмка —
критик (critic) по критерию, названному в самом пункте; ни один этап не
меняет `openspec/changes/orchestrator-core-v2/` — он живёт до архивации.

## Явные незавершённости (честно, не молчаливый пропуск)

- Полный граф легальных переходов PR (design.md, раздел 10, п.4) может
  потребовать уточнения по ходу реализации Этапа 6 — уточнение вносится
  правкой design.md ДО того, как реализующий PR меняет поведение, не
  постфактум.

  первая реализация (Этап 0-1) должна включить измерение по логам за
  представительный период (минимум 7 суток) ДО того, как Этап 4-6
  зафиксирует политику edge-triggered записи как окончательную.
