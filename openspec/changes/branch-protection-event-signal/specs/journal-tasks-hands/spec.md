# Дельта-спека: наблюдение за защитой main (#370)

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Конвейер
(оркестратор)»: новый подраздел «Наблюдение за защитой main (#370)».
Сложен в базовую спеку одновременно с реализацией (#370).

## ADDED: сигнал ослабления защиты main — событием, не опросом

Требование: изменение защиты ветки `main` (создание, правка, удаление
правила) обнаруживается штатным событием GitHub Actions
`branch_protection_rule`, а не периодическим опросом `GET .../branches/
main/protection` — этот эндпойнт требует у токена право `administration`,
недоступное `GITHUB_TOKEN`. Событие несёт изменённое состояние прямо в
payload (`rule`, для правки — ещё и `changes`), читать API не требуется.

Требование: правило, применённое не к `main` (`rule.name` для событий,
где это поле есть), не оценивается и не порождает сетевых вызовов.

Требование: удаление правила защиты (`action == deleted`) — всегда
критическое состояние независимо от содержимого последнего известного
правила: сам факт защиты пропал.

Требование: для `created`/`edited` состояние ПОСЛЕ изменения (`rule`)
сравнивается с ожидаемым (`enforce_admins=true`, обязательные контексты
`test` и `contract`, `strict=true`, force-push и удаление ветки
запрещены — то же состояние, что зафиксировано прозой в AGENTS.md).
Поле, отсутствующее в payload, не проверяется (не гадать на незнакомой
форме события — не превращать неопределённость в ложную тревогу).
Обязательный контекст СВЕРХ ожидаемых — не нарушение: контекстов не
стало меньше, добавление ещё одной проверки — усиление, а не ослабление.

Сценарий: `enforce_admins` выключили правкой защиты `main` → следующее
событие `edited` находит `rule.admin_enforced == false`, отличное от
ожидаемого `true` → сигнал уходит.

Сценарий: к обязательным проверкам добавили третий контекст (например
`lint`) поверх `test`/`contract` → множество текущих контекстов —
надмножество ожидаемого → нарушений нет, сигнала нет.

## ADDED: канал сигнала — общий с предохранителем конвейера, без второго канала

Требование: сигнал уходит тем же каналом, что предохранитель конвейера и
пропавший пульс оркестратора (`pulse_guard.escalate`): комментарий в
issue `WATCHDOG_ISSUE` (#120) + Telegram. Второй канал для класса
«поломка инфраструктуры» не заводится (тот же принцип, что архив сессий
раннера, #119/#174).

Требование: текст сигнала называет ПОСЛЕДСТВИЕ нарушенного поля (что
теперь возможно), а не сам факт изменения настройки, и несёт готовую
команду восстановления (`gh api` под конкретное поле — админ-toggle,
патч status-checks, снятие force-push/deletions, либо полный `PUT` для
случая `deleted`) — тормоз обязан называть газ (AGENTS.md).

Сценарий: `admin_enforced` стал `false` → текст сигнала называет «админ-
токен теперь сливает мимо test и contract», а не «защита main изменена»,
и несёт `gh api -X POST repos/{repo}/branches/main/protection/
enforce_admins` для восстановления одной командой.
