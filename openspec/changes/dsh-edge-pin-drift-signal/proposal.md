# dsh-edge-pin-drift-signal: «апстрим выпустил релиз новее пина» кричит сам

Задача: #134. Дельта-спека: `specs/journal-tasks-hands/spec.md` — подраздел
«Сигнал дрейфа пина» (п.23.1–23.3) в разделе «Самообновление морды»
(сложен в базовую спеку одновременно с реализацией).

## Класс закрываемой ошибки

silent-wrong собственного механизма обновления. Гипотеза из задачи #134
«пульс уже сверяет версии — проверить, почему дрейф не кричал» при проверке
не подтвердилась: пульс не сверял версии никогда. Единственное сравнение версий
живёт в DO морды (#73, `cf-worker/src/harness.ts` `#checkDshEdgeUpdate`) и
сопоставляет npm-latest с задеплоенной `/api/health`, а при расхождении
диспатчит `deploy-dsh-edge.yml` — который с непустым манифестом плагинов
пересобирает ЗАШИТЫЙ пин (`dsh-edge/upstream.json`). Итог: зелёный деплой
каждые 4 часа не может изменить то, ради чего запускается, дрейф «0.7.1 vs
npm 0.8.0» висел с 2026-08-31 до бампа #191 (2026-09-03) и был замечен
владельцем глазами, а не сигналом. Полное переустройство механизма (умный бамп
с разбором чейнджлога) — задача #161; здесь только сигнал.

## Решение

Сверка пина с релизами апстрима — в пульс оркестратора
(`scripts/orchestra/upstream_drift.py`, вызов из `scheduler.main`):

1. Пин (`{repo, sha}` из `dsh-edge/upstream.json`) сопоставляется с тегами
   апстрима (`repos/{repo}/tags` — имена и sha одним запросом).
2. Три исхода: `ok` (пин на теге новейшего стабильного релиза), `drift`
   (есть стабильный релиз семверно новее), `pin-not-tag` (sha пина не на теге —
   нарушение собственной процедуры выбора пина).
3. Сигнал «один раз на эпизод»: маркер-комментарий `[дрейф пина: <тег>]` в
   #134 — та же техника носителя, что у предохранителя конвейера (#120) и
   авто-повторов ai-review (#196); переживает перезапуск оркестратора. Новый
   релиз апстрима = новая цель = новый сигнал.
4. Каналы — общий канал пульса: комментарий в #134 + Telegram
   (`pulse_guard.escalate`) + метка `update-available`. Газ метки автоматичен:
   пин догнал апстрим — тот же прогон снимает метку (строка в реестре
   docs/agents/LABELS.md, гвардия test_label_registry).
5. Сбой сверки не роняет планировщик (слияния важнее), но не молчит: ⚠️ в
   отчёте пульса — сломанная сверка прячет дрейф так же, как её отсутствие.

## Что вне рамок

- Автоматический бамп пина и разбор чейнджлога — #161; бамп остаётся ручным PR
  с полным прогоном деплоя (design.md «Манифест», `dsh-edge/PATCHES.md`).
- Перестройка npm-сверки DO морды (#73) не входит: на префаб-фолбэке она
  остаётся полезной, а её диспатч при непустом манифесте теперь не единственный
  механизм — про дрейф пина кричит оркестратор.
- Цель сигнала — задача #134 (константа `DRIFT_ISSUE`): задача формулирует
  критерий сигнала; если владелец заведёт отдельную задачу-трекер дрейфа —
  константа переносится одной правкой.
