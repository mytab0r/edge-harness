# Дельта-спека: сигнал дрейфа пина апстрима

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Самообновление
морды»: новый подраздел «Сигнал дрейфа пина (#134)» (п.23.1–23.3), дополнен
механическим авто-бампом (#505, п.23.4). Сложен в базовую спеку одновременно
с реализацией (#134/#505).

## ADDED: сверка пина с релизами апстрима

Требование: пульс оркестратора на каждом прогоне сопоставляет пин
source-build морды (`dsh-edge/upstream.json` — `{repo, sha}`) с тегами апстрима.
Сравнивается пин, а не npm-latest против задеплоенной версии: деплой с непустым
манифестом пересобирает зашитый пин, поэтому только сверка пина отвечает на
вопрос «может ли очередной деплой изменить версию морды».

Требование: стабильность релиза определяется по семвер-форме тега
(`dsh-edge-vX.Y.Z` без дефиса в версии); пререлиз никогда не является целью
бампа. Пин на пререлизе с ядром новее последнего стабильного — не дрейф; пин на
rc ядра, у которого вышел стабильный релиз, — дрейф. sha пина, не найденный
ни на одном теге, — отдельное громкое состояние `pin-not-tag` (нарушение
процедуры «sha — тег релиза»), а не «ок».

## ADDED: сигнал «один раз на релиз» с автоматическим газом

Требование: при дрейфе сигнал уходит в задачу #134 (комментарий-маркер
`[дрейф пина: <тег новейшего релиза>]`), меткой `update-available` и Telegram;
повтора на ту же цель нет — цель маркера меняется вместе с релизом апстрима.
Метка снимается тем же механизмом автоматически, когда пин догоняет апстрим;
у метки нет ручного газа как единственного пути.

Требование: сбой сверки (сеть, API, сломанная форма пина) не роняет пульс
оркестратора и остаётся видимым ⚠️-строкой в отчёте — тихо пропавшая сверка
эквивалентна её отсутствию (тот же класс, что до #134).

Сценарий: пин `dsh-edge-v0.8.0`, у апстрима вышел `dsh-edge-v0.9.0` → первый
пульс после релиза: комментарий в #134 + метка + Telegram; следующие пульсы
молчат, пока не выйдет 0.10.0.

Сценарий: бамп пина до 0.9.0 смержен → следующий пульс отвечает `ok` и снимает
метку `update-available` с #134 без ручного действия.

## ADDED: механический авто-бамп пина (#505)

Требование: на каждом эпизоде дрейфа (`state == "drift"`, не `pin-not-tag`)
пульс, помимо сигнала, пытается открыть PR с поднятым пином —
`attempt_auto_bump` (`scripts/orchestra/upstream_drift.py`): заводит новую
задачу пула (label `task`, `area:worker`), ветку `agent/<N>-dsh-edge-upstream-bump`
от `origin/main`, коммит с новым `dsh-edge/upstream.json` (sha — тег
новейшего стабильного релиза апстрима) и PR через `scripts/git/pr-create` (обёртка над `gh pr create`, #496). Патч-серия
`dsh-edge/patches` этим коммитом НЕ перебазируется — решение, что в конфликте
патча смысловое, а что структурное, требует суждения (см. живой случай #505:
три минорных релиза апстрима сломали ровно те файлы, что трогают патчи
0003/0004), а не regex.

Требование: git-операции и `scripts/git/pr-create` (обёртка над `gh pr create`, #496) идут под PAT (`ORCHESTRA_PAT`), не
под `GITHUB_TOKEN` — события, вызванные `GITHUB_TOKEN`, не создают новых
прогонов workflow (документированное ограничение GitHub), и `test`/`contract`
никогда бы не сработали на таком PR. Нет `ORCHESTRA_PAT` в окружении — попытка
не тонет молча, а возвращает видимую строку отчёта пульса и не пытается
писать в git.

Требование: дедуп — единственный открытый PR с фиксированным префиксом
заголовка (`dsh-edge: авто-бамп пина апстрима до `). Пока такой PR открыт,
новая попытка не заводится («не плодить»). PR закрыт без мержа (человек взял
перебазировку патчей на себя под своей задачей) — следующий пульс, увидев тот
же дрейф, открывает новую попытку; автоматика не различает «закрыт, потому что
чинят руками» от «закрыт как неудачный».

Требование: ворота после мержа — `deploy-dsh-edge.yml` (не `test`/`contract`:
`dsh-edge/**` этот workflow триггерит только push в `main`, не `pull_request`).
Если апстрим сломал совместимость патч-серии, шаг «Патч-серия» откажет
громко post-merge — честный сигнал, подхватываемый пульсом отказов деплоя
(#477), а не тихий пропуск версии молчаливо-неверным пином.

Сценарий: дрейф до `dsh-edge-v0.9.0`, `ORCHESTRA_PAT` задан, открытых
авто-PR нет → пульс заводит задачу, ветку, коммит, PR; следующий пульс (тот
же эпизод) видит открытый PR по префиксу заголовка и не заводит второй.

Сценарий: PR смержен, но апстрим 0.9.0 поменял форму файла, который трогает
патч 0004 → `deploy-dsh-edge.yml` красный на шаге «Патч-серия» (post-merge);
пульс отказов деплоя (#477) заводит задачу-дефект; морда продолжает
показывать прежнюю (последнюю успешно задеплоенную) версию, пока патч-серию
не перебазируют вручную.
