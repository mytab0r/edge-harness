# Цепочка провайдеров: честный исход, доля пула и фолбэк по моделям

Задачи: #1307, #1309, #1310, #1311.

Design: [design.md](design.md). Разбивка и приёмка: [tasks.md](tasks.md).

## Summary

Три дефекта одного участка (`scripts/lib/dsh-ci.sh`, цепочка провайдеров и
быстрый провайдер Claude), найденные одним разбором живых прогонов
`worker.yml` 34942030597 и 35010410097 (2026-09-15):

1. **Пул монополизировал общий бюджет ожидания** (#1307). Пул шёл через
   `dsh_run_with_retry` БЕЗ потолка доли провайдера
   (`DSH_RATE_LIMIT_PROVIDER_CAP_SECS`, #1121), хотя каждый элемент цепочки
   этот потолок получает. Тело отказа пула несёт литерал `RATE_LIMIT:`,
   поэтому ретрай считал его обычным временным лимитом и выжигал все 1800с;
   ветка `retryAt` (#1288) запускала пул заново — опять с полным бюджетом.
   Замер: 07:31:18→08:41:56 = 70 минут сна, после чего ВСЕ восемь
   провайдеров цепочки получили «остаток общего бюджета RATE_LIMIT: 0с из
   1800с».
2. **Итог цепочки склеивал несовместимые классы** (#1307). Сообщение
   «цепочка провайдеров исчерпана целиком» печаталось независимо от того,
   почему каждый провайдер не ответил: в прогоне 35010410097 реально без
   квоты был ОДИН из восьми (GLM, сброс 2026-09-17), пять отвалились по
   НАШЕМУ исчерпанному бюджету, два несли мёртвый id модели. На этом тексте
   строится решение оркестратора: `scheduler.trigger_ai_review` видит
   `reset-at` в шапке вердикта и придерживает авто-повтор (#196) до той
   даты — двое суток холостого ожидания по факту одного провайдера.
3. **Мёртвый id модели сжигал живой аккаунт** (#1309). Элемент цепочки нёс
   ровно одну модель; `HTTP_410 Gone` на снятом провайдером id тратил весь
   элемент, хотя ключ был жив и на том же эндпоинте лежали рабочие модели.

Плюс видимость, без которой первый вопрос владельца («два ключа, один точно
рабочий — почему не работает?») не имел ответа в логе: **поаккаунтная
разбивка пула обрезалась на 200-м символе** (#1310), а сам агрегат `reason`
считается через `some()` и в принципе не различает «квота у обоих» от
«квота у одного, второй выбыл по другой причине» (#1311).

**Две поправки владельца по ходу работы, обе приняты и обе вскрыли дефект
глубже, чем был описан.** Первая: вывод «ждать сброса квоты» неверен — квота
исчерпана на одном токене. Вторая: **токен один и рефрешей нет вовсе** — и
это оказалось не деталью, а корнем. Долгоживущий токен без `refreshToken`
отвергали ТРИ гейта подряд (`dsh_import_anthropic_accounts`, `importAccount`
плагина и первая строка `createRefreshCoordinator` — до всякой проверки
срока), причём последний бил на каждом запросе и выходил наружу тем же
агрегатом `pool_unavailable`. То есть «квота» в логе могла означать «этот
аккаунт вообще не пускали внутрь». Требование `refreshToken` снято на всех
трёх уровнях; ротация refresh-токена осталась в документации как ОДНА из
возможных причин `REFRESH_FAILED`, а не как общий диагноз.

## Problem / Motivation

Все три — один класс: **решение принимается по агрегату, который не
различает причины, хотя данные для различения уже лежат рядом** (AGENTS.md,
«Алерт не гадает»). `pool_unavailable` не различал 401 и 429, пока #1192 не
положил `reason` — и ровно так же «исчерпана целиком» не различает «квота»
и «наш собственный тормоз», а один `model` в элементе не различает «ключ
исчерпан» и «id снят из каталога».

Цена измерена: за сутки 2026-09-15 каждый прогон воркера тратил ~70 минут на
сон в пуле и заканчивался «цепочка исчерпана целиком» с датой сброса через
двое суток, при живых GLM/OpenRouter/Ollama и двух живых ключах Anthropic.

## Proposal

- Пул получает такую же долю бюджета ожидания, как любой элемент цепочки
  (`DSH_RATE_LIMIT_PROVIDER_CAP_SECS`), СУММАРНО за все свои попытки, включая
  повторы по `retryAt`; остаток уходит цепочке тем же `initial_rl_used`.
- Исход КАЖДОГО провайдера классифицируется в источнике решения
  (`quota`/`quota_gate`/`our_budget`/`no_secret`/`unconfirmed_model`/
  `dead_model`/`transient`), итог печатает числа по классам и действие,
  следующее из разбора. Формулировка «исчерпана целиком» остаётся ровно для
  случая, когда она верна буквально.
- Новый факт шапки вердикта `chain-retry-useful: 1` — оркестратор больше не
  придерживает авто-повтор, когда часть провайдеров не получила настоящей
  попытки.
- Элемент цепочки получает опциональный список `models`; отказ, привязанный
  к id модели, пробует следующую модель того же ключа. Решение о переходе к
  следующему АККАУНТУ по-прежнему принимает `dsh_chain_should_advance`.
- `accounts[]` из тела `pool_unavailable` печатается отдельно от обрезаемого
  текстового хвоста.

## Non-goals

- Состав цепочки и живые id для NVIDIA-NIM правит PR #1306 (#1289) — здесь
  меняется только ФОРМА записи (список вместо одного id) и наполняется она
  id, подтверждёнными живым листингом каталога.
- Подключение пула Claude к `ai-review.yml` — решение владельца 2026-09-10
  (#860), не трогается.
- Суммарный wall-clock потолок цепочки — ортогональная ось, открытый PR
  #1247 (#1160), не обесценивается: доля пула ограничивает ОЖИДАНИЕ
  RATE_LIMIT, не время работы провайдера.
