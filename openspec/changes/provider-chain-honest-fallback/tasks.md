# Разбивка и критерий приёмки

Исполнитель по всем пунктам — агент сессии 2026-09-15 (ветка
`claude/anthropic-provider-chain-keys-dtfcyt`).

- [x] **Доля пула из общего бюджета ожидания** (#1307).
  `dsh_run_with_pool_then_chain` выдаёт каждой своей попытке
  `min(DSH_RATE_LIMIT_PROVIDER_CAP_SECS − уже потрачено, остаток общего
  бюджета)`.
  Критерий: сценарий 26 `dsh-provider-chain.smoke.sh` — при бюджете 60с и
  потолке 20с цепочка видит «остаток общего бюджета RATE_LIMIT: 40с из 60с».
  Мутация исполнена: снят `DSH_RATE_LIMIT_MAX_WAIT_SECS="$pool_share"` →
  вернулось «0с из 60с», сценарий красный.

- [x] **Классификация исхода каждого провайдера в источнике** (#1307).
  `_dsh_chain_record_outcome` + `_dsh_chain_report_exhausted`.
  Критерий: сценарий 24 (три разных класса на трёх провайдерах — числа в
  сводке, действие названо, `DSH_CHAIN_RETRY_USEFUL=1`) и парный 25 (все
  реально без квоты — прежняя формулировка на месте, повтор назван
  бессмысленным). Мутация исполнена: `if true` вместо `if [ "$quota" -eq
  "$total" ]` → сценарий 24 красный.

- [x] **Оркестратор не придерживает повтор по чужой дате** (#1307).
  Факт `chain-retry-useful` в шапке вердикта (`ai_review.build_comment`,
  `review_labels.FACT_RE`), проброс `ai_dsh.sh` → `ai-review.yml` →
  `ai_review verdict`, чтение в `scheduler.trigger_ai_review`.
  Критерий: `pytest scripts/review/ scripts/lib/` зелёные (1109 passed);
  `pytest scripts/orchestra/` — те же 14 предсуществующих падений, что и на
  чистом `origin/main` (сверено прогоном в отдельном worktree), ни одного
  нового.

- [x] **Фолбэк по моделям внутри аккаунта** (#1309).
  `dsh_entry_model_candidates` / `_dsh_failure_is_model_scoped` + модельный
  цикл в `dsh_run_with_provider_chain`; затравка профиля воркера и рук
  читает `dsh_chain_head_model`/`dsh_chain_head_max_tokens`.
  Критерий: сценарии 21 (аккаунт не меняется, отвечает вторая модель), 22
  (кандидаты кончились → следующий аккаунт как раньше), 23 (обе формы
  элемента, побайтная обратная совместимость). Мутация исполнена: модельная
  ветка заменена на `if false` → сценарий 21 красный («аккаунт меняться не
  должен — мёртв был ID МОДЕЛИ, получено 'SECONDARY'»).

- [x] **Живые id NVIDIA в реестр и манифест** (#1309).
  Два новых подтверждения в `scripts/lib/confirmed-provider-models.json`,
  `models: [...]` у `NVIDIA-NIM-1`/`NVIDIA-NIM-2`.
  Критерий: id взяты из живого `GET /v1/models` (публичный листинг, без
  ключа, 2026-09-15, 82 id), граница подтверждения названа в `evidence`
  дословно — подтверждено ПРИСУТСТВИЕ в каталоге, не успешный
  `chat/completions` на наших ключах.

- [x] **Поаккаунтная разбивка пула доходит до лога** (#1310).
  `dsh_pool_accounts_note`, печатается в каждом сообщении об исходе пула.
  Критерий: сценарии 26/27 `dsh-anthropic-pool.guard.sh` на ДОСЛОВНОЙ
  прод-форме тела из прогона 35010410097. Мутация исполнена: убрана
  подстановка `$pool_accounts_note` → сценарий 26 красный.

- [x] **Потолок доли считается на ПРОВАЙДЕРА, не на кандидата модели**
  (#1309 + #1121) — найдено собственным разбором диффа до коммита: запись с
  тремя моделями получила бы три потолка подряд и вернула бы монополию
  бюджета через новую ось.
  Критерий: сценарий 28 на ДОСТИЖИМОЙ последовательности (429 дважды, затем
  `HTTP_410` — единственный путь, где один аккаунт и тратит ожидание, и
  переходит на свою следующую модель). Первая версия сценария была
  НЕДОСТИЖИМОЙ и мутацию не ловила — это обнаружено исполнением мутации, а не
  чтением, и сценарий переписан. Мутация исполнена на новой версии:
  `provider_cap_left` → `provider_wait_cap` → «20с из 60с», сценарий красный.

- [x] **Валидация элемента без единого id модели** (#1309).
  `dsh_require_provider_chain` падает громко с именем элемента.
  Критерий: сценарий 27 (плюс обратная сторона — обе валидные формы
  проходят). Мутация исполнена: `if false` вместо проверки → красный.

- [x] **Предполётная проверка аккаунтов пула** (#1311) — поправка владельца
  2026-09-15: агрегат `reason: rate_limited` был прочитан как «квота у обоих
  аккаунтов», хотя это `some()` и второй аккаунт мог не пробоваться вовсе;
  владелец в то же время работал на втором. `scripts/lib/
  anthropic_pool_preflight.mjs` + `dsh_pool_preflight` называют КАЖДЫЙ
  аккаунт по имени и факту до старта агента, гасят непригодный на этот
  прогон и прайминг токена снимают с горячего пути.
  Критерий: сценарии 28/29 `dsh-anthropic-pool.guard.sh` — поведенческие, с
  настоящим HTTP-сервером на loopback, на трёх аккаунтах (квота / мёртвый
  refreshToken / живой), с проверкой, что ни один токен не утёк в лог.
  Мутации исполнены: `REFRESH_FAILED` → `NETWORK_ERROR` красит 28; снятие
  ОБЕИХ веток fail loud красит 29 (первая попытка мутации сняла только одну
  ветку и ничего не покрасила — это видно только исполнением).
