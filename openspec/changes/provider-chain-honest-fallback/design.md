# Развилки и почему выбрано это

## 1. Как ограничить пул: доля потолка против «одной попытки без ожидания»

**Отвергнуто:** гонять пул с `DSH_RATE_LIMIT_MAX_WAIT_SECS=0` (одна попытка,
всё ожидание — только через `retryAt`). Красивее как «одно место правды на
ожидание пула», но меняет поведение для отказа пула БЕЗ `retryAt` (сетевой
край, 5xx локального прокси): сегодня такой отказ переживается коротким
бэкоффом, а стал бы мгновенным откатом на цепочку.

**Выбрано:** пул — такой же потребитель ОДНОЙ доли (`DSH_RATE_LIMIT_PROVIDER_CAP_SECS`,
по умолчанию 300с), что и любой элемент цепочки. Ровно то, что комментарий у
`dsh_run_with_pool_then_chain` УЖЕ обещал («пул — 1-я из 10 попыток прогона,
не отдельная ось»), но чего код не обеспечивал. Новой величины не вводится —
переиспользуется уже обоснованная (#1121/#1124).

Доля считается СУММАРНО по всем попыткам пула, включая повторы по `retryAt`:
иначе потолок обходился бы циклом, как обходился общий бюджет до этой правки.

## 2. Где классифицировать исход провайдера

**Отвергнуто:** считать сводку постфактум, разбирая собственные напечатанные
строки. Это второй разбор тех же данных и ровно тот класс, который ADR 0025
закрывает для классов дефектов.

**Выбрано:** `_dsh_chain_record_outcome` пишет класс РОВНО там, где принято
решение о провайдере (гейт квоты, отсутствие секрета, неподтверждённый id,
исчерпание кандидатов, класс отказа). Сводка только суммирует уже готовые
записи `DSH_CHAIN_OUTCOMES`.

## 3. Кто решает, что повтор имеет смысл

Оркестратор придерживал авто-повтор по факту `reset-at` в шапке вердикта. Сам
`reset-at` — честный факт (провайдер назвал дату), менять его нельзя. Поэтому
добавлен ОТДЕЛЬНЫЙ факт `chain-retry-useful`, который ставит тот, кто знает
разбор по классам (`dsh_run_with_provider_chain` → `ai_dsh.sh` → `ai_review.
build_comment`), а `scheduler.trigger_ai_review` его читает. Дата сброса
по-прежнему пишется в персистентное состояние квоты (#857) — гейт сам
пропустит реально исчерпанного провайдера ДО попытки, не тратя вызов, так что
повтор не жжёт ту же квоту.

## 4. Форма элемента цепочки: список моделей

**Отвергнуто:** отдельный элемент цепочки на каждую модель того же ключа.
Просто в реализации (ничего менять не надо), но ломает смысл
`DSH_CHAIN_TRIED`/квота-гейта: три записи с одним `secret_env` выглядели бы
как три независимых аккаунта, и гейт квоты #857 пропускал бы их по одному,
хотя квота у них общая.

**Выбрано:** `models` внутри элемента. Одна запись = один аккаунт (как и
раньше), внутри — упорядоченные кандидаты. `DSH_CHAIN_TRIED` остаётся
списком АККАУНТОВ (ни один существующий потребитель не меняется), детализация
по моделям уходит в новую `DSH_CHAIN_MODELS_TRIED`.

Обратная совместимость: `{model, max_output_tokens}` даёт ровно один
кандидат, то есть цикл вырождается в прежний код побайтно. Смешение форм
запрещено семантически: `models` побеждает, `model` при её наличии не
читается вовсе — иначе два списка кандидатов в одной записи расходились бы
молча.

## 5. Какой класс отказа считать «модельным»

`HTTP_410`, `HTTP_404`, `UNKNOWN_MODEL`, `INVALID_REQUEST: max_tokens` — все
четыре имеют живую прод-форму в репозитории (прогоны 35010410097, 33572445063,
34753001158, 34730173870). Общее у них одно: провайдер отвечает про ID
МОДЕЛИ, а не про аккаунт. Квота/429/таймаут/обрыв SSE — про аккаунт или
транспорт, они модельный шаг не запускают.

Честная граница: класс определяется по тексту stderr, а не по машиночитаемому
полю — у `dsh` его нет. Если провайдер сменит текст, отказ упадёт в общий
путь (следующий аккаунт), то есть в поведение до #1309, не хуже.

## 6. Чего сознательно НЕ сделано

- **Автоматический discovery на 410** — та же причина, что названа в PR #1306:
  судящее действие с сетевыми вызовами по чужому API не должно молча
  происходить внутри гейта. Газ — ручной: `provider_model_discovery.py` +
  рунбук, сообщение цепочки называет это прямо.
- **Гейт по `reason` пула** (не ждать `retryAt`, если `auth_rejected`) —
  отдельное решение, оставлено как было (#1192 честно назвал это не гейтом).
  Вред ограничен потолками: ≤300с доли и ≤2 повторов.
