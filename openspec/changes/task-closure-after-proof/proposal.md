# task-closure-after-proof: закрытие задачи только после пост-мерж доказательства

Задача: #61. Дельта-спека: `openspec/specs/journal-tasks-hands.md`, «Конвейер», п.18.

## Класс закрываемой ошибки

Случай 2026-08-30 (#56/#57): PR с `Closes #N` слит → задача закрыта автоматом →
а критерий готовности задачи живёт ПОСЛЕ мержа (деплой, канарейка) и не был
выполнен. Все проверки (test, contract, review) смотрели на PR и не могли
увидеть пост-мерж последствия: они проверяли шаг (слияние), а не результат
(работающая система). Прямое нарушение правила «проверяй видимый результат,
а не шаг» — но на уровне процесса, а не кода.

## Решение

1. Контракт отклоняет PR с `Closes|Fixes|Resolves #N` — GitHub закрыл бы задачу
   при слиянии сам, поэтому единственная преграда стоит на входе.
2. Оркестратор после слияния не закрывает задачи — ставит напоминание о
   пост-мерж проверке.
3. Закрытие задачи = действие исполнителя после пост-мерж проверки, с уликами.

Принятая плата: на каждую задачу на один ручной шаг больше (закрыть issue с
доказательством). Это шаг и есть проверка результата — убирая его, мы вернём
ошибку.

## Что вне рамок

- Семантическая проверка «доказательства» (что улики достаточны) — остаётся
  на совести исполнителя и ревью; автомат здесь может только напоминать.
- Dependabot-PR — вне пула задач, их судьбу решают проверки (как раньше).
