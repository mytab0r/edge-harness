# session-archive-queue: архив сессии раннера — очередь на метке, а не разовая попытка (#1417)

Задача: #1417. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

До этого change факт «архивацию сессии `harness-<N>` сделать не удалось» жил
только в логе прогона оркестратора. Слитая задача второй раз не сливается,
поэтому повторять было некому и нечего: первая же причина отказа (HTTP 500
морды, квота DO, окно деплоя — причина меняется, свойство «убрать» не должно
зависеть ни от одной из них) теряла информацию о том, ЧТО убирать, навсегда.
Причина отказа остаётся за #1411; этот change делает её неусловием сохранности.

## Что делается

Durable-свойство «эта задача ещё не убрана» — метка `session:archive-pending`
на задаче, не запись в логе:

1. Метка ставится на задачу ВЕТКИ (`task_ref.resolve_pr_task`) ДО попытки
   архивации — даже до логина в морду: недоступная морда и есть тот случай,
   ради которого очередь заведена. Снимается ТОЛЬКО после успеха либо
   терминального исхода, где повтор не поможет (`session-not-found`, отказ
   мигрировать формат — #1430). At-least-once: повторная архивация уже
   архивированной сессии безвредна (идемпотентный RPC), потерянная — нет.
2. `scheduler.py::retry_pending_session_archives` идёт на каждом пульсе
   оркестратора и ничего не помнит о прошлом прогоне — состояние целиком в
   метке; хвост добирается сам после починки любой причины.
3. Гейт вызова архива в `after_merge` — задача ВЕТКИ, не упоминания в теле
   (находка ai-review PR #1418): тело слитого PR без упоминаний открытых задач
   пула — санкционированный путь, и прежде архив не делал ни попытки, ни
   метки. PR без agent-ветки в морду не ходит вовсе.
4. «Что осталось убрать» видно одним запросом по метке
   (`labels=session:archive-pending`); метка внесена в
   [docs/agents/LABELS.md](../../docs/agents/LABELS.md) с газом.

Перекрывает #1415 (архив уезжал на чужие упомянутые задачи) и #1416 (провал
не повторялся никогда) — два симптома одного отсутствующего механизма.

## Проверено

- `python -m pytest scripts/orchestra/test_scheduler.py -q` — 409 passed.
- Мутации (исполнены, не по памяти): снять метку до попытки — красный;
  архивировать по всем упоминаниям тела — красный; снять догоняющий проход
  из `main()` — красный; вернуть гейт архива на упоминания тела — красный
  (`test_after_merge_archives_the_branch_task_even_without_body_mentions`,
  `test_after_merge_without_branch_task_does_not_touch_the_archive_at_all`);
  вернуть в эскалацию безусловное «задача помечена» — красный
  (`test_main_exits_nonzero_and_escalates_on_archive_hard_failure`).

## Что вне рамок

- Причина HTTP 500 морды — #1411, здесь не устанавливается намеренно.
- Заметки-итогов (`append_session_notes`) не сужаются: по-прежнему уходят во
  все упомянутые задачи (#480); вопрос их пользы в related-задаче — отдельный.
- Разовая уборка сессий, накопившихся до этого механизма (на них метки нет),
  — отдельная узкая работа.
