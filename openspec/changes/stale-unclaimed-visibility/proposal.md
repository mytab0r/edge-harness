# stale-unclaimed-visibility: видимость непринятых задач (#427)

Задача: #427. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

`reap_stale` (п.15 базовой спеки, #61) отслеживает только просроченные
НАЗНАЧЕННЫЕ задачи — если задачу вообще никто не брал, ничто в пульсе этого
не видело. Замер 2026-09-06: 84 из 109 открытых задач без исполнителя, из них
44/36/21 старше суток/двух/трёх — большой и растущий хвост, невидимый
владельцу без ручного обхода Issues.

## Что делается

Новый шаг пульса `scheduler.py::mark_stale_unclaimed`, вызывается в `main()`
на том же снимке `pool` (`open_task_issues`), без второго обхода Issues:

- Задача без исполнителя старше `STALE_HOURS` (тот же порог, что у
  `reap_stale` — не второй порог правды) получает метку `stale-unclaimed`
  голым `POST .../labels`.
- Заблокированные (`blocked`) задачи пропускаются — метка уже сигнализирует
  владельцу отдельным каналом, дублировать не нужно.
- Метка не тормоз: ничего не закрывается и не переназначается автоматически.
  Газ («взять / переформулировать / закрыть как отпавшую») — вручную,
  владелец или агент, наткнувшийся на метку: у машины нет признака
  «нужное или отпавшее».
- Метка снимается сама, как только у задачи появляется исполнитель —
  следующий прогон видит `issue["assignees"]` непустым и убирает её
  (`DELETE .../labels/stale-unclaimed`).
- Возраст считается от `created_at` issue, а не от момента, когда задача
  реально освободилась (сознательное упрощение — второе потребовало бы
  обхода timeline на каждую свободную задачу пула).

## Проверено

- `python -m pytest scripts/orchestra/test_scheduler.py -q` — сюита зелёная.
- Мутация 1: убрать вызов `mark_stale_unclaimed` из `main()` —
  `test_main_labels_old_unclaimed_task_end_to_end` краснеет.
- Мутация 2: убрать мок `mark_stale_unclaimed` в
  `test_main_skips_worker_dispatch_while_fuse_paused` — тест бьёт по
  настоящему `gh api` без токена и падает (найдено CI, закрыто отдельным
  коммитом до этой спеки).

## Что вне рамок

- Машиночитаемый признак «задача нужна / отпавшая» — не предмет этого
  изменения; решение всегда за человеком.
- Второй порог правды под именем «возраст с момента освобождения» — не
  заводится, используется `STALE_HOURS`.
