## MODIFIED: Автономный воркер (конвейер пула)

28. Захват задачи воркером — атомарная аренда (ADR 0006, #121):
    `scripts/lib/claim_task.py claim` серверно создаёт замок
    `refs/locks/task-N` и тем же вызовом ставит назначение и след в задаче.
    Назначение — видимость, а не защита; защита от гонки каналов — замок,
    проигравший гонку получает отказ. Работа идёт в ветке `agent/N-slug` от
    свежего origin/main (вход — `scripts/git/task-branch`); если на задачу
    уже открыт PR без исполнителя, воркер доводит его ветку, второй PR не
    открывает (#245). `task-branch` перед созданием ветки отказывает, если N —
    эпик (`is_epic_issue`, тот же признак, что использует приёмка #335):
    критерий готовности эпика распределён по нескольким стройкам и недостижим
    в одном PR, отказ называет газ — взять узкую задачу конкретной стройки
    (#376, класс воспроизведён: PR #162, 44 раунда ревью на ветку, привязанную
    к эпику #77). Исполняет задачу DSH headless; транспорт
    (scripts/worker/task.sh) не принимает за агента содержательных решений.
    Пул кандидатов (до фильтра свободы и аренды) собирается через
    `scripts/lib/task_deps.py` (GraphQL) — REST-листинг не отдаёт
    `blockedBy`/`blocking`, одним пагинированным запросом, не двумя
    расходящимися (REST для списка + GraphQL для графа).

    **Инвариант рабочего дерева (#332):** коммит в `agent/<N>-*` разрешён
    только из рабочего дерева, чьё имя (basename top-level пути) начинается
    с того же числа `N-`. Проверяет `.githooks/pre-commit` перед каждым
    коммитом, чисто локально и до гвардии свежести base; отказ называет
    ветку, текущее дерево и лечащую команду `scripts/git/task-branch
    <N>-<slug>` — она вне CI заводит или переиспользует
    `<корень репозитория>/.claude/worktrees/<N>-<slug>` и печатает путь
    агенту, так что легаси-разнобой имён деревьев (`246-lease-claim` на
    ветке `agent/121-...`, `pr-workflow-sessions-8f1ab5` на
    `agent/323-...`) больше не воспроизводится. В CI
    (`GITHUB_ACTIONS=true`) гвардия отключается с ПРЕДУПРЕЖДЕНИЕМ в stderr:
    одноразовый чекаут воркера называется `edge-harness`, и без исключения
    отказ падал бы на штатный путь конвейера, а не на инцидент #332
    (спутанные деревья агента/человека локально). Повторный вызов
    `task-branch` на существующую ветку переиспользует или усыновляет
    дерево до аренды (класс #360: ничего не захватив, ничего не оставляет
    осиротевшим) и отказывает с командой синхронизации, если локальная
    голова разошлась с `origin/<ветка>` — PR мог подвинуть другой канал
    (оркестратор снимает исполнителя с конфликтного PR и диспатчит нового
    воркера); свои незапушенные коммиты (origin — предок локальной головы)
    расхождением не считаются. Существующие деревья скрипт не удаляет и не
    переименовывает: единственный `git worktree prune` вычищает только
    админ-запись, чей каталог уже стёрт с диска.
