# wip-limit-dispatch: WIP-лимит перед взятием НОВОЙ задачи (#464)

Задача: #464. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

`dispatch_worker` смотрел только на пул задач, не на очередь открытых PR:
замер 2026-09-06 — 29 открытых PR, 25 из них реально ждут доработки
(`ai:changes-requested`/`conflict`/`contract:failed`), а `dispatch_worker` с
той же готовностью диспетчил воркера на тридцатую НОВУЮ задачу. Владелец,
2026-09-06: «вместо того чтобы доделать текущие ПР, агенты идут и создают
новые».

## Что делается

`scheduler.py::wip_gate` — второй, независимый от предохранителя конвейера
(#120) тормоз: считает открытые PR, реально ждущие чужого труда
(`REWORK_LABELS`), и держит закрытым выбор задачи, у которой ещё нет
открытого PR, пока таких PR больше или равно `WIP_LIMIT` (12, обоснование —
комментарий в scheduler.py рядом с константой: темп слияний, время жизни PR,
закон Литтла на живых данных 2026-09-06). Газ — слияние/закрытие PR ниже
порога, снимается автоматически следующим прогоном; если гейт держит взятие
новых задач закрытым дольше `WIP_GATE_STUCK_HOURS` (8ч) — сигнал тем же
каналом, что предохранитель конвейера, причём сам различает «доводить есть
что, но не успевает» и «доводить нечего» по данным того же прогона
(AGENTS.md: алерт не гадает).

**Критическая находка ревью PR #466 (устранена этой же правкой):** гейт,
закрывающий `dispatch_worker` целиком, держал недоступной и доводку уже
открытых PR — `unhealthy_pulls` специально снимает исполнителя с такой
задачи, чтобы её довели (#245), а закрытый WIP-гейт не давал воркеру
вообще прийти. Тормоз без газа (AGENTS.md): очередь физически не могла
разгрестись сама, только вручную. Разведено: `wip_gate` решает только про
НОВЫЕ задачи; `dispatch_worker` при `wip_allowed=False` по-прежнему вправе
адресно запустить воркера (`worker.yml` input `task`) на задачу, у которой
уже есть открытый PR (`task_ref.resolve_pr_task` по ветке, symметрично
`free_task.py::declared_pr_for_task`) — и только на неё; если среди
свободных задач ни одна не объявлена открытым PR, диспатча не будет.

## Что вне рамок

- Второй порог правды под лимит доводки (сколько PR одновременно доводит
  воркер) — не заводится: воркер физически ведёт один прогон за раз
  (concurrency-группа `worker`), поэтому «доводка нескольких сразу» не
  существует как сценарий.
