# soft-failure-digest: дайджест мягких отказов — деградация, живущая в зелёных прогонах (#1121)

Задача: #1121. Дельта-спека: [specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

Класс «механизм работает вполсилы и молчит» — не отказ (его видно) и не
ошибка (её логируют), а деградация, оформленная как штатная работа. Эталон
(#1097): быстрый провайдер Claude падал `NO_ADAPTER` на КАЖДОМ прогоне
worker.yml полтора месяца — система штатно деградировала на медленный GLM,
прогон зелёный, находка — `::warning::`-аннотация, которую никто не читал.
Прочёс 2026-09-13 (#1121) нашёл ещё шесть живых экземпляров того же класса:
`rate_limit_retry_budget_exceeded`, красный шаг гвардии `blocked` под
`continue-on-error` (job зелёный, шаг красный), красная e2e-канарейка
морды, автооткат прода — no-op, но рапортует успех, провайдеры исчерпаны
все разом.

Задача #1121 называет носитель — дайджест мягких отказов — и требует его
построить, доказав живым прогоном, что он находит не менее пяти из
перечисленных находок в первые же сутки.

## Что делается

`scripts/orchestra/soft_failure_digest.py` + шаг «Дайджест мягких отказов
(#1121)» в `.github/workflows/orchestra.yml` (тот же job, что и остальные
гвардии пульса — `continue-on-error: true`, находка видна в step summary,
не гасит зелёный статус job'а, который читает heartbeat_check).

Два канала сигнала за окно `DIGEST_WINDOW_HOURS=24` по пяти workflow
(`worker.yml`, `hands.yml`, `ai-review.yml`, `orchestra.yml`,
`deploy-dsh-edge.yml`):

- **Канал A** — аннотации Checks API (`warning`/`failure`), которые
  переживают маскировку `continue-on-error` (в отличие от `steps[].
  conclusion` через Jobs API — находка #887/#896), сгруппированные по
  нормализованному тексту (workflow+job+текст без id/чисел).
- **Канал B** — условные шаги (`conclusion` в окне то `skipped`, то нет) —
  генерический признак «шаг сработал по условию», без имени шага в коде;
  единственный способ увидеть автооткат прода — тот вообще не оставляет
  аннотации (реальный успех, просто ложный).

Группа, повторившаяся `DIGEST_REPEAT_THRESHOLD` раз и более за окно, заводит
задачу (`task`+`soft-failure`) — дедуп по отпечатку в теле ОТКРЫТЫХ issues с
этой меткой (не по маркеру #120 — тот приём запирает класс навсегда после
закрытия задачи, находка ревью PR #887/#896), суточный потолок
`SOFT_FAILURE_DAILY_CAP`, исчерпание эскалирует #120+Telegram раз в
календарный день. Полный скан — не каждый тик оркестратора: гейт
`digest_due`/`DIGEST_INTERVAL_HOURS` ограничивает частоту (см. докстринг
модуля, «Стоимость по API» — точные цифры первого живого прогона в PR).

Новая метка `soft-failure` зарегистрирована в `docs/agents/LABELS.md` (класс
#207, гвардия `test_label_registry.py`).
