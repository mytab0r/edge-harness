# session-cookie-auth: кука вместо query-токена для WebSocket и заголовков

Задача: #5. Дельта-спека: `openspec/specs/journal-tasks-hands.md`, раздел
«Аутентификация», п.19–22.

## Класс закрываемой ошибки

HANDS_TOKEN ходил в query у WebSocket (`?token=`), потому что браузерный WS не может
ставить заголовки. Токен при этом попадает в логи Cloudflare (query логируется целиком)
и в историю браузера. Это же место делало невозможным вход без JS-состояния: токен
жил в `localStorage`, то есть долгоживущий секрет лежал в браузере в читаемом виде.

## Решение

По образцу dsh-edge (`docs/research/11-dsh-edge.md`: обмен одного высокоэнтропийного
секрета на подписанную 30-дневную HttpOnly `SameSite=Strict` куку):

1. `POST /api/session` — обмен `Authorization: Bearer <HANDS_TOKEN>` на сессионную
   куку `harness_session`: подпись HMAC-SHA256 (ключ — новый секрет воркера
   `SESSION_SECRET`) над сроком жизни; HttpOnly, SameSite=Strict, Secure, TTL 30 дней
   (`SESSION.ttlMs` в `src/config.ts`). `DELETE /api/session` — выход.
2. Сервер принимает И куку (браузер, включая WS — кука уходит с апгрейдом сама),
   И Bearer (job, `scripts/hands/dsh_task.sh` — не сломан).
3. `?token=` отклоняется громко: 400 `query_token_removed` на всех `/api/*`, даже
   при совпадающем значении — класс закрыт целиком, а не только для WS.
4. Фронт (`app.js`) больше не держит токен ни в `localStorage`, ни в JS-состоянии,
   ни в URL: гейт отдаёт токен один раз на обмен, кука невидима JS.
5. `SESSION_SECRET` добавлен в `.dev.vars.example`, комментарий `wrangler.jsonc` и в
   шаги проверки/переустановки секретов `deploy-worker.yml` (идемпотентно, по одному
   шаблону с существующими). Вращение секрета разлогинивает все сессии.

Попутно закрыто белое пятно того же места: `src/api-spec.ts` был ручной копией
`api-spec.json` без гвардии паритета. Теперь снимок генерируется командой
`npm run docs` вместе с `docs/api.md`, и `npm run check` ловит устаревание обоих.

## Принятая плата

- Новый обязательный секрет репозитория `SESSION_SECRET`: без него деплой краснеет
  на шаге «Проверка секретов» с внятной ошибкой (fail loud).
- Кука статична (срок жизни + подпись), без серверного списка отозванных сессий:
  отзыв = вращение `SESSION_SECRET`, для одного владельца этого достаточно.
- Браузер без кук (редкость) входа не имеет; для этого случая есть Bearer и API,
  но не морда.

## Что вне рамок

- Ротация самого HANDS_TOKEN (рекомендуема владельцу отдельно: исторически токен
  уже гулял в query до этого изменения).
- rate-limit на `POST /api/session` — сегмент один владелец, атаки перебором
  против высокоэнтропийного секрета не рассматриваются как актуальная угроза.
