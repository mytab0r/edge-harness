# Дельта-спека: журнал (journal-tasks-hands) — инлайн-кнопки Telegram (#254)

Модифицирует пп. 20 и 32 исходной редакции (третий способ авторизации,
узко для `messagesIngest`, и подключённый вебхук вместо «не подключён»).
Добавляет разделы про `callback_query` и отправку кнопочного сообщения.
Сложен в базовую спеку одновременно с реализацией (PR #486).

20. Запросы к `/api/*` авторизуются либо сессионной кукой (браузер, включая
    WebSocket — кука уходит с апгрейдом сама), либо `Authorization: Bearer`
    (job, `scripts/hands`). Ни один запрос к `/api/*` не несёт токен в URL.
    Единственное исключение — `POST /api/messages/ingest` (см. п.32): третий
    способ, узко для этого одного маршрута, не открывающий остальной API.

## MODIFIED: Инбокс владельца (#20)

~~32. Маршрут админско-релейный и авторизуется как все `/api/*` (пп. 20–22).
    Прямая доставка вебхуком Telegram не подключена — для неё нужен свой
    секрет; релей/админ шлёт update'ы сам.~~

32. Маршрут авторизуется ЛИБО как все `/api/*` (пп. 20–22, релей/админ),
    ЛИБО заголовком `X-Telegram-Bot-Api-Secret-Token`
    (`setWebhook(secret_token=...)`), сверенным константным по времени
    сравнением с секретом `TELEGRAM_WEBHOOK_SECRET` (#254, ADR 0014).
    Матчинг маршрута — ДО выбора способа авторизации: обход открывает ТОЛЬКО
    этот маршрут, не остальной API. Секрет не задан — обхода нет вовсе
    («возможности нет», не тихая дыра), общая авторизация продолжает
    работать без изменений.

    Вебхук-путь ДОПОЛНИТЕЛЬНО требует совпадения `chat_id` с секретом
    `TELEGRAM_CHAT_ID` в обеих ветках (`message` и `callback_query`) —
    секрет вебхука аутентифицирует бота (что запрос от Telegram), не
    отправителя: после `setWebhook` морда получает апдейты из ЛЮБОГО чата,
    где боту написали. Секрет `TELEGRAM_CHAT_ID` не задан или `chat_id` не
    совпал — путь закрыт 401, тем же приёмом, что у `TELEGRAM_WEBHOOK_SECRET`.
    Проверка `chat_id` применяется ТОЛЬКО к вызовам через вебхук-обход —
    вызывающий по Bearer/куке (п.20) уже доверен внутренним токеном, `chat_id`
    ему не навязывается.

## ADDED: callback_query — нажатие инлайн-кнопки решения владельца

Требование: апдейт с полем `callback_query` вместо `message` (нажатие
инлайн-кнопки, `callback_data` формата `wo:<issue>:<option>`, уложен в
лимит Bot API 64 байта) разбирается ОТДЕЛЬНОЙ веткой ДО общего разбора
формы сообщения — у него нет общих полей с плоской формой и формой
сообщения (нет `message`/`text` верхним уровнем).

Требование: морда отвечает `answerCallbackQuery` (кнопка не «крутится» у
владельца) и `editMessageText` (видно выбранный вариант, `reply_markup`
снят — повторное нажатие невозможно) через `TELEGRAM_BOT_TOKEN` (тот же
секрет репозитория, что уже использует `scripts/orchestra/pulse_guard.py`
для исходящих алертов, синхронизирован дополнительно в воркер). Секрет не
задан — Telegram API не вызывается, событие честно логируется, ответ
вебхуку и `repository_dispatch` не падают из-за необязательного внешнего
звонка (best-effort, тот же принцип, что у `send_telegram`).

Требование: РОВНО ОДИН РАЗ (идемпотентность по `update_id`, тот же
`#putMessage`/`UNIQUE(source, source_msg_id)`, что у сообщений) уходит
`repository_dispatch` (`event_type: owner-decision`, `GH_DISPATCH_TOKEN` —
тот же секрет и роль, что у остального dispatch-пути морды, ADR 0008:
Contents+Actions, без Issues) в тонкий job (`.github/workflows/
owner-decision.yml`, только `issues: write` из `permissions`, `github.token`,
без единого нового секрета), который оставляет комментарий первой строкой
«РЕШЕНИЕ: N» — тот же артефакт, что и ручной ответ владельца комментарием
(#470/#471). Второй "apply"-путь не заводится: метку `waiting:owner`
снимает гвардия `scripts/orchestra/waiting_owner_guard.py` (#470/#471) на
следующем пульсе `orchestra`, а не морда напрямую.

Требование: морда отвечает Telegram'у 200 всегда, кроме полностью
нечитаемого апдейта без единого идентификатора (`need_source_msg_id`) и
кроме `chat_id`, не принадлежащего владельцу (401, см. п.32 выше) — 4xx на
кривой `callback_data` заставил бы Telegram ретраить апдейт, которому
ретраи не помогут; кривой `callback_data` даёт честный `callback_ignored`
с ответом владельцу «не понял формат».

Сценарий: владелец нажимает кнопку «Вариант Б» под сообщением о задаче
#471 → callback уходит с `wo:471:2` → морда отвечает `answerCallbackQuery`
(«Принято: Вариант Б»), снимает клавиатуру `editMessageText`, шлёт
`repository_dispatch` → job оставляет «РЕШЕНИЕ: 2» в задаче #471.

## ADDED: отправка кнопочного сообщения — задача с вариантами, найденная гвардией

Требование: `scripts/orchestra/pulse_guard.py::escalate` принимает
необязательный `options: list[str] | None` — задан, Telegram-сообщение
уходит с инлайн-клавиатурой (`build_decision_keyboard`, одна кнопка на
вариант, `callback_data` = `wo:<issue>:<позиция в списке>`); не задан —
поведение не меняется (обычный текстовый алерт).

Требование: единственный вызывающий с `options` —
`scripts/orchestra/waiting_owner_guard.py::waiting_owner_check` (#470/#471):
открытая задача с меткой `waiting:owner` и машиночитаемым блоком
«## Варианты владельца» (`docs/agents/PROTOCOL.md`) — `options` строится
из подписей вариантов (`variant_option_labels`, фраза без номера и без
последствия, Telegram — узкий экран). Задача без блока или с
непоследовательной письменной нумерацией (не `1, 2, …, N` подряд) получает
текстовый алерт, как раньше — позиционная нумерация клавиатуры обязана
совпасть с номером, который владелец видит в тексте и называет в ответе
«РЕШЕНИЕ: N», иначе нажатие «второй кнопки» записало бы решение за другой
вариант.

Требование: обратная проверка — нет открытой `waiting:owner`-задачи с
машиночитаемым блоком вариантов, нечему вызвать `escalate(options=...)`,
кнопочное сообщение не уходит никогда «просто так», без задачи-артефакта в
репозитории (критерий приёмки #254, п.5: «решения только в чате» невозможны
структурно, не дисциплиной).

Сценарий: задача с телом «## Варианты владельца\n1. Секрет с правами
администратора — …\n2. Оставить ручной инструмент — …» получает метку
`waiting:owner` автоматически (уже было, #470/#471) → следующий пульс
`orchestra` шлёт Telegram-сообщение с двумя кнопками «Секрет с правами
администратора» / «Оставить ручной инструмент», а не только текст.
