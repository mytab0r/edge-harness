# Дельта-спека: журнал (journal-tasks-hands) — интервал DO-пульса, калибровка по измеренной стоимости тика (#812)

Секция «Пульс оркестрации» домовой спеки пополняется несколькими
незаархивированными дельтами одновременно (`orchestration-pulse-fail-loud`
пп. 30-33, `do-pulse-watchdog` пп. 42-45, `cf-cron-trigger` п. 46) — номера у
них могут временно пересекаться. Итоговый номер этого пункта присваивается
при архивации, сверяться с доменной спекой на тот момент, не с числом здесь.

## ADDED: Интервал собственного такта DO — решение по измеренной стоимости тика, не по умолчанию

50. `HEARTBEAT.selfOrchestrationMs` (`cf-worker/src/config.ts`) — не
    произвольное число, а результат явного расчёта, обязанного нести
    обоснование числом рядом со значением (докстринг константы), а не
    только в проектной документации: стоимость одного тика скачиваемого им
    `orchestra.yml` в GitHub REST-вызовах (документированная база — issue
    #443, ~150-250/тик при непустой очереди), общий бюджет
    `GH_TOKEN=github.token`, разделяемый ВСЕМИ workflow репозитория
    одновременно в течение того же часа, и явно названное допущение о
    вторичном (content-generating) лимите, когда он не переизмерен нагрузочно.
    50.1. Значение не пересматривается «на глаз» — только повторным замером
        того же вида (свежий прогон `orchestra`, `gh api rate_limit`),
        задокументированным тем же способом, что и решение issue #812:
        число вызовов на тик, первичный бюджет, вторичный лимит (или явная
        пометка «не подтверждено» при его отсутствии), выбранный интервал с
        численным запасом относительно бюджета — не оптимизация на грани.
    50.2. Понижение интервала МАСШТАБИРУЕТ (не требует отдельной правки)
        порог «alarm подвис» у `pulseStale()`/`pulseNeedsRecoveryDispatch()`
        (`2×HEARTBEAT.selfOrchestrationMs`, orchestration-pulse-fail-loud п.32,
        cf-cron-trigger п.46.2) — обе функции читают константу символьно.
        Комментарии, несущие ПРОИЗВОДНОЕ число (наихудшее время починки
        резервом Cron Trigger = порог + интервал cron, `wrangler.jsonc`,
        `docs/research/20-cloudflare-free.md`), обязаны обновляться в ТОМ ЖЕ
        PR, что и само значение — иначе документация несёт неверное число,
        то же нарушение, что AGENTS.md «Утверждение о готовом артефакте
        обязано нести его адрес» — только для чисел, не путей.
    50.3. Любой другой Python- или TS-код, независимо (не через
        `config.ts`/переменную окружения) захардкодивший ожидаемую частоту
        такта как отдельную числовую константу (пример на момент этого
        change'а: `scripts/orchestra/pulse_guard.py::HEARTBEAT_MAX_AGE_MINUTES`,
        `INDEPENDENT_PULSE_STALE_AFTER_MINUTES`, откалиброванные как «N
        тактов × 15 мин»), НЕ обновляется автоматически изменением
        `HEARTBEAT.selfOrchestrationMs` — при пересмотре интервала такой код
        либо становится ТОЛЬКО консервативнее (больше тиков умещается в тот
        же порог минут — задержка обнаружения растёт, ложного молчания
        риска нет), и тогда это долг точности, не блокер; либо становится
        более чувствительным (меньше тиков в тот же порог минут — риск
        ложного срабатывания растёт), и тогда пересчёт этих констант ОБЯЗАН
        войти в тот же change, что понижает интервал, не откладываться.
        Направление проверяется явно (проверено п.50.2 comment /
        proposal.md этого change'а: масштабирование безопасное, долг
        зафиксирован отдельной узкой задачей, не блокирует).
