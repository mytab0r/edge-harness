внешним/ручным агентом, — атомарная аренда `scripts/lib/claim_task.py claim N`
(ADR 0006): серверный git-ref замок `refs/locks/task-<N>`, создаваемый
Git-дата-API. Ветка `agent/<N>-<slug>` создаётся только скриптом
`scripts/git/task-branch` (enforced-правило PROTOCOL.md); он берёт аренду
перед `git switch -c`, если её ещё не взял вызывающий транспорт (см. ниже) —

дисциплине. Защита доказывается фактом существования замка, а не фактом
назначения. Другого пути начать работу над задачей пула в коде нет.

Сценарий: задача под живым замком (держит внешний агент через `task-branch`)
→ облачный воркер (`free_task`) её больше не выбирает как свободную; прямой
`workflow_dispatch --task N` на неё получает отказ claim'а и завершается
зелёным no-op — было наоборот: воркер брал такую задачу как свободную, потому
что assignee и замок не выставлялись вовсе.

Сценарий: `task-branch N-slug` без сети/`gh` (заведомо не может арендовать) →
предупреждение в stderr, ветка всё равно создаётся — офлайн-работа не
блокируется тем, чего физически нет (замок всё равно на сервере, недостижимом
без сети).

## ADDED: Не арендовать дважды за транспортом

Требование: `claim_task.py claim N` не идемпотентен по актору — повторный
claim того же номера тем же держателем отклоняется как «занято» так же, как
чужой claim. Транспорт (`scripts/worker/task.sh`, `scripts/hands/dsh_task.sh`)
арендует раньше `task-branch` (до старта агента — дешёвый fail-fast до траты
ресурсов на промпт/сессию) и пробрасывает НОМЕР арендованной задачи в
окружение агента как `LEASE_ALREADY_CLAIMED=<N>` (не булев признак —
см. «Флаг несёт номер, не признак» ниже); `task-branch` сверяет номер во флаге
с номером своей ветки и пропускает claim только при совпадении. Без флага
(внешний/ручной путь) аренда полностью на `task-branch`.

Сценарий: воркер арендовал #N, собрал промпт, запустил DSH-агента с
`LEASE_ALREADY_CLAIMED=N` в окружении → агент вызывает `task-branch N-slug` →
ветка создаётся без повторного (и отклонённого бы) claim'а.

Сценарий: доводка уже открытого PR — `task-branch` не вызывается вовсе (прямой
`git fetch && git checkout -B`), аренда там остаётся полностью на транспорте/
ручном вызове, как и раньше; этот путь дельтой не затронут.

## ADDED: Флаг несёт номер, не признак

Требование: `LEASE_ALREADY_CLAIMED` несёт НОМЕР задачи, аренду которой уже
взял вызывающий транспорт, а не булев признак «кто-то уже арендовал». Причина:
за один прогон агент может создать вторую ветку на ДРУГУЮ задачу (playbook
это допускает, например для сопутствующей задачи, найденной по ходу работы) —
булев признак не различает «эта аренда моя» от «эта аренда чужого номера»,
и `task-branch` молча пропускала бы claim второй задачи, оставляя её
неарендованной для всех остальных каналов (класс silent-wrong). Пропуск
claim'а в `task-branch` разрешён только когда значение флага численно
совпадает с номером задачи создаваемой ветки; при несовпадении `task-branch`
берёт аренду сама (с предупреждением, что флаг относился к другой задаче).
Значение, не являющееся десятичным числом (устаревший булев `1` без нового
контракта, произвольный мусор), — громкий отказ (`task-branch` не создаёт
ветку): сломанный/устаревший вызывающий обязан быть виден, а не тихо принят
за корректный.

Альтернатива «сделать `claim_task.py claim` идемпотентным по держателю и
убрать флаг вовсе» рассмотрена и отклонена: замок канало-агностичен по
дизайну (#121, `refs/locks/task-N` не хранит канал/прогон — только
свободный текст коммита), держатель (`actor`) один и тот же логин у всех
каналов. Идемпотентность по держателю не отличила бы «этот же прогон уже
взял этот же номер» от «другой параллельный прогон под тем же логином
только что взял тот же номер» — и тихо признавала бы гонку (ту самую,
которую замок обязан ловить) успехом второго claim'а. Явный номер задачи во
флаге такой путаницы не создаёт и не требует менять контракт `claim_task.py`.

Сценарий: транспорт арендовал #50 (`LEASE_ALREADY_CLAIMED=50`), в этом же
прогоне `task-branch` вызывают для `77-slug` → номер не совпал, `task-branch`
берёт аренду #77 сама (claim не пропускается).
