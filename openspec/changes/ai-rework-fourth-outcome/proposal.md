# ai-rework-fourth-outcome: доводка ai-review различает причины, но лечит две из трёх эскалацией с первого раза (#1274)

Задача: #1274. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

`dispatch_ai_review_rework` (issue #1027, дополнена #1253/#1260 —
`ai-rework-age-fairness`) уже РАЗЛИЧАЕТ три причины исчерпания бюджета
доводки на отпечатке диффа: инфраструктурный отказ прогона, «отработал
успешно, находки не закрыты» и «атрибуции нет вовсе». Тексты трёх эскалаций
разные — различение работает. Но ЛЕЧЕНИЕ двух из трёх причин одинаковое:
эскалация владельцу с первого же обнаружения, хотя причины требуют разного
(AGENTS.md, «Воркеру нужны четыре исхода, не два»).

Три реальных эскалации из #120 (`[ai-rework: эскалация]`, ровно одна в
сутки):

| Дата | PR (задача) | Причина | Исход до этого change |
|---|---|---|---|
| 2026-09-12 12:50 | #1020 (#782) | `conclusion='failure'` | Автоповтор без штрафа бюджета — работает (#1027) |
| 2026-09-13 12:28 | #1120 (#1111) | worker.yml успешно, отпечаток не изменился | Эскалация с первого раза |
| 2026-09-14 21:19 | #804 (#720) | «не атрибутирован» | Эскалация с первого раза, ПРИЧЁМ ложная — см. ниже |

Диагноз по каждой причине:

1. **`conclusion='failure'`** (Исход 1, УЖЕ решён #1027) — не предмет этого
   change, только фон.
2. **«отработал успешно, отпечаток не изменился»** (Исход 2) — задание не
   сработало: generic-инструкция «прочитай комментарии PR» не донесла
   находки или агент молча не согласился. Повтор с ТЕМ ЖЕ заданием
   бессмыслен по построению — нужен другой контракт, не второй проход
   старого.
3. **«не атрибутирован»** (Исход 3) — живая проверка на #804/задаче #720
   показала, что это в основном ЛОЖНОЕ срабатывание: прогон `34694760329`
   (созданный ровно в момент дисПатча авто-доводки, `2026-09-12T12:50:13Z`)
   реально клеймил задачу #720 и завершился ЧЕСТНЫМ `conclusion='failure'`
   (проверено `gh api repos/mytab0r/edge-harness/actions/runs/34694760329`
   живьём) — тот же класс, что #1020! Между дисПатчем и перепроверкой
   (2026-09-14T21:19) прошло **43 прогона worker.yml по ДРУГИМ задачам**
   (слот сериализован, `concurrency: group: worker`, ~18-33 прогона/сутки,
   AGENTS.md) — `last_worker_run` смотрел только последние 10 прогонов, и к
   моменту перепроверки честный `conclusion='failure'` давно ушёл за окно.

## Что делается

1. **Расширенное окно атрибуции.** `last_worker_run(repo, task_number, *,
   since=None)` — с анкером (`ai_rework_dispatched_at`, момент последнего
   диспатча на этом отпечатке) ищет постранично (`per_page=100`, до
   `pulse_guard.LAST_RUN_LOOKUP_PAGES=5` страниц — 500 прогонов, при
   серийном слоте это 15-27 суток истории), пока страница целиком не
   окажется старше анкера. Без анкера — старое поведение (10 записей,
   обратная совместимость для `resume_series_by_merge`/
   `dispatch_conflict_rework::last_worker_run_conclusion`, которые этот
   change не трогает). `dispatch_ai_review_rework` теперь всегда передаёт
   анкер.
2. **Исход 2 — один бесплатный доп. заход с ЯВНО другим контрактом, не
   эскалация с первого раза.** Первое обнаружение
   (`conclusion=='success'`, отпечаток не изменился) публикует маркер
   `AI_REWORK_SECOND_CHANCE_MARKER` и дисПатчит worker.yml с контрактом
   «исправь или оставь явный комментарий с маркером
   `AI_REWORK_REBUTTAL_MARKER` и причиной» — без правки `task.sh`/
   `worker.yml`: режим доводки уже велит агенту прочитать ВСЕ комментарии
   PR, значит текст дойдёт. Второе подряд success на ТОМ ЖЕ отпечатке (маркер
   уже стоит) — законная эскалация, текст которой цитирует возражение
   агента, если оно было (не теряет его, AGENTS.md: «тогда это возражение и
   есть результат»), либо честно называет его отсутствие.
3. **Исход 3 — один бесплатный повтор, эскалация только на втором подряд
   отсутствии следа.** Первое обнаружение «атрибуции нет вовсе» ДАЖЕ в
   расширенном окне — маркер `AI_REWORK_UNATTRIBUTED_RETRY_MARKER`,
   автоповтор без штрафа бюджета (симметрично Исходу 1 — нельзя доказать,
   что попытка была честной). Второе подряд отсутствие следа — эскалация,
   текст которой называет ИМЕННО дефект атрибуции («проверь, шёл ли вообще
   прогон worker.yml»), не «посмотри находки ai-review» (находок, возможно,
   никто не читал).
4. **Гейт повторной проверки не завязан на счётчик git-шага.** Бонусный
   повтор Исхода 3 по конструкции НЕ оставляет git-шага (это и есть
   «атрибуции нет») — `ai_rework_attempts` считает только его, значит
   `attempts` остаётся 0 навсегда после такого повтора, и без отдельной
   проверки код диспатчил бы третий/четвёртый/… заход бесконечно, никогда
   не долистывая до эскалации (газ без тормоза — обратный класс дефекта
   «тормоз без газа», AGENTS.md). Решение входит в ветку эскалации тоже при
   `pending_unattributed_retry` (маркер бонуса уже стоит на этом отпечатке
   при `attempts < AI_REWORK_MAX_ATTEMPTS`), не только при
   `attempts >= AI_REWORK_MAX_ATTEMPTS`.

Ни один из трёх исходов не эскалирует владельцу при ПЕРВОМ обнаружении —
Исход 1 это уже соблюдал (#1027), Исходы 2 и 3 теперь тоже.

## Что НЕ делается (сознательно, вне рамок)

- `dispatch_conflict_rework` (очередь `conflict`, issue #588/#474) несёт тот
  же профиль «не атрибутирован» текстом, что и `dispatch_ai_review_rework`
  до этого change, и не получает бесплатного повтора вовсе (эскалирует
  безусловно при исчерпании бюджета). Это отдельный класс дефекта в СОСЕДНЕЙ
  функции — общая помощь `last_worker_run(since=...)` доступна ей тоже (тот
  же файл, та же сигнатура), но её собственный call site (`last_worker_run_
  conclusion`, без анкера) этим change не меняется: изменение решения
  эскалировать для конфликтов — предмет отдельной узкой задачи, не этой.
- Правка `task.sh`/`worker.yml` (новый явный input для промпта) не
  делается: контракт «исправь или возрази» доставляется существующим
  каналом (комментарий PR, который режим доводки уже читает целиком).
- Не проверяется, действительно ли МОДЕЛЬ агента правильно поймёт и
  исполнит контракт возражения — это поведение LLM, не наблюдаемое юнит-
  тестами; проверяется контракт СХЕМЫ (какой текст публикуется, что ищет
  эскалация), не качество исполнения агентом.

## Живой пример: PR #804

По коду ДО этого change PR #804 получил эскалацию «не атрибутирован» —
ложно: реальный прогон `34694760329` честно клеймил задачу и завершился
`conclusion='failure'`, но ушёл за узкое окно `per_page=10`. По коду ПОСЛЕ
этого change тот же снимок данных классифицируется как Исход 1
(инфраструктурный отказ прогона, расширенное окно находит запись) —
автоповтор без эскалации, тот же путь, что уже получил PR #1020.
