# Задачи: dsh-in-job

Исполнение — через пул Issues (#48). Правила — [PROTOCOL](../../../docs/agents/PROTOCOL.md).

## Слайс 1: задача из морды → сессия DSH в журнале

Четыре слоя доказательств (из ревью треда #48, liyangbing): **job/process** →
**DSH bootstrap** → **durable session evidence** → **task outcome**. Heartbeat —
улика только первого слоя и никогда не заменяет остальные.

- [x] `scripts/hands/dsh_task.sh`: клиент — установка DSH tarball'ами (**пин
      versions + SHA-512 integrity**, сверка со скачанным файлом), событие
      `bootstrap` (версии dsh/dsh-headless/node, факт сверки), heartbeat-цикл,
      запуск `dsh --profile headless`, пост событий батчами.
- [x] `job_end` уходит только после принятого журналом флаша (ретраи с бэкоффом,
      иначе job красный) — «зелёный job с непринятым результатом» = silent-wrong.
- [x] Редакция кредов (`nvapi-…`/`sk-…`) во всём, что постится в журнал: GH
      маскирует секреты только в своих логах, DO — нет.
- [x] SIGINT/SIGTERM → graceful-выход (130/143), trap доносит `job_end(fail)`.
- [x] `.github/workflows/hands.yml`: `repository_dispatch` (types: `harness-task`) +
      `workflow_dispatch` с вводом текста задачи для отладки; таймаут job'а и
      cleanup воркспейса.
- [x] Секреты репозитория: `DEEPSEEK_API_KEY` (+ при необходимости
      `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`); токен рук — уже есть (`HANDS_TOKEN`).
- [ ] Подключение плагинов владельца (combo-router из `vars.PLUGINS_SUITE_URL`)
      в раннере — после первого живого прогона с env-провайдером.
- [x] Прогон: `npm pack` устанавливаемых пакетов на ubuntu-latest — подтвердить или
      опровергнуть резолв транзитивных зависимостей (первый прогон #48).
- [x] E2E из морды: задача → «руки живы» → разворот сессии в журнале → финальный
      ответ → задача `done`. Провал любого звена виден в морде, не в догадках.
- [x] Канарейка/дым рук: `workflow_dispatch` прогон с заведомо простой задачей,
      зелёный = «руки живы и ответили».

### Ветки отказов, которые обязаны быть громкими (ревью #48)

- integrity mismatch tarball'а → падение до установки;
- registry/npm недоступен → падение с кодом, не тишина;
- провайдер недоступен/таймаут → `timeout` → rc≠0 → `agent_error` + `fail`;
- прерывание записи журнала → ретраи → красный job, задача не получает `done`;
- повторный запуск job'а (retry) → посев seq с сервера, повторное исполнение
  задачи допустимо и видимо в журнале (новые события, дублей нет);
- отмена job'а (SIGINT/SIGTERM) → graceful 130/143 → `job_end(fail)` от trap;
- осиротевшие процессы — GH убивает дерево процессов job'а; клиент ловит
  INT/TERM заранее, SIGKILL-хвост остаётся на совести раннера (осознанно).
