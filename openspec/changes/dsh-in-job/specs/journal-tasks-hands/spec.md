# Дельта-спека: провайдер DSH — ротация учёток (#215)

Реализация: `scripts/lib/dsh-ci.sh` (`dsh_install_plugins_suite`,
`dsh_mount_plugins_suite`, `dsh_patch_profile`), вызывается из
`scripts/worker/task.sh`, `scripts/hands/dsh_task.sh`. Проводка —
`.github/workflows/worker.yml`, `hands.yml`.

`scripts/review/ai_dsh.sh`/`ai-review.yml` НЕ вызывают suite: этот транспорт
обязательно идёт через цепочку провайдеров (#727/#737,
`dsh_run_with_provider_chain`), а suite с ней конструктивно не совместим —
см. design.md, «Стык suite и цепочки провайдеров». Это решение этого же
change, принятое при слиянии #215 с #727/#737, не последующее сужение
изначального намерения задачи: критерий приёмки #215 (ниже) говорит про
прогон ВОРКЕРА, ai-review в нём не упомянут.

## ADDED: Suite ротации учёток combo-router + anthropic-oauth-pool

Требование: `vars.PLUGINS_SUITE_URL` — тег релиза ЭТОГО репозитория с
ассетами `dsh-combo-suite-0.1.0.tgz` и `dsh-anthropic-oauth-pool-0.1.0.tgz`
(+ `.sha256` рядом), опубликованными тем же способом, что и forge-плагины
(`.github/workflows/plugin-forge.yml`). Значение переменной читается ОДИН
раз (`scripts/lib/dsh-ci.sh`), три workflow только прокидывают её в env —
одно место правды на имя переменной и способ монтирования.

Требование: переменная не задана → поведение как до #215 (одиночный
провайдер из `vars.DEEPSEEK_BASE_URL`/`vars.DEEPSEEK_MODEL`/
`secrets.DEEPSEEK_API_KEY`), с видимой строкой в логе job'а «ротация не
подключена» — не молчаливый дефолт.

Требование: переменная задана → скачивание обоих ассетов публичным HTTPS
(`releases/download/<тег>/<ассет>`, без токена — работает и в trust-zone
AI-ревью, у которой `GH_TOKEN` в этом шаге намеренно нет), сверка sha256 с
sidecar-файлом. Любой сбой (сеть, сошедшийся sha256, форма ассета) — job
падает громко ("suite не установился").

Требование: монтаж — через официальный документированный `dsh plugin
--profile <profile> add <spec>` (не ручная правка `cordis.patch.yml` под
плагин), ПОСЛЕ записи собственного патча профиля (`dsh_patch_profile`) —
порядок доказан живым прогоном этого же репозитория (`hands/dsh_task.sh`,
монтаж `dsh-hands-streamer`, 2026-08-30: «initProfile пишет файлы профиля
только при отсутствии — наш патч при dsh plugin add не перезаписывается»).
Факт монтажа проверяется командой `dsh --profile <profile> --dump-config`
(наличие строк `- id: combo-router` и `- id: anthropic-oauth-pool`), не
предположением. Отсутствие любого из двух id в дампе после `dsh plugin add`
— job падает громко ("suite не смонтировался").

Требование: активация (`agent-default-model: {provider: combo, model: auto}`
+ включённый `combo-router` с ≥1 маршрутом) — МЯГКАЯ, не входит в fail-loud
гейт установки/монтажа. После записи патча повторный `--dump-config`
проверяет, что `provider: combo`/`model: auto` действительно отражены;
если нет — тот же патч перезаписывается плоским (одиночный провайдер),
видимым предупреждением «suite смонтирован, но активация не подтверждена».
Причина разделения: локальная проверка при подготовке #215 не подтвердила
однозначно, что правка `cordis.patch.yml` профиля `headless` (в отличие от
произвольного имени профиля) гарантированно подхватывается сразу после
`dsh plugin add` — а `combo-router` с `enabled: true` и пустым `routes`
падает конструктором роутера (`dsh-combo-router/lib/router.js`), поэтому
неподтверждённая активация обязана откатываться, а не рисковать падением
каждого прогона DSH.

Требование: маршруты combo-router строятся из `PLUGINS_SUITE_CANDIDATE_ROUTES`
(`scripts/lib/dsh-ci.sh`, имена/URL/модели — из собственного примера suite,
`dsh-combo-router/examples/mytab0r.settings.yml`) — маршрут включается,
только если соответствующая `apiKeyEnv`-переменная окружения непуста;
владелец расширяет ротацию созданием секрета с этим именем, без правки
кода. Маршрут `env-provider` (переиспользует уже обязательные
`DEEPSEEK_BASE_URL`/`DEEPSEEK_MODEL`/`DEEPSEEK_API_KEY`) присутствует
всегда — `enabled: true` с пустым `routes` невозможен по построению.

## Не входит в этот change

- Перенос и адаптация артефактов suite (проверка совместимости Node/cordis,
  перенос состояния circuit breaker между job'ами) — #216, отдельная задача.
- Импорт Anthropic OAuth-аккаунтов в ephemeral job (`dsh-anthropic-pool add`)
  — плагин монтируется, но автоматический импорт учёток не реализован
  здесь; см. #216.
- Цепочка переходов между ПРОВАЙДЕРАМИ на уже существующих секретах
  (`vars.DSH_PROVIDER_KEY_SECRET`, индексация `secrets[vars.X]`) — смежная
  задача (#160/#716), не дублируется и не конфликтует: тот механизм выбирает
  ОДИН активный провайдер целиком, этот — маршрутизирует МЕЖДУ несколькими
  одновременно подключёнными учётками через combo-router.
