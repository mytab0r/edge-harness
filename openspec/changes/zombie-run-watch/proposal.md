# zombie-run-watch: сторож зомби-прогонов PR-чеков — queued с нулём job'ов, переэмиссия close→reopen (#1106)

Задача: #1106. Дельта-спека: [specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).
Развилка решений: [design.md](design.md).

## Зачем

Прогоны обязательных PR-чеков иногда застревают `status=queued` с
`jobs.total_count: 0` НАВСЕГДА — job'ы не материализуются вовсе. Это не
очередь раннеров (там job'ы есть, класс #1115/#1176) и не
concurrency-очередь (у repo-ci/pr-review/secret-scan/codeql её нет):
`gh run rerun` отказывает («This workflow is already running» — run числится
живым), PR стоит без единого сигнала, red-check-алертам ловить нечего.

Живой замер (2026-09-14, issue #1106): `GET /actions/runs?event=pull_request
&status=queued` вернул ровно 8 таких прогонов — все 8 required-чеков
PR #1088 (head `9a75c414`, созданы 2026-09-13T08:46:40Z). Живой случай
обошли руками (`gh pr close && gh pr reopen` — переэмиссия `pull_request`-
событий, head SHA не меняется); старые 8 run-объектов остались `queued`
навсегда и остаются в репозитории до сих пор — это ключевой факт для дедупа.

## Что делается

Периодический сторож `.github/workflows/zombie-run-watch.yml` (cron `*/15`)
→ `scripts/orchestra/zombie_run_watch.py`:

- снимает queued PR-прогоны одним вызовом; кандидаты — старше 15 минут
  (обоснование порога — докстринг модуля: живой прогон создаёт первый job
  через ~1 секунду);
- сопоставляет только с ТЕКУЩИМ head ОТКРЫТОГО PR; отбраковывает
  легитимное ожидание concurrency-группы (см. design.md);
- подтверждает зомби нулём job'ов и РОВНО один раз на `head_sha` применяет
  газ — close→reopen под PAT владельца (`GH_PIPELINE_PAT`): события от
  `GITHUB_TOKEN` не зажигают новые workflow-прогоны (класс #18/#929/#955);
- рецидив на прогонах, созданных ПОСЛЕ переэмиссии, — эскалация
  (issue #120 + Telegram), не повторный retry; переэмиссия вхолостую
  (ни одного нового прогона на head) — тоже эскалация;
- все формы отказа различены и не глушат газ молча (докстринг модуля,
  «Порядок действия»).

## Тормоза и газ

Тормоз здесь один — сам газ деструктивнее обычного (close→reopen
перепрогоняет ВСЕ обязательные чеки PR), поэтому: одна попытка на
`head_sha` (дедуп-маркер `[zombie-run-watch: переэмиссия <sha8>]`, автор
фильтруется `trusted_login=EVENT_ACTOR_LOGIN`), запасной носитель маркера
в #120 на случай отказа записи отчёта, повтор газа запрещён — рецидив и
вхолостую-переэмиссия уходят человеку эскалацией. Эскалация, не доставленная
ни одним каналом, красит прогон (fail loud). Сбой первичного чтения
(список queued-прогонов) красит прогон; периферийный сбой на одном PR —
⚠️-наблюдение, PR остаётся на следующий пульс.

## Отвергнутые варианты

В `docs/research/30-rejected-alternatives.md` класс отсутствует. Отвергнуто
по ходу (подробности — design.md): шаг внутри `orchestra.yml` (общий
fail-domain с очередью слияний); повторный `gh run rerun` (API отказывает);
исключение workflow с concurrency-группами из газа целиком (2 из 8 РЕАЛЬНЫХ
зомби #1106 — прогоны workflow именно с группами: класс остался бы открыт на
треть); close→reopen под `github.token` (тихий no-op, класс #18/#929/#955);
потолок цены до сопоставления с открытыми PR (permanent-зомби слитых PR
вытесняли живого, находка ревью PR #1212, круг 4).
