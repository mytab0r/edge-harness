# free-task-declared-scope: свободная задача — декларация PR, не скан прозы (#245)

Задача: #245. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

`scripts/worker/task.sh::free_task()` считал задачу «занятой», если её номер
хоть где-то встречался в теле ЛЮБОГО открытого PR (`jq 'scan("#[0-9]+")'` по
всему тексту) — тот же класс подстрочного/произвольного совпадения, что уже
чинили в `scripts/orchestra/contract_check.py` (#187, #195), только третий
экземпляр. Замер 2026-09-03: из 66 свободных по назначению задач скан ложно
занял 9 (#43, #72, #90, #119, #120, #124, #149, #153, #158) — воркеру было
доступно 50 из 66.

Второй, независимый дефект той же функции: `scheduler.py::unhealthy_pulls`
снимает исполнителя с задачи, у которой PR висит нездоровым дольше порога, и
явно велит «доработай существующий PR» — но `free_task()` исключал из пула
любую задачу с открытым PR, а `task.sh` на явном входе `--task` отказывал
довести. Задача становилась свободна в пуле и невыбираема одновременно.

Оба дефекта чинятся сменой критерия «свободна»: `openspec/specs/journal-tasks-hands.md`
пп. 26 и 28 фиксировали старое поведение как источник правды и разошлись с
кодом ещё до этого изменения (спека не менялась вместе с playbook в задаче
#89/#245) — эта дельта приводит спеку в соответствие с уже реализованным и
покрытым тестами поведением.

## Что делается

- Единственный критерий свободы задачи — `issue.assignees` пуст; открытый PR
  сам по себе больше не исключает задачу из пула (п.26).
- Объявление PR на задачу — по правилу `scripts/lib/task_ref.py::declared_tasks`
  (ПЕРВАЯ непустая строка тела, без учёта HTML-комментариев, начинающаяся с
  `#` и сразу цифрой, #251, #312), то же самое, что использует
  `contract_check.py`; вынесено в одно место правды `scripts/lib/free_task.py`,
  доступное и bash (`task.sh`), и pytest.
- Захват задачи ветвится на два режима: новая ветка `agent/N-slug` от свежего
  origin/main (нет декларирующего PR), либо доводка — чекаут существующей
  ветки уже открытого PR без исполнителя, с той же гвардией свежести базы,
  что ставит `scripts/git/task-branch` (п.28).
- Рёбейз на #121 (атомарная аренда задачи, слита в main во время доработки
  этого PR): `free_task()` в `task.sh` теперь ОДНОВременно фильтрует пул по
  `issue.assignees` (этот класс) и по живым замкам `lease_cli locks` (#121) —
  два независимых, но совместных фильтра, сведённых в `free_task.py`
  (`locked` — необязательный параметр `free_candidates`/`oldest_free`).

## Что вне рамок

- Изменение критерия «нездоровый PR» и порога `UNHEALTHY_PR_AFTER_MINUTES` —
  не трогается.
- Разведение критерия свободы между воркером и подсчётом пульса оркестратора
  (`scheduler.py` считает свободные задачи независимо от `free_task.py`) —
  отдельная задача, заведённая AI-ревью этого PR в беклог.

## Тормоз/газ: два воркера на одну задачу-с-PR

Доводка чужого PR без исполнителя — новый путь: раньше задача с открытым PR
на явном входе `--task` заканчивалась `die` (второй раз не проходило дальше
проверки), теперь `task.sh` доходит до назначения и чекаута ветки. Проверка
газа для нового пути (актуализировано после рёбейза на #121, слитый в main
17:0x 2026-09-03, пока этот PR был в работе):

- **Два прогона `worker.yml` одновременно** — исключены по построению, не
  дупгардом: `.github/workflows/worker.yml:27-29`, `concurrency: group: worker,
  cancel-in-progress: false`, введено ещё в MVP (#91, коммит `0a1c0db`) и этим
  PR не менялось. GitHub Actions гарантирует не более одного `task`-job'а этого
  workflow сразу — второй триггер (пульс, ручной dispatch) встаёт в очередь и
  видит уже назначенную задачу, когда доходит его черёд. Дупгард в начале
  `task.sh` — стопгэп на редкий нюанс очереди, не единственная защита.
- **Воркер против другого канала (`hands`/ручной claim)** — закрыто атомарным
  захватом #121: `task.sh` шаг 4 вызывает `lease_cli claim <N>`
  (`scripts/lib/claim_task.py`), создающий серверный git-ref
  `refs/locks/task-<N>` — атомарность даёт сам GitHub (создание ref'а —
  серверная операция, повторный claim получает 422 и код возврата 1, «занята»,
  зелёный no-op). Эта дельта потребовала ребейза `free_task()` НА новый
  claim-based `task.sh`: критерий свободы теперь тройной — `issue.assignees`
  пуст (эта дельта) И задача не под живым замком (`lease_cli locks`, #121) —
  оба фильтра сведены в `scripts/lib/free_task.py`, третьей расходящейся
  копии не заведено. Гонка на выбор ОДНОЙ и той же задачи-с-PR закрыта тем же
  `claim`, что и для новой задачи: проигравший канал получает `rc=1` и
  завершается no-op ДО чекаута чужой ветки.
