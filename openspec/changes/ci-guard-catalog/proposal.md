# ci-guard-catalog: регистрация CI-гвардии — данные, не рукописный шаг (#749)

Задача: #749.

## Зачем

`.github/workflows/repo-ci.yml` — 62+ рукописных шага «Тесты…»/«Гвардия…»/
«Smoke…»/«Юнит-тесты…», и почти каждая новая гвардия дописывает свой
`- name:`/`run:` в этот общий файл. Замер issue #749 (2026-09-08, живой
`mytab0r/edge-harness`): 17 из 40 открытых PR трогают этот файл, правка
аддитивна у 16 из 17 — то есть любые два PR с гвардиями конфликтуют ПО
ПОСТРОЕНИЮ, а не случайно. Второй, независимый замер (найден при подготовке
этого change, в issue #749 не зафиксирован): отпечаток диффа для второго
гейта (`ai:ok`, PR #753) считается от патча относительно merge-base — база,
трогающая тот же файл (а `repo-ci.yml` трогает почти каждое второе
слияние), законно меняет отпечаток и обнуляет уже добытый вердикт (живой
случай — PR #711, коммиты #767/#764 оба правили `repo-ci.yml`). Файл — узкое
место пропускной способности всего конвейера, не только источник
конфликтов.

## Что делается

Каталог `scripts/ci/guards/*.sh` — один файл на гвардию. Единственный шаг
`.github/workflows/repo-ci.yml` («Каталог гвардий scripts/ci/guards —
перебор», `scripts/ci/run_guards.sh`) перебирает каталог и исполняет каждый
файл целиком; добавление новой гвардии = новый файл, без единой правки
repo-ci.yml. Форма (каталог, не манифест) обоснована в `design.md`.

Миграция — механизм + ОДНА существующая гвардия (протухшая метка `blocked`,
#334) как доказательство, плюс ДВЕ новые гвардии (регистрация механизма,
smoke самого перебора), обе добавлены без единой правки `repo-ci.yml` —
см. `design.md`, «Критерий приёмки» и коммиты PR. Остаток миграции (66
оставшихся рукописных шагов) — отдельная задача, число обязано убывать
(см. `design.md`, «Миграция остатка»).

`scripts/lib/orphan_test_guard.py` дополнен: тест, чей `pytest`/`node --test`
вызов лежит внутри файла каталога (не напрямую в workflow), засчитывается в
покрытие, только если сам перебор реально подключён к workflow — доказано
мутацией в `scripts/lib/test_orphan_test_guard.py`.

`scripts/lib/ci_guard_registration_guard.py` — гвардия на сам механизм:
статическая сверка имён рукописных шагов `job test` с замороженным
`ALLOWLIST`; новое имя вне списка (кто-то дописал гвардию рукописно вместо
каталога) красит CI. Доказано мутацией в
`scripts/lib/test_ci_guard_registration_guard.py`.
