# Дельта-спека: контракт вердикта AI-ревью (#210)

Дополняет описание конвейера (`openspec/specs/journal-tasks-hands.md`,
раздел «Конвейер (оркестратор)», в паре с `docs/decisions/0007-ai-review-gate.md`
п.4 «Контракт вердикта»).

## ДОБАВЛЕНО: rework без единой находки — нарушение контракта

18.1. Второй гейт (`ai-review.yml`, job `verdict`) считает `ВЕРДИКТ: rework`
    без единой находки НАРУШЕНИЕМ КОНТРАКТА ответа модели, симметричным
    отсутствию/неоднозначности самой строки `ВЕРДИКТ: …` — не валидным
    `ai:changes-requested`. «Находка» — любая из трёх категорий, которые уже
    различает контракт (`docs/agents/PROTOCOL.md`, п.8): проза, блокирующая
    мерж; блок `ЗАМЕЧАНИЕ` (некритично); блок `ЗАДАЧА` (вне рамок PR). Все
    три пусты одновременно → PR получает `ai:failed` вместо
    `ai:changes-requested`, тем же путём и с тем же авто-повтором (#196),
    что и любой другой формат-сбой ответа. `approve` с нулём находок этим
    правилом не затронут — одобрение без замечаний остаётся нормой.

18.2. Проверка живёт в `cmd_verdict` (`scripts/review/ai_review.py`), не в
    `parse_verdict`: последний остаётся узким парсером ТОЛЬКО машиночитаемой
    строки вердикта (approve/rework/error по форме строки) — полнота
    findings/tasks/remarks для `rework` проверяется отдельно, чистой
    функцией `rework_without_findings(verdict, findings, tasks, remarks)`,
    вызываемой уже после того, как `cmd_verdict` посчитал все три категории
    (второй разбор `answer` не заводится).

18.3. Причина `error` для этого случая — отдельное, пятое по счёту (после
    `empty_diff`/`diff_source_mismatch`/`all_providers_exhausted`/квоты-
    транспорта) состояние `error_reason(..., empty_rework=True)`: текст для
    человека называет ИМЕННО «rework без находок», не переиспользует ветки
    «строки ВЕРДИКТ нет вообще» или «есть, но не единственная/не последняя»
    — та строка в этом случае есть и однозначна, спутать причины значило бы
    соврать читателю (правило репозитория «алерт не гадает»). Тег в шапке
    комментария (`reason:`) остаётся существующим
    `review_labels.FAILURE_REASON_CONTRACT` — второй тег не заводится,
    `scheduler.py::trigger_ai_review` обрабатывает этот случай тем же путём
    бюджета автоповторов, что и любой другой contract-error.

18.4. `scripts/review/ai_prompt.md` называет это ограничение явно в тексте
    контракта: `rework` без единой находки недопустим, при отсутствии находок
    модель обязана ставить `approve`.
