# ai-review-empty-rework-contract: rework без единой находки — нарушение контракта, не ai:changes-requested (#210)

Задача: #210. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

AI-ревью (второй гейт, #18) различает `approve`/`rework`/`error` только по
машиночитаемой строке `ВЕРДИКТ: …` (`scripts/review/ai_review.py::parse_verdict`)
— полнота `rework` не проверялась вовсе. Модель может ответить одной строкой
`ВЕРДИКТ: rework` без единого замечания; такой ответ проходил как валидный
`ai:changes-requested` с пустым комментарием — ни автор PR, ни воркер не
получали сигнала, что чинить.

Живой случай прямо сейчас: PR #795 (фикс журнала #794 — критичный блокер
конвейера) залип на пустом `rework`, вернулся в пул без движения на 18+
часов. Исходный случай класса, зафиксированный при заведении #210: PR #206,
прогон `ai-review.yml` run `33656180906`, шаг «Вердикт» — весь ответ модели
`ВЕРДИКТ: rework\n`, ни одной находки, метка `ai:changes-requested` выставлена
на пустое тело.

## Что делается

- Новая чистая функция `scripts/review/ai_review.py::rework_without_findings`:
  `verdict == "rework"` И findings (проза после вычитки блоков)/tasks/remarks
  все пусты → нарушение контракта. `approve` с нулём находок НЕ считается
  нарушением (одобрение без замечаний — норма).
- `cmd_verdict` вызывает эту проверку СРАЗУ после того, как findings/tasks/
  remarks уже посчитаны (второго разбора `answer` не заводится — одно место
  правды остаётся в уже существующих `parse_tasks`/`findings_of`/
  `review_checklist.parse_remarks`), и при срабатывании переквалифицирует
  вердикт в `error` ДО простановки метки: PR получает `ai:failed`, тем же
  путём, что и любой другой формат-сбой ответа модели — красный шаг `verdict`
  (fail loud) и авто-повтор по таймеру (#196), без ручного вмешательства.
  `parse_verdict` не трогается: он остаётся узким парсером ТОЛЬКО
  машиночитаемой строки вердикта (свой контракт, см. его докстринг) —
  смешивать туда проверку полноты findings означало бы завести вторую ось
  ответственности в одной функции.
- `error_reason` получает пятое состояние `empty_rework` — отдельный,
  специфичный текст для человека («модель поставила ВЕРДИКТ: rework, но не
  привела ни одной находки»), не путается с двумя существующими ветками
  `verdict_line_present` (там причина другая — строки нет вовсе или она
  неоднозначна; здесь строка есть и однозначна).
- `scripts/review/ai_prompt.md` получает явную строку контракта: `rework` без
  единой находки недопустим, при отсутствии находок — ставь `approve`.
- Причина `reason:` в шапке комментария остаётся тегом
  `review_labels.FAILURE_REASON_CONTRACT` (не заводится новый тег) —
  `scheduler.py::trigger_ai_review` уже обрабатывает этот тег обычным путём
  бюджета автоповторов, второй копии условия не требуется.

## Проверено

- `python -m pytest scripts/review/test_ai_review.py -q` (164 тестов, 2 уже
  красных до этого изменения и не относящихся к нему — `test_redact_masks_
  model_provider_keys`/`test_redact_plain_text_untouched` падают локально из-за
  отсутствия `bash`/WSL в окружении, не из-за правки).
- `python -m pytest scripts/lib/test_review_labels.py scripts/orchestra/test_scheduler.py -q`
  — 362 пройдено, error→`ai:failed`→авто-повтор (#196) не задет.
- Мутация: убрать `if empty_rework: verdict = "error"` из `cmd_verdict` —
  `test_cmd_verdict_empty_rework_prod_form_becomes_error_not_changes_requested`
  краснеет (`rc` становится `0`, метка — `ai:changes-requested`); вернуть —
  тест снова зелёный.

## Что вне рамок

- Сам PR #795 — второй гейт для него перезапускается вручную отдельно, эта
  задача не чинит конкретный PR, только контракт.
- Изменение бюджета автоповторов (#196/#538) — не тронуто: `empty_rework`
  использует тот же существующий тег `FAILURE_REASON_CONTRACT`, второй
  бюджет не заводится.
