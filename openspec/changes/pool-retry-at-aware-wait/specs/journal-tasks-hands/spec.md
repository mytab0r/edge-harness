# Дельта-спека: пул Claude — ожидание по retryAt вместо немедленного отката (#1288)

Дополняет `anthropic-oauth-pool-standalone` («Стык с цепочкой провайдеров»)
— не меняет монтаж/аутентификацию пула, только реакцию
`dsh_run_with_pool_then_chain` на конкретную форму его отказа.

## ADDED: Разбор `retryAt` из тела `pool_unavailable`

Требование: `_dsh_pool_retry_at_wait_secs` (`scripts/lib/dsh-ci.sh`)
принимает файл stderr неудавшейся попытки пула и возвращает (код возврата
0, значение на stdout) количество секунд до заявленного пулом момента
возврата, ЕСЛИ И ТОЛЬКО ЕСЛИ тело ответа — валидный JSON с
`(.error.type // .type) == "pool_unavailable"` и числовым
`(.error.retryAt // .retryAt)` (миллисекунды с эпохи). Любая другая форма
(не JSON, другой `type`, `retryAt` отсутствует/`null`/не число) — код
возврата 1, вызывающий трактует это как «ответ не разобран».

## ADDED: Три исхода отказа пула вместо одного

Требование: `dsh_run_with_pool_then_chain` при неудаче попытки пула
(`dsh_run_with_retry` вернула `rc != 0`) действует по одному из трёх путей:

1. **Ответ не разобран или тип не `pool_unavailable`** — поведение
   идентично состоянию ДО этого change: один `::warning::` с фактом отказа
   (rc + первые 200 символов stderr, `redact()`), немедленный откат на
   `dsh_run_with_provider_chain`.
2. **`pool_unavailable`+`retryAt`, момент в пределах остатка бюджета
   ожидания** (`DSH_POOL_RETRY_AT_MAX_WAIT_SECS`, по умолчанию 300с,
   СУММАРНЫЙ за весь вызов функции, не за одну попытку) — `::warning::`
   называет факт и величину ожидания, `sleep` на названное число секунд
   (отрицательное или нулевое значение — момент уже прошёл — не ждём),
   повтор попытки пула (не переход на цепочку). Повтор может вернуть НОВЫЙ
   `retryAt` — цикл продолжается, пока остаток суммарного бюджета это
   позволяет.
3. **`pool_unavailable`+`retryAt`, момент дальше остатка бюджета
   ожидания** — `::warning::` честно называет и факт retryAt, и превышение
   бюджета (не молчит про наличие поля, не путает с исходом 1), немедленный
   откат на цепочку без ожидания.

Во всех трёх путях суммарное время ожидания RATE_LIMIT внутри
`dsh_run_with_retry` по ВСЕМ попыткам пула (исходное поведение — #877/#880)
накапливается в `pool_rl_used` и передаётся в `dsh_run_with_provider_chain`
как `initial_rl_used`, как и раньше.

## Честная граница

`retryAt` — заявление пула, не гарантия: пул может ошибиться, отдать время
в прошлом (тогда повтор происходит немедленно) или подряд несколько
`retryAt`, каждый из которых по отдельности близок, но в сумме превышают
бюджет ожидания (цикл останавливается на первом же превышении ОСТАТКА
бюджета, не бюджета заново на каждый повтор). Функция никогда не ждёт
дольше `DSH_POOL_RETRY_AT_MAX_WAIT_SECS` суммарно — превышение всегда
оканчивается откатом на цепочку, не бесконечным ожиданием.
