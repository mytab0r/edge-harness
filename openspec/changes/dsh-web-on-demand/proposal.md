# dsh-web-on-demand: полноценный DSH web UI по требованию

Задача: #75. Родитель: [dsh-in-job](../dsh-in-job/proposal.md) — руки уже поднимают
полноценный DSH на раннере; этот change открывает к нему окно владельца.
Смежное: [design](design.md), [задачи](tasks.md).

## Зачем

Морда dsh-edge живёт всегда, но она не desktop-ранг: плагины в неё не подключаются
в принципе ([research/11](../../../docs/research/11-dsh-edge.md), «Подключение
сторонних плагинов: механизма нет»), шелл — `just-bash`, не Linux; установка плагинов
и полноценное управление провайдерами через UI — десктопные возможности web-профиля
DSH, и в харнесе сейчас нет ни одного места, где этот ранг запускается.

Класс ошибки, который закрывает change: **«возможность платформы есть — а места,
где она доступна, нет»**. Морда это не чинит и не должна: её сила — всегда-живой
лёгкий канал, а не полнота ранга.

Решение: руки слайса 1 уже умеют ставить DSH tarball'ами и запускать его на раннере.
Этот change добавляет к рабочей сессии окно: `dsh --profile web` в job'е, раннер
присоединяется к tailnet владельца эфемерным узлом через официальный
[tailscale/github-action](https://github.com/tailscale/github-action), владелец
открывает UI по tailnet-адресу. `~/.dsh` (плагины, настройки, сессии) переживает
job'ы через GH Actions cache. Лёгкий чат dsh-edge остаётся мордой между сессиями —
это **дополнение, не замена**.

## Проверка против отвергнутых вариантов

Каждый пункт — из [30-rejected-alternatives](../../../docs/research/30-rejected-alternatives.md),
с условием возврата:

- **#2 «морда живёт только внутри job»а» (возврат: никогда).** Морда не переезжает.
  Журнал, очередь и лёгкий чат остаются на Workers и живы всегда; в job поднимается
  не морда, а **рабочее место desktop-ранга на время сессии**. Сценарий «зайти, когда
  рук нет» по-прежнему закрывается мордой — отвергнутый вариант предлагал инверсию
  цели, здесь цели инверсии нет.
- **#3 «WebSocket-туннель DO → долгоживущий job» (возврат: self-hosted runner или
  платный CF).** DO в цепочке не участвует вовсе: UI ходит напрямую в tailnet, CF не
  тратит ни запроса, ни GB-s. Обе причины отказа (ToS-чтение про idle-туннель + 85 %
  дневного бюджета) не возникают, условие возврата не требуется.
- **#12 «ловушка Remote & Mobile».** Tailscale здесь — транспорт доступа к харнесу,
  который **реально исполняет работу на раннере**, а не подмена удалённого исполнения
  плагинами доступа.

Различие с #3 по ToS-части разобрано в [design](design.md), «Правовая рамка».

## Что делает (фаза 1 — этот change)

Исследование + дизайн. Артефакты: факты о web-профиле из tarball'а `@deepseek-ai/dsh`
0.1.1-rc.2 (первоисточник), факты о tailscale action / ephemeral-узлах / `tailscale serve`,
факты о GH Actions cache — всё в [design](design.md); план реализации — в
[tasks](tasks.md). Реализация — следующий слайс после ревью владельца.

## Вне рамок

- Интерактивность задач из морды и контракт dsh-headless — не меняются.
- dsh-edge и его плагинный конвейер — не трогаются.
- Всё, что стоит денег, не строится: standard-раннеры публичного репозитория
  бесплатны ([research/21](../../../docs/research/21-github-actions.md)), эфемерные
  узлы tailnet бесплатны в рамках плана владельца (точная месячная квота минут —
  «не подтверждено», см. design).
