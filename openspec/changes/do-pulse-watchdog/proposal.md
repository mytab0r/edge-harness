# do-pulse-watchdog: сторож живости независимого DO-пульса оркестратора (#689)

Задача: #689. Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Боль владельца

Независимый пульс оркестратора (Cloudflare Durable Object,
`cf-worker/src/harness.ts::alarm()`, диспатч через `GH_DISPATCH_TOKEN`) может
умереть неограниченно долго, и по построению узнать об этом некому — если
пульс молчит, некому и позвать на помощь.

## Замер (2026-09-07, живой `gh api repos/:owner/:repo/actions/workflows/orchestra.yml/runs`)

За 2026-09-07 у `orchestra.yml` 73 прогона `workflow_dispatch`. Разбивка по
`triggering_actor.login`: подавляющее большинство — `github-actions[bot]`
(событийный вейк ADR 0012, `scripts/gh/wake_orchestra.sh`, зовут
`pr-review.yml`/`ai-review.yml` с `GH_TOKEN: ${{ github.token }}`), считанные
единицы — владелец `GH_DISPATCH_TOKEN` (независимый DO-пульс,
`attemptOrchestraDispatch`). Живой пример разрыва того же дня: независимый
канал не тикал с `2026-09-07T04:51:45Z` до как минимум `08:53:29Z` (4 ч 8
мин), пока событийный канал тикал каждые 5-15 минут — конвейер держался
только на нём. Ожидаемая частота DO-пульса — тик каждые 15 минут
(`HEARTBEAT.selfOrchestrationMs`) — фактическая случается на порядок реже.

Прецедент того же класса уже документирован в коде: `real_orchestra_ticks`
(`pulse_guard.py`) описывает разрыв 2026-09-05, когда DO-пульс
(`workflow_dispatch`) не создавал ран `orchestra.yml` с 04:35 до 14:24
(~9ч49м), а `heartbeat_check` не закричал ни разу — `pull_request`-прогоны
`contract` маскировали смерть job'а `orchestra` целиком. Этот change чинит
СЛЕДУЮЩИЙ слой той же маскировки: ВНУТРИ одного канала `workflow_dispatch`
два разных источника (событийный и DO) неразличимы для существующего
`heartbeat_check`.

## Причина (не чинится этим change)

`cf-worker/src/harness.ts:1119-1144` (`alarm()`): если обе попытки
`ctx.storage.setAlarm` падают (например исчерпание суточной квоты
rows_written, класс #320), функция выходит без нового будильника —
комментарий в коде сам называет это «цепочка пульса встала до пересоздания
DO». Восстановление — только `#ensureHeartbeat()`, вызываемый из конструктора
DO, то есть требует внешнего трафика к объекту. Трафика нет — мертво
неограниченно долго. Починка самого `alarm()` требует второго независимого
будильника вне DO — отдельная, более дорогая задача. Здесь — только
ВИДИМОСТЬ факта: работающий канал (событийный) следит за мёртвым
(независимым).

## Граница с #519/#522 (не дубль)

Issue #519 и PR #522 — сторож ОБРАТНОГО направления: `event_wake_check`
проверяет, что событийный будильник (`wake_orchestra.sh`) сработал после
завершения ai-review/pr-review (образцовый случай #510, бит исполнения).
Ревью PR #522 (находка №2) само отмечает, что тот сторож не может отличить
тик `wake_orchestra.sh` от тика DO-пульса (оба — один и тот же
`event=workflow_dispatch`), и предлагает разводить каналы по
`triggering_actor.login` — тот же признак, что нужен здесь, но для ОБРАТНОЙ
проверки: не «событийный канал жив», а «независимый канал жив, пока
событийный маскирует его смерть». Разные направления одного признака —
не дублируют друг друга; #522 своей веткой не тронут.

## Что делается

`scripts/orchestra/pulse_guard.py::independent_pulse_check` (вызывается из
`scheduler.main()` сразу после `heartbeat_check`):

- Признак — `triggering_actor.login` прогонов `orchestra.yml` с
  `event=workflow_dispatch`: `github-actions[bot]` (`EVENT_ACTOR_LOGIN`) —
  событийный канал; любой другой логин — независимый DO/ручной канал.
  Хардкодить логин владельца токена нельзя (может смениться) — признак
  устойчивее как «актор НЕ бот-событие».
- Применимость (`decide_independent_pulse`): сигнал только когда событийный
  канал сам подтверждён свежим (не старше `INDEPENDENT_PULSE_STALE_AFTER_MINUTES`
  = 60 = 4 такта DO-пульса — на такт шире симметричного `EVENT_WAKE_STALE_AFTER_MINUTES`,
  потому что цена ложной тревоги здесь выше). Честная граница: если
  оркестратор вообще не диспатчился недавно, отличить «независимый канал
  умер» от «PR-активности просто нет» по этим данным нельзя — тревога не
  заводится, докстринг называет это прямо.
- Сигнал: канал `escalate()` (комментарий в задачу-статус #120 + Telegram),
  дедуп парой маркеров (`DO_PULSE_MARKER`/`DO_PULSE_RESUMED_MARKER`, приём
  `episode_reopened`, тот же, что у `heartbeat_check`). Текст называет
  последствие в часах («независимый пульс не приходил N ч, конвейер держится
  только на событийном канале и встанет, как только прекратится активность
  PR»), не внутреннее состояние.
- Если ни одного независимого прогона в изученной выборке нет вовсе — anchor
  берётся от самого старого прогона выборки (нижняя граница, `exact=False`):
  текст явно помечает это как «как минимум», не выдавая приближение за точное
  число (правило «алерт не гадает»).
- Газ: DO-дисптачи возобновились (снова найден прогон не от
  `EVENT_ACTOR_LOGIN`) — эпизод закрывается автоматически тем же пульсом,
  который его обнаружил, без внешнего вмешательства.
- Цена: 1 запрос `recent_runs` на КАЖДЫЙ пульс (тот же порядок, что уже
  платит `heartbeat_check` за оба легитимных события) — не заводит нового
  постоянного сетевого канала.

## Чем доказано

`scripts/orchestra/test_pulse_guard.py` (прод-форма — реальный `gh api
.../orchestra.yml/runs?event=workflow_dispatch` 2026-09-07, разрыв
04:51:45→08:53:29): чистое решение `decide_independent_pulse` (применимость/
порог/нижняя граница при пустой выборке независимых тиков/мутация «порог —
одна константа»), проводка `independent_pulse_check` на моке `gh` (holостой
ход — 1 вызов; эскалация на прод-форме реального разрыва с точным числом
часов в тексте; дедуп эпизода; закрытие эпизода при возврате независимого
тика). Три направленные мутации (escalate подавлен / dedup снят / gating
applicability снят) — все три красят соответствующий тест, снятие мутации
возвращает зелёный (см. tasks.md).

## Что вне рамок

- Починка `cf-worker/src/harness.ts::alarm()` (второй независимый будильник
  вне DO, ретраи `setAlarm`) — отдельная, более дорогая задача.
- #519/#522 (событийный будильник) — смежная, не тронута.
