# Дельта-спека: Telegram-отчёт воркера и оркестратора (#170)

Расширяет `openspec/specs/journal-tasks-hands.md`: уточняет п. 29
(«Автономный воркер») и раздел «Конвейер (оркестратор)» (последствия
слияния, п. 18). Сложен в базовую спеку одновременно с реализацией (#170).

## MODIFIED: итог запуска воркера — что именно говорит Telegram (п. 29)

Требование: Telegram-отчёт воркера об открытом PR НЕ употребляет слова
«выполнена» — открытый PR промежуточный шаг, и это слово в Telegram значит
ровно одно: задача слита в main. Отчёт воркера: «PR открыт — #M по задаче
#N «заголовок»», где заголовок усечён до первых 6 слов.

Требование: ВСЕ Telegram-сообщения репозитория отправляются с
`parse_mode=HTML`. Отправителей два — `telegram_report`
(`scripts/worker/task.sh`) и `pulse_guard.send_telegram`; новый
отправитель не заводится, второй канал не создаётся (тот же принцип, что
#119/#174: канал решения один). Динамические части текста (заголовок
задачи, причина сбоя) экранируются до отправки: при `parse_mode=HTML`
символы `<`, `>`, `&` управляющие, и неэкранированный заголовок развалил
бы доставку всего сообщения.

Сценарий: воркер открыл PR по задаче «Telegram: отчёт врёт & молчит» →
в чате короткое сообщение, номера задачи и PR кликабельны, заголовок
показан как текст, слово «выполнена» отсутствует.

## ADDED: Telegram о слиянии в main — after_merge

Требование: слияние PR в main — событие, о котором Telegram сообщает
отдельным сообщением: «задача #N выполнена — слито в main: #M
«заголовок»». Отправляет `scheduler.after_merge` через общий
`send_telegram`; слово «выполнена» допустимо только здесь, на факт
слияния. Один PR = одно сообщение (по первой подтверждённой задаче из
тела), даже если тело упоминает несколько задач.

Требование: сообщение best-effort, как весь канал (#120): место правды —
комментарий в задаче; недоставка не откатывает мерж и не красит прогон,
но и не молчит — ⚠️-строка в отчёте прогона.

Сценарий: оркестратор слил PR #405 (задача #170) → в чате появляется
сообщение про «слито в main» с кликабельными #170 и #405; недоступный
Telegram оставляет ⚠️ в отчёте и не ломает остальные действия
after_merge.
