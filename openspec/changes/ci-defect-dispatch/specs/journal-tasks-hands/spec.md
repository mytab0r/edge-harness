# Дельта-спека: журнал (journal-tasks-hands) — немедленный адресный диспетч починки дефектов CI (#552)

Реализация: `scripts/orchestra/scheduler.py::dispatch_defect_rework`, вызывается
из `main()` перед `dispatch_conflict_rework`. Строится поверх ADDED-требований
`openspec/changes/failure-watch/specs/journal-tasks-hands/spec.md` (#477).

## ADDED: Немедленный адресный диспетч починки дефектов CI

Требование: задача, заведённая `failure_watch` (метка `FAILURE_WATCH_LABEL`),
ещё без исполнителя и без метки `blocked`, получает адресный
`workflow_dispatch worker.yml` (`inputs[task]=N`) тем же пульсом, где
предохранитель конвейера (#120) не занят и активного worker-рана нет —
раньше расшивки конфликтов (#474) и обычного подбора новой задачи.

Требование: WIP-лимит (#464) на этот адресный прогон не распространяется —
проверка не читает его вердикт вовсе, симметрично с `dispatch_conflict_rework`.

Требование: предохранитель конвейера (`conveyor_gate`) — единственный тормоз,
гасящий этот путь целиком: если он уже держит паузу, повторного дефект-диспетча
в этом же пульсе нет (тот же класс «сам worker.yml нездоров», что уже держит
`dispatch_conflict_rework`).

Требование: ровно один `workflow_dispatch worker.yml` за пульс — если
дефект-диспетч этим проходом уже дёрнул воркера, ни расшивка конфликтов, ни
обычный `dispatch_worker` вторично его не зовут.

Требование: ровно одна авто-попытка на задачу (`DEFECT_DISPATCH_MAX_ATTEMPTS`
= 1, маркер-комментарий на самой задаче). Исчерпана, задача всё ещё открыта,
без исполнителя и без `blocked` — эскалация владельцу (комментарий в #120 +
Telegram), идемпотентная по номеру задачи; повторной эскалации по той же
задаче не шлём.

Требование: задача с меткой `blocked` (воркер сам эскалировал по
WORKER-PLAYBOOK — не смог починить своими силами) дефект-диспетчем не
трогается — не переэскалирует и не диспетчит повторно.

Сценарий: `failure_watch` заводит задачу «CI: hands.yml падает — task»
(метки `task` + `ci-failure`), она ещё без исполнителя — тем же пульсом уходит
`workflow_dispatch worker.yml` с `inputs[task]=<номер>`; WIP-гейт в этот
момент закрыт (25 PR ждут доработки при лимите 12) — диспетч всё равно
уходит.

Сценарий: адресный дефект-диспетч отработал (маркер попытки на задаче есть),
воркер не открыл PR и снял с себя назначение (задача снова открыта и без
исполнителя, не `blocked`) — следующий пульс видит исчерпанный бюджет попыток
и вместо повторного диспетча эскалирует владельцу с фактом «автопочинка не
справилась».

Сценарий: воркер по адресному диспетчу решил по WORKER-PLAYBOOK, что чинить
нечего его силами, оставил комментарий и метку `blocked` — следующий пульс
эту задачу не трогает вовсе (ни диспетча, ни второй эскалации).
