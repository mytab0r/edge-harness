# Дельта-спека: журнал (journal-tasks-hands) — проверки на входе (#357)

Дополняет п.18 (стадия приёмки, #227) и п.28 (захват задачи воркером, #121) —

## MODIFIED: Конвейер (оркестратор)

18. Ключевые слова авто-закрытия (`Closes|Fixes|Resolves #N`) в теле PR
    запрещены: контракт отклоняет такой PR (GitHub закрыл бы задачу при
    слиянии) — мерж доказывает PR, а не готовность задачи (кейс #56/#57).
    Закрытие идёт стадией приёмки (#227): каждый прогон планировщика
    сопоставляет открытые задачи пула со слитыми PR, которые их ОБЪЯВЛЯЮТ
    (первая строка тела), и решает по проверяемой улике, вид которой зависит
    от состава изменённых файлов слитого PR (деплой/скрипт/документация, три
    исхода — закрыта/не закрыта с причиной/эскалация поломки возможности).

    **Проверка на входе перед закрытием (#357):** улика относится к ОДНОМУ
    слитому PR — этого недостаточно, если задачу ПРЯМО СЕЙЧАС объявляет ещё
    один открытый PR (`task_ref.resolve_pr_task` по свежему снимку открытых
    PR прогона). Живой случай: приёмка закрыла #320, пока по нему был открыт
    второй PR #325 — тот немедленно упал на contract. Найден такой PR →
    задача не закрывается, в отчёт идёт строка «приёмка отложена», следующий
    прогон проверит снова.

## MODIFIED: Автономный воркер

28. Захват задачи воркером — атомарная аренда (ADR 0006, #121):
    `scripts/lib/claim_task.py claim` серверно создаёт замок
    `refs/locks/task-N` и тем же вызовом ставит назначение и след в задаче.
    Назначение — видимость, а не защита; защита от гонки каналов — замок,
    проигравший гонку получает отказ. Работа идёт в ветке `agent/N-slug` от
    свежего origin/main (вход — `scripts/git/task-branch`); если на задачу
    уже открыт PR без исполнителя, воркер доводит его ветку, второй PR не
    открывает (#245).

    **Проверка на входе перед арендой и перед веткой (#357):**
    `claim_task.py::claim` перед созданием коммита/ref'а замка запрашивает
    состояние задачи — `state != "open"` или метка `blocked` отклоняет аренду
    тем же зелёным no-op, что и «занята» (fail loud остаётся за настоящими
    сбоями сети/API, не за «закрыта»/«заблокирована»). Проверка `blocked`
    нужна именно здесь, а не только в `task-branch`: hands (`dsh_task.sh`) не
    проходят через `task-branch` вовсе, единственные их ворота — `claim`.
    `scripts/git/task-branch` перед `git switch -c`
    проверяет: задача существует, открыта, несёт метку `task`, не несёт
    `blocked` — иначе отказ с внятной причиной, ветка не заводится. `gh`
    недоступен (не установлен либо транспортная сетевая ошибка, не HTTP-код)
    — только предупреждение, ветка заводится непроверенной: агент без сети
    не может спросить GitHub вообще, а полный отказ работать обходится
    дороже непроверенной ветки. Явный HTTP 404 (задачи точно нет) — всё
    равно отказ, это не офлайн-случай.
