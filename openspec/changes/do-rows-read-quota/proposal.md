# do-rows-read-quota: heartbeat не сканирует всю историю tasks

Задача: #320. Факт: письмо Cloudflare 2026-09-03 — суточная квота DO
`rows_read` (5 000 000) исчерпана; пульс оркестрации (`cf-worker/src/
harness.ts::alarm`) не бился с 04:35 UTC 2026-09-05 — меньше 5 часов после
полуночного сброса того же дня. Раньше молчание пульса списывалось на egress
403 (#133, гипотеза) — письмо даёт измеренную причину.

## Причина

`#status()` вызывается на каждый heartbeat от job (раз в `HEARTBEAT_SECS`=20 с,
`scripts/hands/dsh_task.sh`) и на каждый принятый батч событий. Внутри — два
запроса без ограничения по объёму данных, оба гоняют ВСЮ таблицу `tasks`
(ретеншена для неё нет, растёт вечно):

1. `SELECT status, COUNT(*) FROM tasks GROUP BY status` — полный скан ради
   агрегата, который меняется только записью, а не течением времени.
2. `SELECT COUNT(*), MIN(dispatch_ts) FROM tasks WHERE status='dispatched'
   AND dispatch_ts < ?` (watchdog #7) — без индекса читает всю таблицу, хотя
   интересующее подмножество («сейчас dispatched») всегда маленькое.

## Решение

1. Индекс `tasks(status, dispatch_ts)` — watchdog-запрос сводится к текущим
   dispatched-строкам вместо всей истории.
2. In-memory кэш агрегата счётчиков по статусу в `Harness`, инвалидируемый
   ТОЛЬКО записью в `tasks` (создание задачи, dispatch, `job_start`,
   `job_end`) — корректно, поскольку агрегат не зависит от времени (в отличие
   от watchdog-запроса, который обязан читаться заново на каждый вызов).
3. Ошибка хранилища DO, похожая по тексту на исчерпание квоты (rows_read/
   rows_written), получает собственный код ответа `storage_quota_exceeded`
   вместо общего `internal` — эвристика по ключевым словам, точный текст
   исключения workerd не подтверждён (docs/research/20, «Что не
   подтверждено»).
4. `alarm()` целиком обёрнут в try/catch (включая первую строку — переустановку
   будильника): раньше падение там уходило из хендлера непойманным и не
   оставляло даже строки в логе. Ветка `main` за время работы над этим change
   получила отдельную фичу отслеживания пульса (issue #269/#303: таблица
   `pulse`, `#getStoredPulse`/`#recordPulse`) — она тоже читает/пишет SQLite и
   тоже может упасть на исчерпанной квоте, поэтому try/catch расширен на весь
   путь дозвона до оркестратора, а не только на `setAlarm`.

## Дельта-спека

`openspec/specs/journal-tasks-hands.md`, разделы «Watchdog зависших задач» и
«Аутентификация»/коды ошибок — расширены требованиями об устойчивости
агрегатов статуса к росту `tasks` и о классификации ошибок хранилища.

## Что вне рамок

- Ретеншн/удаление старых строк `tasks` (тот же класс, что открытые #306/#305
  для `events`/`messages`) — снял бы проблему у корня, но требует отдельной
  политики удаления; не делаем в этом change.
- Троттлинг heartbeat реже 20 с — контракт клиента рук не трогаем без нужды,
  кэш уже закрывает основной объём чтений.
- Подтверждение точного текста ошибки квоты от workerd — нет доступа к живому
  отказу вне окна, когда это уже произошло; помечено «не подтверждено».
