# Дельта-спека: устойчивость к квоте rows_read (#320)

Расширяет `openspec/specs/journal-tasks-hands.md`: подраздел в «Watchdog
зависших задач» (после п.14.3) и новое требование к кодам ошибок (рядом с
п.5).

## ADDED: агрегаты статуса не растут вместе с историей `tasks`

14.4. Запрос watchdog-порога (`status.stale_dispatch`) обязан читать только
подмножество задач в текущем статусе `dispatched`, а не всю таблицу `tasks` —
обеспечено индексом по `(status, dispatch_ts)`. Требование протестировано тем
же приёмом, что 14.3 (состаривание задачи через SQL DO), — стоимость выборки
не оговаривается числом, но watchdog должен видеть зависшую задачу независимо
от объёма истории.

14.5. Агрегат «сколько задач в каждом статусе» (`status.tasks`) не пересчитывает
всю таблицу `tasks` на каждый вызов `/api/status`/heartbeat — он меняется
только фактической записью (создание задачи, dispatch, `job_start`, `job_end`),
и обязан отражать эти переходы немедленно после каждого из них.

Сценарий: Дано — задача создана (`queued`). Когда — приходит событие
`job_start`, затем `job_end`. Тогда — `status.tasks.queued` уменьшается на 1,
`status.tasks.running` сначала растёт на 1 и затем уменьшается на 1,
`status.tasks.done` растёт на 1 — на каждом шаге, без задержки и без
устаревания на предыдущем значении.

## ADDED: ошибка хранилища, похожая на исчерпание квоты, названа отдельным кодом

5.1. Любая необработанная ошибка внутри DO, текст которой указывает на
исчерпание суточной квоты DO SQLite (`rows_read`/`rows_written`, письмо
Cloudflare — см. `docs/research/20-cloudflare-free.md`), отвечает кодом
`storage_quota_exceeded`, а не общим `internal`. Точная форма исключения
workerd не подтверждена доками — классификация эвристическая (по ключевым
словам), это не гарантия распознавания каждого случая, а замена молчания
на попытку назвать причину.

Сценарий: Дано — DO SQLite вернул исключение с текстом, содержащим
`rows_read`. Когда — ошибка дошла до общего catch `#fetch()`. Тогда — ответ
API — 500 с `error.code = "storage_quota_exceeded"`, а не `internal`.
