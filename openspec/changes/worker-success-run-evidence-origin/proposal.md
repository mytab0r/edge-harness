# worker-success-run-evidence-origin: критерий успеха воркера учитывает origin, не только локальный HEAD (#935)

Задача: #935. Регрессия на
[`worker-success-run-evidence`](../worker-success-run-evidence/proposal.md) (#876/#878). Дельта-спека:
[specs/journal-tasks-hands/spec.md](specs/journal-tasks-hands/spec.md).

## Зачем

За ночь 2026-09-11 восемь провалов воркера из восьми — один класс, задачи разные, отравленной
задачи нет. Дословная сигнатура (пример из прогона 34550467839):

```
##[error]Воркер не справился: PR https://github.com/mytab0r/edge-harness/pull/412 по ветке agent/407-worker (merged) существует, но не доказывает работу этого прогона: новых коммитов в ветке за этот прогон нет
```

Хотя коммиты БЫЛИ — просто на origin, не в локальном чекауте воркера.

## Корень

`scripts/lib/dsh-ci.sh::dsh_worker_run_is_success` (#876/#878) требовал `branch_start_sha !=
branch_end_sha`, где обе точки — `git rev-parse HEAD` ЛОКАЛЬНОГО чекаута воркера. Локальный
чекаут доводки PR — линкованный git worktree (`$PR_WORKTREE`, `scripts/worker/task.sh:424-450`),
чей admin-каталог (`.git/worktrees/<name>/`) лежит СНАРУЖИ рабочего дерева, в общем commondir.
Файловая песочница dsh (workspace-write) блокирует запись именно туда — подтверждено дословно
текстом самого DSH в логах воркера:

- прогон 34578536716 (08:53:38Z): «разделяемый `.git` главного чекаута оказался закрыт на
  запись файловой песочницей (канал аппрувов недоступен — отказ финален)».
- прогон 34559273918 (03:59:14Z): «локальный worktree был заперт песочницей на запись в общий
  `.git` (эскалация недоступна: канал аппрувов отсутствует)».
- прогон 34557341675 (03:37:11Z): «DSH-песочница (workspace-write) запретила запись в общий
  git-dir вне workspace, эскалация недоступна (нет канала аппрува)».

Агент обходит блокировку отдельным клоном и пушит напрямую в origin. Работа доезжает (пример
34550467839: PR #412 слит в 02:52Z, в рамках этого же прогона), но локальный HEAD воркера не
двигался → гейт #876/#878 видел «нет новых коммитов» и красил job.

Подтверждение от обратного: прогоны 34578536716 и 34581660543, где агент перенёс `.git`
внутрь того же пути (standalone на месте вместо linked worktree), локальный SHA сдвинулся, и
гейт прошёл штатно.

## Что делается

- `scripts/worker/task.sh` — снимает снимок головы ветки на origin (`git ls-remote origin
  refs/heads/$BRANCH`) ДО и ПОСЛЕ запуска dsh, теми же точками, что и локальный
  `WORKER_BRANCH_START_SHA`/`WORKER_BRANCH_END_SHA`.
- `scripts/lib/dsh-ci.sh::dsh_worker_run_is_success` — третий конъюнкт «есть новый коммит»
  теперь: локальный HEAD сдвинулся ИЛИ голова ветки на origin сдвинулась. Предсуществующий
  PR, чью ветку прогон не тронул НИ локально, НИ на origin, остаётся провалом — регрессия,
  которую закрывал #878, не возвращается.
- Текст `DSH_WORKER_RUN_GATE_GAPS` для этого конъюнкта называет ОБА факта (состояние
  локального HEAD и состояние ветки на origin), не общую фразу — «алерт не гадает».

## Проверено

- `bash scripts/lib/test/dsh-worker-success-gate.smoke.sh` (реестр гвардий
  `scripts/ci/guards/worker-success-gate-guard.sh`) — 10 сценариев зелёные, включая три новых:
  «origin ушёл вперёд, локальный HEAD не двигался» (успех), «ничего нигде не менялось, PR
  предсуществовал» (провал), «PR слит этим прогоном» (успех). Мутация (снять origin-часть
  признака) красит именно сценарий 7 (форма регрессии #878) — до фикса красный, после —
  зелёный.
- `python -m pytest scripts/lib/test_pr_outcome.py -q` — не задет, зелёный.

## Правка по ai-review PR #937

Блокирующая находка: обе строки `git ls-remote origin ...` в `scripts/worker/task.sh` были
голыми подстановками под `set -euo pipefail` — отказ сети/API на них роняет весь job без
`::error::`, без `WORKER_TASK_FAILURE_REASON`, без отчёта (соседние сетевые чтения того же
файла, `gh pr list`/`gh issue view`, уже несли `|| die "... (gh/сеть)"`, эти две — нет). На
END-снимке (после `dsh`, до слива транскрипта в морду) отказ был особенно дорог: убивал job
ДО того, как ход работы этого прогона попадал в морду.

Правка: обе строки несут `|| die "не смог снять снимок головы ветки $BRANCH на origin
(git/сеть)"`; END-снимок перенесён НИЖЕ блока слива транскрипта (`dsh_edge_stop_drain` →
`dsh_edge_drain_spool` → рендер) — точка измерения не меняется (между концом `dsh` и новым
местом строки в ветку никто не пишет), но при отказе сети транскрипт уже доставлен и
проверен, теряется только гейт успеха/шаг 8. Гвардия класса «сетевой снимок без `|| die`» —
`scripts/lib/test_worker_network_snapshot_guard.py` / `scripts/ci/guards/
worker-network-snapshot-guard.sh`, доказана мутацией (снятие `|| die` красит тест).

## Что вне рамок

- Класс «`git rebase`/`commit --amend` двигают HEAD без нового контента» (`#910`, пункт 4;
  находка ai-review PR #880) — origin-признак его тоже не закрывает: ребейз меняет SHA и на
  origin после пуша. Не подтверждено и не устраняется этим change (см. дельта-спеку).
- Столкновение «линкованный git worktree × файловая песочница dsh» само по себе — заведено
  отдельной задачей (`#936`, `white-spot`), здесь не чинится, только называется как контекст
  инцидента.
