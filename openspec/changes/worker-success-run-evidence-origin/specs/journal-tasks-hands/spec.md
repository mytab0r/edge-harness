# Дельта-спека: журнал (journal-tasks-hands) — критерий успеха воркера учитывает origin (#935)

## MODIFIED: Автономный воркер (конвейер пула)

29.4. Требование 29.3 (см. `worker-success-run-evidence`, #876/#878) уточняется: третий
    конъюнкт «в ветке появился хотя бы один новый коммит за время этого прогона» проверяется
    ДВУМЯ способами, успеха достаточно от любого из них:

    - в РАБОЧЕМ ДЕРЕВЕ воркера (сравнение отпечатка HEAD до и после запуска `dsh`, как и
      раньше);
    - НА ORIGIN ветки задачи (сравнение головы `refs/heads/<branch>` через `git ls-remote
      origin`, снятое теми же двумя точками — до и после запуска `dsh`).

    Причина: локальный чекаут воркера при доводке PR — линкованный git worktree, чей
    admin-каталог лежит вне рабочего дерева, в общем commondir; файловая песочница dsh
    блокирует запись именно туда. Агент обходит это отдельным клоном и пушит напрямую в
    origin — работа доезжает, но локальный HEAD воркера не двигается. Origin — то, что видно
    СНАРУЖИ независимо от того, как именно агент обошёл песочницу.

    Предсуществующий PR, чью ветку этот прогон НЕ тронул ни локально, ни на origin, остаётся
    провалом гейта (регрессия, закрытая #878, не возвращается) — конъюнкт срабатывает только
    когда ОБА признака не изменились.

    Текст `DSH_WORKER_RUN_GATE_GAPS` для этого конъюнкта называет оба факта (состояние
    локального HEAD и состояние ветки на origin) явно, не общей фразой.

    **Не подтверждено** (перенесено из 29.3, распространяется и на origin-признак): ни
    локальный, ни origin-признак не отличают НАСТОЯЩУЮ новую работу от `git rebase`/`commit
    --amend`, которые тоже двигают SHA (и локально, и на origin после пуша) без единой строки
    нового содержимого. Узкая форма того же класса #876, не закрытая ни здесь, ни
    `worker-success-run-evidence` (см. issue #910, пункт 4).
