# Дельта-спека: журнал (journal-tasks-hands) — идемпотентная публикация вердиктов гейтов (#203)

## ADDED: Конвейер (оркестратор)

40. Публикация вердиктов обоих гейтов идемпотентна: повторный прогон с тем
    же результатом не выполняет изменяющих вызовов, изменившийся результат —
    публикует. Решение — одно место правды
    `scripts/lib/review_labels.py` (`verdict_label_changes`,
    `comment_update_action`, `latest_comment_by_header`).

    40.1. Метка-вердикт (гейт 1: `review:ok`/`review:changes-requested`/
    `review:large`, гейт 2: `ai:ok`/`ai:changes-requested`/`ai:failed`):
    вердикт не изменился с прошлого прогона — ни `unlabeled`, ни `labeled`
    (каждое событие `labeled` — триггер `orchestra.yml`); сменился — чужие
    вердикты того же гейта снимаются, актуальный ставится. Метки вне
    вердиктов этого гейта (`review:large-ok`, `ai:*` у гейта 1, `review:*`
    у гейта 2, `conflict`) решением не трогаются.

    40.2. Комментарий провала (контракт: «Контракт PR ↔ задача нарушен:»,
    ревью: «Ревью нашло замечания:»): тот же текст уже висит комментарием
    доверенной учётки (`github-actions[bot]`) — публикация молчит;
    изменился — существующий комментарий обновляется (PATCH); своего
    комментария нет — публикуется. Комментарий постороннего участника с тем
    же текстом публикацию не глушит (класс подделки вердикта AI, PR #294).

    40.3. Идемпотентность не отменяет громкость: смена вердикта обязана
    переставить метку, изменение текста нарушений обязано стать видимым
    (обновлением существующего сообщения) — молчание допустимо только как
    доказанное «ничего не изменилось».
