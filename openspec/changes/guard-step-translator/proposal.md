# guard-step-translator: транслятор рукописного шага гвардии в каталог scripts/ci/guards при механическом ребейзе (#897)

Задача: #897.

Related: #749 (`ci-guard-catalog`, в `archive/`), #762/#764
(`mechanical-conflict-rebase`).

## Зачем

`ci-guard-catalog` (#749, `archive/ci-guard-catalog`) перевёл регистрацию
CI-гвардий из рукописных шагов `.github/workflows/repo-ci.yml` в каталог
`scripts/ci/guards/*.sh` — `scripts/lib/ci_guard_registration_guard.py`
красит PR, добавляющий НОВЫЙ рукописный шаг вне `ALLOWLIST`.

Живой замер (ручная миграция PR #890/#895, уже слиты): механический ребейз
(`scripts/orchestra/mechanical_rebase.py`, #762/#764) сводит такие PR
текстуально БЕЗ конфликта — `git rebase` применяет патч контекстно и про
новую схему каталога не знает, поэтому рукописный шаг остаётся на месте.
`ci_guard_registration_guard` после ребейза красит CI этого же PR:
устранённый источник git-конфликтов породил очередь ручной работы. Замер
на дату issue #897: 14 открытых PR, 20 таких шагов суммарно.

## Что делается

1. `scripts/lib/guard_step_translator.py` — детерминированный (без модели)
   перенос рукописного шага (`name`/`run`/`working-directory`) в файл
   каталога `scripts/ci/guards/<имя>.sh`: имя — по файлу, который реально
   исполняет `run:` (тот же разбор, что уже доказал себя в
   `ci_guard_registration_guard.py`), перенос атомарный по вызову (все
   найденные шаги или ни одного). Неразобранная форма (нестандартный ключ,
   `run:` без узнаваемого файла, выражение GitHub Actions `${{ … }}` в
   `run:` — некритичное замечание ревью PR #902, поднятое до громкого
   отказа, коллизия имени) — `UnsupportedStepError` с точной причиной, не
   молчаливый пропуск. Самопроверка ПЕРЕД записью на диск
   (`_verify_removal`, находка ревью PR #902 и её второй круг): (а) ни
   одно перенесённое имя не осталось; (б) deep equality ВЕСЬ новый
   разобранный документ == «старый документ минус перенесённые шаги» —
   ловит порчу соседнего шага (пустая строка внутри `run: |`, класс,
   живущий в 54 местах самого repo-ci.yml), дублирующееся имя шага И
   изменения в любом другом job'е. Схлопывание задвоенных пустых строк —
   только в окрестности удалённых диапазонов, содержимое файла вне их
   сохраняется байт в байт (второй круг: глобальный проход терял пустую
   строку в heredoc чужого job'а мимо всякой сверки по job `test`).
2. `scripts/orchestra/mechanical_rebase.py::migrate_guard_steps_if_needed` —
   вызывается между `attempt_rebase("resolved")` и `push_rebased`: успешный
   перенос коммитится отдельным коммитом поверх перебазированной ветки;
   неразобранный шаг ИЛИ ЛЮБОЙ сбой любого этапа (трансляция, git add,
   git commit — находка ревью PR #902 и её второй круг: до неё git-фаза
   стояла вне try, и `GitError` от `git commit` превращал "resolved" в
   "infra-error" без push'а УСПЕШНО перебазированной ветки) — `::warning::`
   и один `except Exception` на весь перенос, PR всё равно пушится как есть
   (перенос не может ухудшить уже решённый исход "resolved").
3. Газ в `ci_guard_registration_guard.py::check_no_undeclared_step` —
   вместо «перенеси в scripts/ci/guards/<имя>.sh (#749)» сообщение теперь
   называет ТОЧНОЕ имя файла (вычислено тем же способом, что сам перенос),
   шаблон содержимого и что именно удалить из repo-ci.yml.
4. Гвардия транслятора зарегистрирована сразу в
   `scripts/ci/guards/guard-step-translator.sh`, не рукописным шагом.

## Отклонение от текста задачи #897 (не баг, факт репозитория)

Задача #897 называет контракт файла каталога как «шебанг, `set -euo
pipefail`, бит исполнения». Живой снимок каталога на дату задачи и ревью
PR #902 показывает: все файлы `scripts/ci/guards/*.sh` несут режим
`100644` (проверено `git ls-tree` на обе даты; каталог растёт, поэтому
фиксирован РЕЖИМ, а не число файлов — две разные цифры в двух местах
читались как противоречие одного замера, замечание ревью PR #902),
`scripts/ci/run_guards.sh` вызывает каждый файл
ЧЕРЕЗ интерпретатор (`bash "$script"`), не напрямую — бит исполнения этому
механизму не нужен (не тот класс, что #510/#516: там падал прямой вызов
`run: scripts/foo.sh` без интерпретатора). `scripts/lib/exec_bit_guard.py`
проверяет только ПРЯМЫЕ вызовы (`direct_script_invocations`) — файлы
каталога гвардий в его выборку не попадают ни разу. Транслятор пишет файлы
БЕЗ бита исполнения — вслед за фактом репозитория, не вслед за текстом
задачи; расхождение зафиксировано здесь, чтобы не потерялось.
