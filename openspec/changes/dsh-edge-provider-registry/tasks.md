# Задачи: dsh-edge-provider-registry

Исполнение — через пул Issues. Правила — [PROTOCOL](../../../docs/agents/PROTOCOL.md).
Это change #158. Порядок задачи 1 внутри каждого раздела обязателен: тонкий
сквозной разрез (один провайдер через наш namespace, весь путь от UI до хода)
раньше полного слоя — он проверяет самое дорогое допущение design.md
(«занимаем чужой литерал `llm-pi-ai`») до вложения в остальную площадь.
Порядок разделов друг относительно друга зависимостью не считается — читай
явные `(blocked by: N)`.

## 1. Ядро: settings-namespace + реестр адаптеров

- [ ] **Тонкий сквозной разрез.** Патч по образцу серии `dsh-edge-plugin-system`
      (`dsh-edge/patches/000N-*.patch`): плагин читает settings-namespace
      `llm-pi-ai` (изначально с ОДНОЙ тестовой записью `providers.<id>`),
      строит `DeepSeekAdapter` из её `baseURL`/`apiKeyEnv`, вызывает
      `ctx.llm.registerAdapter([id], adapter)` +
      `ctx.llm.registerConfigurableProviders([...])`. Доказательство: в
      собранной морде (source-build, не npm-префаб) провайдер виден в
      пикере моделей и отвечает на реальный ход. Это разрез через все слои
      (namespace → плагин → реестр → пикер → живой ответ) раньше, чем любая
      из задач ниже.
- [ ] Схема namespace `llm-pi-ai.providers.<route-id>` полностью: `displayName`,
      `api` (`openai-completions` для OpenAI-compat), `baseURL`, `apiKeyEnv`,
      `models[]` (`id`, `name?`, `contextWindow?`, `maxTokens?`) — по
      `docs/research/10-dsh-architecture.md`, раздел 10.
- [ ] Цикл регистрации на N записей: один `DeepSeekAdapter` на route-id,
      `registerAdapter` с полным списком provider id, `registerConfigurableProviders`
      с directory-записями для незанятых (кнопка «Add» становится активной).
- [ ] Изоляция коллизии `DUPLICATE_ADAPTER`: id из реестра, совпавший с
      `deepseek-official` или с другим id реестра — громкий `console.error` +
      статус `failed` в DO storage (прецедент `dsh-edge-plugin-system`,
      «Рантайм: инсталл и изоляция»), инсталл остальных продолжается, DO не
      падает.
- [ ] Реакция на изменение namespace (владелец добавил/удалил провайдера
      через UI) — `handle.replace(providers)`, без пересоздания хендла.
- [ ] Существующий провайдер `deepseek-official` — код монтажа
      (`session-store.ts:243`, `session-store.ts:115`) не меняется вообще;
      регрессионный тест: после добавления второго провайдера первый
      по-прежнему отвечает на ход с прежним provider id.
- [ ] Регрессионный тест на `edge-credentials.ts`: ноль строк diff в файле;
      креды нового провайдера читаются/пишутся через существующий generic
      `resolve(ref)`/`set(ref, value)` без новой спецветки.

## 2. Гвардия завязки на литерал апстрима

(blocked by: 1 — гвардия проверяет собранный бандл, в котором уже должен
монтироваться namespace `llm-pi-ai`)

- [ ] Шаг деплоя морды (`deploy-dsh-edge.yml`, рядом с существующими
      гвардиями `verify-edge-plugins.mjs`/`smoke-edge-plugins.mjs`)
      проверяет, что литерал `"llm-pi-ai"` присутствует в собранном
      клиентском бандле (`dist/**`), и падает громко с текстом, объясняющим
      причину (апстрим переименовал namespace-литерал кнопки создания
      провайдера — см. design «Цена решения»), если литерала нет.
- [ ] Доказать мутацией: временно переименовать литерал в фикстуре/тестовой
      сборке (например, симулировать патчем замену `"llm-pi-ai"` на другую
      строку в клиентском бандле перед прогоном гвардии) → гвардия красная
      с ожидаемым сообщением; вернуть литерал → гвардия зелёная. Тест на
      мутацию — часть CI, не разовая ручная проверка.

## 3. Раннеры: синхронизация набора и приоритета

(blocked by: 1 — источник данных, который раннер будет читать, должен уже
существовать и меняться штатно через UI)

- [ ] Решить техническую форму экспорта (design «Не подтверждено», п.5):
      проверить права `GH_RUNNER_TOKEN`/`GH_DISPATCH_TOKEN` на запись
      repository variable, либо спроектировать событие журнала-канала по
      прецеденту `plugin_status`. Зафиксировать выбор в design.md (дополнить
      «Девиации реализации», как это сделано в `dsh-edge-plugin-system`), не
      заводить второе мнение рядом.
- [ ] Реализовать экспорт: изменение namespace `llm-pi-ai` (владелец добавил/
      удалил/перерасставил приоритет) публикует производный артефакт с
      полным списком провайдеров и приоритетом.
- [ ] `scripts/lib/dsh-ci.sh`: заменить чтение единственной пары
      `vars.DEEPSEEK_BASE_URL`/`vars.DEEPSEEK_MODEL` на чтение
      экспортированного набора; сохранить `dsh_require_provider_env`-класс
      громких отказов («источник экспорта пуст/недоступен» — отдельное,
      явно отличимое сообщение от «переменная не задана»).
- [ ] Тест расхождения: провайдер добавлен в морде, но раннер запущен со
      старым экспортом (гонка) — раннер обязан упасть громко или явно
      объявить устаревший набор, не молча работать с частью данных.

## 4. Доказательства (критерий готовности #158)

- [ ] Владелец добавляет второго провайдера через штатный Settings UI морды
      (без правки клиента) — виден в пикере, отвечает на реальный ход.
- [ ] Настройка (namespace `llm-pi-ai` целиком) переживает рестарт DO —
      проверка через `runInDurableObject` или эквивалент, по образцу

      видна в Settings, существующий провайдер продолжает отвечать.
- [ ] Ключ нового провайдера не попадает в репозиторий ни на одном шаге
      (grep по diff/логам CI на предмет значения креда, не только имени
      ref'а).
- [ ] Раннер, запущенный после добавления второго провайдера, использует
      тот же набор и приоритет, что показывает морда (сверка вручную или
      автоматически по экспортированному артефакту).
- [ ] Гвардия литерала (раздел 2) доказана мутацией, зафиксировано в PR.

## Границы

- Плагин владельца `combo/auto` (маршрутизация, failover, cooldown) — не
  часть этих задач; реестр только предоставляет `llm.providers` и
  экспортированный приоритет как данные.
- Свой клиентский DSH-плагин (вариант б) — не создаётся в рамках этого
  change; условие возврата — гвардия раздела 2 покраснела на реальном
  апстримном релизе, не по прогнозу.
- #157 (потолок токенов как свойство модели) и #155 (дефолтная модель из
  морды) — не закрываются здесь; раздел 1 создаёт поле `maxTokens` в схеме,
  не переносит в него существующую константу.
