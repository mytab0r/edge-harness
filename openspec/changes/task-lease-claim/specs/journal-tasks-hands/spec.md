# Дельта-спека: аренда задачи (claim) для всех каналов диспетча

Расширяет `openspec/specs/journal-tasks-hands.md`, раздел «Автономный воркер
(конвейер пула)». Мержится в базовую спеку одновременно с реализацией (#121).

Требование: захват задачи любым каналом (worker auto, worker manual, hands) —
атомарная аренда `scripts/lib/claim_task.py claim N` (ADR 0006): серверный
git-ref замок `refs/locks/task-<N>`, создаваемый Git-дата-API. Защита
доказывается фактом существования замка (успешный ответ сервера на создание
ref'а), а не фактом назначения: назначение и след в задаче — видимость аренды,
не защита (все агенты — один логин). Отказ аренды (замок уже стоит) — зелёный
no-op канала («задача занята»), не красный job; поломка утилиты аренды —
громкий красный job. Другого пути начать работу над задачей пула в коде нет.

Сценарий: два канала одновременно вызывают `claim` одной задачи → ровно один
получает замок, второй — отказ «задача занята» и завершается зелёным no-op.

Сценарий: задача под живым замком → повторный выбор пула (`free_task`) не
возвращает её как свободную (CLI `locks`), а прямой claim всё равно отклонён.

## ADDED: аренда в канале hands

Требование: repository_dispatch с `task_id = issue-<N>` (заказ работы над
задачей пула через runner-bridge) до `job_start` берёт аренду тем же
`claim_task.py claim N`; задачи `manual-<run_id>` — вне пула, аренду не берут.
Отказ аренды: job зелёный, в журнал уходят `agent_error` c `error: task_busy`
и `job_end` c `result: fail` — задача в морде получает честный терминальный
статус, а не висит «dispatched».

Сценарий: воркер держит замок задачи N, морда-агент заказывает `issue-N` →
hands-джоба зелёная, работы нет, в журнале task_busy + job_end fail.

## ADDED: TTL и release

Требование: замок протухает через `LOCK_TTL_HOURS = 24`
(`scripts/lib/claim_task.py` — единственное место правды порога, тот же такт,
что окно просрочки назначений `STALE_HOURS`). Протухший замок снимает
оркестратор (`collect_stale` в scheduler), оставляя след в задаче; задача
возвращается в пул (назначение снимает существующий `reap_stale`).

Требование: release идемпотентен и выполняется 1) оркестратором после слияния
PR (`after_merge`), 2) явно при blocked-эскалации воркера (замок снят,
назначение остаётся — задача ждёт владельца), 3) вручную
(`claim_task.py release N`).

Сценарий: замок старше 24 ч → следующий такт оркестратора снимает его,
в задаче комментарий «протухший замок снят», задача снова в пуле.

Сценарий: воркер эскалировал (метка `blocked`) → замок снят в тот же прогон,
назначение остаётся, автоповтора нет.
