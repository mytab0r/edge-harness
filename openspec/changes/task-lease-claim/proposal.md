# task-lease-claim: атомарная аренда задачи — единый claim для всех пайплайнов

Задача: #121. ADR: [0006](../../../docs/decisions/0006-task-lease-git-ref-lock.md).
Дельта-спека: `specs/journal-tasks-hands/spec.md` — правка п.28 «Захват задачи
воркером» и новые требования «Аренда в канале hands», «TTL и release».

## Класс закрываемой ошибки

Защита «два исполнителя на одну задачу» была дырявой по построению:

1. `free_task` в `scripts/worker/task.sh` — check-then-assign: между чтением пула и
   назначением другой канал успевает взять ту же задачу (TOCTOU).
2. Проверка «занята не воркером» по assignee бесполезна: все агенты — один GitHub-логин
   (`mytab0r`), «занята другим» неотличимо от «занята мной».
3. Канал hands (runner-bridge) вообще не брал GitHub-аренду: морда-агент мог заказать
   работу по задаче, которую уже делает воркер. Живой случай 2026-08-31: ручной dispatch
   + пульсный dispatch — дубль прервал человек; в автономе прервать некому.

## Решение

Носитель замка — серверный git-ref `refs/locks/task-<N>` (ADR 0006): создание ref'а
атомарно на сервере GitHub, второй претендент получает 422 и обязан завершиться зелёным
no-op. Один вход — `scripts/lib/claim_task.py` (модуль + CLI):

- `claim <N>` — замок (TTL 24 ч по дате коммита замка) → назначение → след в задаче;
- `release <N>` — идемпотентное снятие (post-merge оркестратором, явный drop при
  blocked-эскалации, ручное);
- `locks` — машинный список занятых номеров (выбор пула в task.sh);
- `collect_stale` — TTL-сборщик оркестратора: протухший замок снимается со следом
  в задаче, задача возвращается в пул (назначение снимает существующий `reap_stale`
  с тем же порогом — второго места правды нет).

Врезка каналов (было «до #119 не трогать», стало «врезано #121»):

- `scripts/worker/task.sh`: захват = только claim (auto и manual); фильтр живых замков
  в `free_task` — экономия прогона, не защита; проверка «занята не воркером» удалена
  как мёртвая (один логин на всех агентов).
- `scripts/hands/dsh_task.sh`: заказ `issue-N` берёт аренду до `job_start`; отказ —
  зелёный no-op job'а + честный финал в журнале (`task_busy`, `job_end fail`);
  `manual-*` — вне пула, без аренды.
- `.github/workflows/hands.yml`: `contents: write` и `GH_RUN_TOKEN` только на вызов
  аренды (снимается до старта DSH).

## Что вне рамок

- Дубль самих прогонов worker.yml — остаётся за dupguard + concurrency (замок —
  про задачу, не про прогон, см. ADR 0006 «Не решает»).
- Спор о носителе замка (ref / ветка / метка) закрыт ADR 0006, здесь не переоткрывается.
- Watchdog зависших задач морды (14.1–14.2) — без изменений: отказ аренды даёт
  задаче честный терминальный статус, а не новую зависшую.
