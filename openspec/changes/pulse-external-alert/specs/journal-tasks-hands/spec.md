# Дельта-спека: журнал (journal-tasks-hands) — алерт живости пульса из DO (#1103)

Секция «Пульс оркестрации» домовой спеки пополняется несколькими
незаархивированными дельтами одновременно (`cf-cron-trigger` п.46,
`do-pulse-watchdog`, и др.) — номера временно пересекаются, итоговый номер
присваивается при архивации.

## ADDED: DO сам оповещает владельца о неживом пульсе

47. `Harness#tickPulseAlert()` (`cf-worker/src/harness.ts`), вызывается из
    общего `#dispatchOrchestraTick` — то есть и из `alarm()`, и из
    `scheduledTick()` (Cron Trigger, п.46). Решение о тревоге —
    `pulseHealthy()` (уже существующее место правды, не новый порог);
    переход здоров↔нездоров, не каждый тик — дедуп новой таблицей
    `pulse_alert` (флаг `alerted`), решение о переходе — прямое
    переиспользование `storageReadyAlertDecision` (#575), не вторая копия.
    Доставка — существующий `#telegramApi`.

    47.1. Этот алерт — единственный сторож живости пульса, который может
        сработать, даже если ни один workflow этого репозитория не
        запускается вовсе: он не читает GitHub API, решение целиком из уже
        записанного в SQLite DO состояния. Существующий
        `pulse_guard.py::independent_pulse_check` (issue #689) требует
        исполнения `scheduler.py` (то есть живого orchestra.yml) и поэтому
        не может закричать, когда причина падения — общее исчерпание квоты
        GitHub API (#1100, живой инцидент 2026-09-13): рушится каждый вызов
        API, включая dispatch из самого DO, и `scheduler.py` не запускается.
        Оба сторожа не дублируют друг друга: `independent_pulse_check`
        различает независимый DO-канал от событийного, пока хоть один из
        двух жив; `tickPulseAlert` кричит, даже когда оба мертвы одновременно.

    47.2. Текст алерта называет факт (конкретный `detail` последнего тика,
        либо самодостаточный текст для ветки, где `pulseStale()` истинен и
        `detail` в хранилище честно `null`) и план: что уже делает
        самовосстановление (`alarm()` пробует каждые `selfOrchestrationMs`,
        Cron Trigger — каждые 5 минут), и по какому признаку считать
        неполадку требующей ручной проверки (нет подтверждения
        восстановления в течение часа — проверить `GH_DISPATCH_TOKEN`/квоту
        API/`rows_written` DO).

    47.3. 0 добавленных вызовов GitHub API/час: алерт не может усугубить
        причину падения, если она — исчерпание квоты (#1100).

    47.4. N минут до автоматического возобновления пульса этим пунктом не
        меняется — он только делает существующий (п.46) механизм видимым
        владельцу раньше, чем тот успевает самовосстановиться незамеченным.
