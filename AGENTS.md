# Правила работы в этом репозитории

Адресовано агентам и людям одинаково.

## Первое действие в новой сессии

Прочитай [`docs/INDEX.md`](docs/INDEX.md). Там карта всего, что уже исследовано.

Особенно — [`docs/research/30-rejected-alternatives.md`](docs/research/30-rejected-alternatives.md)
**до того, как предлагать архитектурное решение.** Двенадцать вариантов уже рассмотрены и
отвергнуты по названным причинам. Предложить что-то из этого списка заново — не ошибка
суждения, а не прочитанная документация.

## Если ты работаешь не один

Над репозиторием одновременно работают несколько агентов. Правила совместной работы —
[`docs/agents/PROTOCOL.md`](docs/agents/PROTOCOL.md), и они enforced, а не договорные:

- **Пул задач** — GitHub Issues с меткой `task`. Взять задачу = атомарная аренда
  `python3 scripts/lib/claim_task.py claim N` (замок + назначение, #121): отказ
  «задача занята» = её уже делает другой канал, бери следующую.
- **Ветка задачи создаётся только скриптом** `scripts/git/task-branch <N>-<slug>`. Голый
  `git switch -c … origin/main` запрещён: оркестратор сливает PR на сервере, и локальный
  main протухает молча — так появляются ветки от старой базы. Скрипт доказывает свежесть
  через `git ls-remote` и ставит гвардию `.githooks/pre-commit` (`core.hooksPath`), которая
  перед каждым коммитом сверяется с сервером и блокирует коммит от протухшей базы
  (лечится `git rebase origin/main`).
- **Прямой пуш в main** не проходит обязательные проверки. Только ветка `agent/<N>-<slug>` и PR.
- **Слияния делает оркестратор** (workflow `orchestra`), по одному PR за проход и до
  нескольких за запуск (цикл слияний, #297).
- Нашёл белое пятно или противоречие — issue с шаблоном «🕳️ Белое пятно», не молчи и не
  чини тихо: остальные агенты должны увидеть это до того, как обопрутся.

## Что здесь строится

Харнес, у которого морда живёт всегда, а руки поднимаются по требованию. Три слоя:

| Слой | Где | Чем ограничен |
|---|---|---|
| Морда | Cloudflare Workers Assets | 20 000 файлов, 25 MiB на файл |
| Мозг: журнал, очередь, heartbeat | Durable Object с SQLite | **10 ms CPU на вызов**, 100k записей строк/сутки |
| Руки: git, тесты, команды | GitHub Actions job по `repository_dispatch` | 6 часов на job, ~500 триггеров/час |

Жёсткое ограничение, породившее эту раскладку: **всё работает на бесплатных планах.**
Решение, стоящее денег, требует явного согласования с владельцем, а не тихого добавления
зависимости.

## Правила, оплаченные чужими ошибками

**Починил случай — закрой класс.** Если та же ошибка возможна во втором месте, фикс в первом
не считается сделанным. Назови класс одной фразой, найди все места, сведи в одно место
правды, оставь тест-гвардию и докажи её мутацией: сними фикс, убедись, что тест покраснел.

**Одно место правды.** Значение, порог, список требований объявляются один раз и читаются
оттуда. Три одинаковые копии проверки — это отложенный рецидив, а не осторожность.

**Проверяй видимый результат, а не шаг.** «CI зелёный», «HTTP 200», «шаг success» — не
доказательство. Доказательство: артефакт лежит там, где должен, с нужным содержимым.
Шаг, не сохранивший результат, обязан падать громко.

**Fail loud, не silent-wrong.** Молча неверное состояние дороже падения: его не видно, и оно
копится. «Возможности нет» и «возможность есть, но сломана» — разные сообщения, потому что
лечатся по-разному.

**Тест кормит прод-форму данных, а не пересказ.** Тест на разбор чужого ответа собирается из
того, что реально отдаёт система: скопированный JSON, настоящий код возврата. Тест,
построенный на нашем пересказе чужого формата, зелёный и бесполезный.

**Не переисследуй документированное.** Если факт есть в `docs/research/` — бери оттуда.
Если он устарел — правь файл, а не заводи второе мнение рядом.

**Не знаешь — пиши «не подтверждено».** В документации это отдельный раздел в каждом файле.
Догадка, выданная за факт, дороже честного пробела: на неё опираются.

**Не чини затычку, не спросив, почему она ещё жива.** Прежде чем улучшать неудобный
ручной механизм, проверь `openspec/changes/*/design.md` и `tasks.md`: не назван ли он там
временной мерой «до подключения X», где X — невыполненная задача. Улучшенная затычка живёт
дольше и отдаляет настоящее решение. Замер цены: 2026-09-01 полдня ушло на вылизывание
ручной настройки провайдера в `vars`, хотя дизайн `dsh-in-job` прямо называл её временной
«до подключения combo-router», а сама задача стояла невыполненной с #51. Правильный первый
шаг был — спросить владельца, почему затычка ещё на месте.

**Тормоз без газа не принимается.** Любой механизм, останавливающий работу — метка,
блокирующая слияние; пауза диспатча; занятая задача; красная обязательная проверка —
обязан назвать, что именно и при каком условии возвращает движение. Автоматический возврат
предпочтителен. Ручной допустим, но только как объявленное решение с указанием, кто именно
и по какому сигналу его выполняет. Не названный газ — это дефект, а не умолчание. Замер
цены: сплошной прочёс 2026-09-02 нашёл пять односторонних тормозов из шести собранных —
предохранитель диспатча без снятия (#205), `review:large` без автоматики на
`review:large-ok` (#204), протухший вердикт `ai:*` без повторного ревью и занятая задача
без возврата раньше суток (оба #196). Ни один пропуск не был виден до того, как логи
прочли целиком. Реестр газа по каждой метке — [`docs/agents/LABELS.md`](docs/agents/LABELS.md).

**Решение — это механизм, а не текст.** Правило, влияющее на поведение системы
или на работу агентов, обязано иметь носитель: гвардию в `.githooks/pre-commit`,
тест-гвардию по исходнику в CI, шаг workflow, инвариант без альтернативного
пути. Критерий — «нарушить невозможно», а не «написано». Честная оговорка:
часть решений машиной не проверяется (выбор приоритета, трактовка находки) —
их место в `AGENTS.md` и в задании агенту, и это называется вслух, а не
выдаётся за гвардию. Замер цены: правило «блокер — issue с меткой `blocked` и
ссылкой на причину» (docs/agents/ROADMAP.md:29) не проверялось ничем — issue
#268 несёт `blocked` с эскалацией «Блокирована: #265» сутки после того, как
#265 закрылся, и никто не заметил (задача #334, гвардия
`scripts/orchestra/stale_blocked_guard.py`); семантика `task_ref` жила в
докстринге, пока `ai_review.py` не взял не ту функцию — четыре PR судились по
неверной задаче, пока гвардия не легла в CI (#259,
`scripts/lib/test_task_ref_usage_guard.py`); класс «страница GitHub API без
обхода» жил в комментарии и всплывал восемь раз подряд, пока не появилась
гвардия по исходнику (#308/#309, `scripts/lib/test_pagination_guard.py`).

## Работа с документацией

Ссылки — обычные относительные markdown-ссылки. Не `[[wiki-links]]`: в GitHub они не
кликаются, а документация должна читаться там, где лежит.

Выяснил что-то новое о внешней системе → в `docs/research/`.
Принял решение между вариантами → ADR в `docs/decisions/`.
Меняешь поведение системы → дельта-спека в `openspec/changes/<change-id>/`.

## Секреты

В репозиторий не попадают никогда, даже в примерах. Репозиторий публичный.
Секреты живут в GitHub Actions secrets и в Cloudflare, в документации — только имена.

Помни про маскирование: GitHub скрывает в логах только точное совпадение со значением
секрета. Производное — base64, подстрока, часть JWT — не маскируется.
