# Патч-серия dsh-edge

Патчи применяются workflow'ом `deploy-dsh-edge.yml` поверх чистого клона
`pawaca/dsh-edge` на пин SHA из [`upstream.json`](upstream.json). Дисциплина —
по образцу `patches/audit.json` апстрима: у каждого патча есть причина и
`removeWhen` — условие снятия. Порог пересмотра «форк против серии» (design.md,
«Форк-серия»): больше шести патчей или любой патч >100 строк содержательных
изменений.

Порядок применения в CI — лексикографический по имени файла; нумерация
фиксирует требуемый порядок.

| Патч | Файлы апстрима | Причина | removeWhen |

| `0002-edge-plugins-module.patch` | `src/session-store.ts` | Композиция апстрима — статическая очередь `context.plugin(...)`; точки монтирования владельческих плагинов нет. Патч ставит в хвост `initialize()` вызов `installEdgePlugins(storage)`: цикл по сгенерированному списку, изоляция по прецеденту LLM-плагина (строка ~245): упавший плагин не роняет DO, пишет `console.error` + статус в ключ `dsh-edge-plugins:<id>`, цикл продолжается. | `0004-harness-ingest.patch` | `src/http.ts`, `src/instance.ts`, `src/session-store.ts` | Сессии агентов-раннеров (#119) должны быть видны в нативной морде: раннер гоняет своего DSH вне деплоя и зеркалирует канонические события сессии в сессию-просмотрщик. Шов апстрима нет: surface-события пишет только агент-цикл. Патч добавляет `POST /api/sessions/:id/ingest` (владелец-авторизация как у всех маршрутов): батч событий в форме спула раннера `{type, data}`, allowlist = allowlist спула, перенумерация turn поверх хранимого лога (переиспользованная сессия не откатывается), surface-события встают в хвост (`surfaceOp: 'append'`), батч флашится до ответа («принято = сохранено»), публикация живым подписчикам — штатный late-event путь стора. Исправлено: второй аргумент — `this.context.agentDefaultModel.currentSelection().model`, тот же сервис, что `initialize()` строит из `resolveEdgeModel(config.model)` (реальный `DEEPSEEK_MODEL` деплоя, с учётом persisted-оверрайда настроек) — гарантированно модель из каталога, реально смонтированного на этом деплое, а не устаревший исходный литерал. Честная граница: устраняет ли это первопричину 500 — неизвестно. Перепроверка на пине `@deepseek-ai/dsh-llm-deepseek` 0.1.2-rc.1 (версия, реально закреплённая в `apps/dsh-edge/package.json` на этом апстрим-пине) показала, что `modelInfoFor` неизвестный id НЕ бросает, а синтезирует фолбэк-`ModelInfo` — рассинхрон каталога мог вообще не быть тем, что бросает внутри `agents.resume`; настоящая фабрика бутстрапа агента (`@deepseek-ai/dsh-agent-loop`) в этом репозитории не вендорится и недоступна для инспекции. Полностью развязать запись лога от Agent не вышло — у апстрима нет более низкоуровневого примитива дописать событие в сессию (`createSession`/`createBlankSession`/`renameSession` в том же файле идут тем же путём `agents.create`/`resume`, `docs/research/12-dsh-edge-session-api.md`, «Чего в dsh-edge НЕТ»), это архитектурное ограничение апстрима, а не решение этого патча. Второе изменение — классификация: любой сбой `openAgentForTurn`, который не является уже классифицированным `LlmError`/`EdgeSessionStoreError`, оборачивается в новый код `EdgeSessionStoreError('AGENT_UNAVAILABLE', …)` (503, а не слепой 500); общий fallback `http.ts::errorResponse` для по-настоящему неизвестных ошибок (касается ВСЕХ маршрутов морды, не только ingest) сохраняет строку `"Internal runtime error."` байт-в-байт (не ломает существующие отпечатки дедупа), но добавляет поле `detail` (имя класса ошибки + усечённое сообщение) — раньше вообще нечем было отличить один случай от другого без редеплоя с логами. Порог патча (см. «Размер серии» ниже) этим расширением пробит: было ~120 строк содержательных изменений, стало ~210 — решение "серия против форка" не принято этим PR, оставлено явно на рассмотрение владельца. | Апстрим даст штатный API дописывания событий в чужую сессию (или раннеры переедут внутрь DO). |

Фикс — `services: [{binding: HARNESS_SERVICE, service: "edge-harness"}]` в `wrangler.jsonc` деплоя: service binding идёт Worker-to-Worker мимо публичного DNS/HTTP и ограничения 1042 не имеет. | Журнал станет доступен морде same-origin (routes одной зоны — вариант 3 из #105) или апстрим даст штатный шов внешних прокси — патч снимается, плагин читает журнал напрямую. |

| `0007-quarantine-unmigratable-session.patch` | `src/do-session-persistence.ts` | Апстримный `postInitialize()` коммитит апгрейд формата сессий ОДНОЙ транзакцией и сам пишет в комментарии: «An incompatible later session must also roll back earlier sessions». Для харнеса, у которого морда И ЕСТЬ Durable Object, это значит: одна историческая сессия, которую билд не может перевести из v2 в v3, не даёт подняться ВСЕМУ DO — каждый запрос отвечает 500, канарейка деплоя краснеет, автооткат возвращает прошлую версию (живой случай: прогон 35441352792, `format v2 surface before first step cannot acquire a system head without changing chronology`). владельцу — нельзя: под общим PAT оркестратор, агент и владелец в API неразличимы,
и неподписанный dispatch по правилам этого репозитория не отличим от dispatch'а,
отправленного кем угодно из конвейера. Писать «решение принято владельцем нажатием
кнопки» значило бы утверждать атрибуцию, которую собственная улика опровергает, —
и создавать прецедент «неподписанный dispatch = решение владельца», то есть
легитимировать подделку провенанса для следующих `waiting:owner`. Прежняя редакция
этого абзаца ровно это и делала; исправлено по блокирующей находке ai-ревью PR #1399.

**Статус, честно:** вариант 1 применён патчем 0008 при НЕподтверждённом машиной
решении. Разбор вариантов ниже — настоящий и перечитываемый, он от провенанса не
зависит; чего нет — так это аутентифицированного ответа на вопрос «серия или форк».

**Газ (иначе это тормоз без газа).** Вопрос считается закрытым только с
аутентифицированным решением. Пока его нет: восьмой патч обязан поднять «серия против
форка» ЗАНОВО — тем же порядком и с той же ценой вариантов. Снимает это требование
одно из двух, и оба машинно проверяемы: (а) прогон `owner-decision.yml` по задаче
#1379 или её преемнице, завершившийся **успехом** (подпись прошла, решение записано
комментарием) — после починки #1398; (б) явный отказ владельца от пересмотра,
записанный тем же путём.

Что именно решено и почему не форк — коротко, чтобы следующему читателю не пришлось
поднимать вопрос заново:

- **Серия** ошибается ИЗРЕДКА и АДРЕСНО: не легший патч называет номер патча и хунк,
  починка — одна локальная правка. Живой прецедент бампа 0.7.1 → 0.8.0: конфликтовал
  ровно один патч в одном месте. Пин бампается часто (12, 13, 14, 17 сентября —
  восемь бампов за всё время), и серия при этом автоматически не перебазируется;
- **Форк** меняет «изредка одна правка» на РУЧНОЕ слияние на КАЖДОМ релизе, и
  конфликт перестаёт нести причину: `git apply` говорит «патч 0004, хунк такой-то»,
  слияние скажет только «конфликт в файле». Вдобавок теряются `removeWhen` — условия,
  при которых патч вообще можно снять;
- **Третий путь** («обойтись без патча, читать `wrangler tail` во время канарейки»)
  отвергнут не по вкусу: он делает «карантин пуст» неотличимым от «не успели поймать»,
  то есть ровно silent-wrong, запрещённый правилами репозитория.

**Как граница шести была пройдена.** Патч 0007 (#1376) довёл серию ровно до шести и записал здесь: «следующий, кто добавит седьмой патч, обязан сначала поднять вопрос "серия против форка" перед владельцем, а не дописать строку молча». Патч 0008 (#1379) исполнил ПЕРВУЮ половину требования — вопрос поднят с ценой каждого варианта; вторая половина (аутентифицированный ответ) не выполнена, разбор — абзацем выше. Поэтому требование НЕ снято: восьмой патч поднимает вопрос заново, пока не появится успешный прогон `owner-decision.yml` по этой задаче. Цена самого 0007 — перебазировка на каждом бампе — названа в разделе «Цена» ADR 0027 и принята сознательно: альтернатива («морда целиком мертва из-за одной старой записи») дороже.

курсору — `seqIsCursor` (safe-integer `session.seq`) гейтит И чтение, И
запись кэша. Если апстрим переименует/уберёт `seq`, единственный мутант
дрейфа («курсора нет», `seqIsCursor` схлопнут в `true`) ловится тестом 4:
без валидного курсора кэш полностью выключен — нумерация продолжается
безусловным ре-сканом (до-кэшное поведение, CPU-цена без потери
корректности), а не вечным hit протухшего кэша на
`undefined === undefined`. Откат ТОЛЬКО чтения к голому предикату зелёный —
запись всё ещё гейтится (оба гейта читают одно определение `seqIsCursor`;
исполнено 2026-09-17, рецепт мутаций тест-файла).

Честная граница: инвалидация моделирует «всякий писатель дописывает через
тот же журнал сессии, `session.seq` — курсор записи» и НЕ сверена байт-в-байт
с апстримом (не вендорится); перепроверять руками на каждом бампе пина —
авто-бамп стаб не перепроверяет. Газ механизма: если в серию вернётся
машинерия #1049 (PR #1057 открыт; in-flight-охрана — задача #1248) или
апстрим заведёт собственный кэш `baseTurn`, этот патч-уровневый кэш
снимается — два кэша одной величины в одном методе не оставлять.

## Гвардия состава

[`verify-edge-plugins.mjs`](verify-edge-plugins.mjs) — проверка «манифест ↔
артефакт» после сборки: каждый `server: true` плагин обязан быть в обоих
воркер-бандлах (литерал состава `id:"<id>"` из сгенерированного модуля),
каждый `client: true` — в `dist/plugins/<package>/client.js` и в boot-графе
`dist/index.html`. Замечание к design.md (там назван `bundle-meta.json`):
метафайл эфемерен — `bundle-standalone.mjs` удаляет временный outdir; гвардия
проверяет durability-артефакт того же доказательства. Отсутствие плагина в
артефакте — красный деплой, а не тихая неполная морда.

[`smoke-edge-plugins.mjs`](smoke-edge-plugins.mjs) — вторая половина
доказательства, «манифест ↔ рантайм-инсталл» (класс #100): гвардия состава
доказывает «плагин в бандле», но не «плагин инсталлируется» — #100 проехал
зелёной сборкой при плагине, чей apply падал в рантайме DO. Дым исполняется
в CI сразу после кодогенерации: инсталлирует каждый серверный плагин в
настоящий cordis Context с SystemPrompt + ToolRuntime из node_modules клона;
не инсталлировался — красный деплой. Честная граница: дым идёт в Node, не в
workerd, и покрывает путь монтирования (apply + регистрация тулов), не путь
execute() инструментов.
