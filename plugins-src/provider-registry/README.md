# provider-registry — реестр LLM-провайдеров морды (#114)

Серверный DSH-плагин по образцу [runner-bridge](../runner-bridge/): делает
работающими кнопки добавления провайдера в штатном **Settings → Models**
морды dsh-edge без десктопных конфиг-файлов и без передеплоя.

## Как это работает

На десктопе управлением провайдерами занимается пакет `dsh-llm-pi-ai`, который
на Workers не влезает (Node-only транспортные SDK — `docs/research/11-dsh-edge.md`,
`docs/research/30-rejected-alternatives.md` п.1). Клиентский UI при этом мёртв
по двум независимым причинам (вскрыто в research/11):

1. **«Add custom provider»** читает выбор протоколов из settings-namespace
   буквально с именем `llm-pi-ai` (`NS$1` в клиентском бандле) — а namespace
   в морде не смонтирован → `protocolChoices` пуст → кнопка disabled.
2. **«Add»** (добавить провайдера из directory) требует directory-записей,
   которые ещё не настроены — в морде объявлен единственный `deepseek-official`,
   уже настроенный → список пуст → кнопка disabled.

Плагин закрывает обе, не устанавливая `dsh-llm-pi-ai`:

- монтирует settings-namespace `llm-pi-ai` **со своей схемой** (форма
  апстримного `Config`: корень — `providers`-словарь; `api` — union с единственным
  честным протоколом транспорта `openai-completions`), персистентным DO storage
  штатного провайдера настроек морды — переживает рестарт DO без передеплоя;
- публикует directory-записи готовых OpenAI-compat маршрутов
  (`zhipu`, `nvidia-nim`, `openrouter`, `deepseek`) — они видны кнопке «Add»,
  пока не настроены, и становятся обычными строками после;
- каждую настроенную запись `providers.<route-id>` превращает в живой маршрут
  пикера моделей: один переиспользованный `DeepSeekAdapter` (OpenAI-compat
  транспорт апстрима) на маршрут, группа в пикере зовётся `displayName` записи;
- ключи — штатным credentials-механизмом морды (`edge-credentials.ts`:
  DO storage, env-фолбэк): клиент кладёт ключ в `credentials.set`, в namespace
  попадает только **имя** ссылки (`<ROUTE>_API_KEY`), никогда значение.

Изменение раздела настроек перестраивает набор маршрутов атомарно
(`handle.replace` / dispose по одному маршруту); отказ одного маршрута пишет
громкий `console.error` и не мешает остальным (прецедент изоляции патча 0002).
Мусорный профиль отказывается **при записи** (validate → `settings-rejected`
с внятным текстом в карточке Settings): отсутствующий или не-http(s)
baseURL (иначе транспорт молча подставил бы `api.deepseek.com` и унёс ключ
на чужой эндпоинт), пустой id модели, дубликат модели, занятие маршрута
`deepseek-official`.

## Потолок ответа

`maxTokens` маршрута по умолчанию = env воркера `DEEPSEEK_MAX_OUTPUT_TOKENS`
(тот же, что кормит штатного провайдера, в деплое = 131072), иначе 131072.
У адаптера дефолт 256000 — его текущий провайдер владельца отклоняет
(`docs/runbooks/switch-llm-provider.md`). На модели — `models[].maxTokens`.

## Каталог маршрутов

Состав каталога — константа `DIRECTORY` в `server/index.js`: провайдеры,
названные в документах репозитория (runbook переключения провайдера,
research/30). Расширение — PR с новой строкой; baseURL из каталога — каноничный
публичный эндпоинт и остаётся редактируемым в карточке.

## Про inject и ctx.get

Плагин объявляет `inject: ['llm']` — свойство `ctx.llm` читается только в
apply. Сервисы `credentials`/`attachments` читаются ленивым `ctx.get(...)`
в момент хода — тот же паттерн, что у апстримного `dsh-llm-deepseek`
(`inject: ['llm']`, `ctx.get('credentials')` внутри `resolveApiKey`), который
обслуживает ключи штатного провайдера этой морды. Ветка разрешения ключа из
credential-хранилища покрыта юнит-тестом со stub-сервисом.

## Не подтверждено

- `llm.discoverModels` на Edge апстримом не поддержан (`edge-api.ts`:
  `discoverModels: unsupported`) — кнопка «Fetch models» в карточке вернёт
  ошибку; каталог моделей вводится руками. Ровно так море настраивалось и
  до этого (deploy-патч каталога), но живьём карточка не прогонялась —
  нужен владелец с кукой.
- Живой ход через добавленный в морде маршрут не прогонялся этим плагином
  в проде (нужен настоящий ключ владельца); путь транспорта — тот же класс
  `DeepSeekAdapter`, что обслуживает штатного провайдера морды.
