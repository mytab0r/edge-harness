## Версия Bot API

**Замером установлена только нижняя граница.** Полное тело `getMe` выше —
поля версии в нём нет; это ФАКТ прогона. По документации на 2026-09-22
актуальна ветка 10.x, а поле `has_topics_enabled` появилось в 9.2 — значит
сервер не старше 9.2.

**Не подтверждено:** какая именно версия обслуживала этот замер, и существует
ли вообще метод Bot API, сообщающий версию сервера — такого метода я в
документации не нашёл, но «не нашёл» и «его нет» — разные утверждения, и
второго замер не делал.

## Что это опровергает

**1. «Нужен переключатель в @BotFather».** Не нужен — по крайней мере для
этого бота на дату замера. `has_topics_enabled` уже `true`, никто его в этой
сессии не трогал, и первый же `createForumTopic` прошёл. Предположение о
необходимом ручном шаге было прочитано из документации и не проверено;
проверка его не подтвердила.

**2. `createForumTopic` не работает в приватных чатах.** Метод отсутствует в
списке получивших поддержку приватных чатов (там названы только
`editForumTopic`, `deleteForumTopic`, `unpinAllForumTopicMessages`) — но
работает: тема создана, id `1681431`. Список в документации неполон, а не
ограничителен.

**3. tdlib/telegram-bot-api#847 («`sendMessage` с `message_thread_id` в личку
→ 400 message thread not found»).** На этом боте не воспроизводится: шаг 3
вернул `ok`. Отчёт остаётся открытым у апстрима — возможно, он про другую
версию сервера Bot API, другой способ получения `message_thread_id` (не из
`createForumTopic`) или уже починен. **Не подтверждено:** чем именно
отличается наш случай от описанного в отчёте — мы воспроизводили не отчёт, а
свой сценарий.

## Что отсюда следует для харнеса

Категория сигнала (`scripts/lib/alert_category.py`, #1461) может стать
`message_thread_id`, а не только видимым префиксом: механизм доставки в тему
существует и проверен. Остаётся задача хранения соответствия
`категория → message_thread_id` — тема создаётся один раз, её id надо
пережить между прогонами job'ов (кандидаты: DO, ветка данных, закреплённое
сообщение). Это отдельная задача, здесь только факт про API.

## Как перепроверить

```
gh workflow run telegram-thread-probe.yml
```

Замер идемпотентен: создаёт тему, пишет два сообщения (контрольное вне темы и
одно внутри), переименовывает тему, удаляет её за собой. Владелец видит это в
чате несколько секунд.

## Не подтверждено

- **Сохраняется ли тема между прогонами** — замер её удаляет, долговременного
  наблюдения нет.
- **Лимит на число тем в приватном чате** — не измерялся, в документации не
  найден.
- **Поведение при `message_thread_id` несуществующей темы** — шаг замера,
  который отправлял бы в заведомо удалённую тему, не делался.
- **Точная версия сервера Bot API на дату замера** — не публикуется (см.
  раздел «Версия Bot API» выше). Нижняя граница 9.2 выведена из наличия поля
  `has_topics_enabled`, верхняя не установлена.
- **Работает ли это у произвольного бота** — замер сделан на одном боте
  (`G1zm0_bot`). `has_topics_enabled` — поле объекта `User`, то есть
  свойство конкретного бота; значит, у другого бота оно может быть `false`,
  и тогда встанет вопрос про @BotFather, здесь не отвеченный.
