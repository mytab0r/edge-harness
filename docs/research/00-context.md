# Контекст: откуда взялась задача

> Записано 2026-08-28. Это документ о замысле, а не о фактах внешних систем —
> факты лежат в соседних файлах, см. [карту](../INDEX.md).

## Что было до

Существует рабочий харнес самразработки на Python: цикл из шести стадий (план → критик →
ревизия плана → реализация → ворота → ревью), изоляция в git-worktree, детерминированные
ворота (pytest, скан секретов, размер диффа), бюджет-гарды, апрувы через Telegram на
защищённые пути, три workflow в GitHub Actions (selfdev, tick, pr-loop) и Cloudflare Worker
с D1 для входящих сообщений и разбудки раннера.

Там же живёт `ProviderChain` — цепочка провайдеров моделей с fallback и персистентным
cooldown: отказ классифицируется по тексту (usage limit → парсится время сброса,
rate limit/429 → 15 минут, overloaded/529 → 5 минут, credit balance → 6 часов,
невалидный ключ → 24 часа), кулдаун переживает перезапуск в SQLite.

Работает. Не хватало одного: **веб-морды**. Посмотреть, что цикл делает прямо сейчас,
поставить задачу не через коммит в `backlog.yaml`, вмешаться в идущую сессию — было нечем.

## Что предложил владелец

Взять готовый фреймворк — DeepSeek Harness — как платформу, и докручивать своё плагинами,
вместо того чтобы собирать систему из разрозненных решений. Ключевая формулировка:

> Полностью модульная система харнеса, построенная на событийных действиях. То есть
> что-то делает только когда надо.

Требования, которые из этого следуют:

1. Морда доступна **всегда**, а не пока жив какой-то процесс.
2. Что может делать фронт — делает фронт.
3. «Руки» (исполнение команд, git, тесты) — раннеры или удалённая машина.
4. У морды есть механизм понимания статуса рук.
5. Всё это на **бесплатных** планах Cloudflare и GitHub.

Пункт 5 — не пожелание, а ограничитель, определивший архитектуру. Из него следует публичный
репозиторий: на публичных репозиториях standard-раннеры GitHub Actions бесплатны и без
лимита минут.

## Что выяснилось в ходе исследования

Три вещи, которые изменили первоначальный замысел:

**DSH действительно платформа со швами** — исполнение команд, хранилище сессий, провайдер
моделей и даже сам агентский цикл объявлены подменяемыми, и подмена делается строкой в
конфиге, без форка. Замысел владельца в этой части подтвердился полностью.

**Но мультипровайдерность у DSH — это пул выбора, а не роутер.** Модели всех настроенных
провайдеров попадают в один список, откуда выбирают вручную. Автоматического fallback,
балансировки и ротации нескольких учёток одного провайдера там нет. То есть заменить
`ProviderChain` штатным плагином нельзя — логику ротации придётся написать самим, просто
она переедет внутрь `LlmAdapter`.

**Бесплатные планы жёстче, чем ожидалось.** Cloudflare Free даёт 10 ms CPU на каждый вызов
(и каждое входящее WebSocket-сообщение считается отдельным вызовом), а один постоянно живой
Durable Object съедает 85% дневного бюджета GB-s. GitHub Terms прямо запрещают использовать
Actions для активности, не связанной с разработкой самого репозитория. Вместе это закрыло
два очевидных на вид решения — агент-цикл в облаке и WebSocket-туннель к раннеру.

## Что выбрано

Морда на Workers Assets, журнал и очередь в Durable Object, агент-цикл целиком в job'е,
который поднимается по `repository_dispatch` и умирает после работы.

Принятая плата: между «поставил задачу» и «руки начали» проходит недокументированное время
старта job'а. Для автономного цикла это неважно, для живого чата будет заметно.

Развёрнутое обоснование — в [ADR 0001](../decisions/0001-push-model-not-tunnel.md) и
[ADR 0002](../decisions/0002-loop-in-runner-not-do.md).
