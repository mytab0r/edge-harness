# ADR 0017. Второй гейт морды dsh-edge: e2e-смоук на PR против локального воркера

- **Дата:** 2026-09-07
- **Статус:** принято
- **Смежное:** [ADR 0004](0004-api-contract.md) («Два ворот» для cf-worker),
  [issue #502](https://github.com/mytab0r/edge-harness/issues/502)
  (прод-смоук `dsh-edge/e2e-smoke/smoke.mjs`), [issue #600](https://github.com/mytab0r/edge-harness/issues/600),
  [research/20](../research/20-cloudflare-free.md) (лимиты Free-плана).

## Инцидент, из которого выросло решение

Один апстрим-бамп dsh-edge дал владельцу четыре регрессии интерфейса подряд
(удалённый пакет, изменённый API сессии, коллизия неймспейса локали, коллизия
видимой метки вкладки — issue #518 и смежные). Три из четырёх поймал
`dsh-edge/e2e-smoke/smoke.mjs` (issue #502) — но ПОСЛЕ деплоя в прод
(`deploy-dsh-edge.yml`), когда сломанный интерфейс уже отдаёт трафик.
Health-check (канарейка корня, HTTP 200) был зелёным во всех четырёх случаях:
регрессия видна только реальным браузером на реальных вкладках Settings, а не
кодом статуса ответа.

ADR 0004 уже решил ровно эту задачу для cf-worker («edge-harness»): канарейка
на PR против локального `wrangler dev`, канарейка после деплоя против прода —
«сломанная страница не доезжает до прода и не живёт там». Для dsh-edge второй
ворот не было: единственный e2e-смоук стоял только на втором (прод) вороте.

## Главный вопрос: против чего гонять на PR

Прод трогать нельзя — общий, живой, единственный. Рассмотренные варианты:

1. **Preview-деплой на отдельное имя воркера в Cloudflare** (например
   `dsh-edge-pr-<N>`), прогон смоука, снос воркера в конце. Отвергнуто:
   Cloudflare Free — лишний воркер и его гарантированная уборка (в том числе
   при падении job'а до шага уборки) реальное ограничение, а не формальность;
   каждый прогон тратил бы настоящую суточную квоту чтений Durable Objects
   (сегодня уже превышена, 149.8%, research/20) на создание/использование
   реального DO; требует `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` —
   недоступны PR из форка.
2. **Локальный эфемерный воркер через `unstable_dev`** (JS API wrangler,
   Workers-рантайм на месте — тот же `workerd`, что в проде, но с локальной
   SQLite-эмуляцией DO). Тот же приём уже дважды доказан в этом репозитории:
   `dsh-edge/ingest-integration/check.mjs` и `dsh-edge/proxy-integration/
   check.mjs` гоняются в `deploy-dsh-edge.yml` на каждом деплое, поднимая
   собранный артефакт локально, без единого обращения к настоящему
   Cloudflare API. **Выбрано.**
3. **`wrangler dev` CLI-процессом в раннере** (как в `worker-ci.yml` для
   cf-worker) — тоже локально и без Cloudflare, но dsh-edge использует
   `services`-биндинг на журнал (`HARNESS_SERVICE`), а без него раздел
   Integrations получил бы 503 «not configured» и смоук ложно покраснел бы
   на неотносящейся к PR причине. `services`-биндинг между двумя независимо
   запущенными CLI-процессами `wrangler dev` разрешается тем же локальным
   dev-registry, но `unstable_dev` даёт то же самое ОДНИМ Node-процессом (два
   `unstable_dev`-воркера — сама морда + заглушка журнала — резолвят
   биндинг друг на друга без отдельной оркестрации CLI-процессов,
   readiness-поллинга для каждого и управления их временем жизни вручную).
   Отвергнуто как более сложное решение той же задачи без выигрыша.

Итог: **вариант 2**. Ноль обращений к настоящему Cloudflare API/аккаунту —
ноль расхода суточной квоты чтений Durable Objects (замер — «Стоимость»
ниже); ноль секретов (см. «Секреты и форки»); переиспользование уже
проверенной в проде техники, а не новая инфраструктура.

## Решение

1. Новый workflow `.github/workflows/dsh-edge-pr-smoke.yml`, триггер
   `pull_request` с путями `dsh-edge/**` (манифест, пин апстрима, патч-серия,
   кодогенерация/сборка/гвардия и сам e2e-смоук — всё под этим путём).
   `plugins-src/**` сознательно исключён — по той же причине, по которой его
   не читает `deploy-dsh-edge.yml`: сборка берёт плагины готовыми релизами по
   sha256 из `dsh-edge/plugins.json`, правка исходника плагина БЕЗ бампа
   sha256 не меняет то, что реально соберётся, и прогон смоука был бы
   холостым.
2. Job строит ТОТ ЖЕ артефакт, что и `deploy-dsh-edge.yml` (клон на пине →
   патч-серия → плагины по манифесту со сверкой sha256 → pnpm add → кодоген →
   дым инсталла плагинов → сборка → гвардия состава → контракт/детерминизм),
   БЕЗ Cloudflare-специфичных шагов: без `wrangler deploy`, без секретов
   провайдера/интеграций, без косметических патчей (бренд, каталог моделей —
   они не читают консоль/сеть браузера и не влияют на предмет проверки).
3. Новый скрипт `dsh-edge/e2e-smoke/pr-check.mjs` поднимает собранный
   артефакт через `unstable_dev` (тот же приём, что ingest/proxy check.mjs):
   фиктивный `DSH_EDGE_ACCESS_KEY`, заглушка журнала (второй `unstable_dev`
   с `services`-биндингом `HARNESS_SERVICE`, отдаёт пустую страницу событий
   200 OK — без неё раздел Integrations честно получил бы 503 и смоук ложно
   покраснел бы). Прогоняет ОБЩУЮ с прод-смоуком логику обхода вкладок
   Settings и сбора находок консоли/сети — вынесена в
   `dsh-edge/e2e-smoke/browser-walk.mjs` (issue #600), чтобы прод- и
   PR-смоук не расходились в две независимые копии одной и той же проверки.
4. Пустой манифест (аварийный npm-префаб маршрут) — e2e-браузерный шаг
   пропускается: собирать локальный воркер не из чего (нет клона, нет
   плагинов); это редкий аварийный путь, не активная конфигурация морды, и
   прод-смоук после реального деплоя всё равно гоняется на любом маршруте.

## Секреты и форки

Ни одного секрета репозитория не требуется. `DSH_EDGE_ACCESS_KEY` и
`HANDS_TOKEN` для локального воркера — фиктивные строки, собранные в
`pr-check.mjs` (не настоящие секреты — локальный `unstable_dev`, эфемерный
процесс). `gh release download` — публичным `GITHUB_TOKEN` (репозиторий
публичный, ассеты релизов читаются без PAT). `CLOUDFLARE_API_TOKEN`/
`CLOUDFLARE_ACCOUNT_ID` не используются ни на одном шаге. Итог: workflow
гоняется одинаково и на PR из форка — там секретов репозитория нет вообще,
но этому пайплайну они и не нужны.

## Стоимость

- **Cloudflare Durable Objects:** 0 чтений на прогон. `unstable_dev` не
  обращается к настоящему Cloudflare API — вся DO SQLite внутри него
  эмулируется локально (временный файл на диске раннера, стирается вместе с
  job'ом). Суточная квота чтений DO этим workflow не расходуется вообще —
  критично при уже превышенной сегодня квоте (149.8%, research/20).
- **Cloudflare-ресурсы:** 0 — ни один воркер, DO namespace или иная сущность
  на Cloudflare не создаётся и не удаляется. Уборка сводится к остановке
  двух Node-процессов в конце `pr-check.mjs` (`finally`, безусловно, включая
  путь отказа) — на Cloudflare убирать нечего.
- **Время CI:** ~5-10 минут на PR, где путь `dsh-edge/**` задет (клон
  апстрима, скачивание 4 released tgz, pnpm add, сборка, e2e — тот же
  порядок величины, что уже платит `deploy-dsh-edge.yml` на каждом деплое).

## Мутационная проверка

`pr-check.mjs`/`browser-walk.mjs` обязаны красить сборку при живой
регрессии интерфейса и не красить на чистой сборке. Проверено намеренной
поломкой коллизии неймспейса локали (issue #518/#547 — тот же класс, что
уже ловил прод-смоук) на текущем составе манифеста (4 плагина, пин
`dsh-edge-v0.11.1`) с последующим откатом; результат и разбор — в PR #600.

## Цена

- Дублирует часть шагов сборки `deploy-dsh-edge.yml` (клон, патчи, плагины,
  кодоген, build, verify) в отдельном workflow — сознательный компромисс:
  рефакторинг сборки в переиспользуемый composite action/reusable workflow
  дал бы DRY, но требует трогать боевой деплой-пайплайн ради задачи, которая
  этого не требует; риск для прод-пайплайна не оправдан этой задачей (см.
  proposal issue #600, «Не в объёме»). Гвардия класса #43
  (`test_dsh_edge_pnpm_guard.py`) расширена на новый workflow, чтобы
  дублирование не разошлось по дисциплине «pnpm, не npm».
- Новый workflow добавляет ~5-10 минут CI на PR, трогающие `dsh-edge/**` —
  цена соразмерна цене регрессии, которая иначе доезжает до прода.

## Когда пересмотреть

- Сборка `deploy-dsh-edge.yml` вырастет ещё сложнее (новые шаги, новые
  гварды) — тогда цена дублирования шагов в двух workflow превысит цену
  рефакторинга в reusable workflow/composite action; пересмотреть вместе с
  design.md `openspec/changes/dsh-edge-plugin-system/`.
- Cloudflare Free перестанет быть ограничением (переход на платный план) —
  preview-деплой на отдельный воркер станет жизнеспособной альтернативой с
  более точным воспроизведением прод-условий (реальный DO, а не эмуляция);
  на сегодня цена (квота, лишний воркер, секреты) перевешивает эту точность.
