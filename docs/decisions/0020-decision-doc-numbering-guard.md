## Контекст

`docs/decisions/NNNN-*.md` и `docs/research/NN-*.md` — сквозная нумерация, назначаемая
вручную автором PR. Общий числовой ресурс без арбитра конкурирует между независимыми PR
(ровно та регрессия, что ADR 0016 предсказал для номеров инвариантов — здесь тот же класс
проявился на другом носителе). Три живых случая на момент этого ADR:

1. PR #1035 ввёл ADR `0017-stalled-pr-merge-conflict-triage.md`, хотя номер 0017 уже занят
   в main (`0017-dsh-edge-pr-smoke-local-worker.md`, слит раньше). После кругов ai-review
   файл переименован в `0019`, пропустив `0018` без объяснения.
2. Независимый канал держал незакоммиченный `docs/decisions/0015-parallel-work-on-shared-
   code-boundaries.md` — номер 0015 в main занят другим ADR
   (`0015-inbox-dispatch-no-new-secret.md`), а тот же смысл уже слит как `0016`.
3. Живой прогон гвардии (см. «Реализация» ниже) на текущем состоянии репозитория нашёл
   ТРЕТИЙ, ещё не замеченный случай: PR #944 независимо занял номер 0017 файлом
   `0017-delayed-branch-deletion-not-delete-on-merge.md`, тоже коллизия с уже слитым
   `0017-dsh-edge-pr-smoke-local-worker.md`.

## Развилка 1: сквозная нумерация или смена схемы

Проверено по `docs/research/30-rejected-alternatives.md` — схема нумерации ADR/research там
не упомянута, решение принимается впервые.

Цена смены схемы (замер на дереве репозитория, 2026-09-13 — плывёт с каждым слиянием,
подробный снимок и команды в design.md этого change, порядок величин не меняется): 19
файлов `docs/decisions/` + 13 `docs/research/`, 69 + 226 = 295 markdown-ссылок на них в
36 + 96 = 132 файлах. Переход на,
например, `decision-<issue>-<slug>.md` потребовал бы переименовать все файлы и переписать
все ссылки (`git mv` не чинит текст ссылки), а устные упоминания в уже слитых коммитах/PR
(«ADR 0016») стали бы отсылать в никуда без исторического контекста. Выгода смены схемы —
устранение риска коллизии номера — достигается дешевле гвардией ниже, без переименования.
**Сквозная нумерация остаётся** — хронология номеров (ADR 0016 рядом с 0017) не приносится
в жертву без причины дороже самой проблемы.

## Развилка 2: атомарная бронь номера (git-ref lock, ADR 0006) или CI-гвардия

ADR 0006 уже даёт атомарный примитив (`refs/locks/task-<N>`, 422 на повторный POST). Он
мог бы забронировать номер ДО того, как автор напишет файл — коллизия физически
невозможна с первого шага, не только на CI.

**Не выбрано** для этого класса: аренда задачи в ADR 0006 защищает дорогой ресурс
(назначение исполнителя — целый проход воркера); номер ADR — дешёвый, коллизия чинится
переименованием одного файла в PR, который ещё не слит. Бронь требует лишнего шага ДО
написания файла, который легко забыть — в отличие от `claim_task`, здесь нет воркера,
принудительно вызывающего бронь первым действием. Выбрана гвардия: она не устраняет
секундное окно гонки между двумя PR, стартующими одновременно, но делает коллизию
**невозможной в main** — первый из двух коллизирующих PR, дошедший до слияния, «выигрывает»
номер; CI второго покраснеет ДО его собственного слияния, автор обязан переименовать.

## Реализация

`scripts/lib/decision_numbering.py`:

- `NUMBERED_ROOTS = {"docs/decisions": 4, "docs/research": 2}` — одно место, знающее оба
  носителя класса (`openspec/changes/<id>` не подходит — там ключ слаг, не число, коллизии
  номеров там нет по конструкции).
- `next_free_number` — следующий свободный номер, вычисленный из main ∪ всех открытых PR
  (не только локального каталога) — `decision_numbering.py next <root>`.
- `find_number_collisions` — коллизия: номер занят РАЗНЫМИ именами файлов в разных
  источниках **или внутри одного** (например main сразу после того, как два независимо
  коллидирующих PR слились без git-конфликта, — пути разные, конфликта не видно;
  находка ai-review PR #1082: значение `parse_numbered_files` — список, не строка, иначе
  второй файл тихо затирал первый). Тот же номер + то же имя (main и PR, который его лишь
  несёт) — не коллизия.
- Данные собираются РЕАЛЬНЫМ git (`fetch --depth 1` + `ls-tree`/`diff --diff-filter=AR`
  на двух отдельных рефах, БЕЗ диапазона), не GitHub REST files — PR учитывается только
  тем, что он сам ДОБАВИЛ или ПЕРЕНОМЕРОВАЛ (`R`, находка ai-review PR #1082 —
  `--diff-filter=A` без `R` терял переименование унаследованного файла) относительно
  main, иначе PR, просто наследующий уже смердженный файл, ложно засчитывался бы
  участником коллизии (живой случай, найденный при первом прогоне: 19 из 20 посторонних
  PR ошибочно попадали в список коллизии по номеру 0017, потому что все они просто
  содержат уже смердженный `0017-dsh-edge-pr-smoke-local-worker.md`). Диапазон (тройная
  точка `A...B`) отклонён отдельной находкой ai-review PR #1082: `job test` чекаутит
  `actions/checkout@v7` без `fetch-depth: 0` (shallow-клон), а тройная точка требует
  существующего merge-base — `no merge base` красил бы `test` на КАЖДОМ PR репозитория;
  прямое сравнение двух деревьев истории не требует вообще, `--depth 1` при фетче — тоже
  следствие этого же вывода.
- Гвардия `scripts/ci/guards/decision-doc-numbering-guard.sh` (каталог #749, без правки
  `repo-ci.yml`) красит CI, но **только прогон той ветки, которая реально ВИНОВНА в
  найденной коллизии** (`self_source_name`) — без этого сужения долг ОДНОГО PR (пример:
  #944) красил бы обязательную проверку `test` у КАЖДОГО постороннего открытого PR
  репозитория (AGENTS.md, «тормоз без газа не принимается»: единственный тормоз, который
  умеет снять только виновник, не должен вешаться на всех). `main` — особый, НЕ
  симметричный случай (issue #1200, найдено 12+ красными подряд пост-мерж прогонами
  `workflow_dispatch` 2026-09-13/14): `push`/`workflow_dispatch` резолвит `self_name` в
  буквальное `"main"`, а main легитимно «участвует» в ЛЮБОЙ коллизии вокруг номера,
  который он держит, — в том числе там, где вторая сторона это сторонний, ещё не
  смёрженный PR (#944/0017, #667/0018). `main` виновен ТОЛЬКО если ВНУТРИ самого main
  реально сидит дубль — минимум два разных имени файла, оба исключительно из main
  (`main_has_intra_duplicate`) — НЕ то же самое, что `involved == {"main"}`: множество
  участников остаётся `{"main", "PR #N"}`, даже когда дубль сидит внутри main, а рядом
  просто ещё висит сторонний открытый PR (блокирующая находка ai-review PR #1202, живая
  проверка `main_has_intra_duplicate` по `occurrences`, не по `involved`). Тот же приём
  (условие `involved != {"main"}`, БЕЗ этого уточнения) независимо выбрал
  `scripts/lib/invariant_numbering.py::cmd_check` (issue #904/PR #1201) — та же неточность
  живёт там сейчас, зафиксирована отдельно как issue #1227 (не в объёме этого ADR). Гвардия
  ловит коллизию только
  на push/PR — периодический инвариант в `repo_invariants.py`, закрывающий дрейф состояния
  без нового коммита, отложен до слияния PR #1076 (тот же файл правит параллельно, класс
  ADR 0016) — обвязка `check_decision_doc_number_collisions` готова, подключение — задача
  #1090.

Поведенческий тест — `scripts/lib/test_decision_numbering.py`, настоящий временный
git-репозиторий (bare origin + рабочий клон, приём `test_mechanical_rebase.py`), не проверка
имён функций.

## Не в объёме

#904 (номера инвариантов `repo_invariants.py`) — тот же класс, другой носитель (ручные
int-константы в одном файле, не каталог пронумерованных файлов); решение для НУМЕРАЦИИ там
другое (стабильный строковый ключ вместо числа). Реализация (`scripts/lib/
invariant_numbering.py`, issue #904/PR #1201, слит) фактически ИМПОРТИРУЕТ этот модуль
(`build_refs`, `self_source_name`, `find_number_collisions`, `added_files_under_root`) —
переиспользует его целиком, кроме `cmd_check`: свою копию условия виновности main пишет
заново, той же формой `involved != {"main"}`, что и была здесь ДО этого PR (issue #1200) —
неточность (не различает «main виновен» от «main просто среди участников») теперь живёт
там, задача #1227 фиксирует её отдельно (не в объёме #1200/этого ADR). Уже заведена
отдельной задачей, не расширяется этим ADR.
