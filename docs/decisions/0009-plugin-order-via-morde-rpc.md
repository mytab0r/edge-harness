# 0009. Заказ установки плагина: RPC морды (session.prompt), не POST /api/tasks

Дата: 2026-09-03. Задача: #113. Смежные: [ADR 0004](0004-api-contract.md),
[#105](https://github.com/mytab0r/edge-harness/issues/105) (белое пятно:
журнал и морда — разные origin),
[#133](https://github.com/mytab0r/edge-harness/issues/133) (GitHub API 403
из egress морды),
[30-rejected п.5](../research/30-rejected-alternatives.md) (рантайм-установка
кода на CF Free невозможна).

## Контекст

Задача #113: кнопка «Заказать установку» в разделе «Плагины» морды должна
создать заказ конвейера #80 (форж → релиз + sha256 → PR в каталог → деплой).
Задача допускала два транспорта: «задача в пул» (`POST /api/tasks` журнала)
или «сообщение агенту через морду».

Раздел «Плагины» — клиентский DSH-плагин в морде dsh-edge. Журнал
edge-harness — другой origin: кука `harness_session` — `SameSite=Strict`,
CORS журнал не отдаёт (#105), поэтому ни читать `/api/events`, ни писать
`POST /api/tasks` из браузера морды нельзя. Единственный существующий
прокси — PR #230 (только GET статусов), он ещё не слит. Рост патч-серии
dsh-edge ограничен порогом 6 ([PATCHES.md](../../dsh-edge/PATCHES.md)):
на main их 4, PR #230 добавит 5-й, write-прокси стал бы 6-м. Одновременно
agent морды не может исполнить заказ сам: GitHub API из egress морды
блокирован (#133).

## Решение

Заказ — **сообщение агенту через штатный RPC морды**: `session.prompt`
(mode `queue`) в выделенную сессию `plugin-orders` (идемпотентный
create-or-reuse по фиксированному sessionId + pinned title), same-origin,
без новых патчей, секретов и правок deploy-workflow. Заказ несёт
машиночитаемый маркер `[plugin-order:<id>]` и готовую формулировку из
каталога [`dsh-edge/plugins-catalog.json`](../../dsh-edge/plugins-catalog.json);
дедупликация — по маркеру в хвосте истории сессии заказов
(`session.history`, окно 20 сообщений).

## Последствия

- (+) Работает сегодня, не конфликтует с открытыми PR #230/#231/#162 в той
  же области, патч-серия не растёт.
- (+) Заказ виден владельцу как обычный чат — «умный принцип» эпика #77
  в прямом смысле.
- (−) Исполнение заказа агентом морды упирается в #133 (egress 403): заказ
  доставлен, но до его снятия конвейер выполнят руки (пул/воркер). Это
  ограничение всех морда-путей, не выбранного транспорта.
- (−) Дедупликация держится на истории сессии: окно 20 сообщений —
  объявленный газ (заказ, ушедший за окно, можно перезаказать); «навсегда»
  запирать нельзя, потому что отказавший конвейер никогда сам не разрешит
  блокировку.
- Перенос заказа в пул журнала (`POST /api/tasks`) становится осмысленным,
  когда появится write-прокси на стороне морды (продолжение PR #230) —
  тогда задача в пуле даст заказу руки-джобу немедленно, а журнал станет
  единственным местом правды и о статусах, и о заказах. Кнопка и каталог
  при этом не меняются — меняется только транспорт внутри `sendOrder`.

## Альтернативы

- **POST /api/tasks через новый патч-прокси морды** — отвергнута сейчас:
  дублирует часть диффа открытого PR #230 (секреты `HANDS_TOKEN`/`HARNESS_URL`
  в deploy-dsh-edge), доводит патч-серию до порога, а выигрыш (немедленный
  hands-job) нивелируется #133 для морда-путей и существованием пульса
  воркера, который задачи из пула и так подхватывает.
- **localStorage как место правды заказов** — отвергнута: правда о заказе
  обязана переживать браузер и быть видной владельцу вне этой машины
  (история сессии в DO), а не жить в одном браузере.
- **Отдельный endpoинт/воркер для заказов** — отвергнута: против жёсткого
  ограничения владельца «весь UI — DSH-плагин внутри морды, никаких отдельных
  фронтов».
