# ADR 0002. Агентский цикл в раннере, а не в Durable Object

- **Дата:** 2026-08-28
- **Статус:** принято
- **Смежное:** [Cloudflare Free](../research/20-cloudflare-free.md),
  [архитектура DSH](../research/10-dsh-architecture.md),
  [ADR 0001](0001-push-model-not-tunnel.md)

## Контекст

Исходное пожелание звучало как «что может делать фронт — делает фронт, руки только
исполняют». В пределе это означает: агентский цикл живёт в облаке, а раннер вызывается на
отдельные команды.

Технически это выглядело достижимым. Ядро DSH почти свободно от Node: из 45 файлов
`packages/core/*/src/` node-импорты есть в трёх, и все четыре используемых модуля доступны в
Workers с `nodejs_compat`. Более того, в репозитории DSH лежит
`packages/experimental/webworker-runtime`, где всё дерево плагинов запускается внутри
одного Web Worker без Node-хоста. Агентский цикл к тому же объявлен подменяемым швом, а
`ReactLoopAgent` — не резидентный `while(true)`, а машина состояний, просыпающаяся от инбокса.

## Решение

Агентский цикл целиком исполняется в job'е. Durable Object держит журнал сессий, очередь
задач, heartbeat рук и WebSocket с браузером.

## Причины

**10 ms CPU на вызов.** На Workers Free это лимит на invocation, и Durable Objects
подчиняются ему наравне с обычными воркерами: «Durable Objects are Worker scripts, and have
the same per invocation CPU limits as any Workers do». Каждое входящее WebSocket-сообщение
считается отдельным вызовом.

Ожидание сети CPU не тратит — «not time spent waiting on network requests, storage calls, or
other general I/O». Но разбор потока от модели тратит: парсинг JSON каждого чанка, сборка
сообщений, проекция истории. Держать цикл в Durable Object на бесплатном плане означает
укладывать всю синхронную обработку между await'ами в 10 миллисекунд — работа на грани,
причём грань установлена не нами и может двинуться.

**Один живой объект на весь аккаунт.** Непрерывно активный Durable Object расходует ~11 059
GB-s в сутки при дневном бюджете 13 000. Цикл, который «думает» в облаке часами, не оставит
бюджета ни на что другое.

**Гранулярность из [ADR 0001](0001-push-model-not-tunnel.md).** Раз job получает задачу
целиком, а не отдельную команду, цикл всё равно должен жить там, где исполняются команды.
Разнести их — значит вернуть per-command вызовы и вместе с ними туннель.

**В раннере лимитов нет.** Настоящий Linux, настоящие git и pytest, шесть часов на job.

## Последствия

**Принимаем:** цикл не «в облаке». Формально это отход от исходной формулировки — но
наблюдаемое поведение то же: морда жива всегда, показывает состояние и принимает задачи.

**Принимаем:** состояние драйвера не переносится между процессами. DSH персистит только лог
сессии; инбокс и фаза цикла не сериализуются, новый процесс стартует с пустым инбоксом.
Значит job обязан подхватывать сессию через `resume()` из журнала, а не рассчитывать на
живое состояние.

**Получаем:** Durable Object выполняет только CPU-дешёвые операции — принять событие,
записать строку, разослать подписчикам. Это надёжно укладывается в 10 ms и гибернирует между
задачами.

**Узкое место, за которым следить:** 100 000 записей строк в сутки на бесплатном плане. Сессия
агента генерирует сотни событий; при батчинге запас есть, без батчинга — кончится быстро.

## Когда пересмотреть

Переход на Workers Paid: 30 секунд CPU по умолчанию и до 5 минут через `limits.cpu_ms`
снимают главное возражение. Тогда вариант «цикл в Durable Object, руки в Containers»
становится осмысленным — и заодно убирает задержку старта job'а.
