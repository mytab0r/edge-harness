# ADR 0003. Задержка старта job'а: годится ли для интерактивного сценария

- **Дата:** 2026-08-28
- **Статус:** принято (по данным первых замеров; ревизия — после снятия хвоста распределения)
- **Смежное:** [ADR 0001](0001-push-model-not-tunnel.md),
  [известные неизвестные](../research/99-open-questions.md),
  [GitHub Actions](../research/21-github-actions.md)

## Контекст

[ADR 0001](0001-push-model-not-tunnel.md) принял плату за push-модель: между «поставил
задачу» и «руки начали» проходит недокументированное время старта job'а. Для автономного
цикла это было признано несущественным, для живого чата — заметным. Разметка walking
skeleton требовала измерить это число до того, как на него ляжет вся система.

## Данные

22 последовательных замера «`repository_dispatch` → первый heartbeat» на живом воркере
(2026-08-28, ~11:55–12:35 UTC), таймаут 600 с, таймаутов нет:

| | значение |
|---|---|
| min | 6.8 с |
| медиана | **8.3 с** |
| p90 | 10.8 с |
| max | 17.0 с |

Сырые данные: [data/dispatch-latency-2026-08-28.csv](../research/data/dispatch-latency-2026-08-28.csv).
Замер по часам Durable Object (`latency_ms` в задаче) — не зависит от часов машины-измерителя.

За тот же сеанс CPU-расход DO: P50 0.75 мс, P99 1.6 мс на запрос — транспорт удорожания
задержки не создаёт (0 ошибок на 450 запросов).

## Решение

**Задержка приемлема для интерактивного сценария морды** — с явными оговорками:

1. «Морда всегда жива, руки поднимаются по требованию» работает: кнопка → задача в
   очереди мгновенно, первые признаки жизни рук — медианно через 8 секунд, полный
   жизненный цикл job'а виден в журнале в реальном времени.
2. Для живого чата с моделью 8 секунд тишины на старте заметны, но это время до
   **начала** работы, а не до ответа: журнал начинает наполняться событиями сразу
   после heartbeat.
3. Архитектурного ответа «сделать быстрее» нет и не нужно — скорость даёт только
   [Cloudflare Containers](../research/30-rejected-alternatives.md) (вопрос $5/мес,
   отвергнут отдельно), а не переделка этой схемы.

## Что замер не доказывает

- **Хвост распределения.** 22 замера за один короткий сеанс не ловят «часы в очереди»,
  на которые жалуется сообщество. Снятие хвоста (100+ замеров в разное время суток) —
  задача в пуле (#4). До неё действует правило из
  [21-github-actions.md](../research/21-github-actions.md): любое ожидание job'а —
  с таймаутом и путём отката.
- **Стабильность во времени.** GitHub не даёт SLA; числа могут меняться без анонса.
  Замер дешёвый (скрипт готов), повторять при сомнениях.

## Когда пересмотреть

- Хвост-замер покажет медиану > 30 с или регулярные многочасовые зависания — тогда
  вопрос открывается заново, и первым кандидатом остаётся CF Containers (ADR 0001,
  «Когда пересмотреть»).
- Появится сценарий, требующий отклика рук быстрее секунды (реалтайм-чат с инструментами
  в цикле) — это аргумент за Paid, не за туннель; туннель остаётся отвергнутым.
