# 0010. Интеграции внешних систем: REST-инструменты своим edge-плагином, не MCP-серверы

Задача: [#115](https://github.com/mytab0r/edge-harness/issues/115). Дата: 2026-09-03.
Смежные: [ADR 0002](0002-loop-in-runner-not-do.md) (цикл — не в DO), [runner-bridge #95](https://github.com/mytab0r/edge-harness/issues/95),
[plugin-manager #102](https://github.com/mytab0r/edge-harness/issues/102).

## Решение

Интеграция внешней системы = **свой DSH-плагин морды** (один пакет
`@edge-harness/dsh-plugin-integrations`, прецеденты — runner-bridge для
серверной половины, plugin-manager для клиентской):

1. **Инструменты агента** — тонкие REST-обёртки в одной системе координат с
   runner-bridge: `jira_issue`, `confluence_page`, `bitbucket_pr`,
   `slack_post`. Каждый — один HTTP-вызов (I/O, не CPU): тяжёлая работа
   уезжает раннеру через `runner_task`, исполнение интеграций в DO не
   тащится ([30-rejected п.6](../research/30-rejected-alternatives.md)).
2. **Креды** — секреты репозитория, синхронизируемые деплоем в env воркера
   по ИМЕНАМ из реестра `dsh-edge/integrations.json` (прецедент —
   `GH_RUNNER_TOKEN`). Реестр — единственное место правды: что подключено,
   какие инструменты, чей ключ (только имена и описания, значений нет).
3. **UI** — клиентский DSH-плагин в слоте `settings.section` «Интеграции»:
   состав из реестра, живой статус — из журнала (`integration_status`,
   псевдо-задача `integration:<id>`), прецедент чтения — прокси
   `/api/harness/*` (#105). Никаких отдельных страниц (ограничение владельца
   2026-08-31: морда = DSH, UI = клиентский плагин внутри неё).

## Какие варианты рассмотрены и почему нет

**Официальные MCP-серверы Atlassian/Slack — использовать готовое.** Кандидаты
существуют: Remote MCP Server Atlassian живёт на `mcp.atlassian.com`
(эндпоинт проверен 2026-09-03 живым запросом: 401 — существует, закрыт
OAuth-авторизацией); у Slack есть MCP-документация (`api.slack.com/Docs/mcp`,
живой 200). Не взяты по решающей причине: **dsh-edge не умеет говорить MCP** —
клиент MCP в Edge не портирован вовсе ([research/11](../research/11-dsh-edge.md),
апстрим README:125: «не портированы … MCP»), единственный шов инструментов —
cordis `defineTool` (доказан runner-bridge). Подключить MCP-сервер к агенту
морды сегодня = сначала написать свой MCP-клиент, то есть всё равно «своё»,
плюс чужой облачный сервис с OAuth-грантом владельца в цепочке. Не
подтверждено: текущий состав возможностей официальных MCP-серверов (поиск по
вебу в среде воркера недоступен, проверены только существование эндпоинтов).

**МCP-серверы в раннере (headless DSH).** У headless-профиля шов инструментов
тот же — плагины (`dsh plugin --profile headless add`); MCP-мост потребовал бы
отдельного процесса-сервера в job'е ради тех же четырёх REST-вызовов. Отложено:
если инструменты понадобятся агенту раннера, тот же пакет ставится в профиль
без изменений кода (серверная половина — обычный `defineTool`-плагин).

**Хранение кредов в DO KV морды.** У dsh-edge есть `EdgeCredentialProvider`
(DO KV с фолбэком в env-секреты), но его поверхность занята реестром
провайдеров LLM (#158) и пишет только Settings → Models; для интеграций он
потребовал бы нового settings-namespace и UI-редактора. Секреты репозитория
→ env воркера закрывают критерий сегодня, повторяют доказанный путь
`GH_RUNNER_TOKEN` и держат все креды в одном месте (GitHub secrets), откуда
их уже видит владелец. Возврат: когда появится write-прокси настроек
(продолжение ADR 0009) и владелец захочет менять ключи без правки секретов.

**Отдельные инструменты под каждую систему в коде морды (без реестра).**
Отвергнуто: нарушает критерий воспроизводимости («манифест/конфиг + секреты,
без хардкода») — состав секции «Интеграции» и синк секретов читаются из
одного реестра, добавление интеграции не трогает код агента.

## Следствия

- Новая интеграция = запись в `dsh-edge/integrations.json` + секреты
  репозитория + проводка имён в env шага деплоя; гвардия проводки
  (`node dsh-edge/integrations.mjs`) красит CI/деплой, если имена разошлись.
- Значения секретов и их производные не светятся в выводах инструментов:
  `scrub()` в `server/core.js` снимает значение, его base64-форму и
  фактический Basic-заголовок (`base64("user:секрет")` — строится из той же
  пары, что и `Authorization`, а не собирается из частей) — GitHub маскирует
  в логах только точное совпадение.
- Статус интеграции честный: `ready` / `not_configured` (каких секретов нет)
  / `failed` — из журнала, пишется шагом деплоя, читается секцией UI.

## Возврат

- dsh-edge портирует MCP-клиент (перестанет быть верным README:125
  апстрима) → переоценить официальные MCP-серверы Atlassian/Slack против
  своих REST-инструментов.
- Владелец захочет менять ключи из UI без правки секретов репозитория →
  DO KV / settings-namespace для кредов интеграций.
