# ADR 0004. Контракт API: один источник, ключевой доступ, канарейки на двух воротах

- **Дата:** 2026-08-28
- **Статус:** принят; воркер, чей контракт описан здесь, списан в #86 — форма
  ответа журнала живёт как `GET /api/harness/events` на морде dsh-edge
  ([спека](../../openspec/specs/journal-tasks-hands.md)), источник — сессия
  конвейера, а не DO воркера. Текст ниже — история решения, не текущее поведение.
- **Смежное:** [ADR 0003](0003-dispatch-latency-verdict.md),
  [тестовый стек CF](../research/22-cf-testing-toolchain.md)
  (гвардии контракта фронта жили в `cf-worker/scripts/check-frontend-contract.mjs`
  — списано вместе с воркером, история в git)

## Инцидент, из которого выросло решение

После рефакторинга страницы владелец не смог войти в морду: клиент звал
`/api/api/status` — двойной префикс. Клиентский конфиг хранил полные пути **и**
отдельный префикс, а хелпер склеивал то и другое. Сервер, API-тесты и API-смок были
зелёные — сломана была только логика страницы, которую никто не проверял. До прода
дошло; в проде бы не осталось, если бы сломалось что-то крупнее.

## Разбор по источнику проблемы

Вопрос не «каким тестом поймать», а «как сделать класс ошибки невоспроизводимым».
Класс ошибки: **путь API существует в коде как строка, которую можно собрать неправильно.**

| Слой защиты | Что закрывает | Почему это архитектура, а не тест |
|---|---|---|
| `api-spec.json` — единственный источник | Маршрут объявляется один раз: метод, путь, auth, описание. Серверный роутинг построен на этой таблице (`matchRoute`) — «объявлен, но не подключён» невозможно выразить | Таблица **и есть** роутер |
| Клиент работает только ключами | `route("status")` / `routeQ("events", {after})` — путь приходит из таблицы, склеивать префиксы не с чем; неизвестный ключ — громкое исключение | Конкатенация путей в клиентском коде отсутствует как операция |
| Гвардия `npm run check` | Клиентская таблица ≡ спеке; в `app.js` литералы `/api…` запрещены; ключи локализации существуют; `docs/api.md` не устарел | Нарушение невозможно закоммитить мимо CI |
| Канарейка UI (Playwright) | Полный вход в морду реальным браузером: гейт → статус → журнал → WebSocket | Ловит сломанную страницу при живом API — класс инцидента |
| Два ворот | На PR — канарейка против `wrangler dev` (до прода); после деплоя — против прода | Сломанная страница не доезжает до прода и не живёт там |
| `.gitattributes` (LF) | workerd падает crash-loop'ом на JSON-модулях с CRLF, которые git раздаёт на Windows | Устранён источник, а не симптом: файл физически не может приехать с CRLF |

## Решение

1. **`cf-worker/api-spec.json`** — единственное объявление маршрутов. Серверный роутинг
   табличный; клиентская таблица и документация (`docs/api.md`, генерируется командой
   `npm run docs`) производные.
2. **Клиент — доступ по ключам**: `route(name)`/`routeQ(name, params)`. Литералы путей
   в `app.js` запрещены гвардией.
3. **Спека тестируется** (`test/api-contract.spec.ts`): каждый маршрут спеки подключён
   (код ответа — не `not_found`), без токена — ровно 401, незаявленный путь/метод —
   ровно `not_found`. Дока по API (`docs/api.md`) — рендер той же спеки.
4. **Канарейки**: `scripts/canary-ui.mjs` на Playwright. В CI: job `canary` в
   `worker-ci` (против локального `wrangler dev`) и шаг после деплоя (против прода).
5. **`.gitattributes`**: `* text=auto eol=lf` + ренормализация — workerd и CRLF-JSON
   несовместимы (воспроизведено и изолировано пробами; 49 CRLF в файле — crash-loop).

## Цена

- Новый маршрут требует правки одного JSON — роутинг, доки и проверки обновляются
  сами; цена добавления ниже, чем была при разрозненных строках.
- Playwright в CI добавляет ~1–2 минуты на установку браузера.
- Гвардия ложных срабатываний не даёт: литерал в комментарии тоже будет пойман —
  это осознанная строгость.

## Когда пересмотреть

- Появится настоящий OpenAPI-потребитель (внешние клиенты, кодогенерация) — спека
  конвертируется в OpenAPI, гвардию меняет валидатор схем. Свойства «один источник»
  и «ключевой доступ» сохраняются.
