# ADR 0026: заявления агента о своей работе — машинная проверка исполнения, не критик-прочтение

- **Дата:** 2026-09-17
- **Статус:** принято
- **Задача:** [#968](https://github.com/mytab0r/edge-harness/issues/968)
- **Смежное:** [ADR 0023](0023-mutation-recipe-execution-guard.md) (родственный формат
  `MUTATION-PROOF` — разведение поверхностей ниже, п. «Два формата»), #953 (обёртки без
  защиты от обхода — тот же род: правильный путь есть, соблюдение не обеспечено), #893,
  #905/#906 (живые случаи), правило AGENTS.md «Доказывай доказыватель».

## Контекст

Код агента проходит второй гейт (`ai-review`, [ADR 0007](0007-ai-review-gate.md)), а
УТВЕРЖДЕНИЯ агента о своей работе не проверял никто: «доказательство мутацией», «прогнал
на истории», «класс закрыт везде» читались как доказательство и на них принималось решение
о слиянии. Оба живых случая пойманы ВРУЧНУЮ, чтением отчёта:

1. PR #893: заявлено «доказательство мутацией», фактически гвардия проверяла НАЛИЧИЕ имён
   функций (`check_dirty`, `check_unpushed_commits`) — вырезание тела при сохранённом имени
   проходило молча (класс описан в AGENTS.md «Поведенческий тест находит то, чего
   структурный не видит»).
2. #905/PR #906: «выводы перенесены в репозиторий» — три из шести остались в коммитах и
   открытых задачах, то есть ровно там, где следующий агент их не прочитает.

Ручное чтение отчётов не масштабируется и противоречит требованию владельца (2026-09-11):
результаты агентов должны проходить ревью, находки — искаться механизмом, а не глазами.

## Развилка: три варианта из задачи

Задача называет три пути: (1) машинная проверка воспроизводимых заявлений; (2) отдельный
проход критика по заявлениям (модели даётся дифф + список заявлений, она проверяет каждое
и возвращает вердикт); (3) комбинация.

**Выбран вариант 1** — с обязательной пометкой непроверяемого (честная граница ниже).
**Критик-проход (2) отвергнут**, по трём независимым причинам, любой из которых достаточно:

1. **Вердикт критика — такое же заявление, принятое на слово.** Критик — модель в
   отдельном прогоне; его «проверил, автор прав» — проза того же класса, что и проверяемое
   заявление автора, и её так же некому проверить (точнее, не у кого спросить: следующий в
   цепочке — тот же класс актора). Механическое исполнение — единственный путь, не
   требующий доверия к чьим-либо словам; там, где исполнение возможно, оно строже любого
   прочтения (ADR 0023: случай #1173 — заявленное и фактическое числа неразличимы чтением,
   различаются только прогоном).
2. **Цена — второй живой вызов модели на каждый PR.** Второй гейт уже стоит живого прогона
   на каждый PR; замер #252: 100 прогонов `ai-review` за 14 часов, в основном по пустым
   диффам. Всё работает на бесплатных планах (AGENTS.md) — постоянное удвоение
   модельного гейта ради проверки того, что для главного класса заявлений проверяется
   дёшево исполнением, не оправдано.
3. **Класс, ради которого задача заведена, механически воспроизводим целиком.** «Мутация
   доказана» — это ровно «сними фикс → тест обязан покраснеть → верни»: исполняемо без
   всякой модели. Остальные заявления («прогнал на истории») не воспроизводимы в CI
   принципиально — критик не сделал бы их проверяемыми, только комментировал бы
   правдоподобие.

**Условие возврата к варианту 2/3:** если накопится доля заявлений, которые не ловимы ни
исполнением, ни вторым гейтом, и по ним будут проходить слияния (факт, не гипотеза —
замерить на слитых PR тем же способом, каким ADR 0023 мерил 20 PR) — тогда отдельный
критик по НЕмеханическим заявлениям становится оправданным дополнением, не заменой
исполнения.

## Решение (носители)

Механизм, не текст (правило «Решение — это механизм, а не текст»):

- **Контракт трёх машиночитаемых блоков тела PR** (по образцу принятого блока
  «## Варианты владельца», docs/agents/PROTOCOL.md) — `scripts/lib/mutation_claim.py`:
  «## Доказательство мутацией» (строка «Тест: `python -m pytest <путь>[::<id>] -q`» +
  блок ```diff``` с патчем, снимающим фикс), «## Класс закрыт» (`Grep: <ERE>` +
  «Ожидается совпадений: <N>»), «## Непроверено машиной» (пометка читателю).
- **Живая проверка** — `scripts/lib/pr_mutation_claim_check.py`, вызывается каталогом
  гвардий (#749, `scripts/ci/guards/mutation-claim-guard.sh`) на каждый push/PR
  (repo-ci.yml), без нового workflow. Заявление о мутации исполняется ВСЕГДА, когда блок
  присутствует в теле (автор написал — он заявил); ОБЯЗАТЕЛЬНЫМ блок держится только для
  PR, меняющих `scripts/ci/guards/*.sh` — замер цены обязательности командой, не по
  памяти: 19 из 343 коммитов истории трогают каталог (~5,5%), при том что мотивирующий
  случай (#893) трогал только `scripts/git/` и `scripts/lib/` — потому «проверять только
  каталог» и было дырой первой версии механизма, закрытой в PR #1028.
- **Прогон заявления** (`run_mutation_proof`): тест зелёный ДО → патч накладывается →
  тест ОБЯЗАН покраснеть (иначе `false_claim` — заявленная мутация не проверяет
  поведение) → патч откатывается → тест снова зелёный. Ненулевой exit ≠ гвардия
  покраснела: вердикт различает `proved`/`false_claim`/`setup_error` и печатает фазы.

## Два формата мутационного доказательства — две поверхности, не конкуренты

В репозитории теперь два машиночитаемых формата одного класса заявлений. Они разведены по
поверхностям сознательно; ни один не заменяет другой, и парсер тела PR распознаёт чужую
форму адресной ошибкой, а не вводящим в заблуждение «не найдена строка Тест:»
(блокирующая находка ai-review PR #1028).

| | `MUTATION-PROOF` ([ADR 0023]) | «## Доказательство мутацией» (этот ADR) |
|---|---|---|
| Поверхность | закоммиченные файлы (код/доки/комментарии) | тело PR (не коммитится) |
| Что доказывает | заявление об ИСТОРИЧЕСКОМ состоянии: «на ref X было Y» | заявление о ГИПОТЕТИЧЕСКОМ состоянии своего же PR: «сними мой фикс — мой тест покраснеет» |
| Механизм | `git show` исторического содержимого в изолированный worktree, запуск `run`, сверка `expect` | `git apply` патча к ТЕКУЩЕМУ дереву + pytest, фазы до/под/после |
| Движок | `scripts/lib/mutation_recipe_guard.py` (гвардия `mutation-recipe-execution-guard.sh`) | `scripts/lib/pr_mutation_claim_check.py` (гвардия `mutation-claim-guard.sh`) |
| Доверенная граница команд | `run:` произвольная — но блок живёт в проревьюенном файле | `Тест:` сужена до argv-формы pytest — тело PR не проревьюировано на момент прогона |

Почему не выразимы друг через друга: мутация PR-заявления по определению не существует под
никаким ref — она не закоммичена, в этом её смысл; историческое состояние ref не
накладывается forward-патчем на текущее дерево. Плюс радиус исполнения: принимать
произвольный `run:` из непроревьюированного текста тела значило бы дать PR-тексту
произвольное исполнение с правами job'а.

## Честная граница

- **Непроверяемое машиной** («прогнал на реальной истории», «проверил живьём», …) — только
  пометка «## Непроверено машиной» + `::warning::`, НЕ блок: та же фраза легитимно
  встречается в честном пересказе чужого инцидента (как в тексте PR #1028, цитирующем
  #893), жёсткая блокировка по подстроке давала бы много ложных отказов. Это сознательно
  НЕ гвардия, и это названо вслух: непроверяемое машиной место остаётся дисциплине автора
  и вниманию ревью, не выдаётся за автоматическую проверку.
- **Аварийное восстановление дерева** (`git checkout --` после неудавшегося отката)
  возвращает версию индекса — совпадает с состоянием на входе только при чистом на входе
  дереве (как в CI-чекауте); исход несёт `tree_restored` (None/True/False), и
  `tree_restored=False` останавливает цикл заявлений — продолжение давало бы вердикты по
  чужой причине.
- **«Класс закрыт»** проверяет только заявленный признак (`grep` + число), не «везде
  вообще»: это проверка СЛОВА автора о признаке, не независимый поиск класса.

## Доказательство мутацией механизма (исполнено, не описано)

Снят ветку `if mutated.passed: return …("false_claim", …)` в `run_mutation_proof` (патчем
из тела PR #1028) — `test_run_mutation_proof_false_claim_on_pr893_fixture` покраснел,
дословный вывод прогона 2026-09-18: `AssertionError: assert 'proved' == 'false_claim'`,
`1 failed in 0.50s` (pytest рендерит сравнение как в исходнике теста —
`outcome.verdict == "false_claim"` — фактическое значение слева, заявленное справа;
находка ai-review PR #1028: в прежней цитате операнды были перепутаны местами —
цитата не дословная). Возврат патча — `1 passed`, дерево чистое. Тот же патч прогнан
end-to-end самим механизмом в CI PR #1028 (`mutation-claim[proved]`).

## Цена и газ

Тормоз: обязательный блок «## Доказательство мутацией» для PR, меняющих каталог гвардий, и
исполнение любого заявленного блока. Газ: валидный блок → проверка зелёная, мерж идёт;
отсутствует/неверной формы/ложный → `::error::` с `GAS_NOTE` — запушить любой коммит либо
переоткрыть PR (правка тела сама прогон не перезапускает: триггер `pull_request:` без
`edited`; подключать `edited` — отдельное решение о цене, каждая правка тела
перезапускала бы весь job `test` и цепочку ai-review). Метка на PR не вешается, тормоз не
копится: следующий пуш перевсегда перепроверяет.

## Не в объёме

- Замер и решение о расширении обязательного блока за пределы каталога гвардий
  (`scripts/lib/test_*guard*.py`, `scripts/git/*` — класс #893 живёт и там) — задача из
  беклога находок ревью PR #1028, решается числом, не угадыванием.
- Критик-проход по заявлениям (вариант 2) — отвергнут, условие возврата названо выше.
