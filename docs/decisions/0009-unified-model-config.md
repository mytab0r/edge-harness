# ADR 0009: Единое место правды для конфига моделей

**Статус**: Принято (2026-09-01)  
**Альтернативы**: Разные переменные для морды, раннера, веба; конфиг в каждом месте отдельно.

## Проблема

Конфигурация модели LLM (дефолтная модель и контекстное окно) была рассеяна по трём местам:
- `vars.DEEPSEEK_MODEL` — глобальная переменная для раннера и морды
- `DSH_EDGE_MODEL_CATALOG` — каталог моделей для UI морды
- Web-профиль берёт модель из `DEEPSEEK_MODEL` через env

Проблемы:
1. Паритета нет: если веб выбирает модель через UI, раннер не видит этот выбор
2. Контекстные окна жёстко закодированы в vars и не обновляются без переноса
3. Изменение модели требует ручного обновления переменных и перезагрузки компонентов

## Решение

Одно место правды для конфига моделей: **DO storage** в Durable Object морды.

### Архитектура

```
┌─────────────────┐
│ DO storage      │   Одно место правды
│ defaultModel    │   (можно обновить без редеплоя)
└────────┬────────┘
         │
    ┌────┴──────────────┬─────────────┐
    ▼                   ▼             ▼
 GET /api/config   Веб-UI         Раннер
 (по запросу)    (Settings)      (до старта)
```

### Механизм

1. **GET /api/config** → возвращает:
   ```json
   {
     "defaultModel": "glm-5.3-flash",
     "models": [
       {"id": "glm-5.3-flash", "name": "GLM-5.3-Flash", "contextWindow": 131072},
       {"id": "glm-5.3", "name": "GLM-5.3", "contextWindow": 1000000}
     ],
     "maxOutputTokens": 131072
   }
   ```

2. **PUT /api/config** `{"model": "glm-5.3"}` → обновляет DO storage, возвращает `{"model": "glm-5.3"}`

3. **Инициализация**:
   - При пустом storage: использует `DEEPSEEK_MODEL` из env (текущая переменная)
   - При изменении через UI: обновляется в DO storage
   - Раннер и веб запрашивают конфиг перед стартом через GET /api/config

### Контекстные окна (обновлены в vars.DSH_EDGE_MODEL_CATALOG)

- **glm-5.3-flash**: 131,072 (128K)
- **glm-5.3**: 1,000,000 (1M)
- **glm-5**: 1,000,000 (1M)
- **glm-4.7**: 131,072 (128K)

## Следствие

- Веб может менять дефолтную модель, раннер подхватит при следующем старте
- Нет необходимости в перекомпиляции или перезагрузке компонентов
- Контекстные окна в одном месте и легко обновляются

## Что требует доделки

1. **Скрипты раннера** (scripts/hands/dsh_task.sh, scripts/worker/task.sh) должны вызвать GET /api/config и подставить `defaultModel` в `DEEPSEEK_MODEL`
2. **Веб-интерфейс** (dsh-web Settings → Models) должен обновлять модель через PUT /api/config
3. **Инсталляция модели в web-профиль** — на продакшн может потребоваться обновить secret DEEPSEEK_MODEL в CF воркере вручную (раннер не может обновить CF secrets, это требует прав)

## Реализовано

- ✅ API эндпоинты GET/PUT /api/config в harness.ts
- ✅ Хранилище конфига в DO storage
- ✅ Обновлены контекстные окна моделей в vars
- ✅ Каталог моделей включает глm-5.3-flash как дефолт
