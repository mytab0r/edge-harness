# Playbook автономного воркера

Ты — воркер-агент проекта edge-harness, работающий автономно в облаке (раннер).
Владелец делегировал все решения. Этот файл — дистилляция живой практики главной
сессии; [AGENTS.md](../../AGENTS.md) и [PROTOCOL](PROTOCOL.md) — обязательный фундамент, здесь —
только то, чего там нет или что оплачено шишками.

## Главные правила взаимодействия

1. **Не задавай вопросов и не жди действий владельца.** Все решения — твои.
   Ревью делай сам (второй взгляд — отдельный агент на дифф).
2. **Единственная эскалация** — упёрся в то, что существует только у владельца:
   секрет вне хранилища, доступ, деньги, необратимое внешнее действие. Тогда:
   комментарий в задачу (что нужно и почему не сам) + метка `blocked` + Telegram
   (секреты `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`, текст ASCII/UTF-8) — и
   **переходи к следующей задаче**, не блокируй конвейер.
3. **Решение принято — зафиксируй его** в задаче/спеке (что решил и почему) и
   делай. Смена курса владельцем в задаче/комментарии = новый ввод, обрабатывается
   сразу.

## Принципы (детали в AGENTS.md, каждый оплачен ошибкой)

- Одно место правды; fail loud; закрыл случай — закрой класс; проверяй
  видимый результат, а не шаг; тест кормится прод-формой; не переисследуй
  документированное (`docs/INDEX.md`); не знаешь — «не подтверждено».
- DSH прежде инфры; не дублируй построенное владельцем (combo-router,
  oauth-pool); архитектурное предложение — сначала `docs/research/30-rejected-alternatives.md`.

## Конвейер задачи

1. Пул: `gh issue list --label task --state open --json number,assignees` —
   свободная (нет assignee). Открытый PR без исполнителя не блокирует выбор —
   это задача на доводку (#245), не занятая: `scheduler.py::unhealthy_pulls`
   снимает исполнителя с нездорового PR намеренно, чтобы его подхватили. В
   автотранспорте (`scripts/worker/task.sh`) пул вдобавок отфильтрован по
   живым замкам аренды (`lease_cli locks`, #121) — вторая, независимая от
   assignee гарантия.
2. Захват: транспорт делает его сам — атомарная аренда `claim_task.py claim N`
   (замок + назначение + след в задаче, #121). Работаешь руками, не через
   транспорт — возьми аренду той же командой: назначение без замка защитой
   не является. Прочитай тело ЦЕЛИКОМ.
3. Ветка: `scripts/git/task-branch N-slug` для новой задачи; если на задачу уже
   открыт PR без исполнителя (declared_tasks — строка тела, начинающаяся с
   `#N`, обычно первая, `scripts/lib/task_ref.py`) — чекаут его ветки (`git fetch origin <ветка> &&
   git checkout -B <ветка> origin/<ветка>`), новый PR не открывать. Гвардия
   свежести (та же, что у `task-branch`) — при «main уехал» `git rebase
   origin/main` и повтори.
4. Перед кодом: `docs/INDEX.md` → релевантные research/спеки; архитектурное
   решение — сначала `30-rejected-alternatives.md`.
5. Дифф минимальный и правильный; тесты; саморевью (секреты, мёртвый код,
   доки-vs-код, вызовы переименованных функций по всему репо).
6. PR: первая строка `#N`, **БЕЗ** Closes/Fixes/Resolves (контракт отклонит);
   разделы Что сделано / Чем доказано (видимый результат) / Пост-мерж проверка /
   Чек-лист.
7. Ревью: детерминированный гейт даёт `review:ok`, затем AI-ревьюер (#18) —
   `ai:ok` или `ai:changes-requested` (находки — доработать и запушить заново;
   `ai:failed` — сбой ревью-инфраструктуры, повтор `gh workflow run ai-review -f pr=<N>`).
8. Оркестратор сливает (сериализованно, оба гейта зелёные). После мержа задачу
   закрывает стадия приёмки (#227), не ты: планировщик сам сопоставляет слитый
   PR с задачей и проверяет улику (деплой/check-runs/файлы в main) каждые 15
   минут. **Не закрывай задачу вручную** (`gh issue close`) — это обход
   проверки, ровно класс #56/#57, против которого приёмка и вводилась.
   Единственное, что можешь ускорить — реальный пост-мерж прогон (канарейка/
   E2E), если критерий его требует: без него улике неоткуда взяться.

## Грабли конвейера (каждая оплачена)

- Контракт: строка тела с `#N`, задача ОТКРЫТА и назначена тебе; иначе —
  `contract:failed`. Для docs-only после закрытой задачи — метка `orchestra:skip`
  + `gh run rerun <orchestra-run> --failed` + `gh workflow run orchestra`.
- Большие диффы (>800 строк): реальное ревью (второй агент, вердикт в PR) →
  метка `review:large-ok` → merge.
- Второй гейт (#18): после `review:ok` дифф ревьюит AI-агент (workflow
  `ai-review`) — для слияния нужна метка `ai:ok`. `ai:changes-requested` —
  находки в ревью-комментарии PR: доработай и запушь, оба гейта пройдут
  заново. `ai:failed` — сбой инфраструктуры ревью (не твой код): повтор
  `gh workflow run ai-review -f pr=<N>`. Задачи, предложенные ревью в беклог,
  заводятся одной командой: `python scripts/review/file_tasks.py --pr <N>`.
- Оркестратор сливает РОВНО ОДИН PR за запуск и может слить твой PR пока ты
  работаешь дальше по нему — всегда `git fetch` и проверяй состояние перед
  продолжением.
- Прямые пуши в main тихо отклоняются; пушь ветки с проверкой результата.
- `workflow_dispatch` из CI требует actions:write в permissions воркфлоу.

## Мультиагент

- Крупную задачу дели: независимые части — параллельным саб-агентам (штатные
  subagents DSH); ревью крупного диффа — отдельный агент, находки — автору.
- Решения прими сам; журнал решений — в задаче и спеке.

## Механика DSH (всё проверено прогонами)

Источники: [архитектура DSH](../research/10-dsh-architecture.md#дистрибуция-в-npm-подтверждено-замером-2026-08-2829), [runbook смены провайдера](../runbooks/switch-llm-provider.md), [dsh-edge](../research/11-dsh-edge.md).

- Пакеты `@deepseek-ai/dsh-*` ставятся ТОЛЬКО tarball'ами: `npm pack <pkg>@<ver>`
  → установка из локальных tgz (`npm install` даёт 404). [подтверждено замером](../research/10-dsh-architecture.md#дистрибуция-в-npm-подтверждено-замером-2026-08-2829)
- Провайдер и модель приезжают в env раннера из `vars`/`secrets` репозитория
  (`DEEPSEEK_BASE_URL`, `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL`) — единственное
  место правды (#153). Локально не угадывай конкретный эндпоинт/модель;
  процедура смены — `docs/runbooks/switch-llm-provider.md`. Модель — НЕ env
  для самого DSH, а патч профиля `~/.dsh/profiles/<профиль>/cordis.patch.yml`:
  `agent-default-model` → `{provider: deepseek-official, model: <DEEPSEEK_MODEL>}` +
  `llm-deepseek` → `{maxTokens: <лимит модели>}` (иначе modelCode/maxTokens-ошибки). [подтверждено живым прогоном](../research/10-dsh-architecture.md#запуск-headless-с-внешним-openai-compat-провайдером--подтверждено-живым-прогоном-2026-08-30)
- headless: one-shot, exit 0 только при `turn/end completed`; аппрувы
  fail-closed — не формулируй задачи, требующие аппрува; cwd до старта = корень
  воркспейса, после не менять. [контракт headless](../research/10-dsh-architecture.md#дистрибуция-в-npm-подтверждено-замером-2026-08-2829)
- Установка плагинов в headless-профиль: `dsh plugin --profile headless add <tgz>`
  + проверка `--dump-config` до прогона. [подтверждено](../research/10-dsh-architecture.md#12-как-подменить-провайдера-без-форка)
