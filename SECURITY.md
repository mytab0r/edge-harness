# Политика безопасности

## Как сообщить об уязвимости

Пользуйся **Private vulnerability reporting** (вкладка Security → Report a vulnerability):
репорт уходит приватно, без публичного issue. Публичные issue с деталями уязвимостей
закрываются с просьбой переоформить приватно.

## Что считается уязвимостью

- Обход аутентификации `HANDS_TOKEN` на `/api/*` (включая WebSocket `?token=`).
- Утечка токенов в логи/ответы (GitHub скрывает только точные совпадения — помни про
  производные значения, см. docs/research/21-github-actions.md).
- Инъекция в `wrangler deploy` / подмена артефактов деплоя.
- SSRF/инъекции через `payload` задач в Durable Object.

## Что НЕ является уязвимостью

- Публичность репозитория и документации — это осознанное решение.
- Отсутствие мультитенантности/пользователей — аутентификация «один разделяемый
  секрет» принята для текущей фазы (openspec/changes/walking-skeleton/proposal.md).

## Реакция

Цель — первый ответ за 3 дня, исправление критичных — за 7. Исправления идут через
стандартный конвейер (docs/agents/PROTOCOL.md) с меткой `security`.
